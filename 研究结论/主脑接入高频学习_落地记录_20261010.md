# 主脑接入高频学习（一个入口 / 一本知识库 / 一张嘴 / 一道关）——落地记录

**生成：2026-10-10 15:5x｜用户指令：「看看进行更加深入的设计」＋已批准的一体化设计**
**范围：高频 ping-pong 的每一笔来回并入统一学习入口；书/论文蒸馏成带出处的知识卡片；
大模型按车道每轮只提一个白名单旋钮且必须引用知识编号；落地前后各走该车道已有的统计关。**

## 0. 这次真的改了什么（一句话）

此前整个项目的学习是**三套并排转**：中/长线平仓进
`unified_learning.process_outcome`，而高频（`mm_asterdex` 车道的 ping-pong 来回）
自己记 `flow_roundtrip_log.jsonl`、自己算 `pp_symbol_stats.json`，**从不进主脑**。
本次补上那**唯一缺失的入口**，并把「知识库 → 一个旋钮 → 统计关 → 回滚」这条链
全部接在既有组件上（没有新开第二个学习系统、没有新开第二个库）。

| 层 | 改动 | 载体 |
|---|---|---|
| 一个入口 | `lane_ledger` 里新的 PP 平仓腿 → 主脑 `process_outcome` | 新 `market_maker/pp_brain.py` + 新 tick `learning_loop_hft_brain` |
| 一本知识库 | 36 张书/论文蒸馏卡片进既有 RAG 的新 collection `knowledge_cards` | 新 `backend/data/knowledge_cards.json` + `rag_knowledge_service.index_knowledge_cards()` |
| 按车道检索 | 卡片按 `lanes` 过滤 + 与「我们自己的教训」一起给 | 新 `knowledge_lane_retriever.py` |
| 一张嘴 | 每车道一轮、只提一个白名单旋钮、**必须引用卡片编号** | 新 `market_maker/brain_advisor.py` |
| 一道关 | 高频四项旋钮走 `self_tuner.apply_proposal`→`self_tuner_verdict`（改后变差就退回）；中/长线走 `runtime_tuning_store.apply_patches` | 复用既有两条链路，未新写 |

## 3. 隔离设计里**唯一必须记下来的坑**（实测发现并已修）

高频的第一笔进主脑后，`strategy_regime_scores` 的分组键**落进了 `auto_mid_BTC`**：

- `AIStrategy.primary_symbol` 的模型默认值是 `"BTC"`、`timeframe_tier` 的
  server_default 是 `"mid"`（`models.py:831/863`）⇒ 高频的占位父行被建成
  "BTC 的中线策略"；
- `_update_regime_score` 在 `template_id` 为空时用 `auto_{nature}_{symbol}` 合成分组键
  ⇒ 高频样本直接写进了中线的绩效矩阵。

修法两处（都已在本次实现里）：
1. 建占位行时**显式声明** `timeframe_tier='hft'`、`primary_symbol=''`；
2. 已存在的错行**就地自愈**（`_resolve_strategy_id_for_fk` 里回写正确 tier/symbol）。

复验（`backend/tests/tools/accept_hft_inlet_20261010.py` 同族断言）：

```
before: {'auto_mid_BTC': 3455, 'auto_hft_?': 2}
after : {'auto_mid_BTC': 3455, 'auto_hft_?': 5}
auto_mid_BTC 增长 = 0（必须为 0）
auto_hft_?   增长 = 3（应为正：高频有自己的分组）
```
（历史遗留的 `auto_mid_BTC` 旧计数按"历史行仍保留在库中供审计"的既有口径**不回改**。）

## 5. 中/长线白名单：只收**热生效**的键（这是本次最重要的设计约束）

对 `MIDLONG_*` / `TREND_*` / `EXIT_POLICY_*` 做了逐键侦察（约 50 个 mid、30 个 long），
结论：**绝大多数是 `os.getenv(...)` 在 import 期解析一次**，改 `.env` 要重启才生效。
而落地后把关是**改后 30 分钟就比指标**（`self_tuner_verdict` 的 `MM_VERDICT_DELAY_SEC`）
⇒ 一个"还没生效"的参数会被判成"变差"而**误回滚**。

因此中/长线白名单**只收 `data/runtime_tuning.json` 这一条热生效通道**（写入口
`runtime_tuning_store.apply_patches`，带 schema 钳制；读侧 60s 缓存刷新）：

| 车道 | 白名单键 | 边界 |
|---|---|---|
| mid | `mid_daily_cap` | 0–60（与 schema 同） |
| mid | `master_reduce_min_loss_pct` | 0.05–0.20（与 schema 同） |
| mid | `master_close_min_loss_pct_by_tier.mid` | 0.02–0.10（schema 无边界，由白名单给） |
| mid | `by_nature.swing.min_confidence` | 45–80 |
| mid | `by_nature.swing.min_risk_reward` | 1.2–3.0（与 `_BY_NATURE_CLAMP` 同） |
| mid | `by_nature.swing.min_alignment` | 3–10 |
| long | `trend_daily_cap` | 0–60 |
| long | `master_reduce_min_loss_pct` | 0.05–0.20 |
| long | `master_close_min_loss_pct_by_tier.long` | 0.04–0.15 |
| long | `by_nature.trend_follow.min_score` | 40–85 |
| long | `by_nature.trend_follow.min_risk_reward` | 1.2–3.0 |
| long | `by_nature.trend_follow.min_alignment` | 3–10 |

**明确不进白名单**（侦察记录，防止以后被人"顺手加进去"）：
`tier_max_hold_sec.*`（`HOLD_TIME_TUNING_LOCKED=true` 直接拒绝写入）；
`TREND_ENTRY_RULE`/`TREND_STOP_RATCHET`/`TREND_WEIGHTING`/`TREND_CORE_SYMBOLS`/
`EXIT_POLICY_*_TP_STAGES`/`EXIT_POLICY_*_STRUCTURAL_STOP`/`MIDLONG_CHOP_MODE`/
`MIDLONG_EDGE_M_TH`/`MIDLONG_EDGE_Z_BTC_TH`（策略身份）；
`TIER_MID_MIN_SL`/`MAX_SL`/`MIN_TP`/`MAX_TP`/`TREND_SL_SAFETY_NET`/`LONG_V2_PYRAMID_R`
（**死键**：UI 有、交易路径 0 读取，`settings.py:683-689` 是硬编码字面量）；
`PB_MIDLONG_*`（`PB_PAPER_SKIP=true` 下在 paper 上等于死键）。

## 6. 落地后后置把关（无需新增调度）

| 车道 | 落地通道 | 改后把关 | 变差就退回 |
|---|---|---|---|
| hft | `self_tuner.apply_proposal` → `data/flow_learn_params.json`（**下一拍生效**） | `DSH_MM_SELF_TUNE_VERDICT` 每 15 分钟 | `should_rollback_flow`：改后 mean_y < 改前 × 0.8 / 吃单费占比升 / 挂单率降 / 出现强平 / 笔数升而均值降 |
| hft（仅 `pp_bucket_min_n`） | 同上；**额外**先走 `evolution.pp_evolution_round` 的**事前反事实** | 同一条链 | 反事实最优 ≠ 提议值 ⇒ 直接拦下 |
| mid/long | `runtime_tuning_store.apply_patches`（**60s 内生效**） | 同一条链读该车道平仓账 | 同上 |

`pp_rest_sec / pp_thin_frac / pp_exit_ticks` **做不到事前反事实**（账里没有"如果当时歇
20 秒会不会成交"），因此它们只有"改后 30 笔内变差就退回"。这一条是本次设计对
"过统计关才改"的**诚实弱化**，已写进 `brain_advisor` 的模块注释与每轮 journal。

## 7. 显式假设 / 未完成项（不隐瞒）

1. **高频入口要在后端重启后才注册那个 5 分钟 tick**（`register_tasks` 在启动时跑）。
   在此之前可手动补：`python -m backend.services.market_maker.pp_brain`，或调
   `/api/learning/loop/trigger/hft_brain`。
2. **首次开机会补历史**：游标缺省 = `data/pp_era_start_ts.txt`（era 起点，当前
   `1791567757`），era 起已有 **220 条** `rt_bp` 平仓腿；每次 tick 上限
   `MM_PP_BRAIN_LIMIT=200` ⇒ 最多 2 个 tick 追平，**有界**。
3. **卡片只做到"机制类"**：书里的具体数值表格、Cont 等 (2010) 的成簇定量刻画、
   hftbacktest 教程引用的其它文献、交易所官方资金费/强平规则文档——这 4 条**没有**
   写成卡片（找不到可点开的原始出处就**不编造**），已记在卡片文件的 `meta.unverified`。
   所有卡片 `source_url` 均经 Crossref / OpenAlex / arXiv / OpenLibrary 核对。
4. **`auto_hft_?` 里有"?"**：这是 `_update_regime_score` 既有公式
   `auto_{nature}_{symbol}` 在 `primary_symbol=''` 时的产物。它只是分组键、不影响学习，
   故未改公式（改它会动到中/长线的既有分组）。
5. **中/长线的"可调旋钮"还有一大批没进白名单**：它们**在跑但不是热生效**。
   要让它们进自动闭环，需要先把它们接进 `runtime_tuning`（或做"重启感知的改后判定"），
   那是独立的一项工程，不在本次范围。
6. **实盘车道 `mm_asterdex_live`**：`status=stopped`；它一旦启动会**共用**同一份
   `data/flow_learn_params.json`（`sync_live_cfg` 在 `active_flow_mode>0` 时只同步
   symbols，不碰 params）。这是既有耦合，本次不新增也不修复，仅在 journal 记明。
7. **`current_params` 里的中/长线现值**是 `runtime_tuning` 的当前值；对应的
   `.env` 层还有一批同名语义的键（如 `MIDLONG_TIME_STOP_*`）**不在**白名单，
   所以"模型不能改"≠"参数不存在"。
