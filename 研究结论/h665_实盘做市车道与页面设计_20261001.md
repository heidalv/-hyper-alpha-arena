# 实盘做市车道与实盘页面设计(h665,2026-10-01)

> 用户指令:"做实盘页面,实盘和模拟分开"。范围:高频做市(mm)的实盘版。
> 现状:/hft = mm_asterdex **纸面**车道(模拟);实盘执行链已存在
> (AsterdexAdapter maker-first 下单 + 真实余额/持仓 + LiveExecutor),
> 只差"mm 引擎 → 交易所"的执行桥与独立实盘车道/页面。

## 1. 架构

```
mm_asterdex(模拟)                     mm_asterdex_live(实盘,新增)
  │ 同一套引擎代码(runner/plan_tick)      │ 参数独立复制、独立判决
  │ 成交=段内主动量模拟                    │ 成交=交易所真实回报
  │ 账本 lane_ledger                     │ 账本 lane_ledger(lane_id 区分)
  └─ /hft(模拟页)                        └─ /hft/live(实盘页,红标)
```

**执行桥(quote gateway,唯一新核心件)**:每 tick 引擎产出期望报价
(bid/ask/qty) → 桥对照交易所在所挂单 → 价量一致不动 / 不一致则
cancel+place(post-only;减仓侧 reduce-only)→ 成交回报写实盘账本 →
attribution/direction/Q 全复用(同口径)。

## 2. 实盘专属风险闸(模拟没有,全部预注册可回滚)

| 闸 | 默认值 | 动作 |
|---|---|---|
| 总名义上限 | $500 | 超限停加仓 |
| 单币名义上限 | $150 | 超限停该币 |
| 日亏上限 | $30 | 停车道+撤全单 |
| 下单熔断 | 连续 reject ≥3 | 停车道(60s 冷却) |
| kill switch | lane status=stopped | 撤全部挂单,禁止再下 |

## 3. 实施阶段

- **Stage 1 后端**:live 车道注册(mode=live)+ 执行桥 + 实盘账本 + 风险闸 + kill switch。
- **Stage 2 API**:`/api/hft/live/*`(状态/账本/风险/启停/撤单)。
- **Stage 3 前端**:`/hft/live` 实盘页(红标"实盘"、真实余额/持仓/挂单/盈亏/风险/启停;
  确认词双保险),与 /hft 模拟页彻底分离;侧栏"高频交易"组分两个入口。
- **Stage 4 验收**:配置 Asterdex API Key(env 或 exchange_credentials)→
  **最小规模试跑**(名义上限 $100)12h → 判决 → 逐步放量。

## 4. 安全红线(写死)

1. live 车道默认 **active=false**;无 API Key 禁止激活;
2. 实盘参数修改走 mm_apply_params(live 车道),与模拟互不触碰;
3. 实盘页每个控制按钮需确认词;模拟页无实盘按钮;
4. 判决口径复用 d1_verdict(--lane mm_asterdex_live),同 Welch 口径;
5. 实盘首跑禁止自动连跑:每 12h 判决一次,不通过自动回滚停车道。

## 5. 验收判据

- 模拟 /hft 与实盘 /hft/live 完全隔离(启停/参数/账本互不影响);
- 实盘页显示真实交易所余额/持仓/挂单(3s 轮询),盈亏与交易所对账一致;
- 实盘名义≤$500 且日亏≤$30 时自动停;kill switch 一键撤全单。
