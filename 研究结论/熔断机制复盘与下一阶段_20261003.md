## 二、熔断语义修正:熔断的是"这批币",不是整个系统

**原实现(错误):** 日亏触发 → 整车道停摆到日界(≈18.5 小时,且无提示、无复开)。

**新实现(h749/h750,冷却式宇宙熔断):**
```
日亏跌破触发线
  → 停 15 分钟(daily_loss_cooldown_sec=900,超短口径)
  → 记录"熔断宇宙"(当时在跑的这批币)
  → 到点自动复开 + 强制雷达按亏损衰减换币(换一批再打,不原宇宙重启)
  → 触发线按次数阶梯抬高:第 N 次触发线 = 限额×N(每次至多亏一个限额档)
  → 连续触发才升级(车道级兜底)
```

**熔断全部关闭的条件(生命周期的终点):**
- 日亏回升越过**限额线 + 0.5U 滞回裕度** ⇒ 计数归零(复位);
- 北京自然日 0 点日亏归零 ⇒ 天然重武装;
- 裕度是必须的:compound 复利块每 tick 用账户权益重算 equity(实测 283↔300 抖动)⇒
  熔断线每 tick 波动,无裕度时"复位"与"触发"在相邻 tick 互相踩踏 → 无限循环熔断
  (dl_debug 实测确诊;0.5U 滞回已修)。

**提示:** 前端 /hft 页红色横幅(暂停原因 + 复开倒计时)+ worker 事件流;
`/hft/evolution` 带 lane_pause 字段。

## 四、下一阶段:怎么赚钱 + 概率分析完善

**当前已验证的赚钱事实(数据,不是假设):**
1. maker 腿的每腿净由**捕获档**决定(L16):挂宽 4.8bp → 捕获 ≈2bp → d 档 +3.2~5.8bp/腿;
2. 引擎在 145 条 maker 腿上 +0.63U/天,亏损全部来自出场侧(已重做);
3. 方向不可预测(L12:条件胜率 ≈50%±3pt)⇒ 赚钱靠"捕获 − 逆向"的期望值,不靠预测。

**概率分析的三项完善(按优先级):**
| # | 内容 | 依据 |
|---|---|---|
| P4 | **成交强度校准**:触及率 ≠ 成交率;用"实际成交数/触及桶数"逐币校准 λ(δ),让 EV 引擎的期望值诚实 | h739 漏斗:我方/打中桶 ≈11%(还有 89% 的挂单覆盖缺口) |
| P5 | **逐币条件逆向**:用闸门影子数据估计每币每状态的 E[逆向\|成交](替代全局 1.0bp),EV 引擎逐币判定 | 条件胜率表(mp −3pt / ofi +3pt 反) |
| P6 | **KPI 驱动的宽度 regime**:逆向/捕获 <0.7 ⇒ δ*=4.8;0.7~1.2 ⇒ δ*=6(多吃捕获);>1.2 ⇒ 缩量(×0.85)或停挂该侧 —— 概率范式对"毒性"的一致性响应 | KPI 实测 0.4→4.3 全天漂移 |

**验证口径(24/7,用户纠正后修订:加密永续 7×24 交易,没有开盘时间,任何时段都
必须能打,不允许用时段性理由解释亏损):**
- 主指标:**近 4h 滚动窗口每腿净 >0**(n≥20 时),逐桥检查轮追踪,不分时段;
- 近 1h/12h/24h 滚动窗口作为趋势参照;
- 捕获 ≥1bp 的腿占比 ≥70%(死亡档占比 <20%);
- 无 −20bp 以下的出场腿(止损追底已修);
- 薄量时段(如亚盘午后)不是"没市场",是**市场的一种常态** ⇒ 系统必须用
  缩量/放宽等 regime 响应适配,而不是等待别的时段(P6 为最高优先级)。
