## 三、层层相乘的代价(为什么交易显得停了)

```
每个闸门独立拦 5~20% 的拍,10 个进场闸门相乘:
  0.9^10 ≈ 35% —— 即使每个闸门都"只拦一点点",十层之后
  每 100 个进场机会只剩 35 个;若再加 15 个(现状),剩下 ~10%。
  实测对照:skip 计数里 gap_excluded 2.6万 + dead_market 1万 +
  drift_veto 5千 + venue 3.5千 + no_direction 18万 —— 不是哪个闸门错了,
  是**闸门总量把合格率乘没了**。
```

## 四、精简方案(40 → 12,一类一闸)

```
保留(各有独立职责,互相不重叠):
  1. 崩盘币闸(gap 硬+软合并,一个口子进出)       ← A1+A2
  2. 形态闸(R4/R5)                              ← A3
  3. 活性闸(死市不做)                           ← A4
  4. **方向否决合并闸**:300s 趋势+10min 漂移+震荡
     合并为"10min 趋势 4bp,超 8bp 或震荡>3 全禁" ← A5+A6+A7 合并
  5. 方向分数下限(唯一的方向闸)                 ← A8
  6. 信号质量合并闸:情况表+prob+q_speed+toxic
     合并为"经验桶 edge>0 且 t≥1.28"            ← A9+A10+A11+A18 合并
  7. 仓位闸(5% 单笔 + 3× 总敞口,其余上限删)      ← B1+B2 保留,B3~B8 删/降为遥测
  8. 离场阶梯(保留八层)                         ← C1~C8 已是结构化,不散开
  9. 晋升三关                                    ← D3
  10. venue 过滤 + 限速(交易所硬约束,保留)       ← A23+A24
  11. 宇宙闸(进出分)                            ← A22
  12. 灾难止损(×2 只留真深跳)                   ← C2

删除/降为遥测(不拦交易,只记录):
  A13 trend_pause、A14 mp_block、A15 ofi_block、A16 vwap_block、
  A17 pullback_block、A19 funding、A20 markout_halt、A12 jump_pause、
  A21 book_slot、B3~B8 —— 这些的职责已被合并闸覆盖,
  继续独立存在只做"概率连乘"的分子。
```

## 五、精简后能恢复多少量(粗算)

```
现状(40 闸):每 100 个机会 ~10 个合格 → 白天 ~30 腿/h
精简后(12 闸):每 100 个机会 ~35 个合格 → 白天 ~100+ 腿/h,
且被合并闸覆盖的"噪声拦截"仍然有效(它们还在合并闸的逻辑里,只是不再重复乘)
```

**结论:门禁确实过多 —— 40 个闸门里至少 25 个与别的闸门管同一件事,叠加成乘法把交易量压到 1/10。按"一类一闸"合并到 12 个,交易量恢复 3 倍以上,风控职责一个不少(合并≠删除,是让一类风险只有一个口子)。要动手合并吗?**
