# 高频影子做市全面升级设计（h624）

> 版本：2026-09-29  
> 车道：`mm_asterdex`（Aster 永续纸面做市，maker 0 / taker 4bp）  
> 依据：`研究结论/高频做市正收益调研报告_20260929.md`、账本根因、已上线的 h621/h623  
> 目标：费后名义加权净 bp **连续样本 > 0**，且「一笔止损吃光十笔赚」的结构消失  

---

## 1. 设计原则（写代码前先锁死）

| # | 原则 | 违反时的后果 |
|---|---|---|
| P1 | **吃单是保险，不是日常出场** | 4bp × 高频 = 结构必亏 |
| P2 | **捕获 − 逆选择 − 费 > 0 才允许开仓** | 胜率再高也净负 |
| P3 | **库存用报价卸，不用止损猜方向** | 赢小输大 |
| P4 | **单变量上线、可一键回退** | 再瘫痪 / 无法归因 |
| P5 | **回放与实盘同一成交源（逐笔）** | 调参结论不可信 |
| P6 | **KPI = 费后净 bp + 吃单费占比 + 止损占比** | 用笔数会自我欺骗 |

不做的事（本设计明确排除）：

- 全局拉大 `spread_mult` 当「正收益」  
- 无 maker 返佣时做刷量  
- 把 LLM 读新闻变成追涨指令  
- 一次打开多个互相耦合的闸门（下午瘫痪事故的教训）

## 3. 目标架构

### 3.1 逻辑分层

```text
┌─────────────────────────────────────────────────────────┐
│  L4  治理：选币 / 进化 / 试跑晋升 / 日 KPI 熔断           │
├─────────────────────────────────────────────────────────┤
│  L3  体制：平静 | 趋势 | 跳变 | 事件窗口                   │
├─────────────────────────────────────────────────────────┤
│  L2  报价：GLFT/AS 半价差与绝对偏斜 + F280 不穿越钳制      │
├─────────────────────────────────────────────────────────┤
│  L1  成交：逐笔 exact-hit + 队列份额（纸面）               │
├─────────────────────────────────────────────────────────┤
│  L0  数据：book_ticker / trades / 可选事件日历            │
└─────────────────────────────────────────────────────────┘
```

Worker（`mm_lane_worker`）每秒跑一圈：L0→L1 判定旧单→L2 算新单→L3 闸门改两侧许可→落账本→心跳。  
L4 仍由计划任务异步写 `lane_registry.meta`，runner 60s 热加载。

### 3.2 单 tick 决策序（升级后）

```text
1. 刷新新鲜盘口 + 逐笔窗口成交量
2. 判定旧挂单是否成交（tick_fill）
3. 强制出场（止损宽限 / 超时挂单 / 硬顶保险）—— 默认 maker
4. 体制判定：事件? 跳变? 该币 markout 门禁? → 可 pause / 只减仓
5. 库存偏斜 + GLFT 宽度 → compute_quote
6. 盈亏平衡校验：half_capture < break_even → 撤加仓侧
7. 侧许可：entry_block / inv_add / trend_add_q / ofi / …
8. 写报价历史（供延迟可见成交对齐）
9. 账本 + markout 探针异步更新
```

## 4.  dig 功能设计

### 4.1 Markout 毒性门禁（最高优先级新能力）

**问题：** 现在只知道事后 `price_bp`，不知道「成交后市场朝哪走」。

**设计：**

1. 每笔 maker 成交写入 `meta_json`：`fill_ts_ms, fill_px, side, mid_at_fill`。  
2. 后台或同进程延迟任务，在 +1s / +5s / +30s 读 `asterdex_book_ticker` 中价，算：

```text
markout_bp(τ) = side_sign × (mid(t+τ) − fill_px) / fill_px × 1e4
```

买：价格涨为正；卖：价格跌为正。  
逆选择 ⇒ markout 为负。

3. 每币滚动 1 小时（或最近 40 笔）名义加权：

```text
m30 = E[markout_bp(30s)]
cap = E[开仓 spread_bp]
若 m30 + cap < markout_halt_bp（默认 0）⇒ 该币停加仓（减仓豁免）
```

**参数（`LaneRiskLimits`）：**

| 参数 | 默认 | 含义 |
|---|---|---|
| `markout_halt_bp` | 0 | ≤0 关闭；0 开启时表示 m30+cap<0 就停 |
| `markout_window_n` | 40 | 最少样本 |
| `markout_horizon_sec` | 30 | 主门禁地平线 |

**验收：** 单测注入负 markout 历史 ⇒ `skip=markout_halt` 且 ask/bid 仅减仓侧存活；默认 0 时行为不变。

**观测：** 心跳 `markout_by_symbol: {SYM: {m1,m5,m30,cap,halt}}`。

---

### 4.2 开仓盈亏平衡硬校验

**公式（纸面）：**

```text
break_even_bp = max(0, −E[markout_30s]) + taker_fee_bp × p_exit_taker_hat
                 + inventory_cost_hat
```

首版简化（可上线）：

```text
break_even_bp = max(0, −rolling_m30) + 4 × stop_share_hat
```

`stop_share_hat` = 近 24h 该币止损腿数 / 总腿数（上限 0.15，避免冷启动爆炸）。

开仓前：

```text
expected_capture_bp = 当前挂单相对 mid 的半宽（bp）
若 expected_capture_bp < break_even_bp × be_mult（默认 1.0）
  ⇒ 撤加仓侧（skip=break_even_block）
```

**参数：** `break_even_block` bool 或 `be_mult`（0=关）。

**验收：** 捕获 0.4bp、break_even 2bp ⇒ 空仓不挂；有多头仍挂卖。

### 4.3 体制机（Regime）

| 体制 | 触发 | 行为 |
|---|---|---|
| `calm` | 默认 | 正常双边（受其它闸） |

| `jump_pause_sec` | 60 | 撤单持续时间 |
| `event_guard_enabled` | false | |
| `trade_rate_z` | 0 | >0 时成交速率熔断 |

### 4.4 GLFT / AS 报价升级（替换「半价差 × spread_mult」长期方案）

**保留 F280 不穿越钳制**（测试锁死 `best_bid ≤ bid ≤ ask ≤ best_ask` 的「不穿对侧」语义；允许加仓侧劣于最优价）。

**新模式 `quote_mode="glft"`（默认仍 `spread`）：**

```text
c1 = glft_c1_bp          # 基础半价差（或由强度拟合）
c2 = glft_c2             # 库存敏感度
σ  = realized_vol 归一
half = c1 + k_σ · σ
skew = inv_skew_abs_bp · inv_ratio   # 已有绝对偏斜，可再 × (1+k_σ·σ)
bid = mid · (1 − (half + skew_add)/1e4)
ask = mid · (1 + (half − skew_add)/1e4)
再过 F280：加仓侧可劣于 touch；减仓侧可改善到钳制上沿
```

**分阶段：**

- B1：只把 `inv_skew_abs` + `vol_spread_k` 调准（少改）。  
- B2：引入 `quote_mode=glft` 与 `glft_c1_bp/glft_c2`，回放 A/B。  
- B3：线上灰度单币。

**钳制修正（重要）：**  
今日 F280 把买卖都夹进 `[bb,ba]`，绝对偏斜的「加仓侧拉开」会被抹平。  
升级设计：

```text
减仓侧：允许改善到钳制内沿（更优）
加仓侧：允许差于 touch（bb 以下 / ba 以上），但不得穿越对侧
```

需同步改 `test_f280_*.py` 契约，并写清「劣于 touch ≠ 穿越」。

### 4.5 出场状态机（统一）

```text
                 ┌─ 条件解除 ─→ 清 grace，恢复正常报价
                 │
持仓 ─→ 离场信号（止损/衰减/流向/止盈）
                 │
                 └─ 进入 MAKER_GRACE（只挂减仓、撤加仓）
                           │
              ┌────────────┼────────────┐
              ↓            ↓            ↓
         grace 内被      grace 到时    硬顶/跳变
         挂单成交        仍持仓        立即保险
              ↓            ↓            ↓
           记 maker      可选：再延    taker 保险
           平仓          或升 hard
```

**规则：**

1. `timeout` / `ofi_flatten` / `reversal` / `stop` **第一动作都是 MAKER_GRACE**。  
2. 唯有 `jump` 超阈、或 `timeout_hard_taker_sec`、或日亏闸 ⇒ 允许 taker。  
3. 账本 `exit_path` 必须区分：`*_maker` / `*_taker`（已有一半，补齐 stop_maker）。

**参数调整建议（设计值，上线前用试跑窗）：**

| 参数 | 现况 | 设计目标 |
|---|---|---|
| `stop_maker_grace_sec` | 90 | 保持 90～180，看救回率 |
| `timeout_exit_maker_only` | true | 保持 true |
| `ofi_flatten_maker_only` | 1 | 保持 1 |
| `timeout_hard_taker_sec` | 300 | 可提到 450，但要盯敞口 |

### 4.6 选币 / 进化与线上同构

**病根：** `h329_selector_v4` 仍用旧 fade 影子模型，评分与现做市脱节（曾评出「只剩 XRP」）。

**设计：**

1. 选币调用 `replay.replay_symbol(..., tick_series=..., 与线上同一 QuoteParams/LaneRiskLimits)`。  
2. 得分 = **名义加权费后净 bp**；次分 = 吃单费占比（越低越好）。  
3. 硬规则：  
   - `n < 40` 不动；  
   - 开仓净 bp < 0 且样本够 → 摘除或 `entry_block`；  
   - 每次 `max_new ≤ 2`；  
   - 有持仓的币不可从宇宙删除（只标 `entry_block`），防减仓失踪。  
4. 进化奖励：`net_bp_w − λ · taker_fee_share`（λ 建议 2～5）。  
5. Windows 输出 UTF-8（已修箭头崩溃）；计划任务加 `PYTHONIOENCODING=utf-8`。

### 4.7 自动缩仓与踢币（止损经济）

每小时任务（可挂 `DSH_HFT_LANE_ALARM` 旁路或新任务）：

```text
对每个在营币：
  stop_usd = 近 24h 止损净亏
  open_edge = 近 24h 开仓净 bp
  若 stop_usd 占该币净亏 > 70% 且 open_edge < 1bp
      → size_mult *= 0.7（下限 0.15）
  若 open_edge < 0 且腿数 ≥ 30
      → 加入 entry_block_symbols
  若 entry_block 且仓位为 0 且连续 6h
      → 可从 symbols 移除（让出槽位）
```

全部写 `ops_changes`，可回滚。

### 4.8 对冲（阶段 C，不阻塞 A/B）

仅当：

```text
|净敞口| > hedge_trigger_usd
且 减仓侧连续 grace_sec 未被吃
且 费后模拟：对冲腿期望改善 > 2 × taker_fee
```

| 风险 | 缓解 |
|---|---|
| markout 门禁过严 → 无成交 | 阈值从松到紧；只停加仓 |
| 加仓侧劣于 touch → 成交更少 | 预期行为；用减仓质量补 |
| 选币换宇宙过猛 | max_new=2 + 有仓不停宇宙 |
| 跳变暂停过频 | 提高 jump_pause_bp；冷却 |
| 热加载未吃到新字段 | 重启 worker 一次；心跳校验字段 |

回退口令：

```text
注册表把新参数置 0/false
或 MM_SEG_SOURCE=bucket（仅成交源紧急回退）
不回退逐笔与每秒报价（已证实是正确方向）
```
