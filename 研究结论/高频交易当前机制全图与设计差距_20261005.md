## 0. 先回答手续费问题(Aster 主动成交到底多少)

**结论:挂单(maker)0%,主动成交(taker)0.04%(4bp)** —— 与本地假设一致。

| 来源 | Maker | Taker | 备注 |
|---|---|---|---|
| [Aster 官方费率文档](https://docs.asterdex.com/trading/perpetuals/fees-and-specs/fees) | **0%** | **0.040%(4bp)** | Crypto General 组;`$10,000` 吃单 = $4.00 |
| [PerpFinder 实测](https://perpfinder.com/fees/aster)(2026-10-04 06:55 UTC 快照) | 0 bps | 4.00 bps | $10k BTC 市价单实测 4.01bp(含 0.01bp 价差/冲击) |
| 本地账本实证(近 6h) | `flow_entry_maker` 平均 fee = **0.00bp** ✓ | `taker_stop` 平均 **−4.00bp** ✓ | 与官方一致 |

**其他组的费率(同一文档)**:Crypto Group B 吃单 0.1%;USD1 计价的 BTC/ETH/SOL
吃单 0.005%;1001x 模式开平 0.08%;Shield Mode 0.03%。资金费每 8 小时。
对照:Binance 吃单 0.05%、Hyperliquid 0.045% —— Aster 吃单更便宜,但**挂单 0 费
才是这套策略的立身之本**。

**⇒ 含义:任何一次吃单都要先赚回 4bp 才算不亏;一次"挂单进 + 吃单出"的往返
先付 4bp,一次"吃单进 + 吃单出"付 8bp。当前设计已把正常路径全部放在挂单侧。**

> 打的(`dec.exit_path`),同一 tick 里既有挂单腿又有吃单腿时,吃单腿会被标成

> `explore_trend_veto`/`active_flow_error`,说明是混 tick)。**修法:把 exit_path
> 挂到每条腿(`PlannedFill`)上,而不是 tick 上。**

### 一句话概括现在的机制
**单边挂单进出、正常路径 0 手续费、离场优先挂单、吃单只做尾部保险;
进场先过"跳空币/形态/情况表/逆流"四道门,方向由 OFI 定、趋势只否决;
每一笔往返写进往返账本,由"平均 y / 吃单费占比 / 挂单率 / 强平"四指标自动裁决参数。**

## 6. 桥 04:58 复盘 + 趋势否决补上(h867,05:1x)

### 6.1 最差的一小时(-41U)的根因:市场在涨,引擎在空
```
市场(近 30 分钟):BTC **+43.0bp**(区间 51.6bp,末位 90%)、ETH +13.2bp、NEAR +9.1bp
近 45 分钟按方向:buy 55 腿 −6.7bp/腿 | **sell 54 腿 −26.8bp/腿(净 −24.5U)**
近 45 分钟按路径:taker_stop 18 条 **−84.7bp/腿(净 −25.9U)** ← 全是被上涨趋势打掉的空头
```
**根因**:Cursor 版路由里 S1/S4 直接用 `"buy" if ofi>=0 else "sell"` 定方向,
**没有趋势过滤** ⇒ 上涨市里 OFI 短暂为负就去做空 ⇒ 被趋势反复扫损。
(我此前的并行实现里有趋势否决,但被 Cursor 的重写覆盖了。)

### 6.2 修法(最小、有数据支撑)
在路由决定 `_side` 之后加**趋势否决**:
```
若 |300s 趋势| ≥ MM_FLOW_TREND_VETO_BP(默认 8bp)且方向与趋势相反
   ⇒ 本拍不进(reason="trend_veto");S3(均值反转)豁免(它本来就是逆偏离博回归)
```
依据:h658"不 fade 流"定律 + 本轮 54 条逆势空头平均 −26.8bp 的实测。
