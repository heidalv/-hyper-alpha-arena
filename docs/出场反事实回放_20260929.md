# 出场反事实回放_20260929——用本仓真实 K 线检验"最优障碍出场"假设

> 研究性质：纯设计验证，不改后端。脚本：`scripts/counterfactual_exit_replay_20260929.py`；
> 结果表：`docs/counterfactual_exit_grid_20260929.csv`。

> 15m K 线回放（bybit/okx/binance/hyperliquid/asterdex 优先仓位自身交易所）；
> 名义 = margin×leverage（修复了 BTC 空头行 size 为"张"单位的陷阱）；

## 1. 结论先行（三条）

1. **出场手术单独不能翻正 mid**：12 组网格全部负期望。最优组 k=1.0·r2=2·τ=24h：净 −249.11（每笔 −1.06）、盈亏比 0.90、WR 37.9%，vs 实际 −396.79（每笔 −1.68）——**减损 37%，但不翻正**。这与 Carr & Jarrow (1990) / Kaminski & Lo (2014) 的理论一致：**止损不创造 alpha，只截断尾部**。
2. **入场侧过滤的减损效力远大于出场手术**：同样出场规则下，叠加"BTC 1d 动量向上才开仓 + 剔除价格<$1 微盘币"（F1+F2）：n=109，净 −45.99（每笔 −0.42）——**合计减损 82%**，盈亏比 1.12（首次 >1），但仍未翻正。
3. **mid 翻正的最后一步必须在入场边际**（错价/显著性 §5.3 + 空头侧在 bear regime 开仓）——回放证明"出场+过滤"只是止血，造血要靠入场信号本身有正漂移。**长线车道反向验证**：ATR 阶梯出场会伤害长线趋势单（n=27：实际 −107.74 → 阶梯 −122~−138），长线的盈利结构是"骑趋势+少量滚动加仓"，与 mid 的手术对象完全不同。

## 5. 对设计的三处修正（已回写设计文档）

1. §5.4 的原门禁"回测盈亏比 ≥1.5"**被证伪**——出场手术单独只能把盈亏比从 0.93 提到 ≈1.0-1.1。门禁改为"回放口径亏损 −40% 以上"，盈亏比 ≥1.5 移到 P3 联合门禁（出场+过滤+入场边际一起验）。
2. 新增设计要点：**F1+F2 过滤是 P2 的量化原型**（BTC 1d 动量闸 + 微盘币剔除），实测合计减损 82%。
3. mid 翻正的路径明确为：**止血（P1 出场 + P2 账面 regime）→ 造血（P3 错价/显著性入场边际 + bear regime 空头侧）**，顺序不可调换，P4 加仓的前提是 P3 后联合回放盈亏比 ≥1.5 且 OOS 正。

## 6. 方法局限（诚实声明）

- 60 天单窗口 = 单一样本；结论是"设计导向"而非"统计显著"（n=109~235，per-cell 更小）。
- 同 bar 内 SL 优先（保守）；未建模逐币价差差异（统一 0.05%）；未计资金费；名义用 margin×leverage 近似。
- 加仓/减仓仓位（mid 65 笔、long 38 笔）被排除——它们恰好是盈利侧（long 加仓子集 +26.4），说明"滚动"本身有价值，但需要在赢家上滚动（09-28 SOL 教训）。
- F1/F2 过滤器本身有前视风险吗？无——BTC 动量与价格均用入场时刻之前的数据。但参数（1d/5d、$1 阈值）是单窗口试出来的，需 OOS 复验。
