## 0. TL;DR（回答两个核心问题）

**Q1：中长线是被冻结了么？** —— 不是被冻结，是三个机制叠加造成的「事实性停摆」，且前端完全没有暴露任何原因：

1. **亏损冷却禁开**：`MidLongCooldown` 在亏损平仓后同方向禁开 mid=4h / long=12h，连续亏损 ×2 倍惩罚（long 最长 24h）。08-13 连亏后进入冷却 → 当前中长线 **0 持仓**。
2. **LLM 决策链半残**：SwingAgent 反复 `JSON 容错解析失败 → 规则回退`；TrendAgent 大量 `hold score=23~39 < 门槛32 / llm_should_open=false`。
3. **意图→执行转化 0%**：近 14 天 **253 次 NIBBLE/BUILD 意图 → 0 次开仓**（周报自证）。

**Q2：亏损根因是什么？** —— 数据实证的六大根因（详见 §2）：

## 1. 「停止/被冻结」的真相

### 1.1 日志证据链（2026-08-14 00:38-00:50 实拍）

```

[MidLongCooldown] BLOCK BTC sell tier=mid: 刚平空仓(tier=mid)未满240分钟，抑制同向再开（约剩3分钟...）
[MidLongAudit] skip stage=exec symbol=BTC reason=midlong_cooldown_block:刚平...
[SwingAgent] LLM 调用失败，走规则回退: Expecting value: line 14 column 49 (char 859)
[TrendAgent] JSON 容错解析仍失败: Expecting value: line 1 column 830 → 发起 1 次结构化重试
[TrendAgent独立] BTC hold score=39 dir=short why=llm_should_open_false_res...
[TrendAgent独立] ETH hold score=23 dir=neutral why=score_low(23<32) raw_sh...
```

同时（对照）：短线 scalp 正常跑（V5Gate PASS/BLOCK、SizingAgent 下单、持仓更新）→ 证明**调度与执行链路活着，只有中长线这条链路被多层阻断**。

### 1.2 冷却机制详解（代码级）

`backend/services/reentry_cooldown.py`：
- 基准亏损冷却：short=4h、mid=4h、long=12h（`REENTRY_LOSS_COOLDOWN_SEC_*`，long 另设 SL 冷却 `REENTRY_SL_COOLDOWN_SEC_LONG` 默认 48h）。
- **连续亏损惩罚乘数** `_get_loss_multiplier`：连亏时 ×2 → long 最长 24h 同向禁开。
- 反转冷却（反向翻转）另有 24h 级冷却。
- 状态 DB 持久化（`_durable_reopen_blocked` 查最近平仓记录）→ 重启不清零。
- 设计意图（注释自述）："避免信号未变时重复付手续费"——**但把它同时用在了亏损惩罚上，等于在趋势策略最需要重新入场时把它锁死**。

### 1.3 意图→执行转化 0% 断点

周报（`backend/data/midlong_reports/latest.md`，08-11 生成）自证：
- NIBBLE/BUILD 事件 253 次（NIBBLE=247）→ **24h 开仓转化率 0.0%（0/253）**
- 决策漏斗（审计 JSONL 336h）：skip=0 / open_attempt=0 / opened=1
- 即：**MLTO Hub 每 2 分钟在产出 NIBBLE 意图，但执行层一个都没放行**。断点位于 open_gate→Writer/执行之间（`mlto/open_gate.py` 已精简为 5-6 条底线，说明历史上"多闸把 AI 卡死"发生过一轮，现在疑似再次出现在执行层，待量化审查员定位确切位置）。

### 1.4 前端为什么「完全不知道怎么回事」

- `/dashboard` 三周期卡只显示 active_strategies/budget/drawdown/win_rate——**不显示冷却剩余时间、不显示 hold 原因、不显示意图转化漏斗**。
- 冷却/LLM 回退/门禁拦截全部只在日志与内部审计 JSONL 中。
- 周报生成器还有**隐藏 bug**：因租户 RLS 读不到 `paper_*` 表（无租户上下文），回退 `event_log.jsonl`——周报抬头写着「paper_* 表无样本」是**假的**，绩效口径长期失真。

### 2.2 六大根因逐条（证据链）

**① master 总控砍仓 + trend_review 白名单漏网（P0，损失最大来源）**
- 数据（orders 权威口径）：swing `master_running_close` 30 笔 **-33.89**、胜率 10%（其中 23 笔持仓 1-6h）；`trend_review_close`（trend）**12 笔 -44.90、胜率 0%**。
- **代码事实（风控员+量化员双确认）**：针对 master 乱砍的 hard-fact 门控已写好（`master_close_guard` + `unified_exit_executor` 免疫判定），但 `.env` 实测 `RISK_P3_MASTER_CLOSE_REQUIRES_HARDFACT=shadow` + `RISK_P3_HARDFAT_SHADOW=true` —— **当前只检查、只记录、不拦截**。而 `trend_review_close` 挂在 `_AGENT_EXIT_REASON_WHITELIST`（`master_close_guard.py:46`）上，连检查都不走。
- 量化员复核：「timeframe_tier 缺失→免疫静默失效」假设经 DB 抽查不成立（XPL swing 行 tier=mid 有值）——真因就是 shadow 灰度 + 白名单。
- 行为金融定位（风控员）：处置效应（损失厌恶）的自动化——把轻微回撤判成「风险升高→离场」，与人类浮亏时「先保本」冲动同构。
- 对照：swing 盈利单平均持仓 15.7h、峰 +1.92；亏损单平均 5.7h。→ **总控把「本应让它跑」的头寸在噪音窗口内砍掉**。

**② 震荡市开趋势单（P0）**
- 08-13 亏损单 close_reason 原文自证：SOL 多单「ADX 仅 16.9/14.9（均<20），市场状态=ranging（置信60%）」；BTC 空单「4h 虽 bearish 但仅中等偏弱（ADX=23.4），1d mixed 且 ADX=17.4」；ETH 空单「MACD 柱 -0.13、ATR 0.17%、价格与 EMA9 纠缠」。
- 即：**入场门槛没有拦住低 ADX/震荡市**，趋势单开在噪音里 → 快速小亏离场。
- 现有 `open_gate` 对 chop 只做 soft_warning（"chop soft_warning (no veto)"）——等于不拦。

**③ 小币 + 高杠杆（P0）**
- 币种亏损榜：XPL -8.80（7 笔 0% 胜率）、LDO -5.58（8 笔 0%）、KAITO -4.28（2 笔 0%）、ZEC -1.67、BNB -1.24。
- 逐笔特征：10-20x 杠杆、持仓 0.6-12.8h、同币种单日反复进出（LDO 07-17 一天 5 笔、XPL 07-05 一天 6 笔）。
- AI 选币把低流动性小币送进 midlong 池，sizing 层没有按流动性/市值降杠杆。

**④ 盈利回吐失控（P1）**
- 63.6% 曾达峰盈利的 swing 单最终平/亏；均峰 +2.40 → 实收 +0.41（回吐 83%）。
- 分档 TP 从未触发：TP L0 100%、**L1/L2/L3 全 0%**——止盈台阶距离/触发逻辑失效，利润只能靠 emergency_drawdown 和 max_hold_timeout 兜底。

**⑤ 持仓时长倒挂（P1，与①互为因果）**
- <6h：58 笔 -13.16；6-24h：+0.67；1-3d：+9.58；>3d：+36.94。
- 结论：**当前所有「快速退出」路径（master 砍仓/trend_review/trend_broken 止损）都在破坏唯一盈利的持仓形态**。

**⑥ 策略边缘弱（P1，需 walk-forward 重校准）**
- 自有 WFO（`midlong_reports/latest.md` 附件）：BTC OOS Sharpe -0.14 / ETH +0.09 / SOL -0.28；MaxDD 24.6%/32.4%/26.4%；DSR 0.19-0.25（deflated Sharpe，统计上不显著）。
- 含义：**当前参数组合在样本外没有证明有边缘**——不是「好策略被坏执行拖累」那么简单，策略本身需要重新校准（这也解释了为什么靠 26 笔盈利单扛着）。

### 2.4 隐藏问题清单（复核中发现）

1. **周报 RLS 失真**：`midlong_reports/latest.md` 注明「paper_* 表无样本，已回退 event_log.jsonl」——实际 paper_orders 有 ~4900 条平仓记录。周报生成器未带租户上下文，绩效统计长期失真。
2. **分档 TP 全 0 触达**：staged_tp 的 L1-L3 从未触发，需检查 TP 距离设置与触发逻辑。
3. **Live 从未自动交易**：`live_sub_positions`=0——「亏损大户」口径为模拟盘；这同时意味着 Live 门控链从未被真实路径验证过。
4. **LLM JSON 脆弱**：`Expecting value: line N column M` 反复出现；swing 无结构化重试（trend 有 1 次）；失败回退行为危险（见根因⑥）。
5. **pair_research 通道无任何风控证据**（P0 级独立问题）：`pair_VELVET_5m_meanrev` 82 笔 -410.67 仍在跑（08-13 还在开新仓）——5 分钟均值回归在小市值币上被手续费+滑点碾碎，需要单独关停或重构（详见 §5 方案，与中长线方案并列）。
6. **账户日波动极大**：近 12 天日 PnL：+69.89（08-12）/ -414.19（08-13）/ -29.54（08-11）——日亏损熔断档位（3%/15% per-symbol/全局）在 08-13 全未触发（当日 -414.19 主要来自 pair_research 与中长线，但 15% 极端网对 $404 账户 = 允许单日 -$60 才停手）。
