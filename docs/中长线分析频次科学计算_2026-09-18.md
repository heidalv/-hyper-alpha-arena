**结论**：长线信息半衰期 **4 小时**（恰好=其 4h K线周期，因子票 macd@4h 等也是 4h 票——
新信息随 4h 收盘到达）；中线在 **30min-1h** 内去相关（swing 车道操作周期更快）。
**5 分钟级分析的信息增量≈0**（因子分 corr 0.998，即 99.8% 是旧信息）。

### 1.2 冗余层：不同间隔下"分析完结论没变"的比例

6h 才降到 63%——中线的"有效信息间隔"约 1-2h（冗余 80% vs 63% 的拐点之间）。

### 1.3 持仓层：开仓后的风险时钟（80 笔近 30 天平仓 + 15m K线重演）

## 2. 方案选项（等你拍板）

| 项 | 方案A（数据最优） | 方案B（保守：保持现状全频） | 方案C（A+B折中） |
|---|---|---|---|
| 长线·态势/开仓分析 | **每 4h，对齐 4h K线收盘触发**（信息半衰=4h，更频=89-100% 冗余） | 每循环（~4-5min）全频 | 每 1h |
| 中线·态势/开仓分析 | **每 1h，对齐 1h 收盘** + 触发式加密 | 每循环全频 | 每 30min |
| 持仓管理·mid | **开仓后首 2h 每 15-30min → 之后每 1h**（P25=0.7h 风险时钟） | 每循环 | 首 2h 每 15min → 每 30min |
| 持仓管理·long | **每 4h + E1 日任务（08:20）为重决策点** | 每循环 | 每 2h |
| 事件触发（叠加在定时之上，任一方案都建议） | 浮亏达 -1% / 价格进止损 1×ATR 内 / regime 翻转 / E1 跑完 / 持仓超期(hold_timeout) → **立即加一次分析** | 同左 | 同左 |

**我的推荐是方案A**，理由纯数据：4h/1h 是两条车道的实测信息半衰与风险时钟，
事件触发覆盖了"定时间隔内突发"的场景；方案B每 5 分钟的分析有 99%+ 是重复
（不是省钱论点，是"重复分析会稀释注意力/产生噪声决策"的信息学论点——但这是你的系统，你定）。

## 4. 用户裁决后的架构落地：信号触发式调度（替代一切固定间隔）

**用户裁决（2026-09-18）**：固定间隔不成立——间隔应随行情动态浮动；
正确架构 = **因子信号触发 LLM 分析**。

### 4.1 实现（已上线）

`backend/services/full_auto/analysis_trigger.py` + mlto_cycle mid/long 批次门控：

| 触发条件 | 阈值（env 可调，实测校准） |
|---|---|
| 因子复合分真实移动 | \|Δscore\| ≥ **0.05**（P95 校准：75% 采样纹丝不动、P90=0.008） |
| 方向翻转 | 任何翻转立即触发（硬触发，不受冷却限） |
| 置信度跳变 | \|Δconf\| ≥ 0.15 |
| regime 翻转 | 立即 |
| 持仓浮亏破 -1% | 立即（硬触发） |
| 陈旧度兜底 | 有仓 30min / 无仓 120min 强制一次 |
| 最小冷却 | 3min（防风暴，仅限软触发） |

一键回退：`ANALYSIS_TRIGGER_ENABLED=false` 回到每循环全频。

### 4.2 上线实测（间隔动态涌现的直接证据）

  50%~100% 浮动**，后续轮次将随行情在 0%~100% 间自然摆动；
- 校准模拟：551 次原始采样 → 37 次真实触发（平静期趋零、波动期连发）。
