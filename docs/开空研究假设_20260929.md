## 2. 数学假设（已实施）

### H1：方向配对是最低风险的表达方式
```
空头只在 BTC 1d 动量 z ≤ −0.5 时表达；多头只在 z ≥ +0.5 时表达。
```
依据：btc_1d_mom 是 P3 预研最强特征（t=4.00，OOS t=3.57，方向配对消融 −4.9pp）。
含义：**不做"独立于 BTC 的山寨空头"**——小币空头在 BTC 平盘时是负期望（09 月实测）。

### H2：空头边际分数 m_short = |z_btc|（funding 权重 = 0）
```
m_short = |z_btc| > 0.29 才放行；funding_z 对空头的符号未验证 → 权重 0。
```
- 为什么不是 −funding_z（正费率=多头拥挤→空头有利）？**这是直觉，不是数据**。P3 预研中
  funding_z7d 对多头前向收益是**弱正**（拥挤延续），若对空头也"延续"，则 +funding_z
  对空头是**不利**方向——两种符号假设都无样本支持，诚实做法是权重 0，等样本说话。
- 验证设计（§4）：n≥60 空头样本后，跑 `E[r_fwd_24h | z_funding 分桶]` 分侧检验，
  符号为正则空头 m 加 −w_f·z_fund，符号为负则加 +w_f·z_fund，|t|<1 保持 0。

### H3：空头止损距离与多头同规格（k=1.0·ATR(1h)，钳制 [0.8%, 8%]）
依据：障碍出场回放中多空同规格（模拟机 09 月空头 +390.8 即此规格）；空头跳变
（short squeeze）由 §6 账面 regime 与 jump 检测兜底，不靠更宽的止损。

### H4：空头仓位与多头同风险预算（0.5%/笔）
依据：风险对称性；若 H1-H3 样本显示空头波动率/胜率系统性不同，再按 §4 调整。

### H5：空头观察窗（细节调整的触发条件）
- 样本门槛：空头平仓 ≥ 60 笔（预计 4-8 周，视信号频率）；
- 每次满 20 笔做一次中期检查（不调整，只记录）；
- 触发调整的唯一依据 = §4 的预登记检验，不允许盘中拍脑袋。

### H6：空头样本积累可能被"长线多头连锁"拖慢（2026-09-29 运行时观察）
- 观察：主脑已在 BTC 弱 regime 下尝试 mid 空头（BTC/ETH/SOL/BNB/UNI/XRP），
  但被既有 `cycle_conflict: 长线强多(conf=0.68) 禁 mid 开空` 连锁拦截；同时
  ASTER/TRX 空头被 `midlong_edge_price_block` 拦截（我们的闸，符合设计）。
- 含义：**空头样本的积累速度取决于长线车道的多头强度**——长线 6 仓全多头期间，
  mid 空头几乎开不出来。这是既有安全连锁（不轻动），但会让 H5 的"4-8 周 60 笔"时钟变慢。
- 预登记调整（T6，待 H5 触发后一起裁决）：若 2 周内 mid 空头开仓为 0，
  评估"方向配对下的空头表达"与 cycle_conflict 的优先级——候选方案：
  ① 长线强多时 mid 空头降档为"账面对冲额度"（≤ 总保证金 10%）；② 维持现状（记录为否决样本）；
  ③ 连锁仅按 tier 内 open 仓方向判定（mid 空头只被 mid 多头锁互斥，不被 long 锁）。
  任何选择都要预登记 + 最小样本，不盘中拍。

### H7：死区探针（数据工厂保活，2026-09-29 用户反馈后落地）
- 背景：z_btc 连续在 ±0.5 死区 → 方向配对多空都不表达 → "中线没有任何交易"。
- 落地：`MIDLONG_EDGE_DEADZONE_PROBE=true`——模拟账户在死区按 z_btc 符号开 ×0.25 缩仓探针
  （复用 paper_probe 机制）；live 不生效；价格/账面风控照常。
- 探针样本的用途：① 死区前向收益分布（供 T3 重标定死区宽度 ±0.5→?）；
  ② 死区空头样本（绕过部分 H6 制约：z_btc∈(−0.5,−0.05) 时 short 探针放行，
  但上游 cycle_conflict 仍可能拦，拦下的记否决样本）；③ 学习链的全量特征快照。
- 风险边界：×0.25 缩仓 + 同向≤4 + 日亏熔断 −1.5% ⇒ 探针最大暴露可控；
  探针亏损本身就是"死区不交易"这条规则的定价数据。
