仓库里已经有三套互相打架的硬件叙事，**都不要再当现状**：

| 文档 | 它假设的机器 | 本文怎么用 |
|------|----------------|------------|

本机只按 **两张 22GB + 一对 NVLink** 设计。装机后第一件事是核验，不是上 70B。

核验清单（实施时跑，今天只规定）：

1. `nvidia-smi -L`：两张卡、各约 22GB。  
2. `nvidia-smi topo -m`：两卡之间是否真是 **NVLink**（不是只 PCIe）。  
3. `torch.cuda.device_count()==2`，sm 架构 **7.5（Turing）**。  
4. 单卡空载可用显存（扣驱动/桌面）——设计按 **每卡可用 18–20GB** 留余量。

没有 NVLink 也不死：挖掘改「两卡数据并行」，大模型改「单卡 14B」，设计仍然成立。

## 1. 目标与非目标

### 1.1 目标

1. 把现有挖掘/回测的**错误与口径分裂**写进一张可验收的改造表。  
2. 对 GP / MCTS / 池准入 / LLM 造因子 / 正式闸门给出**客观评价**（优点留下，缺点点名）。  
3. 判断「升级进化」该加在哪一层：目标函数、搜索器、算力、还是本地模型。  
4. 用这台双卡机器给出**能跑满、不互抢**的分工：一张挖，一张想。  
5. 本地大模型只做**辅助分析与批评**，不替代相关性和走前检验。

### 1.2 非目标

- 本文件不写交易循环补丁（那是短线中线设计的事）。  
- 不上 AlphaGen / MaskablePPO「生产挖掘」——注释里有，现码没有。  
- 不在 2×22GB 上规划 72B / 235B / 满血 GRPO。  
- 不把种群从 300 盲加到几千，除非 GPU 求值等价性已经绿。  
- 不把云端 DeepSeek 日决策整锅搬本地（延迟、稳定性、运维都还没证明）。

### 1.3 一句总原则

**搜索可以更快，模型可以更会写公式，但「什么叫好因子」必须先统一。**  
否则双卡只是把错误相关算得更快。

## 2. 现有错误（按层，不按情绪）

下面只列**今天打开文件仍在**、且会污染挖掘结论的问题。交易侧 S/M 编号见短线中线审查，这里用 F 编号，避免混谈。

### 2.1 目标函数层（最贵）

| ID | 错误 | 现码 | 后果 |
|----|------|------|------|
| F1 | 挖掘、验收、闸门、成交各用一套「好」 | GP：Pearson \|IC\|；进化环：Spearman ICIR；闸门：滚动 Spearman + Pearson 定方向；纸盘：SL/TP/超时净盈亏 | 挖到的「好」不必能赚钱 |
| F2 | 挖掘奖励绝对值 | `obj = abs(corrcoef)` | 反着准的公式被当天才；中线再 `sign(ic)` 反手，组合权重却把负 ICIR 打成 0 |
| F3 | 前瞻期不齐 | 进化 4h 看 **1 根**；闸门 4h 看 **6 根**；发现预筛固定 **1 根** | 同一「中线因子」三种持有期 |
| F4 | 中线挖掘不管止盈止损 | 三重障碍只开在 5m/15m；因子路由死 5%/10% | 适应度与中线出场无关（交叉 M1/M4） |

### 2.2 数据与前视

| ID | 错误 | 现码 | 后果 |
|----|------|------|------|
| F5 | 回测所 ≠ 成交所，路由复用回测加载器 | `_load_klines` 默认 binance / `purpose=research` | 交叉 M3：币安上的 MACD 不是 Aster 上的那条 |
| F6 | 发现预筛环绕 | `np.roll(closes,-1)` 算收益；`open=np.roll(closes,1)` | 最后一根吃第一根，典型脏 IC |
| F7 | 走前检验折边界前视 | 训练窗末根 `fwd_ret` 跨进测试窗价格 | `orient`（做多还是反手）被轻微偷看 |
| F8 | IC 全是单币时序 | 不是同一时刻跨币截面 | 把时序相关当截面因子，容易高估 |

### 2.3 产物与闸门

| ID | 错误 | 现码 | 后果 |
|----|------|------|------|
| F9 | 双池 | AST 进化仓只喂短线 `evo_*`；中线只读公式商店 `horizon=midlong` | GP 再强也救不了中线活跃因子少（M8） |
| F10 | DSR 自锁 | 默认打分 3 币，`DSR_MIN_SYMBOLS=4`，代码 fail-closed；注释写 fail-open | 结构上容易「挖了、验了、一个都晋升不了」 |
| F11 | registry 旁路 | `scan_registry_midlong` 无 held-out / DSR / 冗余 / cap | 最严闸门被绕开 |
| F12 | 种子含禁算子 | `_mine_candidates` 的 `vp_corr` 用 `"op":"rank"`，矿机池已禁 | 种子段白做或被 audit 丢掉 |

### 2.4 算力与模型接线（和这台机器直接相关）

| ID | 错误 | 现码 | 后果 |
|----|------|------|------|
| F13 | GPU 求值默认关，预算按 1070 | `FACTOR_EVO_GPU_EVAL=0`，`MAX_MEM_MB=1200` | 两张 22GB 晚上在睡觉，CPU loky 在熬夜 |
| F14 | 文档承诺 RL 挖掘 | `alpha_miner`：「生产 MaskablePPO」 | 现码是随机 + LLM AST，读文档会判错阶段 |
| F15 | 本地 LLM 已有钩子、没有本机契约 | ollama 打标、`LOCAL_LLM_BASE_URL`、Codegen 走云端配置 | 双卡装好也不知道该常驻谁 |

这些错误里，**F1–F4、F9–F11 不修，后面所有「进化升级」都是加速噪音。**

## 3. 对现有挖掘算法的客观评价

评价尺度只有四个：它在搜什么、搜得是否有效、有没有防过拟合、和交易是否同构。不看「像不像量化基金宣传」。

### 3.1 遗传编程（GP）— 主矿机

**它实际是什么：** 在项目 DSL 上做树搜索。种群 300、20 代、6 种子、70% 交叉 / 20% 变异、ε-lexicase、ALPS 超龄重生、复杂度与名人堂相关惩罚。GPU 路径已能批量求值，但默认关掉。

**客观分数（相对「自研表达式搜索」，不是相对 WorldQuant 全量集群）：**

| 维度 | 判语 | 理由 |
|------|------|------|
| 搜索能力 | **中上** | 多种子 + lexicase + ALPS，比纯随机强一个档；不是魔法 |
| 目标质量 | **差** | 优化 \|Pearson IC\|，与纸盘净盈亏、中线持有期都不是同构 |
| 过拟合控制 | **中** | 复杂度/相关惩罚、后续还有 purge/DSR；挖掘当下仍会刷绝对值相关 |
| 工程完成度 | **高** | DSL、审计、断点续训、GPU 等价回退都在；注释（gplearn、Rank IC）落后于代码 |
| 算力匹配 | **未用上** | 为 1070 留了栈式求值，本机 22GB 远未打开 |

**一句话：** GP 是合格的「表达式搅拌机」，不是合格的「交易因子工厂」。搅拌机值得留；工厂标准要另订。

**不该做的升级：** 把种群盲加到 2000、上强化学习生成 token、换一套更炫的交叉算子——在 F1 没修之前，都是把搅拌机开更快。

**该做的升级：** 见 §5。核心是换目标，不是换树。

### 3.2 蒙特卡洛树搜索（MCTS）— 改弱因子

**它实际是什么：** 以活跃集里最弱的表达式为根，用 UCT 做局部改写；窗口敏感性（FSA）过高整棵扔掉。

| 维度 | 判语 |
|------|------|
| 搜索能力 | **中**（局部好，全局弱） |
| 目标质量 | **与 GP 同病**（仍是 \|IC\|） |
| 过拟合控制 | **略好于 GP**（FSA 是挖掘链里少有的「参数稳不稳」） |
| 定位 | 维修工，不是勘探队 |

**升级空间：** 短板种子不要只用 \|ICIR\| 最低，改为「纸盘净期望最差 / 与成交所 IC 最漂」的因子。FSA 阈值可以保留。不必上更深的 PUCT 变体。

### 3.3 AlphaPool（池准入）— 挖掘里最清醒的一段

看的是「给你篮子有没有 **时间序列交叉验证** 的边际 IC」，不是单因子刷榜。5 折 TimeSeriesSplit，相关 >0.85 拒。

| 维度 | 判语 |
|------|------|
| 思想 | **对** |
| 覆盖面 | **窄**：只有进化环走；公式商店 / registry / 冷池不走 |
| 目标 | 边际的仍是 IC，不是净盈亏 |

**升级空间：** 把池准入变成**全通路必经**（含 registry）。边际指标从「IC」加一列「成本后净期望影子」。不要另写一套深度学习组合器来替代它。

### 3.4 LLM 造因子（CodegenCritic）— 现在是云端小品

每轮大约 8 条 AST，audit 过后进池。领域提示里已经塞了持有期和费率——这点比随机树懂行。

| 维度 | 判语 |
|------|------|
| 当搜索器 | **弱**（8 条 vs GP 300×20×6） |
| 当批评家 | **还没当**（几乎只生成，很少解释「为什么拒」） |
| 依赖 | 默认云端；本机钩子在，契约无 |

**升级空间：这才是本地大模型该站的位置。** 见 §7。不要让 LLM 取代 GP。

### 3.5 正式闸门（Scorer + WF + DSR/PBO）— 像门，有时是墙，有时是侧门

走前非重叠调仓、训练窗标准化、held-out 判决、closed bar，都是认真的。  
同时：3 币对 4 币自锁、注释与代码相反、registry 侧门、复检不走 held-out。

| 维度 | 判语 |
|------|------|
| 作为科学门 | **中上，被配置打脸** |
| 作为交易门 | **中下**（y 仍不是成交净盈亏） |

**升级空间：** 先修自锁和旁路，再谈「更先进的 deflated Sharpe」。不要在 DSR 公式上再发明第三套。

### 3.6 总评（给「要不要推倒重来」一个答案）

**不要推倒。** 现有矿机 + DSL + 闸门骨架，在个人/小团队项目里已经偏完整。  
真正落后的不是「没有更新的遗传算法」，而是：

1. 好因子的定义分裂；  
2. 挖出的货进错仓库；  
3. 22GB×2 还按 1070 的 1.2GB 预算在跑；  
4. 大模型只会偶尔写公式，不会看门、不会复盘。

## 4. 有没有升级进化的空间？有，分三层

把「进化」说清楚，避免一上来换算法名词。

```
L1  口径进化（必须）     同一张「因子成绩单」
L2  目标进化（值得）     相关 → 可交易净期望（影子否决，不立刻取代 IC）
L3  搜索进化（可选）     多样性档案 / 成交所对齐 / GPU 吞吐
L4  模型进化（辅助）     本地 LLM 批评、解释、少量提案
L5  时尚进化（先不做）   RL token 挖掘、70B、端到端因子 Transformer
```

L5 在 2×22GB Turing 上既贵又容易假阳性。L1–L2 不完成，L3 只是更快地重复错误。

### 4.1 L1 口径进化（一张成绩单）

每条候选因子日志必须同时有、且字段名固定：

| 字段 | 含义 | 谁必须填 |
|------|------|----------|
| `ic_pearson` / `ic_spearman` | 两种都留，禁止只写 `ic` | GP、进化环、闸门 |
| `fwd_bars` / `kline_exchange` / `purpose` | 前瞻几根、哪家所、research 还是 trade | 全链路 |
| `split` | train / val / test / heldout | 禁止全样本冒充 OOS |
| `expected_sign` | 晋升时锁定方向 | 挖掘可看绝对值，路由必须读这个 |
| `entry_source_pool` | `evo_ast` 或 `formula_store` | 解决双池看不见 |

实施时先改日志和存储，公式可以第二步才收敛。**没有这张成绩单，本地 LLM 的复盘也是在瞎编。**

### 4.2 L2 目标进化（影子否决，不政变）

主优化仍可以是 IC（样本多、方差小）。另加一条**不能单独刷、只能一票否决**的影子：

- 短线：与纸盘同向、同持有节奏的净期望（或三重障碍，现码 5m/15m 已有）。  
- 中线：前瞻与闸门对齐（建议统一 4h=6 根或明确「1 根 = 一根 4h 的持有」），并扣 5%/10% 或未来动态 SL 的路径。  
- 成本：往返 21bps + funding，闸门里已有，**挖掘适应度也要减**，不要只在最后减。

规则：影子指标「明显为负」→ 不得晋升。影子「很好」但 IC 不够 → **仍不得晋升**（防止拟合三条幸运成交）。

这是对「高分更亏」（8/16 短线体检）唯一对症的算法升级。

### 4.3 L3 搜索进化（有双卡才值得做）

在 L1/L2 之后，搜索升级只做三件 ROI 高的：

1. **打开并校准已有 GPU 求值**（§6），种群 300→800–1200 可以谈。  
2. **质量-多样性档案**（按类别 × 周期 × 多空偏好分格，每格留 1–2 个），减少「全是动量变体」。不必上完整 MAP-Elites 论文实现，先按 `category` 配额。  
3. **MCTS 短板改用成交所 IC 漂移 / 纸盘净期望**，而不是再写一种 UCT。

明确不做：AlphaGen RL、可微公式网络、用 Transformer 直接输出仓位当因子。

### 4.4 L4 本地模型进化（§7）

模型升级的正确姿势是 **批评家 + 解释器 + 每周复盘**，不是第二台矿机。

## 5. 这台机器怎么用：两张 2080 Ti + NVLink

### 5.1 硬件能做什么、不能做什么

Turing（sm_75）：

- 擅长：FP16/INT8 推理、中等规模 GEMM、现有栈式因子求值。  
- 不擅长：BF16（没有）、现代 vLLM 的很多优化核、70B 满血、长上下文 + 大 batch 同时。  
- 改装 22GB：比公版 11GB 有用，但带宽/算力仍是 2080 Ti，**不是 A6000，更不是 A100**。

NVLink（两卡一对）：

- **适合：** 一张放不下的 32B 量化模型做张量并行；大 embedding 或大面板偶尔对拷。  
- **不适合当默认：** GP 求值。现有执行器是「一代种群一个栈」，**两卡各挖各的种子** 比把一棵树拆到两卡更简单、也更稳。  
- 若 `topo` 显示没有 NVLink：32B 方案降级为「不要 32B」，其余设计不动。

### 5.2 常驻分工（推荐，写进运维契约）

```
GPU0  cuda:0   「手」     因子 GPU 求值 / 冷池批量 IC / 走前检验矩阵
                 显存预算  14–16GB（留 4GB+ 给碎片和驱动）
                 任务      进化环、复检、registry 重打分（排队）

GPU1  cuda:1   「脑」     本地 LLM + 向量嵌入
                 显存预算  常驻 12–14GB 模型 + 2GB embed + 余量
                 任务      批评/解释/少量 Codegen / 观察池打标 / 周报草稿

NVLink         仅当 GPU1 要拉 32B 时启用张量并行（两卡都为「脑」）
                 此时 GPU0 的挖掘必须错峰（夜间或周中维护窗）
```

和 8/9 文档「1070 挖、2080 推」相反：**现在两张卡同级，必须按职责拆，不能两张都既挖又推。**  
和 4 月 6 卡方案也相反：**不要默认张量并行占满两张卡。** 先保证「手」「脑」同时在线。

互斥：

- GPU0 上的 GP 与冷池、深度 GRU、DRL 训练 **排队**（沿用 `gpu_training_operation`，扩到「挖矿也占锁」）。  
- GPU1 上的 LLM 服务尽量常驻，不被挖矿挤掉——否则 Codegen 和复盘会抖。  
- 桌面如果还插在其中一张上，那张卡预算再减 1.5–2GB。

### 5.3 打开已有 GPU 求值（高 ROI，低发明）

现码已经具备：`gpu_batch_eval` 栈式执行 + `GpuEvalContext` 等价性验收失败回退 CPU。

本机建议默认（实施时改配置，不是今天改）：

| 项 | 1070 时代默认 | 本机建议 |
|----|----------------|----------|
| `FACTOR_EVO_GPU_EVAL` | 0 | **1**（验收绿才保持） |
| `FACTOR_EVO_GPU_MAX_MEM_MB` | 1200 | **12000–14000**（GPU0） |
| `FACTOR_EVO_GPU_CHUNK` | 64 | **128–256**（验收后再加） |
| `FACTOR_EVO_GPU_POP_BOOST` | 300→1200 | **先 300 对照，等价后再 boost** |

验收必须留下三张图/三行日志：CPU vs GPU 因子值 Spearman ≥ 0.999、晋升名单是否同一批、单轮墙钟是否下降。  
**验收不过就关 GPU，不要「差不多就 boost 种群」。**

两卡怎么加速 GP（有 NVLink 也按这个，简单）：

- 6 个种子：**GPU0 跑 3 个，CPU/第二进程不要抢 GPU1**。  
- 或：GPU0 专职求值，多种子串行但每代批量极大。  
- 不要：把单一种群的栈拆到两张卡（实现成本高，NVLink 收益小）。

### 5.4 算力用在刀刃上的优先级

1. GPU0 把 **一代种群求值** 从几十分钟打到分钟级（已有设计文档的承诺，应对 2080 兑现）。  
2. GPU0 把 **冷池 / registry 重打分** 从「偶尔扫」变成「每周全量、口径与闸门同一套」。  
3. GPU1 把 **批评与复盘** 做成稳定服务。  
4. 有余力再做：多币面板从 5 扩到 8–12（先修 DSR 3 对 4，再扩币，否则更自锁）。

## 6. 本地大模型：装什么、干什么、不干什么

### 6.1 角色（先定角色，再定参数量）

本地模型在本项目里只允许四种活：

| 角色 | 输入 | 输出 | 可否影响下单 |
|------|------|------|----------------|
| **批评家** | 候选 AST + 成绩单 + 费率/持有期 | 通过 / 驳回 + 一条原因（前视、过拟合、经济上无意义） | **否**，只拦进池 |
| **解释器** | 已晋升因子 + 近周纸盘 | 人话：它在什么行情有效、何时该降权 | 否 |
| **提案手** | 失败案例、短板类别、领域约束 | **8–16 条** AST，仍须 audit + 池 + 闸门 | 间接 |
| **周报助手** | 8/16 式日检、中线周报、因子成绩单 | 起草「这周该冻谁」 | 否，人确认 |

禁止的活：

- 当适应度（「你觉得这个因子几分」直接进 Fitness）。  
- 当出场大脑碎平因子仓（审查 M1：默认规则复查都已经碎过一次）。  
- 日常主路径每 tick 调 70B。  
- 用模型「发明」没有成绩单字段的新指标。

现码 Codegen 已经是「提案手」。缺的是 **批评家和解释器**。升级应补这两人，而不是把提案手的 n 从 8 加到 80。

### 6.2 本机模型矩阵（只对 2×22GB Turing）

按「一张卡常驻还能喘气」选：

| 档 | 模型（示例族） | 量化 | 放哪 | 何时用 |
|----|----------------|------|------|--------|
| **主推常驻** | Qwen2.5-14B-Instruct 或同级 14B | Q5_K_M / AWQ-INT4 | **仅 GPU1**，约 10–12GB | 批评、解释、提案、打标 |
| 轻量备援 | Qwen2.5-7B-Instruct | Q8 / FP16 | GPU1 维护窗 | 14B 挂了还能打标 |
| 嵌入 | bge-m3 或 bge-large-zh | FP16 | GPU1 余量 1–2GB，或 CPU | RAG / 因子说明检索 |
| **可选冲刺** | Qwen2.5-32B-Instruct | Q4_K_M | **两卡 NVLink 张量并行** | 周末复盘、深批评；期间 GPU0 停挖 |
| 明确不上 | 72B、235B-A22B、满血 FP16 32B+ | — | 44GB 不够稳 | 旧 6 卡文档的最优解，本机不是 |

推理引擎：

- **第一选择：Ollama 或 llama.cpp（GGUF）**。Turing 上最省事，现码 `provider=ollama` 已有打标钩子。  
- **第二选择：ExLlamaV2 / 官方 Transformers+AWQ**。14B 单卡足够。  
- **vLLM：** 在 sm_75 上经常缺核或要降版本，**不作为本机默认**。若要 OpenAI 兼容口，用 llama.cpp 的 server 或 Ollama 的 `/v1`。

不要为了「像生产推理集群」强上 vLLM。本机的生产是交易进程稳定。

### 6.3 和现有钩子怎么接（设计，不写代码）

已有：

- `CodegenCritic`：生成 AST（现多走云端配置）。  
- `local_llm.batch_labeler`：ollama 给选币观察池打标。  
- `gate_optimizer_service`：本地模型调门控（`LOCAL_LLM_CONFIG_ID`）。  
- `LOCAL_LLM_BASE_URL` 种子配置。

建议契约：

1. GPU1 常驻 **一个** OpenAI 兼容地址，例如 `http://127.0.0.1:11434/v1`，模型名固定 `qwen25-14b-factor`。  
2. Codegen **优先本地**，云端 DeepSeek 只做「本地超时/挂掉」的降级。  
3. 新增「批评」调用：同一模型，另一套 prompt，**必须吃 §4.1 成绩单 JSON**，禁止只看公式文本打分。  
4. 周报助手一周一次，可临时切 32B（NVLink），跑完卸回 14B，把 GPU0 还给挖掘。

### 6.4 要不要微调？

**第一阶段不要。** 先用基座 14B + 成绩单 + 规则批评模板。  
没有 200 条以上「人审过的：公式 + 成绩单 + 通过/驳回」之前，LoRA 只会记住乱评。

若以后要微调（第二阶段以后）：

- 数据：批评家的人审标签，不是 K 线本身。  
- 方法：14B QLoRA，**只占 GPU1 维护窗**，batch 很小。  
- 不要做「用交易盈亏 RLHF 出仓位」——样本脏、奖励延迟、和 M1 出场问题叠床架屋。

旧文档的 GRPO / 72B SFT 路线，**对本机宣布延期，直到有第三张卡或换 Ampere/Ada。**

## 7. 推荐的整体办法（怎么办）

把人话流程写成一条，避免又拆成互不认的子系统：

```
本周（设计已写清，代码未动）
  1) 核验双卡与 NVLink
  2) 交易 P0 仍按短线中线设计做（和挖掘并行不冲突的人，先做交易）

因子链第一刀（口径，CPU 即可）
  3) 成绩单字段（F1 日志化）
  4) DSR 3 对 4 + 注释与 fail-closed 对齐（F10）
  5) 发现预筛去掉 roll 环绕（F6）
  6) registry 必须走正式闸门（F11）
  7) 种子去掉 rank（F12）

算力第一刀（配置 + 验收，少写新算法）
  8) GPU0 打开栈式求值，12–14GB 预算，300 种群对照
  9) GPU1 常驻 14B + 嵌入；Codegen 改指本地
  10) 资源锁：挖矿占 GPU0，LLM 占 GPU1

目标第二刀（才算「算法升级」）
  11) 挖掘适应度减成本；影子净期望否决
  12) 4h 前瞻进化与闸门对齐
  13) 负 IC：晋升写 expected_sign；路由弱 IC 不反手；权重与路由同号
  14) AST 仓桥接中线或公式仓双写（否则 M8 无解）

模型第二刀
  15) 批评家吃成绩单；解释器写人话
  16) 有 NVLink 的周末 32B 复盘，平日回 14B

明确很后 / 不做
  17) 种群 boost 到 1200
  18) 质量-多样性配额
  19) 不上 RL 矿机、不上 72B
```

3–7 不依赖双卡，**即使卡没核验完也可以做**（仍是以后的编码，不是今天）。  
8–10 是这台机器相对 1070 文档的真正增量。  
11–14 才是「挖掘算法进化」。  
15–16 是本地模型的正确用法。

## 8. 双卡日常作息（避免两张卡互相踩）

| 时段 | GPU0 | GPU1 |
|------|------|------|
| 交易时段 | 空或轻量复检（低占用） | 14B 常驻，供批评/打标 |
| 夜间进化窗 | 开 GPU 求值挖 5m/15m/4h（排队） | 14B 仍在；Codegen 少量调用 |
| 周末维护窗 | 停挖，或只打分 | 可选 32B TP（NVLink）跑周报，然后卸回 14B |
| 故障 | GPU0 挂：挖掘回 CPU loky，交易继续 | GPU1 挂：Codegen 回云端，批评停，交易继续 |

交易热路径 **不依赖** 本地 14B。本地模型挂了，不许变成「因子路由停摆」。

## 9. 验收（设计有没有用，用这些看）

口径刀：

- 任意一条晋升日志能同时读出 pearson、spearman、fwd_bars、exchange。  
- 默认 3 币打分时，DSR 行为与文档**同一句话**（放行或扩币，禁止再各说各的）。  
- 发现预筛单测：序列末根收益不再等于「接到首根」。

算力刀：

- GPU 等价验收绿；关/开 GPU 的晋升集合一致。  
- `nvidia-smi`：夜间 GPU0 高占用，GPU1 稳定 10GB+；交易时段 GPU0 不长期打满。  
- NVLink：32B 只在维护窗出现，窗结束必须回到 14B 单卡。

目标刀（有纸盘之后）：

- 新晋升集在 **新日期** 日检里，高分桶净收益不再系统性差于中分桶（对照 8/16，不改旧文件）。  
- 中线因子仓的 `exit_reason` 不再以方向复查为主（这主要靠交易侧 M1，挖掘侧只保证适应度含持有期）。

模型刀：

- 批评家驳回必须引用成绩单字段；抽查 20 条，无成绩单的「感觉分」为 0。  
- Codegen 本地化后，闸门通过率不作为 KPI；**审计通过且不增前视** 才是 KPI。

## 10. 明确不建议

1. 为了用满 NVLink，日常把两张卡绑死在 32B 上——手就没了。  
2. 把 `FACTOR_EVO_GPU_MAX_MEM_MB` 一次拉到 20000——碎片和驱动会 OOM，求值器会默默回 CPU。  
3. 用本地模型给 Fitness 打分。  
4. 继续维护「6 卡 72B 最优」为现行方案。  
5. 在 F10/F11 未修时扩大冷池扫描——旁路会把脏因子灌进中线。  
6. 用 8/16、8/17 交易数字去调 GP 交叉率。  
7. 假设 NVLink 一定存在；`topo` 说没有就按「无 NVLink」降级，不要改主板故事。
