## 1. 新增包 `backend/services/factors_lab/`（隔离纪律：只写自己的目录 + v7 记忆表，不碰主交易路径）

| 模块 | 职责 | 关键接口 |
|---|---|---|
| `config.py` | 开关/预算/路径（FACTORS_LAB_ENABLED 默认 true；仅控制 cron，手动端点不受限） | `enabled()` / `max_hypotheses()`=4 / `universe_n()`=24 / `data_dir()` |
| `agent1_literature.py` ① | 人工投喂 + arXiv q-fin 监控（httpx，失败静默）→ LLM 抽知识卡 → `knowledge_cards.jsonl`；词汇检索 top-k | `feed(title, abstract, source)` / `scan_arxiv()` / `retrieve(query, k)` |
| `agent2_hypothesis.py` ② | 知识卡 + v7 教训 + lab 经验（带 outcome 的历史假设）+ 市场状态（regime + BTC 动量/波动，复用 hybrid_scoring.kpanel）→ LLM 产假设（AlphaAgent 五组件 schema）→ **多样性前置拒收**（token Jaccard > 0.6 vs 近30天） | `generate(n)` → `hypotheses.jsonl` |
| `agent3_engineer.py` ③ | 假设 → LLM 产 2-3 个 AST 候选（op 白名单=expr OP_REGISTRY 31 算子）→ `parse()` 编译审计 → 最小单测（合成 OHLCV：有限率≥0.6/非常数/头部NaN对齐）→ **AST 相似去重**（节点集 Jaccard，轮内 + vs 上轮） | `realize(hyp)` → `candidates.jsonl` |
| `agent4_backtester.py` ④ | **gpfactor**：AST 在宇宙（复用 kpanel 白名单+黑名单，top N 流动）逐币求值→面板；**gpbacktest**：IC/RankIC 序列、均值/ICIR、五分位价差、换手、IC 半衰期（滞后衰减）；单因子超时 | `evaluate_candidate(cand)` → 报告 dict |
| `agent5_feedback.py` ⑤ | 归因分类（compile_fail/unit_fail/weak_ic/crowded/hot_turnover/pass）→ 写 **v7_lessons**（sqlite 直插 wrapper，kind=failure_case/success_recipe/gate_lesson）+ 回填假设 outcome + `next_round_guidance.jsonl` → 多样性体检（价值序列相关矩阵 + AST 相似分布 + 假设簇纯度） | `attribute_and_remember(round)` / `diversity_report()` |
| `loop.py` | 状态机 LITERATURE→HYPOTHESIZE→ENGINEER→BACKTEST→ATTRIBUTE→MEMORY；预算（假设数/候选数/轮超时900s）；编译失败≤3次重试；轮报告落盘 `round_reports/` | `run_round(force)` |
| `calibration.py` | **WorldQuant 101 校准回归门禁**：库里 102 条 alpha101 公式过 formula_ops 引擎，金样本快照比对（首次生成 golden，后续容差断言）——引擎改动回归防护 | `run_calibration()` |

**LLM 纪律**（全部 agent）：租户配置链复用 channel_b 先例（resolve_admin_tenant_id + get_llm_config）；
失败→该 agent 本轮降级/缺席，不造 0.5 假中性；caller=factors_lab_1..5 计量。

## 2. 数据流（一轮）

```
cron 05:40（或 POST /api/factors-lab/round）
  ① scan_arxiv/人工卡 → ② LLM 生成 4 假设(多样性拒收) → ③ 每假设 2-3 AST(编译+单测+去重)
  → ④ 每候选 gpfactor/gpbacktest(白名单宇宙 1d 面板) → ⑤ 归因+写记忆+下轮指导
  → round_report.json（全链证据：每步输入输出、LLM 原文、指标、失败原因）
```

### 6.2 实施中发现与修复（按时间序）

1. **v7 记忆路径少一层**（parents[1]→services/data 误建库）→ 修正 parents[2] 并清理误建文件；
2. **arXiv 查询编码**：`+OR+` 被 httpx 编成 `%2B` → 改空格分隔；**http→https 301** → 直连 https；
3. **XML 标签抽取逻辑反了**（闭标签位置判断永远 False）→ 修复后 fetched 0→5；
4. **运行时环境差异**：后端真环境是 `backend/.venv`（`.runtime/Python312` 是纯嵌入解释器，
   无 pip/numpy/httpx）→ arXiv 抓取改标准库 urllib（两环境通用）；
5. **首轮 outcome 脏数据**（布尔而非 dict）→ 写入结构修正 + 读取端兼容；
6. **LLM 生成 AST 过审率低**（2/8）→ prompt 补双示例后升至 **5/8**；
7. **arXiv 偶发 406**：优雅降级验证通过（文献阶段缺席，闭环其余阶段照常）——待观察是否需 UA/代理调整。

### 6.3 运行口径

- 自动：每日 05:40 闭环轮（FACTORS_LAB_ENABLED 默认开）、周日 05:20 校准回归；
- 手动：`POST /api/factors-lab/round`（scan 可选）、`/feed`、`/calibrate`、`GET /status|report|diversity`；
- 产物：`backend/data/factors_lab/`（knowledge_cards / hypotheses / candidates / guidance /
  round_reports / calibration_golden）；
- 晋级：pass 候选走 REV-P10/P12 评审（挂 lifecycle 既有 APPROVAL_REQUIRED），闭环本身不碰实盘。
