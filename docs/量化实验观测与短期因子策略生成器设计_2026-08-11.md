# 量化实验观测与短期因子策略生成器设计（2026-08-11）

> 目标：解决「实验看不见、断了不知道、14 天对照不可控」和「AI 选币选出的交易对生命周期短、需要快速适配」两个根问题。

---

## 0. 设计原则（先立规矩）

1. **数据库是唯一事实源**：所有实验/状态/报告落 PostgreSQL，前端和 Obsidian 只是不同的“视图”。
2. **没有灰度 A/B**：新策略必须先在历史数据上通过硬门禁，才允许上线；上线后只有「运行中 / 自动熔断 / 已下线」三种状态，不做“开着看看行不行”。
3. **自动心跳 + 自动断**：每个任务/车道必须周期写心跳；超过 N 分钟没心跳 = 中断，自动告警并冻结相关结论。
4. **存储媒介分层**：
   - PostgreSQL：结构化数据（实验、心跳、候选、绑定、报告）；
   - Obsidian Vault：人类可读知识层（自动生成日报/周报/实验档案/星图 MOC），用双链组织；
   - 前端仪表台：实时状态与控制入口。

---

## 1. 总体架构

```
交易车道 / 研究任务 / 因子生成器
        │ 写心跳 + 写结果
        ▼
PostgreSQL（事实源）
  ├─ scalp_experiment_log       实验登记与状态
  ├─ experiment_heartbeat       任务心跳
  ├─ pair_strategy_candidates   交易对→候选策略
  ├─ pair_strategy_bindings     交易对→已启用策略（受监控）
  └─ reports（JSON/MD）         回测/体检/成本报告
        │
        ├─▶ 前端仪表台（/experiments）
        │     状态、心跳、中断告警、候选列表、一键上线/下线（带确认）
        └─▶ Obsidian Vault（自动导出）
              00-实验仪表台（星图 MOC）
              01-分析报告/日报/周报
              05-因子实验/{实验档案}
```

## 2. 数据模型（新增表）

### 2.1 experiment_heartbeat

| 字段 | 说明 |
|---|---|
| task_id | 任务标识（scalp_chain_health / daily_report / pair_selector / lane_xxx） |
| last_ok_at | 最近一次成功心跳 |
| last_status | ok / degraded / error |
| detail | 最近一次摘要（JSON） |

规则：链路巡检 10 分钟心跳；日报任务每日心跳；车道每 tick 心跳。前端按 `now - last_ok_at` 显示“正常/滞后/中断”。

### 2.2 pair_strategy_candidates

| 字段 | 说明 |
|---|---|
| symbol / period / factor_set | 交易对与因子配置 |
| params_json | threshold/z_window/max_hold/sl/tp/cooldown |
| metrics_json | n/win/PF/t/CI/permutation_p/前后半段 PF |
| gate_verdict | pass / fail / insufficient_data |
| generated_at | 生成时间 |

### 2.3 pair_strategy_bindings

| 字段 | 说明 |
|---|---|
| symbol | 交易对 |
| candidate_id | 绑定哪个候选 |
| status | running / paused / stopped |
| enabled_at / disabled_at | 上下线时间 |
| stop_reason | 自动熔断原因（连续亏损/数据断裂/回测失效） |

## 3. 前端仪表台（/experiments，第一版只读）

首页展示：

- **实验总览卡**：运行中 / 已熔断 / 已下线 / 候选待审；
- **心跳列表**：每个任务最近心跳时间，超时标红；
- **实验详情**：点击查看参数、基线、最近报告、状态时间线；
- **候选策略表**：AI 选币产生的交易对 → 候选因子策略 → 门禁结果；
- **一键操作（二期）**：候选通过后“启用”（写 bindings），启用后自动进入监控，不搞灰度。

## 4. Obsidian 私人 AI 数据库（采用，作为知识层）

结论：**用，但不是数据库，是知识视图**。事实仍存 PG，Obsidian 只消费自动导出的 Markdown。

自动导出脚本（`scripts/export_obsidian_vault.py`）每日/每次实验后运行：

- `00-实验仪表台.md`：星图 MOC，链接所有运行中实验、最近报告、心跳状态；
- `01-分析报告/日报/YYYY-MM-DD.md`：自动汇总当日体检、回测、成本、纸盘结果；
- `05-因子实验/{symbol}-{period}-{factor_set}.md`：每个候选的实验档案（参数、门禁、报告链接、状态）；
- 每次导出生成 `_bases/实验索引.md`，Obsidian 图谱即“记忆星图”。

中断检测：心跳表超时 → 仪表台标红 → 导出脚本在 MOC 顶部写“⚠️ 中断任务”，Obsidian 首页即可见。

## 5. AI 选币 → 短期因子策略生成器（核心新组件）

### 5.1 为什么不能慢慢 A/B

AI 选币选出的交易对可能只存活几天到几周；14 天对照跑完，交易对可能已经死了。所以策略生成必须“快”，且“先验证后启用”。

### 5.2 流程（目标：选币后 10 分钟内产出可评估候选）

```
AI 选币输出交易对
  → 1. 数据就绪检查（5m/1h/4h 覆盖；不足则快速回填，回填失败则拒绝）
  → 2. 快速因子扫描（复用 kline_factor_backtest）
        矩阵：period ∈ {5m,1h,4h} × factor_set ∈ {hybrid,meanrev,breakout}
              × threshold ∈ {0.3,0.5,0.7} × 1~2 组 SL/TP
        单交易对控制在 2~5 分钟
  → 3. 硬门禁（缺一不可）
        n≥100；PF≥1.0；前后半段 PF≥0.95；t>1.0；
        悲观成本下仍为正（可选）；随机基准不劣化
  → 4. 写入 pair_strategy_candidates（不自动上线）
  → 5. 人工/审批启用 → 写 pair_strategy_bindings
  → 6. 监控：每 tick 心跳；连续 N 笔亏损或数据断裂 → 自动暂停并告警
```

### 5.3 快速回填

- 5m 不足 30 天：调用 `scripts/backfill_scalp_5m.py --symbols X --days 60`；
- 1h/4h 不足 90/365 天：调用 `backfill_full_history`；
- 回填失败（交易所无此币）→ 直接拒绝该交易对，不硬撑。

### 5.4 不做的事

- 不对未验证候选开半仓“看看”；
- 不在同一个交易对上同时跑多个未验证策略；
- 不在交易对已失效后继续用旧策略。
