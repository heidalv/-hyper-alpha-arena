# 中短线因子系统深度检查报告（2026-08-14）

> 检查范围：`backend/services/factor_engine/**` 及其上下游（进化循环、调度器、活跃集策略、云端同步、清理服务、事件触发、API 路由、DB 契约、前端类型）。
> 方法：主审方逐文件通读 + 5 个并行审查子代理（打分门控链 / 同步管道存储 / 计算缓存运行时 / 信号融合权重 / 调度演进 DB 契约）+ 运行态实测（API、日志、.env、进程命令行）。
> 所有结论均有「文件:行号」证据；标注"已实测"的经过运行数据验证。

## 一、执行摘要

中短线因子系统的 **「发现 → 验证 → 晋升 → 实盘合成」闭环在四个环节上同时断裂**，且存在一个把全部晋升判死的结构性 bug：

1. **晋升闸门恒拒（P0-1）**：DSR/PBO 多重检验的输入语义错误 + 边界陷阱，默认 3 币配置下数学上恒失败 → 任何因子最多评 C，永远无法晋升 active；而单币时反而 fail-open，安全语义颠倒。
2. **晋升后的因子也进不了实盘（P0-2）**：三类命名空间/类别映射错位——`ai_*` 公式因子类别映射失败落 PATTERN 被排除；`evo_*` 进化因子与精选白名单键不匹配被拦；主 V3 管线又完全不应用精选策略 → 三路径口径分裂，2026-08-13 P0-1"收敛到精选池"的止血修复只在部分路径生效且方向相反（精选路径恒空集）。
3. **在线反馈环是假的（P1 群）**：在线权重学习标签恒 0、短线晋升后被前缀过滤清空、退役/清理持久化全部静默空转。
4. **实盘融合信号带系统性偏差（P1 群）**：资金费率因子双重缩放恒满格看空、无方向因子未过滤重新注入偏多、regime 权重被反向稀释。

结论：**该系统的评分骨架（walk-forward 样本外回测、K线升序假设一致性）是可信的，但"自动发现因子进入实盘"这条业务链目前整体不工作，且部分路径上工作方式是反的。**

## 二、P0 级问题（致命）

### P0-1 DSR/PBO 闸门结构性必失败 → 晋升管道整体死锁（已实测）
- **位置**：`factor_backtest_scorer.py:407-411,452-476`；`dsr_pbo.py:153-157,247-258`；`config/settings.py:1042,1058,1062`
- **证据链**：
  1. `_dsr_pbo_gate` 传入的是"单因子在 BTC/ETH/SOL 上的 3 个 ICIR"（每币一个），`compute_pbo_simple` 规定 `n_factors < 4` 恒返回 `pbo=0.5`（dsr_pbo.py:154-157）。
  2. 调用点门槛 `pbo < _max_pbo`，`_max_pbo` 默认 0.5（settings.py:1062）→ `0.5 < 0.5` 恒假 → `dsr_ok` 恒 False → 评级恒走 `elif not dsr_ok: grade="C"`（factor_backtest_scorer.py:430-432）。
  3. DSR 本身也恒失败：3 样本的 `(max-mean)/std ≤ ~1.4`，恒小于 n_trials=40 的 Gumbel 极值期望 ~2.46 → `significant` 恒 False。
  4. 反向漏洞：`len(icir_list) < 2`（单币）时 fail-open 直接返回 True（factor_backtest_scorer.py:460-464）——"多币全拒、单币全放"。
- **运行实证**：`GET /api/ops/midlong-factors` → 14 个 rejected 的 reason 全部为 `"DSR/PBO 未通过（pbo=0.500）"`，中长线 active=0；`data/discovered_factors.json` 23 条全部 rejected。
- **影响**：`validate_and_promote` / `validate_all_candidates` / alpha101 验证（短线+中线共享 `score_formula`）全部形同虚设；连带 `scalp/midlong_active_factor_set.recheck_and_prune` 复检时 active 因子最高只能拿 C → 第一次复检就被降级摘除。
- **修复**：① PBO 输入应为"一批候选因子的 ICIR 分布"而非单因子跨币 ICIR；② 样本不足（2~3 币）时显式 fail-open 并 WARNING（与单币一致），或跳过 DSR；③ 阈值比较改 `<=`（0.5=无证据不应构成硬阻断）；④ 加 3 币场景单元测试锁定。

### P0-2 晋升/白名单/类别三重错位 → 精选路径恒空集、主路径全量（已实测）
- **位置**：`base_factors.py:404,423,443-448,674-677`；`scalp_factor_exclude.py:27-31,46-81`；`scalp_loop.py:374`；`scalp_factor_router.py:412-435`；`v3_factor_pipeline.py:246`
- **证据链**：
  1. `FactorCategory` 枚举没有 TECHNICAL/COMPOSITE/DISCOVERED/ALPHA101；`_resolve_category` 映射失败静默落 `PATTERN`（base_factors.py:443-448）。自定义公式因子 category 默认 `"discovered"`（custom_factor_store.py:177,232）→ 全部落 PATTERN。
  2. 短线热路径默认 `exclude_categories={PATTERN, BEHAVIORAL}`（scalp_factor_exclude.py:31；.env `SCALP_EXCLUDE_PATTERN=1`），且 exclude 判断先于 allowlist（base_factors.py:674 在 677 之前）→ 即使因子在白名单里也先被排除。
  3. 进化因子以 `evo_{factor_id}` 挂进 FACTORS（base_factors.py:404），而精选白名单从 DB/商店读**裸 id**（scalp_factor_exclude.py:59,74-76），`compute_all_factors` 精确匹配 `name not in allowlist`（base_factors.py:677）→ `evo_xxx` 恒不匹配。
  4. 当前运行态：allowlist={`d6f82d364676127e`,`seed_rev20`,`seed_rev50`}（3 个 PAPER 行）∪ 自定义 active=0 → 在启用 allowlist 的路径上（scalp_loop.py:374、scalp_factor_router.py:414/434 回退路径）`compute_all_factors` **恒返回空集**。
  5. 反向：主 V3 因子管线（v3_factor_pipeline.py:246）调用 `compute_all_factors` **不传 allowlist/exclude** → 全量计算 → 08-13 P0-1"收敛到有 OOS 证据的精选池"的策略对主路径零生效。
- **影响**：三条实盘计算路径口径互相矛盾——精选路径算 0 个因子、主路径算全量（含 130+ 无验证 ai_generated 因子）；`evo_*` 桥接（注释自称"修复进化闭环与实盘脱节的核心断层"）实际仍失效。
- **修复**：① `_resolve_category` 增加 technical/composite/discovered/alpha101→合理类别映射，失败时 WARNING 而非静默 PATTERN；② allowlist 与 FACTORS 键同构（统一剥/加 evo_ 前缀）；③ 主 V3 路径与精选路径共用同一套 allowlist/exclude；④ 加一条"allowlist 非空但命中 0 个键"的启动期告警。

## 三、P1 级问题（高，按链路分组）

### A. 打分/评估
- **P1-A1 `FactorEvaluator` 全局单例 forward_period 首建定死**：`factor_evaluator.py:343-347` 只在首次创建时设置；`factor_backtest_scorer.py:330,346-350` 是唯一调用方且 `evaluate_factor` 不传 forward_period → 进程内第一个被评分因子的前瞻期决定后续全部因子（1h/4h/1d 互污染）的 IC/ICIR/衰减/单调性评级。修复：去掉单例或显式传参。
- **P1-A2 负 IC（反向可交易）因子被评估器/purge 误拒**：`factor_evaluator.py:141-151`、`purge_pipeline.py:259` 用带符号 icir 评级，与 scorer 的 `abs()` 口径（factor_backtest_scorer.py:416-417）矛盾。修复：统一 `abs(icir)`，方向由回测 orient 决定。

### B. 活跃集/退役
- **P1-B1 短线退役/降级写回漏传 tenant_id（静默失败）**：`scalp_active_factor_set.py:122-124,133-135,141-143` 三处 `update_scores` 未传 tenant（中线版已修，短线版漏修）→ `_resolve_key` 返回 None → 写回 False 被忽略 → 内存摘除已执行但目录状态未变 → 热加载/重启后"已退役"因子复活震荡。修复：补 `tenant_id=_resolve_tenant_id()` 并检查返回值。

### C. 进化循环
- **P1-C1 短线晋升前缀过滤 bug → promoted 恒被清空**：`factor_evolution_loop.py:2151-2156`——`_promoted_rows_for_save` 返回已加 `s5m_` 前缀的落库行（:1119-1149），而过滤用未加前缀的 `p["factor_id"]` 比对 → 1m/3m/5m/15m 全部不匹配 → promoted=[] → 晋升日志/事件回测触发/本轮监控全部断链（因子其实已落库）。修复：先 `_tag_one_short_horizon(p, period)` 再过滤，或用 id 映射对齐。
- **P1-C2 在线权重学习标签恒 0**：`factor_evolution_loop.py:1708-1712` 特征取 `evaluate(fields)[-1]`、标签取 `fwd[-1]`，而 `_forward_returns`（:266-271）尾部 horizon 根恒 0 → `learn_one(x, 0)` 永远用零收益训练 → 权重向 0 退化（与运行态"3 个 PAPER 因子 online_weight 全 0"吻合）。修复：特征取 [-2]、标签取 fwd[-2]。
- **P1-C3 晋升绕开生命周期状态机**：`factor_backtest_scorer.py:510-532` A/B 直写 `status="active"` 并热加载进 FACTORS，不经过 lifecycle 的 ORTHO→PAPER→SMALL_LIVE→ACTIVE 影子期/审批；三套状态词汇（FactorState 大写 / factor_active_set.state 大写 / custom_factor_store.status 小写）互不映射。修复：明确职责边界并统一 SSOT。
- **P1-C4 `TRADABLE` 含 PAPER**：`active_set_policy.py:23` 把 PAPER 归入实盘热路径，与 lifecycle.py:29"PAPER=纸上影子"语义冲突（ops 面板注释称其为刻意设计，需产品确认）。

### D. 清理/审计
- **P1-D1 清理服务持久化全程空转**：`factor_cleanup_service.py:67-77` 取 registry 类因子 id（rsi/macd…），`194-205` 调 `set_status`（无 tenant，键 `t{tid}:ai_*` 永不命中 → 全部 False 被忽略）；`245-260` 读取时 `list(status=..., tenant_id=None)` 恒返回空（custom_factor_store.py:331-333）→ 每周 7 天一次的大批量 IC 评估产物无人消费，功能是假的。修复：目标改为 factor_runtime_weights 文件或显式租户。
- **P1-D2 清理服务若修复将绕过闸门直接晋升**：`factor_cleanup_service.py:185-200` 按 |IC| top-N 直接 `set_status(fid, "active")`，不经过回测/DSR/冗余闸门。修复：清理只允许收紧动作，晋升唯一入口是 `validate_and_promote`。
- **P1-D3 瘦身审计 quarantine 首次命中即物理移文件（每周二 3:30 自动 apply=True）**：`factor_slimming_audit.py:221-236,325-330` + `main.py:1628-1643`——不查 `factor_active_set`、无观察期、无恢复逻辑、不降权；当前 ACTIVE 因子一周 IC 偏低即被永久移出实盘。修复：active/live 因子强制只报告不移动；quarantine 加观察期与恢复。

### E. 信号融合（实盘热路径）
- **P1-E1 资金费率双重缩放 → 恒满格看空**：`base_factors.py:1002-1006` 已 `×100` 转百分比，`factor_signal_generator.py:78-80` 又 `-value×100` → 正常 0.01%~0.1% 费率恒输出 -1.0，且 |direction|=1 必进 top-15 聚合，注入恒定空头偏置。修复：统一单位口径（单次缩放 + 合理饱和）。
