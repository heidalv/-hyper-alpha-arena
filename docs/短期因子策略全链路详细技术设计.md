## 0. 公共设计约定

### 0.1 灰度开关命名

所有新功能开关统一 `FEATURE_<MODULE>_ENABLED`，默认值一律 `false`（除明确标注安全默认）。
开关读取统一走 `backend/config/settings.py` 的 `os.getenv` 模式，并在
`/api/system/feature-flags` 暴露只读状态，便于验收。

### 0.2 审计与可观测

- 每个模块关键事件写结构化日志：`[<Module>] <event> <json>`；
- 涉及决策/评分的写审计表（见各模块）或复用 `decision_core.record_block_event`；
- 所有新增表在 alpha_analytics（因子/回测/学习类）与 alpha_arena（交易类）按职责分库。

### 0.3 错误处理

- 新服务全部 fail-safe：异常返回旧行为 + 告警计数，不允许抛出到交易链路；
- 外部依赖（交易所 API/LLM）超时统一 `asyncio.wait_for`，默认 10s。

## 3. M3 因子暴露矩阵服务（详细）

### 3.1 模块与接口

```python
# backend/services/factor_engine/exposure_service.py（新增）
class FactorExposureService:
    """单例；内存缓存 30s + DB 快照（10min）。"""

    def exposure(
        self,
        symbol: str,
        period: str = "5m",
        count: int = 200,
    ) -> list[dict]:
        """返回：[{factor_id, expr_id, z_score, net_ic, weight, expected_alpha}]"""

    def snapshot(self, symbols: list[str], periods: list[str]) -> None:
        """后台任务：写 factor_exposure_snapshots（热币每10分钟）。"""

    def matrix(self, symbols: list[str], period: str = "5m") -> pd.DataFrame:
        """选币/PRL 用：行=symbol，列=factor_id，值=expected_alpha。"""
```

**计算流程**：

1. 加载 `factor_active_set WHERE state='ACTIVE'`（内存缓存 60s）；
2. `data_center.get_klines(symbol, period, count=max(200, window*3))`；
3. 每因子 `expr.evaluate(fields)` → rolling z-score（窗口 = max(因子窗口×3, 30)）；
4. `expected_alpha = z_score × net_ic × weight`（net_ic 来自 M2，缺省 0）；
5. 任一因子抛异常 → 跳过并计数（`fail_factors`），不阻断整 symbol。

### 3.2 API

```json
GET /api/market/factors/exposure?symbol=BTC&period=5m
{
  "symbol": "BTC", "period": "5m",
  "as_of": 1785599999,
  "factors": [
    {"factor_id": "f_abc123", "z_score": 1.23, "net_ic": 0.031,
     "weight": 0.02, "expected_alpha": 0.00076}
  ],
  "fail_factors": 0,
  "source": "factor_exposure_service"
}
```

### 3.3 快照调度

- 复用 `task_scheduler`：`factor_exposure_snapshot` 每 10 分钟；
- 币集：运行中会话 symbols + 持仓 + watchlist（上限 60）；
- 周期：5m/15m（热币）、1h/4h（会话币）。

### 3.4 验收测试

| 用例 | 方法 |
|---|---|
| 缓存命中延迟 | 连续两次请求，第二次 P95<100ms |
| 失败隔离 | 构造 1 个坏因子表达式，接口仍返回其余因子且 `fail_factors=1` |
| 快照落库 | 15 分钟后 `SELECT count(*) FROM factor_exposure_snapshots` 增长 |
| 与权重联动 | 手动改 `current_weight` 后接口 `expected_alpha` 同步变化 |

```python
def _score(sig: PeriodSignal) -> float:
    d = 0.0 if sig.direction == "neutral" else (1.0 if sig.direction == "long" else -1.0)
    return d * (sig.confidence / 100.0) * W[tier]

def resonance(symbol) -> float:
    return sum(_score(s) for s in recent(symbol, max_age=WINDOW[tier]))
```

窗口：short 最近 10 分钟、mid 最近 30 分钟、long 最近 60 分钟；
权重：`PRL_W_SHORT=0.35 / MID=0.40 / LONG=0.25`。

### 7.2 行为矩阵

| 场景 | 判定 | 动作 |
|---|---|---|
| 短顺中且顺长 | aligned(score≥0.30) | position_pct×1.0，hold×1.5 |
| 短顺中/长其一 | aligned(score 0.15~0.30) | position_pct×0.75 |
| 无中长数据 | no_data | 维持原 proposal（不惩罚） |
| 短与中反向 | conflict | position_pct×0.5 或禁开（由 PRL_CONFLICT_BLOCK=true 决定） |
| 短与中长全反向 | conflict(score≤-0.30) | 禁开 + 日志 `PRL reversed block` |

### 8.2 quant_layer 修正

```python
def compute(packet, thesis, db=None):
    signals = _existing_rules(packet, thesis)          # 现有规则信号
    anchor = thesis.factor_anchor
    if anchor is not None:
        exp = exposure_service.exposure(packet.symbol, anchor.period)
        z = next((e["z_score"] for e in exp if e["factor_id"] == anchor.factor_id), 0.0)
        # 同向：confidence += min(10, |z|*4)；反向：confidence -= min(20, |z|*6)
        # 反向且 z ≤ -1.5 → 触发证伪（见 8.3）
    return signals
```

### 8.3 证伪状态机

```
active --(z_score ≤ -1.5σ 或 net_ic<0 连续3次评估)--> watch
watch  --(24h 内 z 回到 >+0.5σ)--> active
watch  --(24h 未恢复)--> invalidated（thesis 降权，停止新开仓）
```

触发点：`qual_layer.update_thesis` 的 LLM 更新前执行；
日志事件：`factor_anchor_invalidated {symbol, thesis_id, factor_id, z}`。
