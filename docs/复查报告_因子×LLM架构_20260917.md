### 27.2 结论：**实盘 prompt 有 6 个模板占位符恒为 "N/A"，而预览显示真值**

> **口径更正（F374，2026-09-18）**：本节初版写的是"**47 个变量**恒为 N/A"——**那是虚高的**。
> 47 出自"AST 收集到的所有 dict 字面量键"，其中包含大量**嵌套数据结构的键**
> （如 `{"15m":…, "1h":…, "long":…}`），它们**根本不是模板变量**。
> 用**真实模板占位符**求交后，会渲染成 N/A 的缺口是 **6 个**（见下表）。
> **这是我自己第 23 次更正**，也第二次犯"用错口径数数"的错（第一次是 §24.3 用 `len(dict)`）。

| 项 | 读数 |
|---|---|

| 预览 `_build_prompt_context`（`ai_decision_service.py:628`）产出键 | **83** |
| 仅预览（AST 口径，**不可直接对外报**） | 42（其中 36 个不是模板占位符） |
| 真实模板数 / 静态占位符总数 | **22 / 49** |
| **模板在用、实盘不给**（= 会渲染成 N/A） | **6** |

**这 6 个缺口（按补齐成本排序）**：

| 占位符 | 预览侧来源 | 选项①要做什么 |
|---|---|---|
| `market_regime`、`market_regime_description` | 由其它字段派生 | 在子构造器内补派生（不动签名） |
| `recent_trades_summary` | 派生 | 同上 |

**机制（为什么是静默的）**：实盘渲染是

### 32.2 但 `backtest_wisdom` 的内容是**样本内极值**

**机制（`backtest_insight_compiler._extract_risk_wisdom():230-251`）**：

```python
good_runs = [r for r in runs if (r.sharpe_ratio or 0) > 0.5 and (r.win_rate or 0) > 0.35]

```

**三重问题**：
1. **样本内选择**（`sharpe>0.5 且 win_rate>0.35` 是同一批数据上的筛选）；
2. **再取最大值**（双重选择性偏差），且**无 OOS / 无收缩 / 无去膨胀**；

4. 文本标签"（基于50次回测）"里的 50 是**筛后条数**，与每个 Sharpe 背后的样本量无关 ⇒ **读数误导**。
5. 本路径 header（`:194`）只有"(自动生成)"，**缺**另一处 header（`:108`）的"仅供参考"。

**影响**：这些数字（含由"好样本"中位数派生的**建议杠杆 8x**）每轮都进主脑 prompt，
被 LLM 当作"经验参考"。这是"评分是否科学"主题下**又一例**：数字算得出来 ≠ 它科学。

**未改**（改文本 = 改主脑输入 = 决策行为变更，需你同意）。已把机制钉成回归锁
`backend/tests/unit/test_backtest_wisdom_selection_20260918.py`（6 条）：

## 35. 综合：进入决策的数字必须自带**样本量 + 口径 + 不确定度**（F379 + 一族收敛）

### 35.1 F379：`factor_route` 呈现层（第 1 问的呈现面）

真实载荷（BTC 实价下抓取，**1813 字符**，进主脑 `extras["factor_route"]`）：

```json
{"symbol":"BTC","action":"hold","score":-0.1779,"confidence":55,
 "votes":{"macd@4h":{"z":-0.902,"vote":-0.902,"ic":-0.1143,"trend_inverted":true},
          "hv@4h":{"z":-0.442,"vote":-0.442,"ic":0.0961}, …共 16 条},
 "reason":"factor_route score=-0.178 n=16 votes=macd@4h:-0.902 …"}
```

**做对的地方（先说好话）**：每票带 `ic`；反向使用显式标 `trend_inverted: true`；`reason` 带票数。

**三处不足**：
1. **票里有 `ic` 但没有样本量**——`ic=-0.1143` 是在多少样本上算的？LLM 无从得知。
   而上游**本来就有**：`factor_runtime_weights.json` 的 `stats` 段实测 **216 个因子带 `n`**
   ⇒ **有而没透传**（不是拿不到）。结合 §14 已查实的"重叠窗口 / 208.8 行每笔"，
   "给 IC 不给 n"正是同一缺口。
2. **`confidence` 不是置信度**：`midlong_factor_route.py:457`
   `confidence = clip(50 + abs(score)*30, 0, 80)` —— **|score| 的仿射映射**，
   不含样本量、不含显著性、不含票间离散度，但字段名叫 `confidence`。
3. **`reason` 把 16 票原样再抄一遍**（与 `votes` 重复）：1813 字符里相当一部分是裸数字噪声。

回归锁：`backend/tests/unit/test_factor_route_presentation_20260918.py`（6 条，
含反向标注"别退化"的锁与"上游确有样本量"的反证）。

### 35.2 一族的共同形态（这才是要治的病）

| 证据 | 进入决策的数字 | 缺什么 |
|---|---|---|
| §14 十条错误级发现 | rank-corr / NDCG / forward_returns… | 统计口径本身错 |
| §18 Parity | `score` | 结构性无信息（常数基准）／未比对写成满分 |
| §32 `backtest_wisdom` | 「最优夏普 11.46」 | **样本内极值**、无 OOS、无收缩 |
| §33 `consolidated_lessons` | 「3 笔 胜率 67%」当**长期规则** | 样本量阈值过低、文本无不确定度；`days` 声明≠实际 |
| §34 主脑 `recent_pnl_14d` | 「近 14 天盈亏」 | **毛口径**（未扣费用，偏乐观 11%） |
| §35 `factor_route` | 16 票的 `ic` + `confidence` | **无样本量**；`confidence` 名不副实 |
| §35.5 `chart_review`（**载荷最大项**，2716 字符＝30%） | 详尽的 `key_levels` / `position_advice` + `accepted: false` | **「未过共识门」没有口径说明**，与肯定语气并存 |

**共同形态**：**数字算得出来，但没人负责它是否成立、是否同口径、是否该被当成结论。**

### 35.3 建议的一条治理原则（可执行）

> **P-1：任何进入决策路径（LLM prompt / 权重 / 门控）的数字，必须自带
> ①样本量 ②口径声明 ③不确定度（或显式的"样本不足/存疑"标记）。
> 三者缺一，则要么补齐，要么在渲染层显式标注"仅供参照、不足以支撑结论"。**

落地方式（按代价从低到高）：
1. **透传样本量**（`factor_route` 票里加 `n`；上游已有 216 个因子的 `n`）——最小；
2. **渲染层加标注**（§32 的 `best_sharpe`、§33 的小样本规则、§35 的 `confidence` 改名或标注）；
3. **口径统一**（§34 改用净口径，或直接改用 `trade_facts`）；
4. **筛选阈值提高**（§33 `min_samples` 3 → ≥10）与**让声明生效**（§33 的 `days`）。

**其中 1 与 2 属"读数诚实性"，不改变任何策略判定**（只改数字的**呈现**），
是本报告建议**优先做**的部分；3 与 4 会改变主脑看到的内容，需与重启决策一并考虑。

### 35.4 为什么这不是吹毛求疵（三个具体后果）

1. 主脑读到的近期盈亏**偏乐观 11%**（§34）⇒ 它对"自己最近打得怎么样"的判断是被抬高的；
2. 40% 的"长期规则"只有 **3 笔**（§33）⇒ 主脑可能在噪声上建立信心；
3. "最优夏普 11.46 / 胜率 92.9%"（§32）连同由此派生的**建议杠杆 8x** 每轮进 prompt
   ⇒ 它被当作可追求的目标，而不是应当存疑的样本内巧合。

### 35.5 同族补一例：载荷最大项 `chart_review` 的 `accepted: false`

**纪律 24 的运用**：前 39 节里最大的一笔未打印载荷是 `chart_review`（§38.2 表内第一行，
2716 字符 ≈ extras 的 30%）。把整段打出来后（`B._chart_feed("BTC")` / `("ETH")`，运行态）：

```
structure / timeframe_alignment / key_levels[{price, note}] / invalidation /
position_advice / key_factors …   +   "accepted": false, "consensus_score": 0.152   (ETH 0.14)
```

**内容是高质量的**（分层位、每层带 note、有失效条件、有仓位建议），这部分没有问题。
问题只有一处，且**严重度低**：

| 项 | 事实 |
|---|---|
| `accepted: false` 是什么 | 图审**未过其自身共识门**的标记。代码把它列进 `_SOFT_MISS_MARKERS`（`brain.py:296`）⇒ 语义是"**软证据缺失，不阻止分析、不阻止开仓**" |
| 呈现层是否解释了它 | **没有**。`chart_role`（`brain.py:1199`）原文只写：「附加证据。缺失或 `source=none` 不阻止分析、也不等于必须观望。」——解释了 `source=none`，**没解释 `accepted=false`** |
| 为什么仍值得记一笔 | 内容详尽 + 语气肯定（给出具体价位与仓位建议），而**唯一的反向信号是一个布尔字段**。按纪律 24 打印全文后的直觉反应是"这份图审很有料"，要看代码才知道它其实没过门 |

**低严重度的理由（不夸大）**：①字段名基本自解释；②设计上它确实只是附加证据，
`is_soft_missing_item()` 的处置是正确且刻意的；③`consensus_score` 也在同一个块里，
有判断力的读者可以自己打折。

**修正方式（一行，属"读数诚实性"，不改任何判定）**：把 `brain.py:1199` 的 `chart_role` 补成
「…缺失、`source=none` 或 `accepted=false`（图审未过其自身共识门）都不阻止分析、
也不等于必须观望。」——把已在代码里明确的语义**补到 LLM 能读到的地方**。

**钉住用例**：`test_chart_review_accepted_flag_has_no_explanation`
（断言 `chart_role` 此刻**尚未**提及 `accepted`；修好后用例失败 ⇒ 提醒同步本节与 B18）
＋ `test_chart_feed_passes_accepted_through`（断言 `_chart_feed` 是**原样透传**上游
`accepted`/`consensus_score`，不是自己算的门）。两条均绿。

## 37. F382：`similar_episodes`（海马体模式完成）——**承诺"及其结局"，交付 5 个「未开仓」**

### 37.1 现象（运行态实测，135 字符全文）

```
ranging/low波动 neutral → 未开仓；ranging/low波动 short → 未开仓；ranging/low波动 neutral → 未开仓；
ranging/low波动 neutral → 未开仓；ranging/low波动 short → 未开仓
```

n=5，**全部 `opened=false`、`outcome_pct=null`**；5 条几乎完全相同（3×neutral + 2×short，similarity 全为 3）。
而主脑饲料自己的说明写着：*"相似市场指纹的历史情景**及其结局**。做对了参考，做错了别再摔。"*
——**承诺了结局，交付的是 5 个「未开仓」**。

### 37.2 三处缺陷（层层递进，都有代码实证）

**缺陷 1：检索不筛「有结局」**
`episodic_memory.retrieve_similar():234` docstring 写"检索与当前指纹相似的历史情景（**带结局**）"，
而其查询（`:241-250`）只有 `symbol`/`tier` 过滤 + `order_by(created_at).desc().limit(200)`
——**没有 `opened==1`、没有 `outcome_pct.isnot(None)`**。
**反证**：同模块的 `consolidate_daily():333` **有**这两个过滤 ⇒ **是漏写，不是不会写**。

**缺陷 2：产出侧严重饥饿，且失配**静默**
| 项 | 读数 |
|---|---|
| BTC/mid 情景总数 | **261** |
| 其中带结局（`opened=1` 且 `outcome_pct` 非空） | **6（2.3%）** |
| 最新 200 条（检索池）里带结局的 | **6（3.0%）** |

⇒ 无论怎么排序，**top-5 几乎必然是"未开仓"**。
唯一写入方 `backfill_outcome()` **只有一个调用点**（`paper_trading_engine.py:2136`），
它取**该 paper 账户最新的 `FullAutoSession.session_id`**（`:2137-2143`）去精确匹配
`MltoEpisode.session_id`，并要求 `tier` 字符串一致 ⇒ **会话轮转或 tier 标签不一致就匹配不到**。
而两条失败路径的可见性分别是：

| 失败形态 | 行为 |
|---|---|
| **匹配不到那条情景**（`row is None`） | `return False`，**零日志**（连 debug 都没有）⇒ **真静默** |
| 抛异常 | `logger.debug(...)` ⇒ 生产日志级别 INFO 下**看不见** |

**缺陷 3：归属粗糙**
匹配口径是"该 (session,symbol,tier) 下 `outcome_ts IS NULL` 的**最新一条**"
⇒ 回填到的可能**不是**开出这笔仓的那条决策情景 ⇒ "相似情景 → 结局"的因果链自身不可靠。

### 37.3 结论与处置

## 42. F387：主脑的「复盘记忆」**丢掉了"为什么平仓"**（字段结构性恒空）

**发现方式**：纪律 24 的最后一轮应用 —— 把 extras **26 个键全文落盘**
（`scripts/dump_brain_payload.py` → `logs/payload_dump_*/`），逐键阅读。
§38.2 原表里 `reflexion_memory` 标着"**干净**"，但那是**没读过全文时的判断**。

### 42.1 现象（运行态实测）

`reflexion_memory`（885 字符，载荷第 4 大）里 8 条交易记录，
**`"exit"` 字段 8/8 都是空串**：

```json
{"side": "long", "pnl_pct": -2.01, "result": "loss", "exit": "", "at": "2026-09-17 00:55"}
```

### 42.2 根因（一行代码，可执行证明）

`mlto/brain.py:980`：

```python
"exit": str(r.get("close_reason") or "")[:40] if isinstance(r, dict) else "",
```

而 `r` 来自**同一函数**的 `db.execute(...).mappings().all()`（`:960`）⇒ 行类型是
`sqlalchemy.engine.row.RowMapping`。**`RowMapping` 是 `Mapping`，但不是 `dict`** ⇒
`isinstance(r, dict)` **恒为 False** ⇒ 三元永远走 `else ""`。

`scripts/probe_reflexion_exit_field.py` 用**同样的查询**实测：

| 检查 | 读数 |
|---|---|
| 行类型 | `sqlalchemy.engine.row.RowMapping` |
| `isinstance(r, dict)` | **False** ← 代码里的判断 |
| `isinstance(r, collections.abc.Mapping)` | **True** |
| 库里 `close_reason` 非空 | **10/10** |

被丢弃的实际内容（这是"为什么平仓"，主脑一个字都看不到）：

```
thesis_should_close ×3        exit_policy:min_roi_decay ×3
breakeven_tp ×2               profit_drawdown_full ×1
trend_weaken: 原始多头论点已失效：4h 空头排列(EMA9<21<50)、MACD柱-169，
              1d MACD柱-761 转负，趋势生命周期由减速上涨转为反转。价格 75765 跌破开仓价
```

### 42.3 为什么这不是小事（与 F378 的差别）

`reflexion_memory` 的 `role` 文案是「这是你近期在本币的**真实决策后果**。连胜别飘、连败别犟；
若同方向连续亏损，降低 confidence 或要求更强证据。」—— 它要教的正是"从亏损里学"。
但亏损的**性质**恰恰只在 `close_reason` 里：

- `thesis_should_close` / `trend_weaken:` = **判断错了**（论点失效）⇒ 该降 confidence；
- `exit_policy:min_roi_decay` / `breakeven_tp` / `profit_drawdown_full` = **纪律性退出**（判断未必错）。

⇒ 现在主脑只看到 8 个 `pnl_pct` 和一个 `loss`，**无法区分"我判断错了"与"我按纪律退出但没吃到"**。
它被要求"连败别犟"，却拿不到判断"该不该犟"的唯一线索。这与 §34（毛口径偏乐观 11%）不同：
那不是失真，而是**整整一个字段的静默丢失**。

**同族但更轻的一例（记录，不单列缺陷）**：`daily_brief` 每轮进 prompt 的 200 字符里
`regime/direction/symbol_view` 全 `null`、`summary=""`、`accepted=false` ⇒ **空壳**。
判过代码：`_brief_view`（`brain.py:854-880`）是**诚实**的（如实透出 `age_h`/`stale`/`accepted`，
无内容就置 null），空来自上游 `data/latest_daily_brief.json`；`role` 也写明"背景非指令"。
⇒ 属"上游产物为空"，**不是渲染缺陷**，故只记录，且它与 §35.5 一样带着未解释的 `accepted: false`。
