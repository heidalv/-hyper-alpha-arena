## 0. 结论（TL;DR）

1. **诊断成立，且比"各玩各的"更具体**：本仓库的因子系统与 LLM 决策系统是**单向弱耦合**——
   因子以"复合分 4 标量 + 执行层硬否决"约束 LLM，而 LLM 对因子几乎零反馈；真正的决策主力车道
   （短线/中线）已"去 LLM 化"（纯因子路由）。共定位 **8 个断点**（§1）。
2. **统一主题的答案在 GP 平台文档里已经写好**："因子 × LLM alpha 混合策略"——
   **thesis 是一等 alpha 信号，因子是一等 LLM 证据**，双向流动、统一记忆、双循环进化。
   本仓库缺的不是零件（零件全都有且比 GP 设计文档设想的更厚），缺的是**把它们接起来的那条主线**。
3. **重整方案 = 修 3 个真 Bug + 建 3 条双向流**（§3），全部落在本仓库现有组件上，
   不需要引入 QAA 内核（那是 GP/A股侧的载体选择；本仓库等价能力已存在于
   MasterController/调度器/v7记忆/RAG）。

## 1. 诊断：8 个断点（全部 file:line 实证）

**总体架构事实**：两条 LLM 决策车道（主车道 MasterController；备用车道 call_ai_for_decision），
两条"去 LLM 化"车道（短线 scalp_factor_router 纯规则；中线 midlong_factor_route 因子直出决策）。

但**彼此之间没有统一主题串联**，这正是"各玩各的"的机制性根源。

## 3. 重整设计：修 3 Bug + 建 3 条双向流

### 3.1 P0 修真 Bug（半天量级，立刻改变"LLM 看不到因子"的现状）

1. **修断点 1/2**：`strategy_context.py` 调用签名与属性名修正，接 `ai_decision_integration`
   的真实现；备用车道 prompt 恢复因子块；`_build_prompt_context` 的 D7 因子引导经 builder 复活。
2. **修断点 3**：`evolution_scheduler` 传真实 `factor_snapshot`（活跃集 SSOT 现成：
   `factor_active_set` + `factor_signal_generator` 的当日值）。
3. **修断点 6**：`call_ai_for_decision` 读取 trigger_context 里的 `fusion_verdicts` 注入 prompt。

### 3.2 流 A：因子 → LLM 证据包（统一"LLM 看什么"）

主车道因子块从"4 标量"升级为**因子证据包**（复用 hybrid_scoring 证据包模式）：
`{复合信号, top因子暴露, 近期该因子IC/衰减状态, 上次该因子投票的交易盈亏(factor_signal_log归因), factor_weights(断点4复活)}`。
关键增量：**归因回流**——把 `factor_signal_generator.FactorContribution` 的逐单归因摘要注入
master prompt（"最近10单，因子X投多票的4单净亏-2.1%"），LLM 第一次能看到"因子的战绩"。

### 3.3 流 B：LLM thesis → 因子/打分（统一"LLM 产出什么"）

1. **thesis 数值化为一等特征**：MasterController/MLTO 辩论的 `(方向, 置信度, 论点)` 从
   decision_envelope 落入 **hybrid_scoring 通道A 的 thesis 特征位**（混合打分中心原设计的 A1 消融臂，
   目前是空位）——TradingAgents 范式的核心一步：分析师观点=alpha 源。
2. **thesis 作为"软因子"进因子评价体系**：thesis 命中率按 regime 统计（outcome 禁令式 T+N 评估），
   进 v7 记忆 + RAG（断点 5 的因子维度顺势补齐：DecisionSnapshot 加 factor_votes 字段）。
3. **辩论证据双向**：辩论层输入加因子证据包（断点 7 正向）；辩论分歧度作为因子拥挤度信号回传
   factors_lab ⑤（反向，先以日志口径）。

### 3.4 流 C：统一记忆与双循环（统一"学什么"）

- **记忆统一**：RAG 的 DecisionSnapshot 补因子维度（当日 top 因子票 + 事后因子归因）；
  v7 教训池出第二出口——除 Codegen/factors_lab②外，**精华教训注入 MasterController prompt**
  （复用 `build_codegen_context` 的检索，走 `ai_shared_prompt_context`）。
- **双循环**（QuantAgent）：内循环=factors_lab 每日闭环（已上线）；**外循环（新建）**=
  周任务：thesis 准确率 × 因子贡献盈亏 × 模拟vs实盘偏差 三表联查 → 产出"周进化报告" →
  ①修正 factor_weights 学习率 ②生成下周 master prompt 的策略倾向指令 ③喂 gpllm 语料池（SFT 前置）。
- **统一主题载体**：把上述三条流的产物汇聚到**因子研究中心前端**（已上线）加"统一策略"页签：
  thesis 表（方向/置信/证据链/T+N 命中率）× 因子战绩表 × 周进化报告——用户要的
  "值得延续和学习的统一主题"就在这一页。

### 3.5 与 GP/QAA 的边界

QAA 内核是 GP（A股）侧的载体选择；本仓库按 ADR-25 精神**不引入**，等价能力用本仓库件：
调度=task_scheduler、记忆=v7+RAG、审批=lifecycle APPROVAL_REQUIRED、事件溯源=jsonl 落盘纪律。
两平台共享的是**论文范式与反思策略模板**，不共享代码与状态。

## 11. 第六批：strategy_detached 根治（2026-09-18）

**根因链（DB 实证）**：AI 注入币在注入时由 `auto_create_strategy` 自动建策略（`auto_*` 前缀，
如 VIRTUAL/auto_efd68a88ca），但策略生命周期清理会归档/删除（VIRTUAL 的现为 archived）——
WLFI 注入（23:31）→ 策略建 → 提案推进到下单段（23:53-59）→ 策略被清理 →
`ensure_bound_strategy` 重查为空 → `strategy_detached`×7。注入币 LINK/PLAY 同样无策略行。

**修复**：`evaluate_and_execute_proposal` 中 strat 缺位时**自动补建一次再解析**
（挂 host.auto_create_strategy = svc._auto_create_strategy；dup 检查幂等）；
与 BlockCooldown 协同（补建连续失败 5 次即冷却 30 分钟，防重建风暴）。
验证：25/25 测试、重启 health、模块导入全过。上线后观察期见日志。
