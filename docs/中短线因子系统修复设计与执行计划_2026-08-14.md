# 中短线因子系统修复设计与执行计划（2026-08-14）

> 依据：`docs/中短线因子系统深度检查报告_2026-08-14.md`（2×P0、20×P1、26×P2、24+×P3）。
> 目标：把「发现 → 验证 → 晋升 → 实盘合成」闭环恢复为真实可用，且每条修复可独立提交、可回滚、可验证。
> 范围：`backend/services/factor_engine/**` 及其上下游（进化循环、调度器、活跃集、同步、清理、触发、路由、DB 契约）。

---

## 一、设计原则（贯穿所有修复）

1. **单一事实源（SSOT）**：状态词汇、阈值、因子键名、类别映射各只有一处定义，其余引用；禁止再散落魔法值。
2. **失败语义对称**：任何闸门要么明确放行+WARNING，要么明确拒绝+原因落库——不允许"恒 0.5 < 0.5"这类无意的永久拒绝，也不允许静默吞异常。
3. **显式告警 > 静默降级**：凡 fallback（租户解析失败、allowlist 空命中、数据回退）必须 WARNING 且计数，运维台可见。
4. **白名单优先于黑名单**：精选池（有 OOS 证据的因子）一旦命中，不受类别排除影响——这是 P0-2 的核心语义修正。
5. **渐进发布**：行为变更（尤其影响实盘信号）一律配 env 开关灰度，默认先跑 paper 观察 24h。
6. **一个修复一个 commit**：延续本项目"独立 commit 可 revert"的纪律；数据层变更带迁移与备份。

## 二、架构性修复设计（P0/P1 分块）

### 块 A：晋升闸门修复（P0-1、P1-A1、P1-A2）

**现状**：`_dsr_pbo_gate` 把"单因子 3 币 ICIR"当候选分布喂给 PBO；`n_factors<4 → pbo=0.5`；`pbo<0.5` 恒假 → 全拒；单币 fail-open。

**目标设计**（两级）：
- **A1 立即止血（最小改动）**：
  - `dsr_pbo.py:compute_pbo_simple` 样本不足时返回显式 `indeterminate=True`（pbo=0.5 仅作展示值），不再参与判定。
  - `factor_backtest_scorer._dsr_pbo_gate`：`len(icir_list) < FACTOR_SCORER_DSR_MIN_SYMBOLS(默认4)` → 返回 `(True, None)` 跳过 DSR + `logger.warning("[FactorScorer] DSR 样本不足(%d<4)，fail-open 跳过")`；单币与 3 币行为一致化（同一分支）。
  - 阈值比较 `pbo <= max_pbo` 并保留 `pbo=None` 显式跳过路径；DSR 部分保留（`significant` 判断在样本充足时才生效）。
  - `scores.reason` 落库注明 `"DSR skipped: insufficient cross-section(n=3)"`，运维台可见。
- **A2 正确语义（第二阶段）**：
  - 批次入口 `validate_all_candidates`/`run_validate_alpha101` 增加"跨候选 DSR/PBO"：先全部打 ICIR，再用候选池分布做多重检验（复用 `purge_pipeline` 参考实现），单因子接口复用批次结论缓存。
  - 新增配置 `FACTOR_SCORER_DSR_MIN_SYMBOLS`、`FACTOR_SCORER_DSR_SKIP_POLICY=open|closed`（默认 open+告警，可由用户拍板收紧）。

**配套修复**：
- **P1-A1**：`get_factor_evaluator(forward_period=fwd)` 改为每次调用都更新单例 `forward_period`（标量写，无需锁），或 `score_formula` 显式传 `forward_period=fwd`（两处都改，防御）。
- **P1-A2**：`factor_evaluator.py:141-151` 与 `purge_pipeline.py:259` 评级改 `abs(icir)`；`monotonicity` 字段语义统一（落库字段改存"单调比例"，p 值字段单独命名）。

**测试锁定**：单测构造"已知好因子"（高 |IC|、正 OOS sharpe、非冗余）在 3 币配置下必须能通过 → 防回归。

### 块 B：命名空间/类别/白名单统一（P0-2）

**现状**：三类键名（`ai_*`/`evo_*`/裸 id）× 三类状态词汇 × 类别映射静默落 PATTERN × 三条计算路径口径分裂。

**目标设计**：
- 新增 `factor_engine/key_utils.py`：`normalize_engine_key(fid)`（剥 `evo_` 前缀）与 `to_engine_key(fid)`；`base_factors.py:677` 的 allowlist 比对、`scalp_factor_exclude.py:46-81` 的白名单构造、`_detach_from_engine` 全部改走该工具。
- 类别映射表（`base_factors.py` 顶部集中定义）：`technical→按 subcategory 映射（默认 TREND）`、`composite→STRENGTH`、`discovered→PATTERN`（或由用户拍板归入 MOMENTUM）、`alpha101→PATTERN`；`_resolve_category` 未知值 → WARNING + 可配置 fallback（不再静默）。
- **白名单优先语义**：`compute_all_factors` 过滤顺序改为——`allowlist 非空且 name∈allowlist → 计算（不受 exclude 影响）`；否则按 exclude 过滤。白名单命中因子不再因类别被误杀。
- **三路径统一入口**：新增 `compute_live_scalp_factors(klines, md)` 封装 allowlist/exclude 逻辑；`scalp_loop.py:374`、`scalp_factor_router.py:414/434`、`v3_factor_pipeline.py:246` 全部改调该入口（V3 主路径纳入精选策略，用 `SCALP_VETTED_IN_V3=1|0` 灰度）。
- 启动自检：`allowlist 非空但命中 FACTORS 键数=0` → 启动期 ERROR 级告警 + `/api/ops/factor-pool` 展示命中率。
- 状态词汇映射层（见块 H-阈值 SSOT）。

**测试锁定**：端到端——seed 一个合成因子 → validate 晋升 → 断言 `FACTORS` 键与 allowlist 命中 → `compute_live_scalp_factors` 返回该因子。

### 块 C：信号融合方向/权重修复（P1-E1~E4、P2-7/8/19）

**现状**：资金费率双重缩放恒空、无方向因子未过滤、regime 权重反向稀释、D7 死代码、hold 否决失效、side 硬编码 long。

**目标设计**：
- **单位约定（单点定义）**：`funding_rate` 全链统一为百分比数值（0.01=0.01%）；`compute_funding_rate` 单次换算；`_funding_rate_direction` 改为 `-value/0.05` 饱和（0.05% 费率=满格看空，符合原语义），删除二次 ×100。
- **幽灵因子过滤**：`factor_signal_generator.py:276-292` 循环开头加 `if not getattr(fv,'is_directional',True) or not getattr(fv,'has_data',True): continue`（注释与实现一致化）。
- **权重语义统一**：把 `factor_evaluation_pipeline.py:189-212` 的"均值归一为围绕 1.0 的乘数"提取为公共函数 `weights_to_multipliers(weights)`；`ai_decision_integration.compute_fusion_decision` 传权重前先转换；`_aggregate` 缺失 key 默认值改为显式参数（默认 0.0，调用方决定）。
- **D7 引导复活**：`build_factor_guidance_for_prompt` 改调 `generate_signals(...)`（FactorValue 对象不再提前转裸 float，新增 raw 字段供展示）；`fuse` 按真实签名传参。
- **fail-closed 语义**：`decision_fusion_engine.py:77-86` 让 `orchestrator_action∈{hold,frozen}` 都短路为 hold；`data_quality=="low"` 可选强制 hold（env 开关）。
- **side 修正**：`ai_decision_integration.py:303` 用 `positions` 实际方向传 side。

**发布**：全部行为变更走 env 灰度 + paper 观察（详见执行计划阶段 2）。

### 块 D：假闭环修复（P1-C1/C2、P1-B1、P1-D1/D2/D3、P1-C3/C4）

**现状**：短线晋升被前缀过滤清空、在线权重标签恒 0、短线退役写回无租户、清理服务持久化空转且藏免检晋升、瘦身审计每周二自动物理删文件。

**目标设计**：
- **P1-C1**：`factor_evolution_loop.py:2151-2156` 改为先 `_tag_one_short_horizon(p, period)` 再过滤（或 `_promoted_rows_for_save` 同时返回 id 映射）；补单测断言 5m 场景 `promoted` 非空且触发 `on_factor_promoted`。
- **P1-C2**：在线权重改为特征 `evaluate(fields)[-2]`、标签 `fwd[-2]`；`fwd==0/NaN` 样本跳过并计数；权重输出加"样本数/跳过数"审计字段。补单测：构造上涨行情，断言学习后权重不趋 0。
- **P1-B1**：`scalp_active_factor_set.py:122-143` 三处补 `tenant_id=_resolve_tenant_id()` 并检查 `update_scores` 返回值，失败 WARNING。
- **P1-D1/D2**：清理服务目标改为 registry 因子 → 产出 `data/factor_cleanup_decisions.json`（`{rejected:[], low_signal:[]}`）；`factor_evaluation_pipeline` 改读该文件（替代 `custom_factor_store.list`）；**删除** `set_status(fid,"active")` 免检晋升逻辑（晋升唯一入口 = `validate_and_promote`）。
- **P1-D3**：`factor_slimming_audit.run_audit` 分类前查 `factor_active_set`，`state∈{ACTIVE,SMALL_LIVE,PAPER}` 的因子只报告不移动；quarantine 加 14 天观察期状态机（`pending_quarantine → confirmed`）+ 恢复逻辑；首月调度降级为 `apply_changes=False`（只出报告）。
- **P1-C3/C4**：状态词汇统一映射层 + `TRADABLE` 是否含 PAPER 由用户拍板（见 §八）；scorer 晋升写 active 前先写生命周期状态映射（PAPER 起步，由拍板结果定）。

### 块 E：安全加固（P1-E5、P1-F1、P1-F2）

- **云端同步**：`_localize_factor` 所有元数据改用 `json.dumps(...)` 生成字符串字面量（消除裸插值注入面）；`calculation_code` 走 AST 白名单校验（仅表达式、numpy/pandas 白名单调用，禁 import/属性链）；`factor_id` 正则清洗 + 拒绝路径分隔符；localize 成功后 status=`candidate`（由 validate_and_promote 晋升），并检查 `_register_localized_factor` 返回值；同步配置默认 `enabled=False` 直到加固完成。
- **AI 生成因子**：`ai_factor_discovery_service.py` 同款 AST 白名单 + factor_id 清洗；生成的 .py 先 `compile` 再写入。
- 注入用例回归：构造带 `"""`/换行/`import os`/`../` 的恶意定义，断言被拒。

### 块 F：DSL 前视修复（P1-G1、P2-20）

- `cs_rank` 单序列上下文：改为滚动 `ts_rank(x, w)` 或直接抛错要求横截面注入（默认抛错，横截面注入路径显式开关）；`expr/audit.py` 增加对 `rank`/`scale` 在单序列模式的拦截。
- `scale`：标记 deprecated（audit 警告），新公式禁用；存量公式迁移到滚动范数。

### 块 G：调度/并发/鉴权（P1-H1~H4）

- TOCTOU：`evolution_scheduler.py` 检查+置位移入同一锁临界区。

- 因子端点鉴权：`factor_sync_routes.py` 校验/批量/alpha101 端点加 `require_admin`（或 `require_user_tenant` + 显式 tenant 传参）。

### 块 H：数据完整性/SSOT/加固（P2 批量，按优先级分批）

- **factor 表迁移**：`factor_active_set` 补列迁移（current_weight/deactivated_at/last_evaluated_at/expr_id）；`factor_evolution_log.action` 加宽到 String(32)。
- **计算层修复**：MACD 整序列 EMA（P2-12）、factor_cache datetime 序列化（P2-13）、stream logger（P2-14）、taker_ratio -inf 防护（P2-23）、HV 年化系数（P3）、adapter K线升序归一 + 入口断言（新增 P2）。

## 四、测试策略

1. **单元测试（每个修复必配）**：闸门数学（3 币好因子必须过 / 单币与 3 币行为一致）、键归一化、类别映射、权重乘数转换、funding 单位、标签配对（[-2]/fwd[-2]）、前缀过滤顺序、租户写回、清理决策文件、注入用例拒绝。
2. **端到端集成测试（新）**：`tests/unit/test_factor_pipeline_e2e.py`——seed 合成因子 → validate 晋升 → FACTORS 加载 → allowlist 命中 → `compute_live_scalp_factors` 返回该因子 → 信号生成有方向。
3. **运行时冒烟**：修复后 `validate_alpha101` 重跑，验证：晋升 0 或"非 pbo=0.5 的真实拒绝原因"（不再出现 pbo=0.500 的机械拒绝）。
4. **回归矩阵**：`compileall backend`、`check_config_drift.py`、定向 pytest、数据对账（paper_orders vs paper_balance）、`next build`（若动前端）。

## 六、风险与回滚

- 实盘风险：本项目 Live 从不自动交易（`live_sub_positions=0`），信号方向变更（阶段 2）先经 paper 观察；熔断只挡新开仓。
- 数据风险：任何目录/DB 变更前备份（`postgres_backup/`、JSON `.bak`）；迁移含 downgrade。
- 行为风险：阶段 2/3 的所有行为变更保留 env 开关，出问题一键切回旧路径（旧路径本身是"全量计算"，切回即止血）。
