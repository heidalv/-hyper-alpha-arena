# L1 做市 · 交易看板设计（F246，2026-09-16）

> 目标：像真实交易所一样"一眼看懂"——盘口（对手盘）、我们的挂单位置、持仓盈亏、最近成交。
> 原则：只展示**真实存在**的数据，数据层没有的一律标注"未采集"，绝不画假深度。

## 1. 数据能力盘点（现状）

| 数据 | 有？ | 说明 |
|---|---|---|
| 最优买/卖价（top-of-book） | ✅ | `market_orderbook_snapshots`（15s 快照）|
| 我们的挂单价（bid/ask） | ✅ | `/shadow` states.quote_bid/quote_ask + 挂宽 |
| 持仓（qty/均价/浮盈） | ✅ | `/shadow` states + `/positions` |
| 最近成交（本车道） | ✅ | `lane_ledger` 近 N 笔（含价/量/方向/平仓标记）|
| 成交判定上下文 | ✅(F256) | `/shadow` fill_notes 最近 60 笔：触发原因/判定 σ/挂单年龄/六维分量/平仓标记——快盘窗口每笔成交自解释 |
| 盘口深度（10 档） | ✅(F248) | 采集器已有 20 档 → 落库 raw_levels(JSON) → /board 下发 → 看板阶梯展示 |
| 逐笔成交流 | ✅(桶) | 15s 桶聚合（无逐笔）|

⇒ 看板第一版用现有数据：**每币一张"做市卡片"**，包含
① top-of-book 买/卖价 + 中价；② 我们挂的买/卖价（在价尺上标注位置）；
③ 持仓数量/均价/浮盈；④ 最近 5 笔本车道成交。深度档位作为数据层任务另行立项。

## 2. 布局（车道详情页新增「交易看板」块，5 币横排卡片）

每币卡片（约 280px 宽）：

```
┌──────────────────────────────┐
│ BTC        中价 76,042.55 ▲  │  ← 中价 + 涨跌色
│ 卖一 76,045.0   ← 对手卖价    │
│ ─────────── 我方挂卖 76,050.5 │  ← 我们的 ask（标注"我方"，高亮青色）
│          （价差 12.4bp）      │
│ ─────────── 我方挂买 76,032.0 │  ← 我们的 bid（高亮）
│ 买一 76,030.5   ← 对手买价    │
│ 持仓 +0.28 @76,010  浮盈+0.41 │
│ 近5笔: B0.01 S0.02 S0.03 …   │
└──────────────────────────────┘
```

- 价尺自上而下：对手卖 → 我方卖 → 中价 → 我方买 → 对手买（买卖价只展示存在的，
  单边行情下缺一侧如实留白）；
- **我方挂单价永远高亮标注**（青色边框 + "我方"标签），并显示挂宽 bp；
- 持仓行：qty（正负色）、均价、浮盈（mid 对 avg_mid 口径，与引擎一致）；
- 最近成交：方向色点 + 数量，来自账本（15s 轮询）。

## 3. 深度数据层任务（单独立项）

要在看板里显示 5/10 档深度，需要新增数据采集：
- asterdex 是否有深度接口？若有：新增 `market_orderbook_depth` 表（venue/symbol/ts/
  第 N 档 bid/ask 价量），采集器每 1~2s 写一次（或只在变化时写）；
- 若无深度接口：看板退化为"最优价 + 我方挂单"（第一版即如此），并在卡片上注明
  "该场地无深度数据"。
- 后端 API：`GET /api/trading/lanes/{lane}/board` 一次返回 5 币的
  {top_bid, top_ask, mid, my_bid, my_ask, width_bp, position, recent_fills}，
  前端 15s 轮询（复用 useLaneStream）。
