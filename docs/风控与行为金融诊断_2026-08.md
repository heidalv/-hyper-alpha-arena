## 一、结论先行（Top 5）

1. **单笔亏损穿过了「1.5% 权益硬顶」的防线，但防线本身是按「预估止损距离」计算的，小币穿仓/止损移动会让已实现亏损突破该值**（XPL -7.55 ≈ 1.9% 权益、KAITO trend 单笔 -14.55 ≈ 3.6% 权益均超过 1.5%）。
2. **08-13 单日 -9.68（≈2.4% 权益）不会触发任何日亏损熔断**：当前日亏防线为 per-symbol 3%（DRG Rule 3a）、全局极端 15%（DRG Rule 3b）、session 级 5%（仅 Live 路径 `live_trading.py` 的 `check_daily_loss_breaker`）。**2.4% 落在所有阈值之下；且 paper 中长线没有「5% 停开新仓」这一档**（5% 熔断在 Live 专用文件里）。
3. **最严重的行为病灶不是 master_running_close，而是 `trend_review_close`：DB 实测 12 笔、胜率 0%、总 -44.90（≈11% 权益）**。它走 `_AGENT_EXIT_REASON_WHITELIST` 白名单，**绕过了 master_close_guard 的硬事实门控**——系统用 hard-fact 拦住了 Master LLM 的乱砍，却给「方向破坏复查」这条同样 0% 胜率的通道开了免检口。
4. **master_running_close 是处置效应自动化的实证，且系统已自我发现、但补丁尚未真正生效**：代码注释（settings.py:1663-1690）自认「mid/long 占比 33%、胜率仅 16%」，已建 `MID_TIER_PROTECTED_FROM` + hard-fact 门控 + S0-6 验收；但 **`.env` 实测 `RISK_P3_MASTER_CLOSE_REQUIRES_HARDFACT=shadow` —— 门控当前只检查/记录、不实际拦截**。DB 全量口径 master_running_close 仍 148 笔 -35.42、胜率 44%，与「shadow 未 enforce」一致。
5. **冷却机制是「合理的风控 + 部分的情绪化惩罚」**：S0-8 审计证据（亏损后 24h 同向再开率 57.4%）支持长冷却打断恶性循环；但它**只惩罚亏损侧、不保护盈利侧**——63.6% 曾盈利单回吐、平均峰 +2.40 → 实收 +0.41，与「亏了禁开、赚了拿不住」形成行为不对称，与「让利润奔跑」直接冲突。

## 二、风险层审查

### 2.1 小市值币 + 10–20x 杠杆：仓位设计是否失控

机制（`position_sizing_agent.py`）：
- 杠杆由**波动率反向映射**：vol 0.5% → 20x、vol 1.5% → ~6.7x、vol 3% → ~3.3x（`_resolve_leverage`），下限 5x。
- 当前 `.env` `DYNAMIC_LEVERAGE_MAX=10`，但 DB 实证存在 **20x** 的 LDO/KAITO 单（07-17/18，杠杆上限改 10 之前的存量或旁路）。10x 下，小币反向 10% = 保证金亏光；KAITO/LDO 这类币日波动 20–40% 是常态。

**诊断**：
- 波动率映射对小币是**反直觉的陷阱**：低波动窗口期（窄幅盘整）会给小币开出最高杠杆档，而小币的低波动往往是大波动的「压缩弹簧」，恰恰是最危险的开仓时点。
- 单币保证金上限（`max_symbol_margin_pct`）与组合净敞口（`MIDLONG_MAX_NET_EXPOSURE_PCT=1.5×`）**没有按「市值/流动性分档」**：XPL 这种超小币与 BTC 共享同一把尺。
- 结论：不是「单个参数失控」，而是**「杠杆映射 × 小币流动性 × 无市值分档」三者叠加**导致小币实际风险敞口被系统性低估。

### 2.2 单笔 -7.55（XPL）应否被事前拦截

机制（`clamp_position_by_risk_cap`）：名义仓位被钳制为 `equity×1.5% / SL距离`——即「预估亏损 ≤ 1.5% 权益」是**入场时**按当前 SL 算的。

**诊断**：
- 理论应拦；实际漏过的三种路径：① SL 太宽 → 分母大 → 名义被放大；② 小币流动性差，SL 被跳空/穿仓（realized 亏损 > 预估）；③ 持仓中 SL 被 AI 移动放宽（`trend_broken` 复查会调 SL/TP）后回不到入场钳制。
- 本质：**1.5% 是「计划风险」闸，不是「已实现亏损」闸**。事后看 XPL 单笔 -7.55（1.9% 权益）已越线，但系统没有「已实现亏损超 1.5% → 强制风控事件」的反馈回路。
- 建议：这是**硬规则缺口**——应加「已实现单笔亏损 >1.5% 权益 → 记录 RiskEvent + 该币 24h 禁开 + 复盘必查」。

### 2.3 08-13 单日 -9.68 是否触发日亏损熔断

现有防线（代码实证）：
| 层 | 阈值 | 覆盖 | 触发行为 |
|---|---|---|---|
| DRG Rule 3a per-symbol | 当日该币亏损 ≥3% 权益 | paper+live 开仓前 | 禁开该币 |
| DRG Rule 3b 全局极端 | 当日已实现亏损 ≥**15%** 权益 | paper+live 开仓前 | 禁开全部 |
| session `daily_loss_limit_pct` | 默认 5% | **仅 Live**（`full_auto/live_trading.py`） | pause session |
| health_check_cycle | 日亏>15% 或回撤>50% | 全 mode | session defensive |

**诊断**：-9.68 ÷ 404 = **2.4%**，低于 3%、5%、15% 全部阈值——**没有触发任何熔断，且按当前配置本就不该触发**（这是配置合理的结果，不是故障）。
但暴露三个缺口：① **5% 这一档（「停开新仓、观察」）对 paper 中长线不生效**——只在 Live 文件里；② 15% 极端网对 $404 账户意味着允许单日再亏 ~$60 才全面停手，对小账户的「已实现伤害」太深；③ 阈值按「已实现」计，08-13 若为浮亏回吐则更晚才被感知。
结论：**日亏损熔断存在但档位对小账户过宽、且 5% 档不覆盖 paper**；建议把 3%→5%→10% 三档做成跨模式统一配置，并对 $404 级小账户下调档位（如 2%/4%/8%）。

## 三、行为偏差审查

### 3.1 master_running_close：处置效应的自动化版？

**是的，且系统已经承认并打了补丁**：
- 证据链：DB 全量 148 笔 -35.42（均 -0.24）；代码注释（settings 1663-1690）白纸黑字「Master 微亏越权砍中长线、占比 33%、胜率 16%」。
- 已建防线：`master_close_guard.check_master_close_hardfact`（浮亏≥tier 阈值 4%/7%、SL 穿透≥1.5x、风险分>80、硬原因白名单）+ `MID_TIER_PROTECTED_FROM` 阻断 + `verify_midlong_s0s2` 验收占比≤5% + `RISK_P3_MASTER_CLOSE_REQUIRES_HARDFACT`（当前 shadow/enforce？见 .env）。
- 行为金融定位：这本质是**「损失厌恶 × 处置效应」的工程化**——Master LLM 把轻微回撤解读为「风险升高→建议离场」，和人类在浮亏时想「先保本」的冲动同构。补丁方向正确（要求硬事实才能砍）。

**残余问题（已确认为当前状态）**：`.env` 实测 `RISK_P3_MASTER_CLOSE_REQUIRES_HARDFACT=shadow`、`RISK_P3_HARDFAT_SHADOW=true` —— **hard-fact 门控处于 shadow（只记录不拦截）模式**。即：代码写了硬门，但运行态是「检查 + 日志 + 放行」。DB 全量 master_running_close 148 笔 -35.42、胜率 44%，与「门未真正关」一致。**第一步应把该开关切到 enforce 并观察一周**，再谈其他。

### 3.2 trend_review_close：白名单上的漏网之鱼（本轮最重要发现）

- DB 实测：**12 笔、0% 胜率、总 -44.90、均 -3.74**（≈11% 权益）。
- 机制：`midlong_position_manager` 的「持仓发展分析」→ `_dim_direction` 判方向破坏 → `trend_broken` 离场；`trend_review_close` 在 `_AGENT_EXIT_REASON_WHITELIST`（master_close_guard.py:46）→ **放行**。
- 行为金融定位：这是**「确认偏误 + 过度反应」的自动化**——LLM 用 4h/1d 蜡烛在 90 分钟节流下复查趋势，把正常回撤判成「方向破坏」；0% 胜率说明这 12 次判「破坏」**事后看全部是错的**（要么本应持有，要么至少该减不该清）。
- 「在支撑位附近平空单」类文案（prompt_routes:914 是通用建议「支撑位做多/阻力位做空」）：止损/离场决策贴着**微结构噪音**（支撑阻力位在 1h 级别频繁失效），是「追逐噪音」的行为特征；趋势策略的止损应锚定**结构位 + ATR 缓冲**，而非 LLM 临时读图。

### 3.3 63.6% 盈利单回吐：兑现侧的系统性缺陷

- 峰 +2.40 → 实收 +0.41（63.6% 曾盈利单最终平/亏）；`profit_drawdown_full` 24 笔、`breakeven_tp` 89 笔、`max_hold_timeout` 77 笔（DB 全量）共同构成「拿到手又还回去」。
- 行为金融定位：**处置效应在兑现侧的另一半**——系统不是「让利润奔跑」，而是「浮盈到了某个心理锚点就想落袋/保本」（breakeven_tp 89 笔就是保本心理的代码化）。
- 与冷却的不对称：亏损侧有 4h/12h/48h + 连亏倍率的强惩罚；盈利侧没有任何「利润保护」硬规则（只靠 AI 软建议）。**行为上这是「亏了禁、赚了跑」的镜像失衡**。

### 3.4 冷却机制：风险控制，还是情绪化惩罚？

**判定：主因是合理的风险控制，但有副作用**。
- 支持「风险控制」的证据：S0-8 审计（57.4% 亏损后 24h 内同向再开率；窄冷却不足以打断恶性循环）；分层设计（任意亏损 4h/12h、sl 12h/48h、连亏 ×2/×3、tier 隔离、DB 耐久冷却防重启蒸发）；`reopen_blocked` 的文案也明确「避免信号未变时重复付手续费/翻转双重损失」——这些都是**反报复交易**的教科书结构。
- 「情绪化惩罚」的成分：冷却按 `close_pnl<0` **一刀切**，不区分亏损来源。若亏损来自 `master_running_close`/`trend_review_close`（即系统自己砍错），冷却惩罚的是「被错误纪律拖累的标的」，反而让「砍仓通道 0% 胜率」这一病灶多了一个帮凶（错砍 → 冷却 → 无法立即纠错回场）。
- 与「让利润奔跑」的冲突：**不对称**——利润奔跑需要的是「浮盈保护 + 回吐熔断」，冷却机制不提供任何正向激励，只加负向惩罚。
