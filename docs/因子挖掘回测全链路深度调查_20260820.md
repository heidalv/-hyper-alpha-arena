## 0. 一句话

因子链**不是一条流水线**，而是 **两套产物池 + 至少四套挖掘器 + 至少三套打分口径**。  
挖掘算法本身（GP / MCTS / 种子 / LLM AST）设计完整、有复杂度惩罚和池准入；真正危险的是：**挖的目标、打分的目标、交易结算的目标不是同一种东西**，挖出来的因子还经常进不了中线。

| 问题 | 现码事实 |
|------|----------|
| 挖什么 | GP 默认最大化 **Pearson \|IC\|**（简单未来收益）；5m/15m 可选三重障碍标签 |
| 怎么验 | 进化环用 **Spearman ICIR**；正式闸门再用滚动 Spearman + Pearson 定方向的 3 折 WF |
| 谁用 | AST 进化仓进短线 `evo_*`；中线只读公式商店 `horizon=midlong` |
| 和交易的缝 | 回测默认 Binance research；成交跟活跃所。中线按 `sign(ic)` 反手；组合权重却把负 ICIR 置 0 |

## 3. 挖掘算法（深度）

### 3.1 总入口

`backend/services/evolution/factor_evolution_loop.py` → `_mine_candidates`

顺序：种子模板 → GP → MCTS → LLM AST。  
面板：默认最多 5 币（`FACTOR_MINE_SYMBOLS` / 进化币解析），多币拼成长向量再算适应度。

### 3.2 种子模板（始终跑）

固定 AST：

- `rev{w}`：`-mean(returns, w)`，w∈{5,10,20,50}
- `mom{w}`：`mean(returns, w)`
- `vol{w}`：`std(returns, w)`
- `vp_corr{w}`：`rank(corr(close, volume, w))` —— **`rank` 在 `LOOKAHEAD_BANNED_OPS` 里**（截面秩，审计禁前视）。种子仍生成它，后续 audit 可能整段丢掉。
- `ts_rank(close, w)`：合法时序秩
- 有 funding/oi 时加 `PERP_FACTOR_EXPRS`

### 3.3 GP 遗传编程（主挖掘器）

文件：`backend/services/evolution/gp_miner.py`  
头注释写「gplearn / \|IC_rank\|」——**两边都过时**：实现是纯 numpy + joblib；适应度用的是 **Pearson `corrcoef`，不是秩相关**。

| 项 | 代码默认 |
|----|----------|
| 种群 | 300 |
| 代数 | 20，连续 3 代无提升早停 |
| 种子 | 6 路独立跑再合并 |
| 交叉 / 变异 | 70% 子树交叉 / 20% 点变异 |
| 精英 | top 5% |
| 选择 | 默认 `lexicase`（ε-lexicase）；可退锦标赛 |
| ALPS | 默认开，超龄 12 代换成随机新生 |
| 树深 | 2–5 |
| 窗口常量 | {3,5,10,20,50}（窗口算子最后一参强制常量） |
| 算子池 | `OP_REGISTRY` 去掉 `rank/cs_rank/scale` |
| 预算 | `FACTOR_GP_BUDGET_SEC` 默认 1800s |
| 目标 | `FACTOR_GP_OBJECTIVE` 默认 **`ic`**（不是 icir） |
| LLM 热启动 | `FACTOR_GP_LLM_WARM_START` 默认关 |

**适应度（CPU `_fitness_core`，与 GPU 路径对齐）：**

设因子值 \(f\)、目标 \(y\)（默认未来 \(h\) 根简单收益），有效掩码 \(M\)，样本 \(\ge 50\)，\(f\) 非常数。

默认 `objective=ic`：

\[
\mathrm{obj} = \bigl|\mathrm{corr}_{\text{Pearson}}(f_M,\, y_M)\bigr|
\]

`objective=icir` 且面板按币切开、有效段 \(\ge 2\)：

\[
\mathrm{IC}_s=\mathrm{corr}(f_s,y_s),\quad
\mathrm{obj}=\left|\frac{\mathrm{mean}(\mathrm{IC}_s)}{\mathrm{std}(\mathrm{IC}_s)}\right|
\]

否则回退 \(|\mathrm{IC}|\)。

完整适应度：

\[
\mathrm{Fitness}
= \mathrm{obj}
- \lambda_1 N_{\mathrm{nodes}}
- \lambda_2 \max_{e\in Elite}|corr(f,e)|
- \lambda_{\mathrm{hof}}\max_{h\in HoF}|corr(f,h)|
\]

默认 \(\lambda_1=10^{-3}\)，\(\lambda_2=0.05\)，\(\lambda_{\mathrm{hof}}=0.1\)。

**算法评价：**

- 优点：有复杂度惩罚、精英/名人堂去同质、ALPS 防早熟、窗口常量离散化、lookahead 算子从矿机池剔除、多币面板。
- 缺点：优化的是 **\|Pearson IC\|**，不区分「正向预测」和「反向预测」——负 IC 因子会被当成好种子。这和中线 M9「按符号反手」是同一哲学，和组合权重「负 ICIR 置 0」冲突。
- 目标 \(y\) 默认是简单未来收益，**不是**纸盘 SL/TP/超时净盈亏。5m/15m 可切三重障碍（`FEATURE_FACTOR_LABELS_ENABLED` 默认 true），4h/1d 中线挖掘仍是简单收益。
- 头注释「IC_rank」与实现 Pearson 不一致——读注释会判错算法。

### 3.4 MCTS（并列挖掘器）

文件：`backend/services/evolution/mcts_miner.py`

把 AST 当树节点，边是局部改写：参数变异 40% / 子树 25% / 换算子 20% / 根包装 15%。

- UCT：\(Q/N + 1.4\sqrt{\ln N_p / N}\)
- 默认每根约 300 次迭代
- 短板种子：活跃集 \|ICIR\| 最低 3 个 AST
- FSA：窗口 ±50%/100%/150%，`max_sensitivity > 0.8` 整棵拒绝
- 宏微分档：micro(1m/5m/15m) 更短窗口、更重复杂度惩罚；macro(4h/1d) 更深

适应度比 GP 少一项名人堂：

\[
\mathrm{Fitness}=|IC|-\lambda_1 N_{\mathrm{nodes}}-\lambda_2\max_{r\in Roots}|corr(f,r)|
\]

**算法评价：** 适合「改已知弱因子」而不是从零搜索。FSA 是挖掘链里少有的「参数稳不稳」检查。仍用 \|IC\|，同样鼓励反手因子。

### 3.5 AlphaPool 池准入（挖完先进池）

`backend/services/evolution/alpha_miner.py`

1. 单因子 \(|corr| \ge 0.02\)
2. 与池内列相关 \(> 0.85\) 拒
3. TimeSeriesSplit 5 折边际 IC：\(\Delta IC_{CV} > 5\times 10^{-3}\)
4. 接纳后权重 `sign(corr)`

这是挖掘阶段**最好的一段设计**：看的是「给组合有没有样本外增量」，不是单因子刷分。  
但它只活在进化环；公式商店 / registry / 冷池 **不走** 这套池准入。

### 3.6 LLM AST / 公式 / Python 类（三条旁路）

| 通路 | 文件 | 产出 | 安全 | 打分 |
|------|------|------|------|------|
| CodegenCritic | `alpha_miner.py` | JSON AST | `expr.audit` | 进进化环 val/test |
| OpenCode 发现 | `backend/services/factor_discovery.py` | numpy 公式字符串 | `eval` + 算子注入 | **自己预筛**再 `validate_and_promote` |
| LLM 提案 | `llm_proposal.py` | numpy 公式 | AST 白名单 | 更严闸门（Sharpe+0.1、PBO 0.4、符号一致） |
| D7 AI 类 | `ai_factor_discovery_service.py` | `factors/ai_generated/*.py` | 代码白名单 | **生成即可热加载**，不强制 OOS |

`alpha_miner.py` 仍写「生产 MaskablePPO / AlphaGen RL」——**现码没有 RL**，只有随机 + LLM。

### 3.7 发现预筛（`factor_discovery._validate_factor`）——算法最脏的一段

现码约 417–462 行：

1. K 线走 **UnifiedDataPool**，不是 scorer 的 Binance research。
2. `open = np.roll(closes, 1)`：第一根 open 被最后一根 close 污染（环绕）。
3. 前瞻：`forward_returns = (np.roll(closes,-1)-closes)/closes` —— **最后一根吃到第一根**，典型未来函数/环绕。
4. 前瞻固定 **1 根**，与正式闸门 1h→2 / 4h→6 / 1d→3 以及进化环 4h→1 **全对不上**。
5. 门槛：聚合 \|IC\| > 0.05，全样本 in-sample，无 WF / DSR。

预筛过的公式再进 `validate_and_promote` 时口径会变。结果：预筛过松或过严都可能，**不能把「发现日志里的 IC」当正式成绩**。

## 4. 回测 / 打分算法（深度）

系统里至少有 **四套「回测」**，名字都叫 IC，不是同一件事。

### 4.1 进化环验证（挖完之后）

`_evaluate_candidates` → `evaluation.evaluate_factor(..., method="spearman")`

- 默认 **Spearman** 滚动 IC → ICIR
- 目标仍是 `_forward_returns`（简单收益或 5m/15m 三重障碍）
- 切分：`_PERIOD_SPLIT_DAYS`，4h/1d = **180 / 60 / 30 天**，测试集不参与挖掘与选因
- 前瞻：`_PERIOD_FWD_BARS`，4h/1d = **1 根**（约 4h 或 1 天），与正式闸门 4h **6 根** 不一致

净 IC：`net_ic = ic_mean - turnover × 0.001`

测试终审：测试集 IC 均值 ≥ `FACTOR_EVO_TEST_IC_MIN`（默认 0.01）

**坑：** 挖掘用 Pearson \|IC\|，验证用 Spearman ICIR。同一个体可能「挖的时候很好、验的时候很差」或反过来。

### 4.2 正式闸门 `FactorBacktestScorer`（公式晋升 SSOT）

文件：`backend/services/factor_engine/factor_backtest_scorer.py`

**取数**

- `FACTOR_BACKTEST_KLINE_EXCHANGE` 默认 **binance**
- `data_center.get_klines(..., purpose="research", closed_only=True)`
- 不够 120 根回退 UnifiedDataPool（又换源）
- 短线默认币：**BTC,ETH,SOL**（`FACTOR_SCORER_SYMBOLS`）
- 短线 1h lookback 720（自适应下限 500）；中线 4h 2400 / 1d 1000
- 前瞻：1h→2，4h→6，1d→3（可被 `FACTOR_SCORER_FWD_PERIOD` 覆盖）

注释写得很清楚：回测故意用 Binance 深度，成交另走活跃所。这在研究上说得通，在 **中线路由复用同一 `_load_klines`** 时就变成 M3。

**IC 定义（`factor_evaluator.py`）**

- 滚动窗口 \(W=\max(20, n/10)\) 内，对因子与前瞻收益各自 rank 再 Pearson = **Spearman**
- \(ICIR = mean(IC)/std(IC)\) —— 这是 **单币时序 IR**，不是「同一时刻跨币截面 IC」
- 可选中性化：`FACTOR_SCORER_NEUTRALIZE=true` 时对 pooled OLS 残差收益算 IC
- 换手：\(1 - corr(rank_t, rank_{t-1})\)，是因子秩自相关，**不是**交易换手
- 分层：单币时序 qcut 5 档，看收益均值是否单调 —— **不是**截面五分组组合

**Walk-forward（`_walk_forward_backtest`）**

- 3 折；第 0 折只当训练，**不计绩效**
- 训练窗 **Pearson IC** 定 `orient = ±1`（负 IC 在这里已经反手）
- 测试窗 z-score 用训练窗 μ/σ（这点正确，无测集泄露）
- 每 `fwd` 根非重叠调仓；成本 `cost × |Δpos|/2`；另加 funding
- Sharpe：按 `bars_per_year/fwd` 年化，用笔数封顶

**WF 算法坑：**

1. 训练窗末若干根的 `fwd_ret` 会用到测试窗价格 → **方向 `orient` 轻微前视**。
2. IC 用（可选）中性化收益，WF 绩效用原始 close 收益 —— 两套 y。
3. 有效 OOS 大约只有后 2/3 样本。

**DSR / PBO**

- DSR：**不是**完整 Bailey 公式。现码是聚合 \|ICIR\| 对 0 的正态检验 + Bonferroni（`n_trials` 用同档候选数，下限 40）。
- PBO：IC 时序切段 CSCV，IS 定方向、OOS 衰减 >50% 计过拟合；`FACTOR_SCORER_MAX_PBO=0.5`。
- `FACTOR_SCORER_DSR_REQUIRED=true`。
- `FACTOR_SCORER_DSR_MIN_SYMBOLS` **settings 默认 4**；`FACTOR_SCORER_SYMBOLS` 默认 **3 币**。
- 现码 `_dsr_pbo_gate`：币数 < 下限 → **fail-closed 拒绝晋升**。
- settings 注释写「fail-open 跳过、由 OOS 兜底」——**和现码相反**。

未改 `.env` 时：正式闸门对默认 3 币打分，DSR 要求 4 币 → **结构上容易 0 晋升**（8/19 刚改过 DSR 口径，自锁仍在）。

**held-out（`validate_and_promote`）**

- 丢掉末尾 `max(30, lookback×20%)`，先完整 DSR
- 判决段再跑一遍 `score_formula(skip_dsr=True)`
- 判决：`|IC|≥0.03`、`oos_sharpe≥0.3`、符号一致、`trades≥5`
- 失败保持 `candidate`，不是直接 rejected

**复检 `recheck_and_prune` 不走 held-out / DSR。**

**晋升门槛（A/B 才 admitted）**

| | A | B |
|--|---|---|
| \|IC\| | ≥0.05 | ≥0.03 |
| \|ICIR\| | >0.5 | >0.3 |
| OOS | Sharpe ≥ 门槛且每笔净利 > 5bps | 同左 |
| 冗余 | 与 active \|corr\| < 0.7 | 同左 |
| DSR/PBO | 要求开则必须过 | 同左 |

评级用 **\|IC\|**，负 IC 可以 A/B 晋升。  
`FactorEvaluator` 内部 grade 仍要求 **带符号** `icir>0.5` 才 A —— scorer 会覆盖这套，语义混。

### 4.3 Registry / 冷池（更松的「回测」）

`scan_registry_midlong`：自己的 `_score_one_registry_factor`，A/B 直接 `active`。  
**没有** held-out、DSR、冗余池、人数 cap。这是中线弹药的重要来源，也是「闸门看起来很严、实际有旁路」的原因。

冷池 `midlong_cold_pool`：GPU 批量 IC，报告里标过 `multi_fwd_variant_selection_unadjusted`（多前瞻挑选未做多重检验）。

## 6. 设计怎么样（评价，不调参）

### 6.1 真的做得好的

1. **DSL + audit**：表达式可静态查前视；矿机池已剔除 `rank/cs_rank/scale`。
2. **train/val/test 分离**（进化环）和 **held-out 判决**（公式闸门）思路正确。
3. **WF 非重叠调仓 + 训练窗标准化**：比「全样本 IC 直接交易」更接近可交易。
4. **AlphaPool 边际 IC CV**：挖的时候看组合增量，比单因子刷榜成熟。
5. **MCTS FSA**：窗口过敏就扔掉，是过拟合的对症药。
6. **closed_only=True**：回测不吃未收盘 bar。
7. **短线已桥接 evo_***：8 月中旬「进化仓没人读」对短线不再成立。

### 6.2 算法层的结构性问题（按严重度）

| ID | 级 | 问题 |
|----|----|------|

### 6.3 和短线 / 中线审查的交叉

| 审查项 | 因子链含义 |
|--------|------------|
| **M3** 训练所≠成交所 | 挖掘、打分、**中线路由** 都复用 `_load_klines`。设计里「运行时跟活跃所、回测保持 binance」必须先给路由单独 loader，否则改回测默认会污染晋升。 |
| **M8** 活跃因子少 | GP 晋升进 AST 仓 **不增加** 中线 active。要加弹药应桥接或走公式闸门；registry 旁路会让「少」和「脏」同时出现。 |
| **M9** 负 IC 反手 | 不是路由独创：GP/WF 从挖掘起就按 \|IC\| + sign 反手。只在路由加 `\|ic\|<0.02` 跳过，挖的时候仍会大量生产弱负 IC。 |
| **M4** 固定 5/10 SL | 三重障碍标签只服务 5m/15m 进化，**没接到** factor_route 的 SL/TP。中线挖掘优化 1 根 4h 收益，交易却用 5%/10%。 |

## 7. 对修复设计的延伸（仍不改交易代码）

短线中线设计文档的 P0（S1/S2/S8、M1 落库、M2、M3 运行时分离）**仍然先做**。因子链不要插队改挖掘超参。

建议在后续设计里单开「因子链」一节，顺序如下：

### 第一刀：让口径诚实（不换算法）

1. **统一「IC 说明书」**：挖掘 / 进化验证 / scorer / 路由各自写清 Pearson 还是 Spearman、前瞻几根、哪个交易所。先改注释和日志字段，再改公式。
2. **修 DSR 自锁**：要么默认币扩到 ≥4，要么 `DSR_MIN_SYMBOLS` 改为 3 并与注释一致；fail-open / fail-closed 必须和 settings 注释同一句话。
3. **修发现预筛**：禁止 `np.roll` 环绕；前瞻与闸门同表；K 线走同一 research 源。预筛只做「别把语法错误送进闸门」，不要自己宣布 IC。
4. **registry 扫描**：至少复用 `score_formula` 的冗余 + held-out；不许 A/B 直通 active。

### 第二刀：让挖的东西能被该用的人用

5. AST 进化仓 → 中线：要么晋升时同步 `custom_factor_store(horizon=midlong)`，要么中线路由增加 TRADABLE AST 源。否则 M8 与 GP 无关。
6. `FACTOR_ROUTE_KLINE_EXCHANGE=active`（已在短线中线设计 M3）：只改路由，不改 `_backtest_exchange()`。
7. 负 IC：挖掘侧可继续看 \|IC\|，但**晋升写清 expected_sign**；路由弱 IC 不反手（M9）；`combo_weights` 与路由同一套符号规则。

### 第三刀：让目标接近交易（才动适应度）

8. 短线进化：5m/15m 三重障碍保持；晋升增加「纸盘同向结算净期望」影子指标，不替代 IC，只否决「IC 很好、分桶净亏」。
9. 中线进化：4h 前瞻与闸门对齐（不要一边 1 根一边 6 根）；SL/TP 用结构/ATR 后，挖掘标签再跟持有期对齐。
10. **不要**先上 AlphaGen RL。接口广告和实现差太远，先删注释或做成明确未实现。

### 明确先不要做

- 不要为了「多挖一点」关 DSR/PBO。
- 不要把回测默认交易所改成 asterdex（样本变短，晋升更吵）。
- 不要用 8/16、8/17 交易成绩去调 GP 种群/代数。
- 不要假设打开因子路由后，进化仓里的 AST 会自动变成中线仓位。
