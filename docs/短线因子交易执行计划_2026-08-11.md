## 0. 执行纪律

- 每个里程碑必须有独立验收，未验收不进入下一步。
- 每个行为改动必须：单变量、有开关、写 `scalp_experiment_log`、可回滚。
- 每周五输出一次周报（数据+改动+对照），与评估计划口径一致。
- 任何「回测变好」都不算完成，必须与纸盘影子/parity 对齐。

## 2. M0：基线固化与止血（08-12 ~ 08-18）

### 任务

1. 导出 `.env` 中 `SCALP_*`/`FEATURE_FACTOR_LABELS_ENABLED`/`SCALP_META_*` 到 `config/scalp_env_baseline_2026-08-11.json`。
2. 实现 `scalp_daily_health` 调度（`backend/main.py` 注册，日级 05:30）：
   - 指标：信号量、已结算、胜率、平均净收益、成本占比、分数分桶+单调性、平仓原因/符号/时段/regime 归因、权重 Gini、meta 摘要、数据陈旧度。
   - 输出：`reports/scalp_daily/scalp_health_YYYY-MM-DD.json` + `.md`。
3. 实现 `scalp_chain_health` 巡检：K 线新鲜度、信号→结算延迟、calibrator/meta 产出、队列堆积。
4. 实现 `scripts/audit_scalp_cost.py`：taker fee、滑点 bps（place vs fill vs mark）、funding、P95 极端滑点。
5. 补齐 signal_log / paper_positions 归因字段（只读核对，不改退出逻辑）。

### 验收

- [ ] 基线文件生成且与当前运行配置一致；
- [ ] 连续 7 天每日体检无断层、字段完整；
- [ ] 成本审计产出悲观成本参数（P95×1.5）给 M1；
- [ ] 链路巡检能发现 1 类已知风险（如数据陈旧）并告警。

### 回滚

- 全部为新增只读任务/脚本，停止调度即回滚；不改任何交易行为。

## 3. M1：验证基础设施（08-19 ~ 09-08，3 周）

### 3.1 数据回填（先行，W2 同步启动）

- 扩展 `kline_backfill_manager` 与 `backfill_full_history.py`：
  - 支持 5m 多币批量、分批 6h、限流退避、断点续传；
  - 首批候选币：auto_coin 当前集合 + 主流通币（BTC/ETH/SOL/BNB/XRP/DOGE/ADA/AVAX/LINK/SUI 等，共 20–30 个）。
- 目标进度：W2 末 30 天，W4 末 90 天；评估是否可行到 365 天。
- 每日 `data_quality_report`：缺孔率、重复率、时间戳对齐。

### 3.2 策略级回测（W2–W3）

- 新增 `backend/services/scalp/scalp_strategy_backtest.py`：
  - 复用 `backtest_engine`、`walk_forward`、`overfitting_metrics`；
  - 双口径结算：固定前瞻 vs 三重障碍；
  - 成本：taker fee + 悲观滑点 + funding；
  - 输出 JSON 落 `scalp_backtest_run` 表。
- 先做 3 个币（BTC/ETH/1 个 auto_coin 高分币）冒烟，再扩到全候选集。

### 3.3 随机基准与门禁（W3–W4）

- 随机信号 permutation（≥200 次）、标签 shuffle 基准；
- 封装 `scalp_validation_gate`（五道硬门：净收益>0、p<0.05、PBO<0.1 或 DSR>0.95、分桶单调/分层转正、parity 达标）；
- 接入因子晋升与参数变更流程（先只读报告，M4 才硬拦）。

### 验收

- [ ] 90 天 5m 数据完整率 ≥99%（按缺孔率口径）；
- [ ] 回测报告可复现：同一 commit + 同一数据 = 同一结果；
- [ ] 随机基准与 PBO/DSR 输出字段完整；
- [ ] 回测与现有 30 天纸盘在净收益方向一致（parity 初版）。

### 风险门禁

- 若 5m 历史只能拿到 30 天：冻结 M2 的分数重构为「仅影子」，不切换默认打分；
- 若回测与纸盘方向相反：先查成本/滑点/结算口径，不强行上线任何新信号。

## 4. M2：信号重建（09-09 ~ 09-22，2 周）

### 任务

1. 打分公式改造（默认 `SCALP_SCORE_MODE=legacy`）：
   - 新增 `calibrated` 模式：用校准后 p_win × 期望净收益排序；
   - 影子模式先记录两种分数分布，不切换。
2. Active set 统一：
   - 审计 `scalp_active_factor_set`（18）与 `factor_runtime_weights`（974）读取路径；
   - `SCALP_ACTIVE_ONLY=0|1` 开关，默认 0；
   - 增加权重 Gini / 有效因子数指标。
3. 标签对齐：
   - 纸盘开 `FEATURE_FACTOR_LABELS_ENABLED=true`（5m 进化走三重障碍）；
   - meta 双口径报告；`predict_win_prob` 强制 usable。
4. 选币联动（只读）：
   - `symbol_scalp_profile` 表 + 日更任务；
   - auto_coin 输出追加「短线可交易性」字段；
   - AAVE/KAITO/ZEC 观察名单告警。

### 验收

- [ ] 新打分在 30/90 天回测与纸盘影子中分桶单调（或分层组合转正）；
- [ ] active set 与权重读取路径唯一；
- [ ] 三重障碍标签在 5m 进化生效，4h 路径未变；
- [ ] meta usable=false 时绝不进入 EV；
- [ ] 选币联动字段上线且不参与选币分数。

### 回滚

- 全部默认关：`SCALP_SCORE_MODE=legacy`、`SCALP_ACTIVE_ONLY=0`、`SCALP_META_IN_EV=0`；
- `FEATURE_FACTOR_LABELS_ENABLED=false` 可随时关回。

## 5. M3：决策与执行优化（09-23 ~ 10-06，2 周）

### 任务

1. EV 门槛实证：
   - `SCALP_EV_SHADOW=1` 先记录被拒单 14 天；
   - 若影子显示新门槛（候选 0.05%–0.15%）拒掉的单净收益为负，则切 `SCALP_EV_MIN_PCT`；
2. Master 干预审计：
   - `master_intervention_review` 周报（干预时刻信号、仓位、方向、后续走势）；
   - 不改干预规则，除非单独过门禁。
3. 持仓时长对齐：
   - 回测「缩短 max_hold」vs「改标短波段」两个方案；
   - 与评估计划标签口径统一后选择其一。
4. 降频止血（每项独立开关、单变量）：
   - 高分区 triage（`SCALP_HIGH_SCORE_TRIAGE`）；
   - 提高 EV 门槛；
   - 负期望符号降频（观察名单）。

### 验收

- [ ] 每项改动都有 14 天前/后对照表；
- [ ] 无一项是「多改动一起上线」；
- [ ] Master 干预审计周报连续 2 期；
- [ ] 持仓标签/退出方案二选一且记录到策略规格。

### 风险门禁

- 任何降频动作若导致成交过少（<100 笔/周）而无法统计，暂停继续收紧，先扩充数据窗口。

## 6. M4：学习闭环与持续运营（10-07 ~ 11-03，4 周）

### 任务

1. Meta 三步接入：
   - 影子（已完成）→ 软进 EV（`SCALP_META_IN_EV=1`，仅 usable）→ 2 周达标后硬过滤。
2. 因子归因 prune：
   - 结算 `top_factors` 日聚胜率/PPE，尾部 10% 连续 7 天不达标进淘汰候选；
   - 走现有 purge/lifecycle。
3. 晋升硬门全开：
   - `SCALP_EVO_GATE_STRICT=1`；新 `s5m_*` 必须五道门禁全过。
4. 月度复盘与再校准：
   - 每月重估因子半衰期、成本参数、regime 分布；
   - 产出《短线因子月度审计》文档。

### 验收

- [ ] 门禁闭环运行 30 天无绕过；
- [ ] Meta 若 usable=true，接入前后对照达标（见评估计划）；
- [ ] 月度审计包含：因子 IC 分布、权重 Gini、成本占比、parity、随机基准 p 值。
