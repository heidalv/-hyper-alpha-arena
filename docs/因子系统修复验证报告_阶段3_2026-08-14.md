## 二、修复内容

1. **P1-C1**：`factor_evolution_loop.py` 晋升收尾——先 `_tag_one_short_horizon(p, period)` 再与 to_save 前缀 id 对齐过滤。旧顺序 1m/3m/5m/15m 全部不匹配 → promoted 恒被清空（晋升日志/事件回测触发/本轮监控断链，因子其实已落库）。
2. **P1-C2**：在线权重学习——标签配对从 `(特征[-1], fwd[-1])`（fwd[-1] 恒 0 → 权重向零收敛）改为 `(特征[t], fwd[t])`，`t = n-1-horizon`；三重障碍标签模式下 horizon=12 对齐 `_forward_returns`；标签非有限跳过。
3. **P1-B1**：`scalp_active_factor_set` 三处 `update_scores` 补 `tenant_id=_resolve_tenant_id()` + 返回值检查（写回失败 WARNING）。
4. **P1-D1/D2**：清理服务持久化改为 `data/factor_cleanup_decisions.json`（旧实现对 registry 因子调 custom_factor_store.set_status：命名空间错配全失败+读取恒空=假闭环）；**删除 `set_status(fid,"active")` 免检晋升旁路**；读取函数改读决策文件。
5. **P1-D3**：瘦身审计——factor_active_set 可交易因子（ACTIVE/SMALL_LIVE/PAPER）只报告不移动；quarantine 增加 14 天观察期状态机（首次降权 50% 观察，期满才物理移动并记录 src）；新增 `restore_quarantined_factors()` 恢复函数；**调度 apply_changes True→False（每周二 3:30 只报告）**。
6. **P1-C3/C4**：PAPER 可交易拍板定稿文档（用户确认保留现状，active_set_policy 注释）；`PAPER_FACTOR_WEIGHT_CAP=0.5` 权重上限（pipeline 对 state=PAPER 因子强制 min(w, cap)，TTL 300s 缓存查询）。
