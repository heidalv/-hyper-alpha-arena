```
                                                                    ├─ [J主动平仓重构]
                                                                    └─ 到期/TP/SL → 平仓
```

| 升级 | 改动文件数 | 减亏/增收 | 优先级 | 风险 |

**保守估计**: 累计减亏/增收约 **$30-40/周**（当前亏 -21/周 → 预期 **+9~+19/周**）。

### 1.3 设计原则

1. **每个改动可独立开关**（环境变量门控），出问题秒回滚
2. **不破坏现有安全网**（手续费闸/EV闸/冷却/预算/风险硬顶照旧）
3. **先减亏后增收**——P0 改动只消除已知亏损源，不引入新逻辑
4. **数据真实性不变**——拿不到数据标缺失，绝不造假

## 2. 升级 A: TP/SL 窄止盈引擎重构

### 2.1 问题

实测数据（125 笔仓位）:

| TP 距离 | 笔数 | 胜率 | 净PnL |
|---------|------|------|-------|
| <1% | 23 | 43% | -0.55 |
| **1-2%** | **15** | **73%** | **+1.74** |
| 2-4% | 38 | 39% | -5.90 |
| **≥4%** | **49** | **33%** | **-16.58** |

当前 `structure_stop_calculator.py` 生成的 TP 平均 3.6%，**78% 的亏损来自 TP≥4% 的远止盈单**。

### 2.2 设计方案

修改 `backend/services/scalp/structure_stop_calculator.py` 的 `compute_sl_tp` 方法：

**修改前** (行 102-106):
```python

    tp_pct = min(0.08, sl_pct * 2.5)
else:
    tp_pct = min(0.10, sl_pct * 2.0)
tp_pct = max(0.02, tp_pct)
```

**修改后**:
```python

# 新策略：TP 锁在 1.5-2.5% 区间，配合 RR≥1.3 设计。
# 默认 TP=1.8%（实测最优区间中值），SL 跟随 TP÷RR。

# TP 固定窄目标 + ATR 自适应微调
tp_pct = max(0.012, min(0.025, SCALP_TARGET_TP))
# SL = TP ÷ RR（确保盈亏比 ≥ MIN_RR）
```

## 3. 升级 B: 时间衰减 ROI 表

### 3.1 问题

实测平均持仓 2.53 小时，`max_hold_timeout` 平均 15.8 小时。短线应快速退出，持仓越久期望越低。

### 3.2 设计方案

新建 `backend/services/scalp/roi_decay_manager.py`（~80行）:

```python
"""
ROI 时间衰减管理器（借鉴 Freqtrade ROI table 设计）。

短线持仓时间越长，TP 目标越低，最终强制平仓。
确保每笔单快速退出，不让亏损仓位拖延。

时间表（环境变量可配）:
  0-10min:  TP = 原始 TP（给行情发展时间）
  10-20min: TP = 原始 TP × 0.7
  20-30min: TP = 原始 TP × 0.4
  30-45min: TP = 0.3%（微利就跑）
  45min+:   强制平仓（不论盈亏，除非在 TP/SL 附近）
"""
import time
import logging
from typing import Optional

logger = logging.getLogger(__name__)

# ROI 衰减时间表: (经过秒数, TP 保留比例)
_ROI_SCHEDULE = [
    (0,     1.0),   # 0-10min: 原始 TP
    (600,   0.7),   # 10-20min: 70%
    (1200,  0.4),   # 20-30min: 40%
    (1800,  0.15),  # 30-45min: 15%（微利就跑）
    (2700,  0.0),   # 45min+: 强制平仓
]

class RoiDecayManager:
    def get_decay_factor(self, hold_seconds: float) -> float:
        """返回当前持仓时间对应的 TP 保留比例。"""
        for threshold, factor in _ROI_SCHEDULE:
            if hold_seconds < threshold:
                return factor
        return 0.0  # 超时

    def should_force_close(self, hold_seconds: float, current_pnl_pct: float) -> bool:
        """是否应强制平仓。超时且不在 SL 附近就平。"""
        if hold_seconds < 2700:  # 45 分钟内不强制
            return False
        # 超时：只要不亏（或有微亏但不到 SL 的 50%）就平
        return current_pnl_pct > -0.005

roi_decay_manager = RoiDecayManager()
```

### 3.3 接入点

在 `scalp_loop.py` 的持仓监控 tick 中（或 paper_trading_engine 的 tick 中），对每个 scalp 仓位:

```python
hold_s = time.time() - position.opened_at
factor = roi_decay_manager.get_decay_factor(hold_s)
adjusted_tp = original_tp_pct * factor

# 如果当前价已达衰减后 TP → 平仓
if current_pnl_pct >= adjusted_tp:
    close_position(reason="roi_decay_tp")

# 强制平仓
if roi_decay_manager.should_force_close(hold_s, current_pnl_pct):
    close_position(reason="max_hold_timeout")
```

### 3.4 环境变量

```bash
SCALP_ROI_DECAY_ENABLED=true
SCALP_ROI_FORCE_CLOSE_SEC=2700  # 45分钟强制平仓
```

## 4. 升级 C: 止损死亡区间跨越

### 4.1 问题

| SL 距离 | 笔数 | 胜率 | 平均PnL |
|---------|------|------|---------|
| <1% | 12 | 50% | -0.05 |
| **2-4%** | **62** | **18%** | **-0.44** |
| ≥4% | 51 | 69% | +0.13 |

SL=2-4% 是"死亡区间"——正好是插针/止损猎杀的高发区。胜率仅 18%。

### 4.2 设计方案

修改 `structure_stop_calculator.py` 的 `compute_sl_tp`，SL 算出后检查是否落入死亡区间，如果是则跨过去：

```python
# [升级C] 跨越死亡区间：SL 2-4% 胜率仅18%（插针高发区）。
# 如果 ATR 算出的 SL 落在 1.8%-3.5%，收紧到 1.5%（快速认错）。
DEATH_ZONE_LOW = 0.018   # 1.8%
DEATH_ZONE_HIGH = 0.035  # 3.5%

if DEATH_ZONE_LOW <= sl_pct <= DEATH_ZONE_HIGH:
    # 死亡区间内：收紧到 1.5%（快认错，等更好的入场机会）
    sl_pct = 0.015
    logger.debug(f"[StructureStop] SL {sl_pct:.3f} 在死亡区间，收紧到 1.5%")
```

升级 A 把 `max_sl_pct` 从 4% 降到 2.0%，升级 C 再把落在 1.8-2.0% 的进一步收到 1.5%。两者配合后 SL 范围: **0.8%-1.5%**，完全避开死亡区间。

## 7. 升级 F: 流动性过滤

### 7.1 问题

CHIP 仅 4 笔就亏 **-$11.33**（占总亏损 53%）——低流动性币插针严重。

### 7.2 设计方案

新建 `backend/services/scalp/liquidity_filter.py`（~60行）:

```python
"""
流动性过滤器：排除日成交量不足的币种，防止插针/滑点。

数据来源：ccxt fetch_ticker 的 quoteVolume（24h 成交额）。
阈值默认 $50M（BTC/ETH/SOL/BNB 远超此值，CHIP 类远低）。
"""
import time
import logging
from typing import Optional

logger = logging.getLogger(__name__)

_VOLUME_CACHE: dict = {}  # {symbol: {ts, volume_usd}}
_CACHE_TTL = 300  # 5分钟

MIN_VOLUME_USD = 50_000_000  # $50M

# 白名单（即使成交量低也允许——用户配置的交易对）
_WHITELIST: set = set()

def is_liquid_enough(symbol: str, market_data: dict) -> bool:
    """检查币种流动性是否足够交易。"""
    sym = symbol.upper()
    if sym in _WHITELIST:
        return True
    
    # 优先从 market_data 读 24h 成交量
    vol = float(market_data.get("volume_24h_usd", 0) or market_data.get("quote_volume_24h", 0) or 0)
    if vol <= 0:
        # 从缓存读
        cached = _VOLUME_CACHE.get(sym)
        if cached:
            vol = cached.get("volume_usd", 0)
    
    if vol <= 0:
        return True  # 拿不到数据不拦（数据真实性：无数据=放行）
    
    return vol >= MIN_VOLUME_USD
```

### 7.3 接入点

在 `scalp_loop.py` 的 `for sym in symbols:` 循环开头（K线拉取之前）:

```python

if not is_liquid_enough(sym, _md):
    logger.info(f"[ScalpRouter独立] {sym} 流动性不足，跳过")
    continue
```

## 8. 升级 G: 订单流因子注入加固

### 8.1 问题

CVD/OI/Taker/Funding 4 个高价值因子声明了 `required_keys`，当 `inject_orderflow_for_factors` 注入失败时（DB 连接竞争），`has_data=False` → 权重=0 → **4 个因子形同虚设**。

### 8.2 设计方案

修改 `backend/services/factor_engine/factor_bridge.py` 的 `inject_orderflow_for_factors`:

**问题**: `get_indicator_value` 内部每次创建独立 DB session（`_get_market_db()`），在 DB 连接紧张时阻塞。

**方案**: 增加进程级内存缓存 + 降级容错:

```python
# factor_bridge.py 修改

# 进程级缓存（5分钟 K线桶内不变，不查库）
_OF_CACHE: dict = {}  # {symbol:timeframe → {bucket, data}}

def inject_orderflow_for_factors(symbol, market_data, timeframe="5m"):
    # ... 现有缓存命中逻辑 ...
    
    # 缓存未命中时：查库，加超时保护
    _of = {}
    try:
        from backend.services.market_flow_indicators import get_indicator_value as _giv
        # 用 ThreadPoolExecutor + timeout 保护，防止 DB 阻塞
        import concurrent.futures
        with concurrent.futures.ThreadPoolExecutor(max_workers=1) as pool:
            future = pool.submit(_query_orderflow, _giv, sym, timeframe)
            try:
                _of = future.result(timeout=3.0)  # 3秒超时
            except concurrent.futures.TimeoutError:
                logger.debug(f"[FactorBridge] {sym} 订单流查询超时(3s)，跳过")
                _of = {}
    except Exception:
        _of = {}
    
    # 如果查不到，用 market_data 已有的数据兜底（而非空）
    if not _of:
        # 从 aggregate_market_collector 缓存读（已在 market-intel 端点验证可用）
        try:
            from backend.services.market_aggregation.aggregate_market_collector import aggregate_market_collector
            for ck, cv in aggregate_market_collector._cache.items():
                if sym in cv:
                    mk = cv[sym]
                    if mk.get("available"):
                        rates = mk.get("funding_rates", {})
                        if rates:
                            avg_fr = sum(v for v in rates.values() if v) / len([v for v in rates.values() if v])
                            _of["funding_rate"] = avg_fr
                        break
        except Exception:
            pass
    
    # 合并 + 落缓存
    ...
```

### 8.3 核心改善

- 3 秒超时防止 DB 阻塞拖慢 scalp 循环
- 从聚合采集器缓存兜底（已验证数据可用）
- 确保至少 `funding_rate` 因子能稳定参与决策

## 14. 风险评估

### 14.1 窄止盈风险

**风险**: TP 太近可能频繁被手续费吃掉利润。

**缓解**: TP=1.8% 在 Hyperliquid taker 费率 0.045% 下，往返 0.09%，TP 是手续费的 20 倍。只有在 TP=0.5% 以下才有风险。

**监控**: 如果 TP 触发但净 PnL < 0 的比例超过 20%，考虑把 TP 提到 2.2%。

### 14.2 强制平仓风险

**风险**: 45 分钟强制平仓可能在行情还没发展完就退出。

**缓解**: `should_force_close` 只在"不亏或微亏"时触发。浮亏超过 SL 50% 的让 SL 自然管理。

### 14.3 流动性过滤误杀

**风险**: 过滤阈值太高导致可交易的币种太少。

**缓解**: $50M 阈值下 BTC/ETH/SOL/BNB/ASTER/ARB 都能通过。用户配置的白名单始终放行。

### 14.4 MR 扩展风险

**风险**: 放宽 MR 触发条件后在非震荡市也进入 MR 逻辑。

**缓解**: `classify_regime` 判断是前置条件，仍然要求 `regime==ranging`。放宽的只是振幅范围和 RSI 阈值。

```python
def predict_win_rate(tp_pct, historical):

    实测数据(125笔):

      TP 1-2%  → 胜率 73%

    # 历史分桶
    buckets = [
        (0.005, 0.43),   # <1%
        (0.015, 0.73),   # 1-2% (最优点)

        (0.05,  0.33),   # ≥4%
```

#### 指标 2: 单笔期望值 (EV)

```python
def calculate_ev(win_rate, tp_pct, sl_pct, tp_real, sl_real, cost):
    """
    EV = win_rate × (tp_pct × tp_realization)
       - (1 - win_rate) × (sl_pct × sl_realization)
       - round_trip_cost

    示例: win_rate=0.58, tp=1.8%, sl=1.2%, tp_real=0.55, sl_real=1.0, cost=0.15%
    EV = 0.58 × 1.8% × 0.55 - 0.42 × 1.2% × 1.0 - 0.15%
       = 0.574% - 0.504% - 0.15%
       = -0.08% (需要 win_rate > 60% 才正)
    """
    ev = (win_rate * tp_pct * tp_real
          - (1 - win_rate) * sl_pct * sl_real
          - cost)
    return ev
```

#### 指标 3: 日化预估

```python
def estimate_daily_return(ev_pct, position_pct, leverage, expected_trades):
    """日化 = EV × 仓位 × 杠杆 × 预期笔数

    注意: 这是名义仓位口径（notional = equity × position_pct）。
    杠杆只放大保证金，不改 EV 正负。

    示例: ev=-0.08%, position=30%, lev=10x, trades=3
    日化 = -0.08% × 0.30 × 10 × 3 = -0.72% (亏损)

    如果调到 ev=+0.14%, trades=3:
    日化 = 0.14% × 0.30 × 10 × 3 = +1.26% ← 接近目标
    """
    # EV 是名义仓位口径（价格%），保证金收益 = EV × 杠杆
    daily = ev_pct * position_pct * leverage * expected_trades
    return daily
```

#### 指标 4: 盈亏比

```python
def calculate_rr(tp_pct, sl_pct, tp_real, sl_real):
    """实际盈亏比 = (TP×实现率) / (SL×实现率)"""
    actual_tp = tp_pct * tp_real
    actual_sl = sl_pct * sl_real
    return actual_tp / actual_sl if actual_sl > 0 else 999
```

#### 指标 5: 最大回撤预估

```python
def estimate_max_drawdown(sl_pct, leverage, position_pct, consecutive_losses=3):
    """预估最大回撤 = 连续亏损笔数 × 单笔保证金亏损率

    单笔保证金亏损 = sl_pct × leverage × position_pct
    假设最坏情况: 连续 3 笔止损（历史最大连续亏损）

    示例: sl=1.2%, lev=10x, position=30%, consec=3
    单笔保证金亏 = 1.2% × 10 × 0.30 = 3.6%
    最大回撤 = 3.6% × 3 = 10.8%
    """
    per_trade_loss = sl_pct * leverage * position_pct
    return per_trade_loss * consecutive_losses
```

### 16.4 参数联动逻辑

| 拖动参数 | 自动联动 |
|---------|---------|

### 19.4 实时生效机制

配置保存后**无需重启**，通过两个路径实时生效:

1. **settings.py 值更新**: 后端 `PUT /api/scalp-config/` 处理器直接修改 `os.environ` + `settings` 模块的属性值，下个 tick 读取时就是新值
2. **运行时覆盖**: 服务类（如 `scalp_ev_gate`、`scalp_factor_router`）每次 `self._cfg()` 读 settings 时自动拿到新值（它们已经是 `getattr(settings, name, default)` 模式）

```python
# PUT 处理器核心逻辑
def apply_scalp_config(params: dict):
    # 1. 更新 os.environ（持久化到 .env）
    env_map = {
        "target_tp_pct": "TIER_SHORT_TP_PCT",
        "target_sl_pct": "TIER_SHORT_SL_PCT",
        ...
    }
    for config_key, env_key in env_map.items():
        if config_key in params:
            value = params[config_key]
            os.environ[env_key] = str(value)
            # 写入 .env 文件
            update_env_file(env_key, str(value))

    # 2. 热重载 settings 模块属性
    import importlib
    from backend.config import settings
    importlib.reload(settings)

    # 3. 已确认的持仓不受影响（用开仓时的参数管理退出）
    # 新参数从下一个 scalp tick 开始生效
    return {"success": True, "effective": "next_tick"}
```
