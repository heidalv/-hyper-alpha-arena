# 短期因子策略全链路深度审查报告

> 审查日期：2026-08-01
> 范围：因子挖掘 → AI 选币（因子匹配）→ 回测 → 学习进化 → 模拟盘应用 → 实盘；
> 附：中长线 AI 策略考察、多周期联动设计。
> 数据前提：模拟盘有效历史仅 3 天（2026-07-29 起），此前数据被判定为垃圾、不参与评估。

---

## 0. 结论先行

这个项目的骨架**不是玩具级**：DSR/PBO/CSCV 过拟合硬门、purge/embargo、因子生命周期
（PAPER→SMALL_LIVE→ACTIVE）、影子期推进、漂移监控、置信度校准（PAVA）、EV 门、
meta-model AUC 门、统一成本模型、三层晋升门（shadow→canary→full）——这些在个人量化项目里
属于**第一梯队**。但全链路存在四类系统性问题：

1. **组件多、闭环少**：WalkForwardOptimizer 是孤立脚手架（零调用点）；100 个"ACTIVE"因子
   只有 1 轮进化日志，因子库疑似"僵尸化"；因子挖掘只喂单一币种。
2. **选币环节没有真正用因子**：AI 选币是"行情/情绪/资金评分 + LLM 定性审核"，与
   `factor_active_set` 的 100 个因子是两条平行线，缺少用户要求的"因子匹配"。
3. **模拟盘→实盘晋升统计不充分**：有效样本只有 3 天（实测 7-29 仅 13 单、7-30 196 单、
   7-31 236 单、8-1 26 单），胜率 46%、净收益 -10.6%，任何统计晋升门在当前样本下都不可信。
4. **周期割裂**：scalp/mid/long 是三个独立调度器 + 独立信号 + 独立仓位，联动只有
   "反向缩仓"这一道防御性约束，没有"共振进攻"和统一组合层。

## 1. 因子挖掘（Factor Mining）

### 1.1 现状（代码证据）

- 入口：`evolution/factor_evolution_loop.py`，每日 3 点由 `evolution_scheduler.py` 触发。
- 候选来源（`_mine_candidates`）：
  - 种子因子：反转（rev5/10/20/50）、动量（mom5/10/20）、波动（vol10/20/50）、
    量价相关（vp_corr10/20）、时序排名（ts_rank20/50）；
  - 永续合约因子（funding/OI，`perp_factors.py`）；
  - `AlphaMiner` 随机 AST 搜索（默认 2000 次，`FACTOR_MINER_MAX_ATTEMPTS`）。
- 验证：train/val 切分（`VAL_BARS` 样本外），逐币算 IC/ICIR，跨币种取均值；
  `purge_pipeline` 做增量去相关（incremental corr）；
  `overfitting_metrics.py` 提供 DSR/PBO/CSCV（López de Prado 标准），
  `_auto_oversight_approve` 自动审批（DSR 显著 且 PBO≤0.30 才放行）；
  生命周期 `factor_engine/lifecycle.py`：PAPER→SMALL_LIVE→ACTIVE，影子期复评推进，
  `drift_watcher` 连续衰减自动隔离，`_replace_degraded` 补挖，在线权重更新。

### 1.2 缺陷

1. **单标的挖掘**：随机搜索只用 `first_df`（通常 BTC）拟合 target，跨币验证在后。
   挖出来的因子天然偏向 BTC 微观结构，对山寨币可能无效——这与"选山寨币做短线"的目标错配。
2. **标签太粗**：目标标签是 5 根 forward return（`_forward_returns(horizon=5)`）。
   项目已有 `labeling/triple_barrier.py`（行业标准的三重障碍 + meta-labeling），
   但因子挖掘线没有使用；无波动率归一、无路径依赖/止损感知标签。
3. **因子库治理失控信号**：`factor_active_set` 实际有 **100 个 ACTIVE**，而
   `PurgeConfig(max_active_factors=50)`；`factor_evolution_log` 只有 1 轮完整记录。
   说明大量"活跃因子"是历史 bootstrap 遗留，从未经过新门禁复核——因子库有僵尸化风险，
   组合权重会被一堆无效暴露稀释。
4. **挖掘周期与交易周期错配**：进化 3 天一轮（`CYCLE_SECONDS = 3*24*3600`），
   而 scalp 是 5m/10s 级别。5m 因子的 IC 半衰期通常以小时计，3 天一轮的挖掘/替换
   追不上衰减速度；drift watcher 是每日粒度，对短线因子太慢。
5. **无容量/换手/成本感知**：因子上线只看 IC/ICIR/DSR，没有"交易次数、换手率、
   每单位 alpha 的成本消耗（即净 IC after cost）"；5m 高频因子的手续费敏感度极高，
   当前 100 个因子里很可能混着"毛 IC 为正、净收益为负"的因子。
6. **表达式库规模小**：种子 + 随机 AST 共 ~2000 次尝试，远小于行业 Alpha101 级库；
   随机搜索无进化压力（注释自己承认"纯随机搜索、无进化压力"）。

### 1.3 行业对比

| 维度 | 本项目 | 行业（Qlib/WorldQuant/LEAN） | 差距 |
|---|---|---|---|
| 过拟合控制 | DSR/PBO/CSCV/purge/embargo | DSR/PBO/CSCV 是标配 | 无差距（亮点） |
| 因子表达式库 | 几十个种子 + 随机 AST | Alpha101 + 组合爆炸 | 差距大 |
| 标签 | 5-bar forward return | Triple-barrier + meta-labeling + volatility scaling | 差距大（代码有，未接线） |
| 分层测试 | 无 | Quantile spread / IC 分层 | 缺失 |
| 容量/换手分析 | 无 | 全行业标配 | 缺失 |
| 因子组合 | 在线权重（EW/IC 加权） | 均值方差/风险平价/正交化组合 | 中等差距 |
| 挖掘周期 | 3 天 | 按因子半衰期自适应 | 错配 |

## 2. AI 选币 / 因子匹配

### 2.1 现状

- `auto_coin_selector.py`：阶段 1 五维评分（trending/momentum/fund/volatility/trend），
  regime 自适应权重（trending/ranging/extreme 三套权重表）；
  阶段 2 用链上/衍生品数据 enrich；阶段 C 三层渐进式 LLM 审核（layer + test_position），
  4h 一次完整审核；再注入运行中会话；有 retention 评分、分级冷却、黑名单、新上市检测。
- 流程合理度：这是"市场扫描 + LLM 审核"型选币，工程完整。

### 2.2 缺陷

1. **没有因子匹配**：用户点名的"因子匹配"环节实际不存在。选币评分用的是
   "24h 涨跌/成交额/资金费率/波动率"这类**宏观代理变量**，而不是
   `factor_active_set` 里 100 个因子的实时 z-score 暴露。因子层和选币层互相不知道对方存在。
2. **LLM 定性审核缺少定量锚**：LLM 审核的 prompt 有行情快照，但没有
   "该币在这些已验证因子上的暴露 × 因子当前 IC"的量化矩阵，AI 只能凭"感觉"给层。
3. **样本依赖**：retention/表现评分在 3 天有效历史上会过拟合最近行情。
4. **审核频率与交易频率脱节**：选币 4h 一轮，但 scalp 10s 一轮；币池一旦注入，
   短线信号质量完全由 10s 因子决定，选币层无法在盘中及时纠错（只有硬止损兜底）。

### 2.3 行业对比

行业（尤其加密货币自营团队）的标准做法是：
**因子暴露矩阵 × 因子 IC 向量 → 预期 alpha 排序 → 风险约束（相关性/集中度）→ ML 或组合优化 → LLM 只做否决与解释**。
本项目是"规则评分 + LLM 做主审"，相当于把最该量化的环节交给了最不稳定的环节。

## 3. 回测

### 3.1 现状

- `backtest_engine/`：walk_forward、DSR/PSR/MinTRL/CSCV、lookahead 分析、
  parity_score、extreme_scenario、pipeline_replay、统一 cost_model
  （taker/maker、滑点分级、SL 滑点乘数、资金费率——与实盘 `fee_guard.py` 对齐）。
- `strategy_evolver.py`：遗传进化 + `walk_forward_split=0.7` + PBO_AUDIT_ENABLED=true。
- `backtest/trigger.py`：事件驱动回测（因子晋升/权重变化/参数变更触发）。
- `backtest_reporting/`：报告生成、指标计算、策略对比。

### 3.2 缺陷

1. **WalkForwardOptimizer 未接线**：`walk_forward.py` 注释自己写明
   "`WalkForwardOptimizer.run()` 目前在全代码库没有任何调用点（孤立脚手架）"。
   真正的过拟合门靠 factor_evolution_loop 和 strategy_evolver 各管一段，
   **没有一条完整的"策略级 WFO"管线**。
2. **事件驱动回测是简化版**：`_simple_factor_backtest` 只是单因子信号回放，
   与真实执行链（门禁/保护/分批止盈/冷却）不对齐；pipeline_replay 是纯函数库，
   是否被完整执行链使用需要进一步核实（目前看是"可用但未接入主决策"）。
3. **成交假设**：paper_exchange_simulator 对市价单按当前价直接成交，
   无盘口深度/排队/冲击建模；成本模型虽然存在，但模拟盘成交价没有按
   CostModel 的滑点分级滑价（至少需要核实；若未接入，回测与模拟盘的
   "成本真实感"就是脱节的）。
4. **样本与周期错配**：短周期回测数据只有 1 年（crypto_klines 2025-06 起），
   且有效策略样本仅 3 天；walk-forward 的 train/test 在 5m 上需要数十万根 K 线，
   目前深回测只到 1d/4h，5m 深度只有 1 天（`KLINE_P1_DEPTH_DAYS_1M=1`）——
   **短线回测数据深度严重不足**（这是基础设施级缺陷）。

### 3.3 行业对比

行业标准：事件驱动撮合（订单簿模拟）+ 成本/冲击模型 + 多周期 WFO + 组合回测 + 稳健性检验。
本项目理论组件齐，但**接线率低**：理论 90 分，落地 50 分。

## 4. 学习进化

### 4.1 现状

- `learning_loop_service.py`：交易结果批次结算、模拟盘结果回填、Kelly 组合、协调器心跳。
- `decision_feedback_service.py`：归因 → 净教训 → prompt 注入 → 每日报告。
- `scalp_confidence_calibrator.py`：PAVA 等渗回归做胜率校准（行业级做法）。
- `scalp_ev_gate.py`：EV 门；`SCALP_META_*`：meta-model AUC 门（0.53）。
- `evolution_scheduler.py`：3 天 GA、每日 wisdom、6h 假设扫描、5min 跨所扫描、
  10min QAA 检查、RAG 周更。
- `hermes_*`：prompt 优化、架构进化（LLM 元学习）。
- `mlto`：中长线 thesis + qual/quant/debate 四层。
- `rl/`：DRL 训练任务、kelly 仓位、trading_env（离线/辅助性质）。

### 4.2 缺陷

1. **反馈信号弱且样本小**：3 天有效交易、胜率 46%、净收益 -10.6%。
   学习回路（教训/复盘/权重更新）在这么小的样本上很容易把噪声当规律。
2. **RAG 实际降级运行**：日志显示 embedding 模型加载失败（huggingface 离线），
   RAG 全程 degraded（SQL 检索兜底）。记忆检索的"语义相似"实际没生效，
   学习闭环的"经验复用"是打折的。
3. **LLM 复盘缺乏统计归因**：教训是按"方向/币种"归因，没有按**因子暴露**归因；
   无法回答"亏的钱是哪个因子贡献的"。
4. **进化节奏与短线脱节**：GA 3 天一轮、权重日更；短线因子需要小时级重估。
5. **多套学习系统并存**：learning_loop / hermes / evolution / QAA / MLTO / RL 各自为政，
   没有统一"样本仓库 + 标签中心 + 评估器"，互相之间通过 prompt 注入耦合，
   可解释性和可审计性差。

## 5. 模拟盘应用

### 5.1 现状

- 执行链完整：scalp 独立循环（10s）→ 因子路由 → 执行门/闪崩否决/EV 门/MTF 约束 →
  V5 统一门 → paper_engine 开平仓 → 完整保护（TP/SL/追踪/保本/超时/爆仓/资金费率）。
- 参数化：`paper_fast_trial_controller`（PARAM_DEFS + blitz/turbo/warm 档位）。
- 信号落库：`scalp_signal_log` + 事后结算，供校准与 meta-model 训练。

### 5.2 缺陷

1. **胜率 46% + 手续费后负收益**：当前 scalp 参数（TP 2.3%、SL 2.5%、10x）在
   5m 周期上，毛胜率不足以覆盖 taker 费 + 滑点（SCALP_META_COST=0.0008）。
   说明**因子信号本身的边缘不足，参数层只是在调盈亏比**，而非创造 alpha。
2. **成交假设乐观**：市价单按现价成交，无滑点模拟（需核实 paper 是否接入 CostModel）。
3. **保护逻辑过重**：单仓全量保护计算 20-30s（已拆快/慢路径缓解），
   但完整保护仍 30s 一巡——对 5m 持仓仍偏慢（用户此前已要求秒级）。
4. **模拟盘与实盘执行差异**：模拟盘下单即成交、无交易所拒绝/部分成交/网络重试，
   live_executor 的 `place_ai_driven_order` 链路（风控/手续费门/滑点）不会在模拟盘被验证。

## 6. 实盘

### 6.1 现状

- `live_executor.py` → `place_ai_driven_order` → `risk_engine`（下单频率/精度/减仓/名义）
  + `fee_guard` + `decision_core/unified_gate` + `decision_arbiter`；
- 晋升门：`promotion_gate_service`（shadow→canary→full，PROMOTION_GATE_ENABLED=true），
  由 `promotion_scan_service` 按 learning_loop 周期扫描；
- 事件源对账：event_sourcing phase2 C7（有"extra_in_proj"不一致告警）。

### 6.2 缺陷

1. **从未真正实盘**：唯一实盘账户停用、无 API Key——晋升门、实盘滑点、对账全是"纸上设计"。
2. **3 天样本撑不起晋升统计**：任何 shadow/canary 统计门在当前样本量下都是噪声。
3. **实盘 TP/SL 依赖交易所条件单**：手动下单传 takeProfitPrice/stopLossPrice，
   但 Asterdex 条件单行为、断线重连后的条件单恢复、盘口触发滑点都没有回测验证。
4. **对账告警未清零**：C7 投影不一致说明事件源投影与真实状态有 drift，
   实盘前必须清零。

## 7. 中长线 AI 策略（一并考察）

### 7.1 现状

- `trading_analysts.py`：规则分析师（Position/Market/Intel/Risk/Strategy）+
  KlineAnalyst（LLM 多周期 K 线，rotate 分批 + 缓存）+ MasterController（LLM 综合决策）。
- `mlto/`：thesis_store + quant_layer（规则信号）+ qual_layer（LLM 更新 thesis）+
  debate_layer（多空对抗辩论）+ decision_hub。
- `strategic_analyst/`：宏观/跨市场报告 + 记忆系统。
- 调度：midlong 独立循环 120s，tier scheduler（mid 120s/long 240s）。

### 7.2 缺陷

1. **量化锚缺失**：mid/long 信号主要是 LLM 定性 + 简单规则（RSI/MACD 阈值），
   `factor_active_set` 的 1h/4h/1d 因子完全没有接入 MLTO quant_layer。
2. **LLM 成本与新鲜度矛盾**：KlineAnalyst rotate 缓存 TTL 内复用旧结论，
   4h/1d 周期尚可，但"mid 120s tick"与 LLM 分钟级分析不匹配，决策实际节奏远慢于配置。
3. **thesis 收敛慢**：qual_layer 每次 LLM 更新 thesis，但无量化确认/证伪机制，
   一个错误 thesis 可以存活很久直到止损。
4. **与短线完全割裂**：见下节。

## 8. 周期联动：当前是"约束式防御"，不是"共振式进攻"

### 8.1 现状

- 已有：`scalp_mtf_constraint`（scalp 方向 vs 4h/15m 反向 → 禁开/缩仓）、
  `mtf_resonance_engine`（1h/15m/5m 三层共振分析，偏展示）、
  `decision_core/midlong_mtf_constraint`、tier_tick_scheduler 三档调度。
- 已有代码说明作者意识到了问题（scalp_mtf_constraint 的 docstring 承认
  "独立 scalp 循环完全绕过多周期编排器，这是短线亏损的根因之一"）。

### 8.2 缺陷

1. **联动只有"不做什么"**：反向时缩仓/禁开，但同向时没有任何"共振加成"；
   三周期各自算仓位，互不共享风险预算。
2. **信号生成割裂**：scalp 因子引擎、MLTO thesis、MasterController 三套信号
   在三个循环里独立产生，没有统一"周期信号总线"。
3. **持仓管理割裂**：scalp 持仓和 midlong 持仓在同一账户互不知情，
   保证金、浮盈、止损预算没有按周期分层管理（Kelly 只按账户汇总）。
4. **进化割裂**：短线因子进化 3 天一轮、中长线 thesis 无因子锚，
   两者不会互相学习（例如"4h 转多"本应上调 mid 因子权重）。

## 9. 独特升级设计：把"因子工厂"升级为"全周期共振 Alpha 工厂"

### 9.1 统一因子层（Alpha 工厂）

1. **表达式库与挖掘升级**：
   - 建立 Alpha 表达式库（按 Qlib Alpha158 思路扩展：动量/反转/量价/波动/资金/OI 家族），
     挖掘从单币 BTC 改为"多币横截面初筛 + 代表性币纵向拟合"；
   - 标签升级：接入已有的 `triple_barrier.py` + 波动率归一 + meta-labeling；
   - 挖掘产出必须带**净 IC（扣费后）**、换手率、容量估算，上线门槛改为
     "净 IC 显著 + DSR 显著 + 换手可承受"。
2. **因子库治理收口**：
   - ACTIVE cap 强制 50，每轮进化对全部 ACTIVE 复评（现在只评影子期因子）；
   - 短线因子（5m/15m）日更或小时更权重，3 天周期只保留给 4h/1d 因子；
   - 因子分层测试（quantile spread）纳入晋升门。
3. **因子画像服务**：为每个交易对维护"因子 z-score 时序 × 因子当前 IC"的
   实时暴露矩阵（挂到数据中心），供选币、scalp、mid/long 三方共用。

### 9.2 选币 = 因子匹配引擎（补上用户点名缺口）

- 选币评分 = Σ(因子暴露_z × 因子预期IC) + 流动性/相关性惩罚 + 组合分散约束；
- LLM 从"主审"降级为"否决与解释"（只对量化分边缘的币做审核，省 LLM 成本）；
- 盘中每 5-10 分钟重算因子暴露，币池按因子预期 alpha 排序动态换血，
  而不是 4h 一次注入。

### 9.3 回测正式 WFO 闭环

### 9.4 全周期共振组合层（核心原创设计）

在三周期之上加一个轻量 **Portfolio Resonance Layer（PRL）**，消费三路信号，
统一输出仓位：

```
scalp(5m) ─┐
mid(1h/4h) ─┼→ 周期信号总线 → 共振评分 → 组合管理器 → TradeProposal
long(1d)  ─┘      （方向+置信+时限）      （分层仓位/风险预算）
```

- **同向共振**：短周期顺中长周期 → 允许全仓 + 持仓时限延长；
- **中性**：短周期独立交易但缩仓（现有约束升级为评分制）；
- **反向**：短周期只允许"对冲性均值回归"或禁开；
- **统一风险预算**：按周期分层分配保证金（scalp 层 ≤30%、mid ≤40%、long ≤30%），
  浮盈共享、止损互不踩踏；
- **联动学习**：PRL 的共振胜负按周期组合归因，反哺因子权重
  （例如"4h 转多后 15m 动量因子 IC 提升"这种跨周期规律可以被进化系统学到）。
