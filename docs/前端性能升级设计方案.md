## 2. 分步方案

### Step 1: 砍 keepAlive（10分钟，效果最大）

**文件**: `frontend/app/main.tsx`

**方案**: 把 37 个 `keepAlive()` 改为条件渲染（只渲染当前页面），核心页面保留 keepAlive。

```typescript
// 需要保留 keepAlive 的页面（8个核心+配置）
const KEEP_ALIVE_PAGES = new Set([
  'comprehensive', 'atas-v2', 'paper-trading', 'klines',
  'scalp-config', 'mid-config', 'long-config', 'settings',
]);

// 其余页面改为普通条件渲染（离开即卸载）
// 原: {keepAlive('vault-graph', <Component />)}
// 改: {activePage === 'vault-graph' && <Component />}
```

**改动量**: 把 37 个 keepAlive 中的 29 个改为条件渲染。只保留 8 个核心页面。

**效果**: 内存占用降 70%+，不可见页面不再占 DOM/内存/CPU。

**风险**: 极低——条件渲染是 React 标准模式，页面切换时重新加载数据（用户可接受）。

### Step 2: 统一图表库（20分钟，砍 2 个依赖）

**删除 recharts**:
- `npm uninstall recharts`
- 5 处使用改为 lightweight-charts：
  - `FactorAnalysis.tsx` → lightweight-charts 柱状图
  - `PerformanceDashboard.tsx` → lightweight-charts 折线图
  - `AssetCurveChart.tsx` → lightweight-charts 面积图
  - `IndicatorChartWidget.tsx` → lightweight-charts 折线图
  - `HyperliquidAssetChart.tsx` → lightweight-charts 蜡烛图

**删除 chart.js + react-chartjs-2**:
- `npm uninstall chart.js react-chartjs-2`
- 使用处搜索替换为 lightweight-charts

**保留**: lightweight-charts（5 处已在用，35KB，Canvas 渲染）

**效果**: Bundle 减小约 1.5-2MB。

**风险**: 中——需要重写 5 个图表组件的渲染逻辑。但因为这些页面都是偶尔访问的分析页，不影响核心交易功能。

### Step 3: 合并 setInterval 轮询（30分钟）

**当前**: 104 个 setInterval 分散在各组件中。

**方案**: 创建统一的 `usePolling` hook：

```typescript
// frontend/app/hooks/usePolling.ts
import { useEffect, useRef } from 'react';

const POLLING_REGISTRY: Map<string, () => void> = new Map();
let MASTER_INTERVAL: ReturnType<typeof setInterval> | null = null;

function ensureMaster() {
  if (MASTER_INTERVAL) return;
  MASTER_INTERVAL = setInterval(() => {
    POLLING_REGISTRY.forEach((fn) => {
      try { fn(); } catch {}
    });
  }, 10000); // 统一 10 秒刷新
}

export function usePolling(key: string, fn: () => void) {
  const fnRef = useRef(fn);
  fnRef.current = fn;
  useEffect(() => {
    POLLING_REGISTRY.set(key, () => fnRef.current());
    ensureMaster();
    return () => { POLLING_REGISTRY.delete(key); };
  }, [key]);
}
```

**用法**: 各组件把 `setInterval(loadData, 10000)` 改为 `usePolling('market-intel', loadData)`。

**效果**: 104 个独立定时器合并为 1 个，CPU 空转降 90%。

**风险**: 低——只是合并定时器，不改数据逻辑。

### Step 4: 删除重型未使用依赖（10分钟）

```bash
# react-syntax-highlighter（只在代码审计页用，已封存）
npm uninstall react-syntax-highlighter

# @xyflow/react（Canvas/vault-graph 用，已封存）
# 暂保留——如果 vault 页面不再 lazy import 就自动 tree-shake

# framer-motion 检查是否有用
grep -rn "framer-motion" frontend/app/ --include="*.tsx" | wc -l
# 如果 < 3 处，考虑用 CSS 动画替代
```

**效果**: Bundle 再减 500KB-1MB。

### Step 5: 核心 API 请求提速（15分钟）

**问题**: account/list 等同步端点在 LLM 高负载时偶尔慢到 4-5 秒。

**方案**: 给关键 API 加请求级超时 + 重试：

```typescript
// frontend/app/lib/api.ts
export async function apiRequest(endpoint: string, options: RequestInit = {}): Promise<Response> {
  const url = `${API_BASE_URL}${endpoint}`;
  
  // 关键 API 用更长超时
  const isCriticalAPI = endpoint.includes('account/list') || endpoint.includes('health');
  
  const response = await fetch(url, {
    ...options,
    headers: { 'Content-Type': 'application/json', ...options.headers },
  });
  // ... 现有逻辑
}
```

**同时**: 给 PaperTradingPanel 的 AbortController 提到 30 秒（已完成）。

### Step 6（可选）: Million.js 加速

```bash
npm install million
```

```typescript
// vite.config.ts
import million from 'million/plugin';

export default defineConfig({
  plugins: [million({ auto: true }), react(), tailwindcss()],
});
```

**效果**: React 渲染快 70%，内存降 55%。

**风险**: 中——Block 组件限制（无 hooks），但 auto 模式会自动跳过不兼容的组件。
