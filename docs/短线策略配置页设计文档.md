## 3. EV 实时计算引擎

### 3.1 公式

```
ev_pct = p_win × tp_pct × tp_realization - (1-p_win) × sl_pct × sl_realization - round_trip_cost

round_trip_cost = 2 × (taker_fee + slippage)
               = 2 × (0.00035 + 0.0007)  # Hyperliquid taker + intraday滑点
               = 0.0021 (0.21%)

breakeven_win_rate = (sl_pct × sl_real + cost) / (tp_pct × tp_real + sl_pct × sl_real)

daily_return = ev_pct × leverage × position_pct × trades_per_day
             = ev_pct × 10 × 0.30 × N

monthly_return = daily_return × 22  # 22个交易日/月（加密24/7可更多）
```

### 3.2 计算示例（默认新配置）

```
TP=1.8%, SL=1.2%, RR=1.5, p_win=58%(假设), tp_real=0.55

ev = 0.58 × 0.018 × 0.55 - 0.42 × 0.012 × 1.0 - 0.0021
   = 0.005742 - 0.005040 - 0.0021
   = -0.001398 (-0.14%)

breakeven = (0.012 × 1.0 + 0.0021) / (0.018 × 0.55 + 0.012 × 1.0)
          = 0.0141 / 0.0219
          = 64.4%

# 需要胜率 > 64.4% 才盈利——太高了
# 降低 TP实现率假设(改进后不再被砍仓): tp_real=0.75
ev = 0.58 × 0.018 × 0.75 - 0.42 × 0.012 - 0.0021
   = 0.007830 - 0.005040 - 0.0021
   = +0.000690 (+0.069%)

breakeven = 0.0141 / (0.018×0.75 + 0.012) = 0.0141/0.0255 = 55.3%
# 胜率>55.3%即可盈利——实测1-2% TP桶73%，可达
```

### 3.3 前端实时计算逻辑

```typescript
function calculateEV(params: ScalpConfig): EVResult {
  const roundTripCost = 0.0021; // 固定 0.21%
  const ev = params.pWin * params.tp * params.tpReal
           - (1 - params.pWin) * params.sl * params.slReal
           - roundTripCost;
  
  const breakeven = (params.sl * params.slReal + roundTripCost)
                  / (params.tp * params.tpReal + params.sl * params.slReal);
  
  const dailyReturn = ev * params.leverage * params.positionSize * params.tradesPerDay;
  const monthlyReturn = dailyReturn * 30; // 加密 24/7
  
  return { ev, breakeven, dailyReturn, monthlyReturn };
}
```

## 5. 后端 API 设计

### GET /api/scalp-config

返回当前全部配置 + 实测统计 + EV 计算:

```json
{
  "config": {
    "tp_pct": 0.018,
    "sl_pct": 0.012,
    ...
  },
  "stats": {
    "last_7d": {
      "trades": 125,
      "win_rate": 0.416,
      "net_pnl": -21.29,
      "avg_hold_hours": 2.53,
      "profit_factor": 0.36
    }
  },
  "ev_calc": {
    "current": {
      "ev_pct": -0.0014,
      "breakeven_win": 0.644,
      "daily_return": -0.014,
      "monthly_return": -0.42
    }
  }
}
```

### PUT /api/scalp-config

接收修改后的配置，写入 .env 并热加载:

```json
{
  "tp_pct": 0.020,
  "sl_pct": 0.012,
  ...
}
```

后端逻辑:
1. 更新 `os.environ`（即时生效——settings.py 每次读 `os.getenv`）
2. 写入 `.env` 文件（持久化）
3. 返回新的 EV 计算

### GET /api/scalp-config/simulate

传入假设参数，返回计算的 EV（不修改实际配置）:

```json
// Request
{ "tp_pct": 0.020, "sl_pct": 0.015, "p_win": 0.55 }
// Response
{ "ev_pct": 0.0008, "breakeven_win": 0.52, "daily_return": 0.008 }
```

```tsx
  format="percent"

  hint={`TP每+0.5%需要胜率+${calcWinRateIncrease(v)}%`}
  warning={v >= 0.04 ? '⚠️ TP>4%实测胜率仅33%' : undefined}
```

```
│  [保守] [均衡] [激进] [纯MR]  ← 点击应用预设       │
└────────────────────────────────────────────────────┘
```

---

## 7. 数据流

```
用户拖动滑块 → ParamSlider.onChange
    ↓
updateConfig(key, value) → 更新本地 state
    ↓
EVSimulator 自动重算 → 更新显示
    ↓
用户点击"保存并应用"
    ↓
PUT /api/scalp-config → 后端写 .env + 更新 os.environ
    ↓
settings.py 下次读取就是新值（热生效）
    ↓
scalp_loop 下一 tick 用新参数
```

### 热生效原理

settings.py 的所有参数都用 `os.getenv()` 动态读取。配置页直接修改 `os.environ`，下次代码读 settings 就是新值——**不需要重启后端**。

只有 `.env` 文件写入是为了持久化（重启后不丢）。

## 8. 完整参数影响矩阵

| 改动 | 对胜率影响 | 对盈亏比影响 | 对频率影响 | 对风险影响 |
|------|-----------|------------|-----------|-----------|
| TP↓(窄止盈) | ↑↑↑ 大幅提升 | ↓ 降低 | ↑ 增加 | ↓ 降低 |
| SL↓(紧止损) | ↓ 降低 | ↓ 降低 | — | ↓ 降低（单笔亏少） |
| RR↑(高盈亏比) | ↓ 降低（需更准） | ↑↑ 提升 | — | — |
| 持仓时间↓ | ↑ 提升（快速退出） | ↓ 降低 | ↑ 增加 | ↓ 降低 |
| 执行阈值↑ | ↑↑ 提升（信号更准） | — | ↓↓ 减少 | ↓ 降低 |
| 仓位↑ | — | — | — | ↑↑ 增加 |
| AI反向禁用 | ↑↑ 提升（去掉10%胜率行为） | ↑ 提升 | ↓ 减少 | ↓ 降低 |
| MR权重↑ | ↑ 提升（MR单笔亏损1/4） | ↓ 降低 | — | ↓ 降低 |
| 流动性过滤↑ | ↑ 提升（去掉插针） | — | ↓ 减少 | ↓↓ 大幅降低 |

> 这个矩阵让用户理解每个参数的连锁影响，避免"只调一个不管其他"。
