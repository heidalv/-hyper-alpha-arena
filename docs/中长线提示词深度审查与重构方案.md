## 1. 现有提示词的致命问题

### 1.1 问题一：把大模型当计算器用

**现有 swing prompt 片段**：
```
## 分析步骤（逐一思考后回答）
1. 趋势判断：1h 和 4h 的 EMA9/21/50 排列 + RSI → 当前趋势方向和强度
2. 支撑阻力 + 猎杀止损：价格是否刚扫过 swing high/low？
3. 成交量确认：vol_ratio > 1.5 = 放量突破
...
```

**问题**：这完全是在告诉 LLM "按固定公式算"。EMA/RSI/vol_ratio 这些**代码已经算好了**，再让 LLM 重算一遍毫无意义。大模型的长处是**理解上下文、推理因果、综合判断**，不是做数学。

**行业对比**（[TradingAgents](https://github.com/taurricresearch/tradingagents)）：
```
"你是一名资深宏观分析师。基于以下数据和你的专业知识，分析：
1. 当前市场叙事是什么？谁是推动者？
2. 这个叙事可持续吗？什么会改变它？
3. 如果我是对的，最可能的3种未来情景是什么？概率各多少？
4. 如果我错了，最可能的失败模式是什么？"
```

### 1.2 问题二：过度约束扼杀推理

现有提示词充满了"禁止"和"必须"：
- "禁止在 paper 模式下输出 hold 且 confidence≥48：达下限必须 buy/sell"
- "盈亏比与置信度（与代码执行层一致）：Paper RR≥1.5 confidence≥48"
- "持仓目标 2-8 小时"

**问题**：这些约束**代码层已经强制执行了**（`_normalize` 里的 `max(0,min(95,confidence))` + RR clamp + action 判定）。提示词里重复这些约束让 LLM 变成了"约束执行器"而非"分析师"。

### 1.3 问题三：没有发挥推理模型的深度

当前用的模型是 `deepseek-v4-pro`（推理模型，有 thinking 能力），但提示词完全没有引导深度推理：
- 没有要求"先思考再回答"的 CoT 结构
- 没有"反向假设检验"（虽然有提到但没展开）
- 没有"多场景推演"（scenario analysis）
- 没有"事实 vs 叙事"分层推理

### 1.4 问题四：提示词编辑器只暴露了单个 task，没有体现 MLTO

当前提示词配置页只显示了 3 个独立 prompt（swing/trend_direction/trend_review），但项目实际有完整的 **MLTO 多对话编排器**（7 阶段流水线、辩论层、论点账本、分批入场），这些完全没有在提示词管理中体现。

## 2. 行业最佳实践调研结论

### 2.1 推荐的提示词架构（综合 6 个来源）

| 维度 | 推荐做法 | 来源 |
|------|---------|------|
| **角色定义** | 给出人格+经验+决策哲学，不是规则清单 | [TradeRank 13个交易模型提示词](https://www.traderank.ai/blog/ai-trading-prompts-engineering) |
| **推理结构** | CoT 强制多步推理（技术→资金→情绪→叙事→综合→反向检验） | [arXiv 2501.00826 多Agent加密交易](https://arxiv.org/html/2501.00826v3) |
| **事实/主观分层** | 区分硬数据（价格/OI/费率）与叙事（情绪/故事），让 LLM 标注每条论据属性 | [arXiv FS-ReasoningAgent](https://arxiv.org/html/2410.12464v3) |
| **多场景推演** | 要求输出 3 种情景（基准/乐观/悲观）+ 各自概率和触发条件 | [TradingAgents](https://github.com/taurricresearch/tradingagents) |
| **反思机制** | 回看历史亏损单，提炼"这次要避免什么" | [EMNLP 反思 Agent](https://aclanthology.org/2024.emnlp-main.63.pdf) |
| **对抗辩论** | 多空双方各自给最强论点，最后综合 | [TradingAgents 辩论框架](https://tradingagents-ai.github.io/) |
| **reasoning effort 分级** | 高风险决策用 high effort | [OpenAI Reasoning Docs](https://developers.openai.com/api/docs/guides/reasoning) |

### 2.2 加密永续合约专属要点

| 要点 | 说明 |
|------|------|
| **资金费率叙事** | 费率不只是成本，是市场情绪温度计——极端正费率=多头拥挤可能反转 |
| **清算级联风险** | 价格接近高杠杆清算密集区时，可能引发连锁爆仓→插针→V型反转 |
| **24/7 无间断** | 没有开盘收盘，"日内"概念不同——需要时间衰减而非日K |
| **流动性幻觉** | 订单簿深度浅时价格容易操纵，大单可以打穿 |
| **叙事驱动** | BTC ETF 流入、监管新闻、链上巨鲸转移，这些"故事"驱动资金流向 |

## 3. MLTO编排器——被隐藏的核心能力

### 3.1 项目已有的强大能力

项目实际上有完整的 **7 阶段 MLTO 编排器**，但提示词配置页完全没有暴露：

```
① thesis_store.get_or_create    → 创建/加载论点账本
② evidence_ingest.ingest_tick   → 证据摄入（技术面+资金面+情绪面）
③ layered_memory.retrieve       → γ衰减记忆检索 Top-8 历史事件
④ qual_layer.update_thesis      → LLM 更新论点（thesis_update prompt）★
⑤ quant_layer.compute           → 7个确定性框架信号
⑥ debate_layer.run_debate       → 灰区辩论（多空对抗）★可选LLM
⑦ decision_hub.fuse_signals     → 三层信号融合 → 开单门控 → 分批入场
```

### 3.2 论点(Thesis)系统

每个币种每个周期维护一个持续更新的"论点"：

```json
{
  "direction": "long",           // 方向判断
  "thesis_summary": "BTC突破...", // 核心论点（2-3句）
  "reasoning_content": "...",    // 完整思维链（6000字）
  "llm_conviction": 72,          // LLM确信度(0-100)
  "hub_adjusted": 0.68,          // 综合调整后的分值
  "consistency": 0.85,           // 多信号一致性
  "open_readiness": 65,          // 开仓就绪度
  "direction_history": ["long","long","long","neutral","long"],  // 最近5次方向
  "review_count": 8,             // 已复盘次数
  "invalidation": {"price": 59000, "condition": "跌破支撑"},  // 论点失效条件
  "owm_weights": {...}           // 学习权重（赢+0.02/亏-0.03）
}
```

### 3.3 辩论层

灰区（信号不明确时）自动触发**多空对抗辩论**：
- **看多 Agent**: 给出最强做多论点+证据
- **看空 Agent**: 给出最强做空论点+证据
- **风险角色**: 3个风险角色（激进/保守/中立）评估
- **裁决**: 综合所有论点，net≤-0.15 拒绝，net≥0.15 放行

### 3.4 学习闭环

平仓后自动反馈：赢的交易→对应信号源权重+0.02，亏的-0.03，下次融合时自动调整——**系统会从自己的错误中学习**。

## 4. 提示词重构方案

### 4.1 核心原则

1. **代码能算的不要让LLM算**（EMA/RSI/ATR 等已在 evidence 里给好了）
2. **LLM 应该做的是推理和判断**（因果链、叙事分析、场景推演、风险评估）
3. **约束留给代码**（RR/confidence门槛已在 `_normalize` 里强制执行）
4. **发挥推理模型优势**（CoT、深度思考、多步推理）

### 4.2 重构后的中线提示词结构

```markdown
# SwingAgent 中线波段分析

## 你是谁
你是华尔街顶级加密永续合约波段交易员，有10年实战经验。
你不追求频繁交易，而是等待高胜率的回调入场机会。
你擅长从多维度数据中提取因果链，而非机械套用指标公式。

## 当前市场快照
{{deep_context}}

## 你的任务
基于以上数据，进行**深度分析**（不是机械计算，数据已为你准备好）：

### 第一步：市场叙事识别
当前市场在交易什么故事？谁是主要推动力？（如：ETF资金流入/监管预期/
技术升级/宏观避险/风险偏好切换...）这个叙事的强度和可持续性如何？

### 第二步：资金流分析
- 聪明钱在做什么？（CVD/OI变化/大单方向）
- 散户在做什么？（费率/情绪/拥挤度）
- 两者是否背离？背离意味着什么？

### 第三步：关键价位与博弈
- 当前价格在区间什么位置？（不是机械报数字，而是分析博弈含义）
- 上方/下方的关键价位是谁在防守？如果到达会发生什么？
- 是否有止损猎杀（stop hunt）的迹象？

### 第四步：3种情景推演
| 情景 | 概率 | 触发条件 | 目标价位 | 对你的仓位影响 |
|------|------|---------|---------|--------------|
| 基准 | __% | ... | ... | ... |
| 乐观 | __% | ... | ... | ... |
| 悲观 | __% | ... | ... | ... |

### 第五步：反向假设检验
如果这笔交易亏了，最可能的3个原因是什么？
你怎么给自己的论点"找茬"？

### 第六步：历史教训
{{memory_block}}
基于上述历史经验，这次有什么特别需要注意的？

## 输出格式（JSON）
{
  "action": "...",           // buy/sell/hold
  "confidence": ...,         // 0-95
  "direction": "...",        // long/short/neutral
  "sl_pct": ...,             // 建议止损距离
  "tp_pct": ...,             // 建议止盈距离
  "risk_reward": ...,        // 自动计算
  "thesis": "...",           // 一句话核心论点
  "scenario_base": "...",    // 基准情景描述
  "scenario_bull": "...",    // 乐观情景
  "scenario_bear": "...",    // 悲观情景
  "key_risk": "...",         // 最大风险
  "cited_fact_ids": [...],   // 引用的证据
  "reasoning": "..."         // 完整推理过程
}
```

{{deep_context}}

- 当前处于牛市/熊市/震荡的哪个阶段？（积累/上涨/分配/下跌）

### 4.4 重构后的 thesis_update 提示词（MLTO核心）

```markdown
# 论点更新

## 你正在维护的交易论点
{{thesis_block}}

## 最近的市场变化
{{delta_block}}

## 历史记忆（你的过往经验）
{{memory_block}}

## 你的任务
基于最新数据，更新你的交易论点。关键问题：

1. **论点是否仍然成立？** 新数据是支持还是削弱了你的论点？
2. **确信度变化了多少？** 是加强了（+delta）还是削弱了（-delta）？幅度？
3. **是否需要调整方向？** 如果证据发生重大变化，要有勇气承认错误。
4. **论点的失效条件是否触发了？** 如果触发了，recommend_open=false。
5. **还缺什么证据？** 你需要看到什么才会更确信？

## 输出格式（JSON）
{
  "direction": "...",
  "conviction_delta": ...,      // -8到+8
  "thesis_summary": "...",      // 2-3句更新后的核心论点
  "cited_event_ids": [...],
  "missing_evidence": [...],    // 还需要什么证据
  "invalidation": {...},        // 更新后的失效条件
  "recommend_open": ...         // 是否建议开仓
}
```
