### 1.2 资金费（每日扣）——机制与本地数据

- 永续按**资金费**结算：多头付、空头收（费率为正时），**按持仓名义 × 费率**，按交易所的结算周期（币安主流为每 **8 小时**一次 = 每日 3 次；部分币种/平台为 1h/4h）。
- **数据我们已经有**：`alpha_market.perp_funding` —— **22,171,923 行 / 1,352 个币 / 2026-03-30 至今**，字段 `exchange, symbol, timestamp, funding_rate, mark_price`。
  ⇒ 结算周期与每日成本**不需要靠外部文档**，可以直接从这张表量出来（§1.3）。

### 1.3 待补的两个测量（都是只读、几分钟出结果）

1. **各所各币的结算周期**：按 `exchange+symbol` 统计相邻 `timestamp` 差值众数 → 得到"每日几次"。
2. **每日资金费成本分布**：按 `symbol` 统计 `sum(funding_rate per day)` 的分位（中位/均值/p90）。
   - 多头在费率为正时付费 ⇒ **长线（持仓数天~数周）是主要付费方**，这正好对上你说的"尤其是长线"。
3. （可选，用来校准 taker 费率）**用真实成交反算**：拿 `paper_orders` 的实际成交价 vs 同期行情，估有效费率/滑点，与 §1.1 的表对账。

### 1.4 缺失的严重性（量级估算，先给结论，待 §1.3 精确化）

用"资金费 ≈ 每日 0.03%（= 0.01%/8h × 3，牛市常见量级）"试算，名义 $456：

| 车道 | 典型持仓 | 每笔资金费 | 相对该车道单笔期望 |
|---|---|---|---|
| 短线 scalp | 分钟~小时 | ≈ $0.01~0.05 | 可忽略 |
| **中线 mid** | 数小时~2 天 | ≈ **$0.14~0.28** | 单笔期望是 **−0.15% ≈ −$0.68** ⇒ 资金费占 **20~40%** |
| **长线 long** | **数天~数周** | **$0.14/天 ⇒ 持有 30 天 ≈ $4.1 = 名义的 0.9%** | 长线 7 天合计仅 **+$39.58**（13 笔）⇒ **资金费足以吃掉它** |

**结论：模拟盘现在把这笔成本当 0，等于系统性高估了所有车道的收益，长线最严重。** 这也解释了一部分"账面小亏/小赚"与真实可执行性的差距。

## 2. 设计（三层：**算** → **记** → **显**）

### 2.1 算：资金费入账模型

```
对每个持仓 pos：
  for t in perp_funding 时间戳 where pos.opened_at < t <= (pos.closed_at or now()):
      名义_t = pos.size × perp_funding.mark_price(t, pos.symbol)
      费用_t = 名义_t × funding_rate(t) × dir        # dir: 多=+1（付费），空=−1（收费）
      累计 → pos.funding_paid / pos.funding_received
```
- **口径必须写明**：① 用结算时刻的 `mark_price` 或 `pos.mark_price`（要定一个，不能混）；② 持仓跨结算时刻才算（`opened_at < t ≤ closed_at`）；③ 未平仓仓按 `now()` 累计（"浮动资金费"）；④ 杠杆不影响资金费（按名义算）。
- **不改交易决策**：第一版只把资金费**计入盈亏与展示**，不进 `_calc_tp_sl`/闸门；等你看过账再决定是否让入场闸门（`funding_net_rr_ok`）也用它。

### 2.2 记：数据落库（**不混进手续费**）

- 新建 **`position_funding_events`**（逐笔可审计）：`position_id, account_id, symbol, exchange, funding_ts, funding_rate, mark_price, notional, amount_usd, direction, created_at`。
- `paper_positions` 增两列：**`funding_paid` / `funding_received`**（累计值，供列表/看板直接用）。
- **与 `partial_fee_paid` 严格分开**：手续费是成交成本，资金费是持仓成本，混在一起以后没法分析"到底是手贵还是拿太久"。
- 幂等：以 `(position_id, funding_ts)` 唯一约束，重跑不重复扣。

### 2.3 显：记录与显示（你明确要的）

| 位置 | 显示内容 |
|---|---|
| 持仓列表/详情 API（`/api/paper/positions*`） | `funding_paid`、`funding_received`、以及"未平仓仓的浮动资金费" |
| 车道汇总（mid / long / short 的 PnL 报表） | **净收益 = 已实现 + 资金费 − 手续费** 三列分开列，别只给一个数 |
| 平仓事件流（已有 `funding_accrued` 字段，`paper_trading_engine.py:2552`） | 沿用并补上"逐次结算明细" |
| 每日对账 | 一张"当日资金费支出 top N 持仓 + 车道合计"的表（长线是第一大户） |
| 画布/车道节点 | 车道节点上显示"本车道今日资金费"，与手续费并列 |

### 2.4 与已有代码的关系（避免重复造）

- 已有：`_funding_accrued_total()`（`paper_trading_engine.py:2552/4726` 调用）——**现在只进遥测/日志，不进盈亏**。设计上把它**升级为唯一口径**的实现，落库到 §2.2，禁止再另起一套算法。
