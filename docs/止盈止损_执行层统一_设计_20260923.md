# 止盈止损 · 执行层统一修复 设计（2026-09-23）

**用户拍板的两件事**：① 止损三层归一为"结构止损（Chandelier）+ 统一保本提升"；② 把声明的
分档止盈真正接进执行层。**性质**：改"执行"不改"参数"（8/15/25 是既有声明，只接执行不发明阈值）；
全部带开关、默认关或影子先行、每步可回滚。本文档只做设计，**不动任何代码**，等批准。

## 1. 现状盘点（代码考古结论，全部有文件/行号）

### 1.1 止损为什么是"三层"

| 层 | 落点 | 实测表现 |
|---|---|---|
| 声明层 sl_pct 2.5~3.2% | `exit_policy.py:175`（long 车道快照，写进 exit_state_json） | **从不用于止损**（chandelier 模式注释明确"价在 pos.sl_price"） |
| 初始 sl_price | 开仓路径写入 pos.sl_price | **口径不统一**：LINK 在 −3% 被扫；BTC 跌 −3.6%、XRP 跌 −11% 未被扫 ⇒ 有的仓初值=entry×(1−sl_pct)，有的=Chandelier 初始 |
| 日常上移 | `full_auto_trading_service.py:4363` → `manage_long_position` → `decide_long`（`long_tier_manager.py:242-258`） | 峰值≥2%推保本、≥3%锁1/3、Chandelier上移取高 → tighten_sl。BTC/XRP 的 SL 已在成本上方（Chandelier 上移），ETH/SOL 未动 |

已证实的两个执行缺口：
- **a. `peak_pnl_pct` 依据疑似陈旧**：4 个开仓该列读数全为 0.1，而由 `peak_unrealized_pnl`/名义
  反推的峰值价格%应为 XRP 14.2%、BTC 37.5%、ETH 6.7%、SOL 6.4% ⇒ 保本/锁利判定
  （依赖该列）对部分仓从未正确触发（09-18 曾有 ×100 单位 bug，已修过一次，需再现场验证）；
- **b. 初始 sl_price 写入点不统一**（普通开仓 / trend-v2 / E1 三条路径）。

### 1.2 止盈为什么"声明与执行脱节"

- 声明：`tp_stages=[8,15,25]%`（`lane_policy.py:231`、`exit_policy.py:175`）；
- 执行候选有三套，**没有一套在长线趋势仓上运行**：
  1. `long_tier_staged_tp.py`（D14）：已标 **DEPRECATED**（待删），开关 `RISK_USE_LONG_TIER_STAGED_TP` 默认 false；
  2. `nature_staged_tp.py` + `position_exit_orchestrator.py`：管 swing/intraday 等层，
     `position_exit_orchestrator.py:34` **明确跳过 v2 趋势仓**（防双触发）；
  3. `decide_long` 的"结构目标减半 + Chandelier 追踪"：唯一实际生效的出口，
     但它是**结构目标/回撤触发**，不是价格分档止盈。
- 结论：**8/15/25 分档确实没有任何执行层** —— 用户的判断被代码证实。

## 2. 目标设计（三个 Phase，每个都有独立开关与回滚）

### Phase 1 — 止损归一（纯口径修正，零参数改动）

- **P1.1 统一初始 sl_price**：所有长线趋势仓（含 E1 之外）开仓时
  `sl_price = Chandelier 初始值 = entry − mult×ATR(1w)`（`chandelier_long_stop` 首值，同核函数）；
  声明 sl_pct 停止参与开仓止损（字段保留，仅审计/展示）。
- **P1.2 统一上移**：只保留一个 tighten 来源 = `decide_long.tighten_sl`
  （保本 ≥2% 峰值→entry；锁利 ≥3%→entry×(1+峰值/3)；Chandelier 上移取高者），
  走已有的单调守卫 `_tighten_sl_unified`（long 只升不降）。
- **P1.3 修复峰值口径**：`peak_pnl_pct` 统一为小数（无杠杆价格%），由引擎 tick 按
  `max(现价pct, 旧值)` 更新（加仓 rebase 已有：`paper_trading_engine.py:811-829`）；
  补充单测钉死单位（扩展现有 `test_peak_pnl_pct_unit_mismatch_20260918`）。
- 开关：`LONG_SL_UNIFY`（默认 **false**）；回滚=关开关。
- 验收：修复后任取一仓，`sl_price` 轨迹 == max(Chandelier 序列, 保本/锁利线) 可逐日对账；
  `peak_pnl_pct` 与 `peak_unrealized_pnl/名义` 反推一致（±1%）。

### Phase 2 — 分档止盈执行化（开关默认关，影子先行，验证后才可转正）

- **P2.1 落点选 `decide_long`**（`long_tier_manager.py`），理由：
  ① 回测/实盘同核唯一函数（`test_long_v2_same_core` 已覆盖）；② 每日一次、只认 1d 收盘，
  符合车道"不追盘中噪声"设计；③ 与 PEO/状态机天然无双重触发（它们已跳过 v2 仓）。
- **P2.2 规则插入顺序**（在 decide_long 现有顺序中）：
  结构破坏 → Chandelier 打穿 → 极端回撤（90%全平/75%减半）→ **分档止盈（新增）** →
  早期 no_progress → 金字塔加仓 → 保本/锁利 tighten。
  - 收盘价 ≥ entry×1.08 → 减 50%（staged_tp1）+ SL 推保本（entry）；
  - ≥ entry×1.15 → 再减 25%（占原仓，即剩余的一半）；
  - ≥ entry×1.25 → 清掉剩余 25%（staged_tp3）——即 8/15/25 档 × 50/25/25 比率；
  - 幂等标记存 `exit_state_json.staged_tp_done=[1,2,3]`（与 target_halve_done 同款）；
  - 每档减仓走引擎现有分批平仓通道，并同步 tighten SL。
- **P2.3 诚实标注（重要）**：把 8/15/25 + 50/25/25 接进执行 = **上线一组未经 60 天回测
  验证过的参数**（09-23 网格结论：分档类总 Δ 正但前半/agg 不稳）。因此转正必须**影子先行**：
  - 方案 X（推荐）：先扩展 `long_exit_shadow`，逐仓记录"若执行分档，今日该减多少、SL 该到哪"，
    攒满写死标准（≥30 平仓、≥10 震荡桶、双桶 Δ 非负、双价源一致、尾部不恶化）再转正；
  - 方案 Y：直接开在 paper 账户试运行 + 每日对账（更激进，不推荐先做）。
- 开关：`LONG_STAGED_TP_EXEC`（默认 **false**）；回滚=关开关。

### Phase 3 — 观察期

- 每日对账日志：分档触发次数 / 每档减仓名义 / SL 上移轨迹 / 与影子基线逐日 diff；
- 任何一项偏离（如分档触发后 Chandelier 仍被快速打穿）即暂停并复盘。

## 3. 验收与安全（写死）

1. Phase 1 验收见上（对账 + 口径单测）；
2. Phase 2 转正门槛（沿用 09-23 已定稿的标准）：影子样本 ≥30 笔平仓、≥10 笔震荡桶、
   双桶 Δ 非负、双价源方向一致、尾部不恶化 —— 任何一条不满足 = 不转正；
3. 快照/回滚：执行前导出 paper_balances / paper_positions 快照，关开关即恢复旧行为；
4. 不做的事（防跑偏）：不改任何触发阈值与比率参数；不动 mid 的 ExitPolicy/PEO 管线；
   不动 E1 引擎（trend_e1_engine 自管 Chandelier 3×ATR20）；不删任何 DEPRECATED 模块（另立清理任务）。
