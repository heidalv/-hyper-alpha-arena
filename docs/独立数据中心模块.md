# 独立数据中心模块

> 更新：2026-08-03  
> 目标：**采集与交易主进程分离**；增强实时性；补齐数据完备性。

## 为什么要独立

| 现状问题 | 后果 |
|----------|------|
| K线/Ticker 挂在 FastAPI 进程里 | 主服务重启 / `--reload` → **采集中断** → 山寨币 K 线过期 |
| P0 只保「正在交易的热币」 | VIP 选币看板上的币靠慢速 P1 轮转 → 因子/选币读到 stale |
| 盘口/OI/资金费率多为按需拉 | 不是常驻管道，完整度不足 |

原则不变：**业务只读 `data_center`，写只由采集器打交易所。**

---

## 怎么用（现在就能用）

### 1. 单独启动数据中心

```bat
scripts\start-data-center.bat
```

或：

```powershell
powershell -File scripts\start-data-center.ps1
```

健康检查：<http://127.0.0.1:9100/health>  
日志：`logs/data-center.log`

进程内启动：

- `kline_realtime_collector`（P0/P1/P2）
- `asterdex_ticker_poller`
- `live_kline_engine`
- `depth_backfill` / `freshness_inspector`（受各自开关）
- `market_flow`（能启则启）

### 2. 主交易服务改为「只读」

在 `.env` 增加：

```env
DATA_CENTER_MODE=standalone
```

然后照常 `dev-start.bat` 启交易 API / 前端。  
主服务会**跳过**内嵌 K线/Ticker/回填，避免双写抢资源。

| `DATA_CENTER_MODE` | 含义 |
|--------------------|------|
| `embedded`（默认） | 老行为：采集跟主服务一起启 |
| `standalone` / `external` / `worker` | 主服务不采，只读独立进程写入的 Market DB |

推荐日常：**先开数据中心窗口，再开交易栈。**

## 实时性增强（已做 / 建议）

### 已做
1. **VIP/选币近 7 日候选币并入 P0 热路径**（`get_research_priority_symbols`）  
   → ADA 这类「在看板、未进会话」的币也会被分钟级刷，不再只靠 P1。
2. **因子暴露读 K 线用 `purpose=research`**  
   → 略过期仍可用，不再被 trade 门控清空。
3. **独立进程**  
   → 重启交易服务不再停采集。

### 建议调参（`.env`，可按机器加）

```env
# 全市场轮转更快（山寨新鲜度）
KLINE_P1_INTERVAL_S=40
KLINE_P1_CONCURRENCY=6
KLINE_P1_BATCH_SIZE=12

# 热路径更宽
KLINE_P0_CONCURRENCY=20
KLINE_P0_TIMEOUT_S=50

# 额外强制热币（逗号分隔）
KLINE_RESEARCH_SYMBOLS=ADA,ENA,UNI,ZEC

# 深度回填打开（历史完整性）
KLINE_DEPTH_BACKFILL_ENABLED=true
```

## 数据完备性：已有 vs 缺口

### 已有（主路径）

| 类型 | 状态 | 备注 |
|------|------|------|
| K线 1m~1w | ✅ | P0 热币分钟级；P1 全市场轮转 |
| Asterdex 全市场 ticker | ✅ | ~2s REST |
| Live forming bar | ✅ | 依赖 ticker |
| Symbol catalog / heartbeat | ✅ | 运维表 |
| Whale（定时） | △ | 120s，覆盖有限 |
| Asterdex 盘口/成交流 | ✅ | 默认 `ACTIVE_MARKET_FLOW_EXCHANGES=asterdex`（禁止默认 Hyperliquid） |

### 缺口（按优先级）

| 优先级 | 缺口 | 影响 | 建议 |
|--------|------|------|------|
| P0 | **山寨 15m/1h 刷新慢** | 选币/因子 stale | P0 并入成交额 Top100 + P1 默认所加权（已落地，见 `KLINE_P0_VOLUME_TOP` / `KLINE_P1_ACTIVE_WEIGHT`） |
| P1 | **多所 funding/OI 非常驻** | 费率套利、持仓成本盲 | 打开 multi_venue funding；OI 写正式表 |
| P1 | **Bybit 未进默认同步列表** | 读口有、写口弱 | `KLINE_SYNC_EXCHANGES` 加 bybit |
| P1 | **缺 2h/8h/12h/3d/1M 采集** | 长线研究周期不全 | 扩 `KLINE_P1_PERIODS` |
| P2 | **`oi_history` 表缺失** | 选币 SQL 风险 | 建表或改查询 |
| P2 | CoinGlass/链上深度 | 机构级 alpha | 中长期外部源 |
| P2 | 补洞默认关 | 历史空洞难自愈 | 打开 depth_backfill + quality_repair |

### 读口未实现的声明 API
`data_center.py` 文件头曾写 `get_orderbook` / `get_derivatives` / `get_snapshot`，类内尚未统一实现——盘口/衍生品仍走 Hub / aggregate / market_flow 旁路。完备化时应收口到 `data_center`。

## 目标架构（分阶段）

```text
┌─────────────────────┐     只读      ┌──────────────────────────┐
│  FastAPI 交易主服务  │ ◄────────── │  Market DB (alpha_market) │
│  Agent / 选币 / 因子 │              └────────────▲─────────────┘
└─────────────────────┘                           │ 只写
                                         ┌────────┴─────────┐
                                         │ 数据中心 Worker   │
                                         │ :9100 /health     │
                                         │ P0/P1/P2 + ticker │
                                         └────────┬─────────┘
                                                  │ REST/WS
                                         ┌────────▼─────────┐
                                         │ 各交易所          │
                                         └──────────────────┘
```

| 阶段 | 内容 | 状态 |
|------|------|------|
| **M0** | 独立 worker + `DATA_CENTER_MODE` + 选币进 P0 | ✅ |
| **M1** | `start-dev` 一键先 DC 后 API；stop 默认保留 DC | ✅ |
| **M1b** | 默认 Asterdex market_flow（可选手动加 HL）；多所 funding 常驻（DC 内默认开） | ✅ |
| **M2** | Bybit 默认同步；OI 正式表；补洞默认开 | 计划中 |
| **M3** | Ingress 队列 + 指标看板（延迟/覆盖率/空洞率） | 中长期 |

### 日常命令

```bat
dev-start.bat
:: 等价：先起数据中心(:9100) → API 以 DATA_CENTER_MODE=standalone 启动

:: 只要停交易、不停行情：
powershell -File scripts\stop-dev.ps1

:: 连数据中心一起停：
powershell -File scripts\stop-dev.ps1 -StopDataCenter
```
