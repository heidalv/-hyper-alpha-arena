## 0. 一句话结论

用户记忆中的"开仓后切换持仓分析"设计**真实存在且代码活着**（`midlong_position_manager.py` 模式 B 六维分析，docstring 与设想逐字吻合），但它今天处于三个裂口状态：

1. **long 仓空转**：模式 B 对 long 仓让位给 `long_trend_v2`（`midlong_position_manager.py:848`），而 V2 的唯一执行入口 `_run_midlong_active_exit` 被 `.env:345 MIDLONG_ACTIVE_EXIT_ENABLED=false`（2026-08-22 止血设置）关闭至今 → 长线仓实际只剩引擎硬层（SL / 4×SL 合成 TP / 爆仓 / 超时）+ Master 软退出。
2. **scalp/短线从未有持仓分析**：`scalp_loop.py:376` 明文注释"本循环不负责平仓"；开仓后有异步复审线程但 `SCALP_AI_REVERSE_DISABLED=true` 只记录不动作；持仓期间每 tick 仍做全套入场分析（浪费算力），仅在下单前跳过。
3. **真正在管仓的是规则引擎**：`paper_trading_engine` 的 3s/30s tick（统一分批止盈 + D6 盈利回撤保护 + 超时强平/AI 延长），退出侧另有 4 套分批止盈实现并行、`exit/` 状态机只有 3 个调用方、`cross_tier_arbitration.py` 全模块死代码。

本设计不新增第五套规则，而是**收口成一个 Agent 循环 + 三层决策 + 单一执行出口**，把用户设想（盈亏监视 / 补仓 / 分批止盈止损 / 回撤止盈 / 延长持仓上限）逐条映射到现有组件，并加上"理论到执行"的可行性硬门。

## 2. 成熟案例借鉴（设计依据）

### 2.1 Freqtrade `adjust_trade_position`（最成熟的开源仓位调整框架）

可借鉴的机制设计（来源：[Freqtrade Strategy Callbacks 官方文档](https://www.freqtrade.io/en/stable/strategy-callbacks/)、[issue #11078](https://github.com/freqtrade/freqtrade/issues/11078)）：

1. **单一回调、每轮调用、必须轻量**：所有加仓/减仓决策收敛到一个入口，回调里禁止重计算（重指标在别处缓存）——对应本设计"每 tick 最多一个实质动作"（模式 B 已有此约束，保留）。
2. **框架层最小名义金额拒绝**：策略只报意图（stake 数量），订单是否低于交易所 minNotional 由框架统一拒绝——对应本设计"可行性硬门在执行出口统一拦截"，而不是散在各规则里。
3. **部分平仓的量纲坑**：返回的是名义额而非币数，换算错误是最高频 bug（#11078）——本项目 `_partial_close_by_pct` 用百分比口径已规避，但**剩余量与平仓量双边的 min notional 检查缺失**（§4.4 第一优先补）。
4. **`max_entry_position_adjustment` 次数上限**：调整次数有限化，防止高频微操被手续费吃掉——对应本设计的 fee budget 门。

### 2.2 分批止盈 vs 一次性止盈的实证研究

量化回测的主流结论（[Quantified Strategies 的 Scaling Out 回测](https://www.quantifiedstrategies.com/scaling-out-trading-strategy/)、Bulkowski 在 [thepatternsite.com](http://www.thepatternsite.com/ScaleOut.html) 的系列测试）：

- **期望值口径：全平优于分批**。分批=系统性提前砍掉赢家仓位，截断右尾（正期望系统的利润主要来自右尾大赢家）。
- 分批的真实收益是**胜率提高、资金曲线平滑、回撤降低**（心理与风控收益），在"分批价靠近系统最优出场区"时损失接近中性。
- **对本项目的直接推论**：小资金（当前实盘权益量级、单仓 $10-25）下，把 $20 的仓拆成 25%/25%/30% 三档=每档 $5-7，贴着交易所 minNotional($5-10) 下限，**手续费+滑点占档位盈利比例过高，分批的数学劣势被放大**。→ scalp/短线默认**单档 TP + 追踪**；梯子只对名义额足够大的仓启用（可行性门控自动降档）。

### 2.3 趋势仓出场（Turtle / Chandelier）

本仓库已采用周线 Chandelier（`long_trend_v2.py`，`LONG_V2_CHANDELIER_ATR=2.0`）与 Turtle 式分批金字塔（0.5/0.35/0.25），方向正确，无需改动参数本身——问题是入口被关（§4.6 Phase 2）。

## 3. 设计：Post-Fill Position Agent

### 3.1 定位与原则

**定位**：成交确认后接管控仓的"专职 agent"，覆盖 short/mid/long 全 tier、paper/live 双模式。它不是新的规则引擎，而是：

- **P1 单一编排**：一个循环入口（挂靠现有 coordinator/unified loop，不新建线程），对每个 open 仓位产出"监视快照 + 本 tick 动作（至多一个）"。
- **P2 三层决策，硬规则优先**：L0 交易所端硬线 → L1 每 tick 确定性规则 → L2 低频分析复审（LLM 仅 mid/long）。
- **P3 单一执行出口**：所有动作经可行性硬门后走 `paper_engine.close_position/_partial_close_by_pct`（live 经 `LivePositionManager.close/reduce_sub_position`），带 reason_code 落 `PositionExitEvent`。
- **P4 账实分离**：本地账本（PaperPosition）是决策依据，交易所端挂单是兜底，两者通过对账（120s）与 `live_tpsl_sync` 收敛。

### 3.2 状态机（复用 exit_state_json，新增子态）

```
FILL_CONFIRMED → BASE → [BREAKEVEN] → [SCALING_OUT] → [TRAILING] → EXITED
                    ↘ EXTENDED(AI延长, 仅mid/long, ≤3×) ↙
```

- 状态存 `exit_state_json`（现有字段 `tp_level_reached/trailing_active/max_hold_ext_until` 已够用，新增 `watch_state` 枚举、`mae_pnl_pct`、`funding_accrued`、`actions_used`）。
- **分批止损明确不做**：亏损侧只有硬 SL 全平（一次性费用更低、避免"止损分批=分批确认亏损"的反 expectancy 行为；研究结论同 §2.2 对偶）。亏损侧的"分档"由 **SL 单调收紧规则**承担（现有，禁止放宽，commit e0cbcbf 已定）。

### 3.3 监视数据集（PositionWatchContext，每 tick 刷新）

|---|---|---|

| MFE/MAE | peak_pnl_pct（已有）、**mae_pnl_pct（新增）** | MAE 新字段，平仓后供因子进化闭环归因 |
| 回撤 | drawdown_from_peak = 1 − pnl/peak | 派生 |

### 3.4 决策规则（用户设想逐条落地）

**a. 分批止盈（可行性门控自动降档）**
- 档数计算：`feasible_tiers = f(notional, min_notional, fee_budget)` —— 名义 $<30 → 单档 TP+追踪；$30-100 → 2 档（40/60）；>$100 → 现有 TP1-3。
- 替换 `_run_unified_staged_tp` 内的固定 25/25/30% 为档数参数化；其余 3 套实现冻结退役（§4.6 Phase 3）。

**b. 盈利回撤止盈（周期反转判定）——统一为一个回撤阶梯，消除 4 套重叠**
- 保留 D6 `profit_drawdown_guard` 作为唯一实现，其他路径（统一块 ATR 回撤、状态机兜底、profit_manager emergency）改为向它投票或删除；参数按 tier 一张表（现有波动自适应阈值不动）。
- L2 复审可把"回撤 + regime 翻转 + 因子反向"打包成 `reversal_exit`（CRITICAL，走状态机硬事实层直通，复用 liq_magnet 模式）。

> **[2026-08-31 收口裁决]** 执行现状：未退役到 D6 唯一，三套阶梯并存（D6 / 统一块
> ATR 回撤 / profit_manager drawdown+emergency）。经审查同 tick 已有 early-return
> 串行化 + D6 15min 部分平仓冷却 + 统一块档位单调消费 + M0-10 stale-size 防护，
> 连环触发风险被结构性约束。**本设计正式承认并存方案并文档化仲裁顺序**（不再追求
> "D6 唯一"）：
>
> `_run_v2_protection` 单 tick 内固定顺序执行：
> 1. `_enforce_max_hold_timeout`（硬 SL/TP failsafe/爆仓/超时——最优先，命中即 return）
> 2. `profit_manager.get_protection_action`（仅计算，结果暂存）
> 3. D6 `profit_drawdown_guard`（L1 收紧 SL / L2 部分平仓 50% / L3 全平——命中即 return）
> 4. DSM ATR 追踪（仅收紧 SL，不平仓）
> 5. 统一块 `_run_unified_staged_tp`（TP 安全网 80% → 三档/两档/单档分批 → ATR 回撤
>    硬 4×/软 2× → TP3 后追踪；全平 return / 减仓后跳过 profit_manager stale 结果）
> 6. 应用第 2 步暂存的 profit_manager 结果（breakeven/分批锁利，M0-10 尺寸校验）
>
> 跨 tick 语义互斥：D6 部分平仓后 15min 冷却；统一块 TP 档位单调消费（档位不消费
> 仅在可行性门拦截时发生，下 tick 重试）；profit_manager 锁利档位随 progress 单调。
> 若未来要再收敛，用 `EXIT_DRAWDOWN_SINGLE_IMPL`/`RISK_V2_UNIFIED_STAGED_TP` 开关
> 逐套停用做 A/B（配 §3.7 影子遥测），而不是一次性删除。

**c. 延长持仓（有上限、有成本核算）**
- 上限维持 `复审点 × 3`（`TIER_HOLD_EXTENSION_MAX_MULT=3`），短线维持禁延长。
- 延长前提（新增硬条件）：peak ≥ 1R 且当前未破追踪线 且 regime 未翻转 且 **预计剩余持仓期 funding 成本 < 剩余浮盈的 20%**。
- scalp 超时浮盈续命 15min 机制保留（已验证的短周期特例）。

**d. 补仓**
- 逆势 DCA：维持永久禁止（产品原则，不设开关）。
- 顺势 pyramid：mid/long 保留现有 5 层门控（浮盈≥3% + 4h/1d 同向 + 敞口封顶），重新可达的前提是 Phase 2 打开长线管理入口；scalp 保留 `SCALP_ROUTER_MAX_ADDS=2` 的同向加仓但每次加仓同样过可行性硬门。

**e. 持仓期分析切换（scalp 侧补齐）**
- scalp tick 内：该 symbol 已有 open scalp 仓 → 跳过入场分析重路径（因子计算可复用给监视上下文），执行轻量 `scalp_position_review`（L1 规则 + ShortTierExit 状态机已有 breakeven/ATR 尾随/fast_cut，只需把结果从"建议"接到"执行"）。
- 这同时省掉了持仓期间白跑的 LLM/融合算力（现在每 45s 全套照跑）。

### 3.5 三层决策表

| 层 | 频率 | 内容 | 现有组件复用 |
|---|---|---|---|
| L0 交易所端 | 常驻 | 硬 TP/SL 挂单兜底（本地失联也要能止住） | `live_tpsl_sync` |
| L1 规则层 | 每 tick（3-30s） | 硬线触发、分批 TP（降档后）、回撤阶梯 D6、保本位移、超时、SL 单调收紧 | `reprice_position`/`_run_v2_protection`/`_enforce_max_hold_timeout` |
| L2 分析层 | 90min-4h | 方向延续/反转叙事、TP/SL 调整提案、延长持仓提案、pyramid 提案；LLM 仅 mid/long，输出必须过 L1 保护层（min_hold/微利禁减/冷却） | 模式 B 六维、`trend_agent.review_position`、`hold_timeout_trend_review` |

仲裁沿用 `unified_exit_state_machine.submit()` 四层（硬事实→保护→动态→AI），**不需要新状态机**；把 L1 中绕过状态机的直调路径（硬线全平）显式补登 `ExitSource.TAKE_PROFIT/STOP_LOSS` 事件，消除"枚举定义了没人用"的账实分离。

### 3.6 可行性硬门（FeasibilityGate，执行出口统一拦截）

每个动作（reduce/add/改单）发出前依次过：

1. **minNotional 双边检查**：平仓份额 ≥ 交易所最小名义，且平后剩余份额 ≥ 最小名义（否则合并为全平或放弃该次 reduce）。来源：`risk_engine.py:237` 已有单边检查，扩展到部分平仓路径（`_partial_close_by_pct` 当前**没有**该检查——已核实）。
2. **qty step 取整后 ≥ minQty**（live 下单前）。
3. **fee budget**：本仓累计费用（开+平+分批+改单）已超目标的 x%（scalp 建议 15%）→ 禁再触发微操档。
4. **限频**：单仓每 tick 最多 1 个实质动作（现有约束全局化）；改 SL 频率 ≤ 1 次/N tick，防与交易所挂单同步风暴。
5. **funding 窗口**：临近结算(<10min)且 funding 显著逆向 → 只允许收紧方向的动作。
6. **冷却**：reduce 冷却（现有 30min/1h/2h）与加仓冷却统一进 gate。

### 3.7 遥测与闭环

- 每次动作落 `PositionExitEvent`（已有表），扩展：`mae_pnl_pct`、`funding_accrued`、`decision_snapshot`（当 tick 的监视上下文 JSON）。
- 平仓后把 (MFE, MAE, 回撤路径, 各规则触发史) 喂给 `DecisionRetrospective` → `ai_factor_discovery_service` 已有的"亏损归因生成因子"闭环（现状它只拿到 exit_reason，加 MAE/MFE 后能区分"止损太紧"vs"方向错"）。
- **[2026-08-31 落地]** 影子遥测（无 A/B 直接全开的补位）：
  - `postfill_telemetry_staged_tp_cf`：单档/两档 TP 触发时记录旧三档
    实现"若执行"的比例（legacy_close_pct=0.25）与实际动作，供假设 PnL 对比右尾截断。
  - `postfill_telemetry_extend_rejected/extend_granted`：延长持仓硬条件的拒绝/放行
    成对事件，供统计通过率与"若放行"的假设 PnL。
  - `POSTFILL_OBSERVE_ONLY=true`（默认 false）：scalp 持仓复审进入只记不执行模式，
    决策落 `postfill_observe_only_decision` 事件——未来任何规则调整可先开此开关
    跑一周影子对照再全开。
- A/B 评估开关：Agent 动作先 `observe_only` 模式跑一周（只记不执行），对比"若执行"的假设 PnL，再放开执行——这是对"理论漂亮执行拉胯"风险的直接对冲。
