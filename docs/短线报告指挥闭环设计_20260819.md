# 短线报告指挥闭环设计（2026-08-19）

## 一、背景：深度检查发现的三项问题

| # | 问题 | 证据 |
|---|---|---|
| P1 | 37% 退出是「持有超时」（max_hold_timeout 303/814 次），TP/SL 距离偏宽 | 近 7 天 537 笔短线平仓，退出分布 max_hold_timeout 303 / symbol_removed 141 / tp 128 / breakeven 55 / sl 50 |
| P2 | 盈亏高度集中：6 个币持续失血（GPS -5.94/BNB -5.81/LIT -5.67/ASTER -4.76/VIRTUAL -4.51/ETH -4.18），CYS 一笔 +20.86 贡献大头 | loss_attribution by_symbol |
| P3 | PnL 记账口径混乱：partial_realized_pnl 大多为 0（仅部分平仓才写），全平盈亏须靠价差估算 | 537 笔中 partial 几乎全 0 |

**P1 的根因（新增发现）**：网格训练已产出 learned TP/SL（short: tp=2.5% / sl=0.8%，rr≈3.1），且 RISK_USE_LEARNED_TP_SL=true，但 learned 覆盖只接了 tp_sl_prices.py 一条路径；**ScalpMR（scalp_ranging_mr）均值回归信号路径不读 learned**，自己算 rr=1.0 的 ±1.22%——宽 TP/SL 导致大量仓位磨到超时。

## 二、核心架构：报告指挥层（report_directives）

日报/周报生成时，除展示数据外，额外产出一组「指挥指令」（directives）——每条指令 = 触发条件 + 目标 + 执行钩子。指挥层只做「判定与触发」，执行全部复用已有钩子（不新造执行器）：

```
period_daily_report / period_weekly_report（已有）
      │ 分析段（loss_attribution + 新增 metrics）
      ▼
report_directives.analyze(report) → directives[]
      │
      ├─ D1 超时治理：max_hold_timeout 占比 > 35% → 触发 tp_sl_grid_trainer 重训 + ScalpMR 接线 learned
      ├─ D2 亏损币治理：某币连续 2 天亏损且笔数≥5 → 币级降权（factor_runtime_weights）→ 回测验证 → 拉黑/恢复
      ├─ D3 PnL 口径统一：日报/周报/归因全部改用「价差+partial」权威口径
      └─ D4 因子治理（预留）：周报 ICIR 衰减 → decay_trigger 补挖（已有）
```

指令落库 period_daily_reports.payload_json.directives（前端可观测「日报指挥了什么」），执行结果回写 action_taken 字段——闭环可审计。

## 三、三项治理方案

### D1 超时治理（修 P1）
1. **接线**：scalp_ranging_mr 的 tp/sl 计算改读 learned（复用 tp_sl_prices 同款 get_learned_pct，band=mr），learned 缺失时回退现有 rr=1.0 口径；
2. **监控**：日报 metrics 增加 max_hold_timeout 占比与平均持有分钟；
3. **指挥**：周报若超时占比仍 > 35% → directive 触发 tp_sl_grid_trainer 重训（缩短网格回看窗口，聚焦近 30 天）；
4. **验收**：接线后观察 7 天超时占比下降；单测覆盖 learned 覆盖/回退。

### D2 亏损币治理（修 P2）
1. **判定**：loss_attribution 已有 by_symbol；directive 触发条件 = 连续 2 天该币净亏 且 累计≥5 笔；
2. **动作**：该币在 factor_runtime_weights 增加 symbol_penalty（0.5 系数，半仓信号强度）→ 回测验证该币近期因子有效性（backtest_event_trigger.on_param_change）；
3. **升级**：连续 5 天仍亏 → 加入 short_tier 观察名单（短期禁开该币，人工/自动复审）；
4. **恢复**：回测达标或 3 天转盈 → 自动解除 penalty；
5. **验收**：单测覆盖触发/降权/恢复全状态机。

### D3 PnL 口径统一（修 P3）
1. 新模块 pnl_authority.py：统一函数 realized_pnl(position) = partial_realized_pnl（>0 时）+ 价差×(size 剩余)；
2. 日报/周报/loss_attribution 全部改用该函数（此前 loss_attribution 用 PaperOrder.pnl，部分路径为 0）；
3. **验收**：单测——partial=0 的仓位用价差口径复原；日报数字与 537 笔价差估算对齐。

## 四、执行计划

| 步 | 内容 | 验收 |
|---|---|---|
| 1 | D3 pnl_authority.py + 报告/归因切换 | 单测 + 日报数字对齐 |
| 2 | D1 ScalpMR 接线 learned + 日报超时指标 | 单测 + 接线生效 |
| 3 | D2 亏损币状态机 + factor_runtime_weights 接线 | 单测全状态机 |
| 4 | report_directives.py 指挥层 + 日报/周报产出 directives | 单测 + 前端可观测 |
| 5 | 回归 + 提交 + 重启 | 全绿 |

## 五、边界
- 指挥层只触发、不自动改实盘参数——参数变更一律走 shadow 审批 + 回测验证（与现有 promotion/calibration 纪律一致）；
- 不改短线信号/门禁逻辑本身，只治理出场参数与亏损币；
- 全部动作写入 directives 审计字段，可观测可回滚。
