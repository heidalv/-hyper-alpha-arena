## 二、IC评估器BUG（新发现）

### 2.1 IC=1.0 是假象

| 因子 | DB存储IC | DB存储IC标准差 | 手动重算IC(513条) |
|---|---|---|---|
| ai_gen_trend_rev | 1.0000 | 0.0000 | **0.1205** |
| ai_gen_vsp | 1.0000 | 0.0000 | （同样bug） |

### 2.2 Bug根因

`factor_ic_evaluator.py:155` 的 IC 计算逻辑：
```python
ic = _pearson([d for d, _ in pairs], [p for _, p in pairs])
```

每次评估调用 `run_factor_ic_evaluation` 时，只取最近一次 `SignalTradeFeedback` 的数据（不是全部历史）。如果这批只有3-5个样本且方向碰巧全对，IC=1.0。

### 2.3 真实IC vs 存储IC

用全部513条样本重新计算：
- ai_gen_trend_rev: 存储IC=1.0，**真实IC=0.12**
- direction均值=-0.0265（几乎全是微负值），long_equiv均值=-0.30
- 这说明因子方向和PnL只有弱正相关，不是IC=1.0

**影响：35个"IC>0.3的有效因子"中，IC=1.0的2个（trend_rev/vsp）是bug假象。其余因子IC也可能偏高（因为每次只算一小批样本）。**

## 四、IC最高 vs 最低因子公式对比

### 4.1 IC最高因子

**ai_gen_dust_squeeze (IC=0.99, 样本172, IC标准差0.35)** — 缩量窄幅后突破
```python
vol_ratio = data['volume'] / data['volume'].rolling(20).mean()  # 量比（周期20）
range5 = (high.rolling(5).max() - low.rolling(5).min()) / close.rolling(5).mean()
ma5 = close.rolling(5).mean()
```
- **加密原生数据：否**（纯OHLCV量价分析）
- **但这个因子IC标准差=0.35（不是0），说明IC有波动，是真实的**

**ai_gen_trend_rev (IC=1.0, 样本508, IC标准差0.0)** — 趋势反转概率
```python
# 因子值范围：-0.12 ~ 0.003，几乎全是微负值
# direction = tanh(raw) → 几乎全是-0.01~-0.12
```
- **IC=1.0 标准差=0 是bug**——手动重算IC=0.12
- **根因：因子输出值集中在-0.01~-0.12，tanh映射后几乎全负，与PnL碰巧在小样本上完美相关**

### 4.2 IC最低因子

**ai_gen_vdp (IC=-1.0)** — 放量下跌信号
```python
condition = (ret < -0.01) & (vol_change > 0.1)  # 价格跌1%+量增10%
signal = -condition.astype(float) * 1.0  # 给负信号
```
**为什么在加密反向**：
- 股市逻辑：放量下跌=机构出货→看空→给负信号
- 加密实际：放量下跌=清算瀑布→价格被压低后反弹→负信号变成反向
- 学术依据：日强平占持仓多头3.51%、空头1.89%（2102.04591），清算瀑布在加密是系统性事件

**ai_gen_extreme_rev (IC=-0.98)** — 布林带(20,2)+RSI(14)反转
```python
ma = close.rolling(20).mean()  # 周期20
std_mult = 2.0  # 2σ
rsi_period = 14  # 周期14
```
**为什么在加密反向**：
- BB(20,2)在股市=95%置信区间（正态分布假设）
- 加密收益服从重尾分布（GARCH+t分布，1909.04903），2σ只覆盖~85%→频繁假突破
- RSI(14)在5m上=70分钟，加密超买超卖阈值需要更短周期

**ai_gen_whale_cleanup (IC=-1.0)** — VWAP偏离+量比
```python
vwap = (typical_price * volume).rolling(20).sum() / volume.rolling(20).sum()
```
**为什么在加密反向**：
- 股市VWAP是机构成本基准（有明确开盘/收盘）
- 加密24/7无收盘，rolling(20)的VWAP窗口不固定，语义模糊
- 加密市场VWAP行为与股市不同（无隔夜缺口，24h连续定价）

## 五、4个核心断点

### 断点1：994个AI因子无验证直接上线

**现状**：`factor_loader.py` 扫描目录 → 逐文件import → `register_factor()` → `_merge_registry()` → scalp_loop每轮计算全部因子

**问题**：
- 1021个因子100%是LLM用传统金融知识生成的
- 99%是RSI/MACD/BB/ATR传统指标变体
- 0个使用资金费率/CVD/OFI/链上数据
- 38%的IC为负（方向相反）
- **从生成到上线没有任何验证环节**

### 断点2：挖掘器空壳

- `alpha_miner.py:207` mine_random() — 随机AST，0命中
- `alpha_miner.py:298` generate_and_audit() — LLM占位，`_has_llm=False`
- `factor_discovery.py` / `ai_factor_discovery_service.py` — 有代码但从未被调度

### 断点3：影子期从未运行

- ShadowJudge状态机完整
- 但 `paper_sharpe` 是 ICIR×√252 代理值（非真实模拟）
- `live_deviation` 依赖未接入的 DualTrackExecutor
- `factor_active_set` 的 state 全是 ACTIVE（没有 PAPER/SMALL_LIVE）

### 断点4：IC评估器有bug

- **新发现**：IC=1.0的因子（trend_rev/vsp）是因为每次评估只取一小批样本
- 用全部513条样本重算，真实IC=0.12（不是1.0）
- **IC评估方法本身（事后归因IC）也有问题**：
  - 只记录开仓时的因子值（有幸存者偏差）
  - 不是forward returns IC（事前预测力）
  - IC=Pearson(方向, PnL) 而非 Rank IC

## 六、参数根源分析

### 6.1 为什么是周期14和20

| 参数 | 发明者 | 发明时间 | 原始用途 | 被LLM套用情况 |
|---|---|---|---|---|
| RSI(14) | J. Welles Wilder Jr. | 1978年《New Concepts in Technical Trading Systems》 | 股市日线超买超卖 | LLM直接使用411次 |
| BB(20,2) | John Bollinger | 1980年代 | 股市月线标准差通道 | LLM直接使用822次 |
| ATR(14) | J. Welles Wilder Jr. | 1978年 | 股市日线真实波幅 | LLM直接使用 |
| MACD(12,26,9) | Gerald Appel | 1970年代 | 股市日线快慢EMA交叉 | LLM直接使用 |
| EMA(9,21,50) | 传统 | — | 股市日线三线系统 | LLM直接使用 |

**根因：LLM的训练数据里这些是"因子"的默认值，LLM生成因子时直接套用——没有考虑加密5m K线的周期特性。**

### 6.2 传统指标在加密市场失效的学术依据

| 传统指标 | 股市逻辑 | 加密市场实际行为 | 学术文献 |
|---|---|---|---|
| RSI(14)>70=超买 | 股市均值回归 | 加密高波动下RSI可长期>80不回调 | Hurst 0.42→0.49(2402.11930) |
| 放量下跌=看空 | 机构出货 | 清算瀑布→底部反弹 | 日强平3.51%(2102.04591) |
| BB(20,2)=95%置信 | 正态分布 | 重尾分布，2σ只覆盖~85% | GARCH+t(1909.04903) |
| VWAP偏离 | 机构成本基准 | 24/7无收盘，VWAP窗口模糊 | 加密无隔夜缺口 |
| 周期14 | 日线14天=2周 | 5m×14=70min≠日内节律 | 5m/1H自相关显著但周期不同(2003.13517) |
