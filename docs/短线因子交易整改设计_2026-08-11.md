# 短线因子交易整改设计（2026-08-11）

> 前置文档：`短线因子交易深度评估报告_2026-08-11.md`（结论）、`短线因子全链路调查报告_2026-08-11.md`（链路与断点）
> 状态：设计稿。本文只给设计与落地顺序，不改代码；确认后再按执行计划逐步实施。

---

## 0. 设计原则（先立规矩）

1. **模拟盘是唯一主战场**：所有改动先在纸盘/影子验证，不碰实盘逻辑，不新增任何实盘入口。
2. **先证明边缘，再放量**：没有统计上可验证、成本后为正的信号之前，优先收缩无谓交易，而不是加因子、加门控、加杠杆。
3. **复用已有设施**：WFO、DSR/PBO、backtest_engine、purge/lifecycle 均已存在，只把它们接成短线硬门禁，不造第三套轮子。
4. **与中长线隔离**：短线改动只走 `s5m_*`/`scalp_*` 命名空间；共享层（FactorEngine、promotion gate）只加开关，不改默认行为。
5. **可回滚是硬要求**：每个行为改动必须有 env 开关或 feature flag；默认值保持与现状一致，直到证据支持翻转。

---

## 1. 整改总目标与成功定义

总目标：在 90 天内，把「能成交但没有可验证正期望」变成「有可复现、成本后为正、防过拟合门禁通过的信号集合」，或者在诚实评估后主动下线/收缩短线车道。

成功定义（全部满足才算达标）：

- 独立回测与纸盘结果一致（parity_score ≥ 阈值，见评估计划），而不是只看回测好看。
- 分数分桶单调性显著（Spearman p<0.05）或分层组合净收益转正，≥60 桶不再是最差桶。
- 成本后每笔期望为正，且随机基准检验 p<0.05。
- Meta OOS AUC ≥ 0.55 且 top30% 过滤净收益转正（暂定，见评估计划）。
- 选币高分币在短线因子上的历史命中率不再系统性垫底。

## 2. 现状根因（只留决策所需）

| 根因 | 证据 | 本次设计对应 |
|---|---|---|
| 因子分不是排序变量 | 5 个分数桶净收益全负，≥60 桶（占 68%）最差 | Phase 2 打分重构 |
| 无独立回测/诚实成本 | 只有实跑日志与因子级回测，没有策略级 WFO | Phase 1 验证设施 |
| 数据积累不足 | 5m 历史仅约 7–10 天，无法支撑高频验证 | Phase 1 回填 |
| 学习闭环断裂 | Meta usable=false 且未接入；974 权重近等权 | Phase 2/4 |
| 执行与标签错配 | 平均持仓 2.16h，但按 5m 剥头皮设计与评估 | Phase 3 持仓/标签对齐 |
| 选币×因子断裂 | AAVE/KAITO/ZEC 为短线亏损重灾户 | Phase 2.4 联动仪表 |

## 3. 分阶段整改设计

### Phase 0：基线固化与止血（第 1 周）

目标：冻结交易逻辑，建立可对比的基线，找出数据/成本审计缺口。

#### 0.1 冻结并记录基线

- 将当前 `.env` 中所有 `SCALP_*`、`FEATURE_FACTOR_LABELS_ENABLED`、`SCALP_META_*` 关键开关导出为 `config/scalp_env_baseline_2026-08-11.json`。
- 之后任何改动必须记录「改前/改后」对照，禁止静默改阈值。

#### 0.2 每日策略体检（新增只读任务）

新增调度任务 `scalp_daily_health`（挂在 `backend/main.py` 调度区，日级），输出 JSON + Markdown 到 `reports/scalp_daily/`：

- 信号量、已结算量、胜率、平均净收益、成本占比；
- 分数分桶表 + 桶间单调性检验（Spearman/Kendall）；
- 平仓原因归因、符号归因、小时段归因、regime 归因；
- 权重分布（分位数、>1.0 数量、Gini/有效因子数）；
- meta 报告摘要、数据陈旧度、链路延迟。

验收：连续 7 天出报告；报告字段与评估计划口径一致。

#### 0.3 成本模型审计

- 审计 `fee_guard.calc_slippage_rate` 假设 vs 纸盘实际成交价差（place 价 vs fill 价 vs 同时刻 mark）。
- 输出 `scripts/audit_scalp_cost.py`：taker fee、滑点 bps、funding 实际扣费、极端滑点分位数。
- 目标：得到「悲观成本」参数（如 P95 滑点 ×1.5），供 Phase 1 回测使用。

#### 0.4 链路健康巡检

- 新增 `scalp_chain_health` 巡检：K 线新鲜度、信号→结算延迟、calibrator/meta 是否按时产出、signal_log 是否丢段、队列是否堆积。
- 告警进日志与前端，但不改变交易行为。

---

### Phase 1：验证基础设施（第 2–4 周，最关键）

#### 1.1 短线策略级独立回测

新增 `backend/services/scalp/scalp_strategy_backtest.py`，复用 `backtest_engine`、`walk_forward.py`、`overfitting_metrics.py`。

必须包含：

- 数据：`alpha_market.crypto_klines` 5m/15m，先短窗口跑通，随回填扩展；
- 结算双口径：① 固定前瞻窗口（与现 signal_log 口径一致）；② 三重障碍 SL/TP/max_hold（与纸盘一致）；
- 成本模型：taker fee + 悲观滑点（参数化，默认取 0.3 审计出的 P95×1.5）+ funding；
- 输出：IC/RankIC/ICIR、分层组合净收益、PF、最大回撤、随机基准 z-score、PBO、DSR、MinTRL；
- 结果落 `scalp_backtest_run` 表（JSONB）供对照。

#### 1.2 5m 数据回填与完整性

- 扩展 `kline_backfill_manager` / `backfill_full_history.py`：支持 5m 多币、分批、限流、断点续传（复用 `KlineCollectionTask`）。
- 目标：30 天 → 90 天 → 365 天；覆盖 auto_coin 候选集（20–30 个币）+ 流动性主币。
- 订单流/盘口历史若交易所不提供：**不虚构、不占位**，回测中显式剔除无历史因子，并在报告中标注覆盖率。
- 每日 `data_quality_report`：缺孔率、重复率、时间戳对齐、涨跌停异常。

#### 1.3 随机基准与防过拟合门禁（硬门）

- 随机信号基准：同频率、同方向的 permutation test（≥200 次），输出 p-value；
- 标签 shuffle 基准：meta/因子 IC 的随机标签分布；
- 门禁（任何因子/权重/阈值变更必须通过）：
  1. OOS 净收益 > 0 且覆盖悲观成本；
  2. 随机基准 p<0.05（或 |t|>2）；
  3. PBO<0.1（robust）或 DSR>0.95；
  4. 分数分桶单调或分层组合转正；
  5. 回测-纸盘 parity 达标（见评估计划）。

---

### Phase 2：信号重建（第 4–6 周）

#### 2.1 打分体系重构

- 把 `score=|direction|×100` 改为「校准后的期望排序」：`calibrated_p_win × 净收益期望`，至少在分桶上单调。
- 短期止血：在证据出来前，可对 ≥60 桶（占 68% 且最差）先降频/降权，但必须走开关（如 `SCALP_HIGH_SCORE_TRIAGE=0|1`），并单变量对比。

#### 2.2 因子集精简与权重收敛

- 审计 `scalp_active_factor_set`（18 条）与 `factor_runtime_weights.json`（974 条）是否同源；若 pipeline 实际读 974 条，则统一为「active set 才是交易输入」。
- 权重改为稀疏收敛：低 IC 因子淘汰、冗余去重；新增「有效因子数 / Gini 系数」指标，目标不再是权重数量。
- 月检：权重 >1.0 的因子必须有可复现证据，否则回落到 1.0。

#### 2.3 标签与实盘结算对齐

- 纸盘开启 `FEATURE_FACTOR_LABELS_ENABLED=true`（仅影响 5m 进化，4h 不变），使挖矿标签与 SL/TP/超时结算一致。
- Meta 训练目标并列输出：固定前瞻 vs 三重障碍，usable 判定只认与纸盘一致的口径。
- `predict_win_prob` 强制检查 `usable`：usable=false 一律返回 None，不参与 EV。

#### 2.4 选币 × 因子联动（同步分析，非本轮重点）

- 新增 `symbol_scalp_profile` 表：每 symbol 近 7/30 天的因子 IC、命中率、每笔期望（PPE）、流动性覆盖、数据覆盖。
- auto_coin 打分输出追加「短线可交易性」字段，默认只展示、不参与选币分数（Phase 3 再评审是否加权）。
- 对 AAVE/KAITO/ZEC 建立观察名单：短线因子命中率低于阈值时告警，并联动 AI 选币 agent 的上下文（不改其默认行为）。

---

### Phase 3：决策与执行优化（第 6–8 周）

#### 3.1 EV 门槛实证化

- `SCALP_EV_MIN_PCT` 当前默认 0.0（即不拦）。改为由 Phase 1 回测/纸盘影子给出候选值（0.05%–0.15%），分档放量：
  - 影子日志先记录「若按新门槛会拒掉哪些单」；
  - 2 周对照后按评估计划决定是否切换。

#### 3.2 Master 干预规则审计

- `master_running_reduce`（164 笔 −22.39）与 `master_running_close`（71 笔 −9.65）合计 −32.04，是第二大亏损源。
- 第一步只审计：记录每次干预时的信号、仓位、干预方向、后续走势，形成 `master_intervention_review` 周报。
- 第二步才改规则：任何干预规则改动单独过 Phase 1.3 门禁，不与因子改动混在一起。

#### 3.3 持仓时长与策略标签对齐

- 平均持仓 2.16h 与「5m/15m 剥头皮」标签错配。二选一并写进策略规格：
  a) 缩短 `max_hold_timeout` 并回测 5m 目标；或
  b) 改标「短波段（2–4h）」并按该周期评估胜率/成本/资金费率。
- 评估计划中的标签、结算口径随之统一。

#### 3.4 降频止血（可回滚）

- 目标：在信号未证明有效前，减少高成本、低质量交易。候选动作（每项独立开关）：
  - 提高 `SCALP_EV_MIN_PCT`；
  - 对 ≥60 桶做 triage（见 2.1）；
  - 收紧 `SCALP_MAX_OPENS_PER_TICK` 或冷却时间；
  - 对每笔期望为负的符号（如 AAVE/KAITO/ZEC 观察名单）降频。
- 所有候选必须进入 `scalp_experiment_log`，单变量 A/B，禁止一次改多个。

---

### Phase 4：学习闭环（第 8–12 周，持续）

#### 4.1 Meta 接入决策（分三步）

1. 影子：`SCALP_META_IN_EV=0` 但 `predict_win_prob` 结果写 signal_log/审计（Phase 0 已做）；
2. 软进：usable=true 且连续 2 周影子对照达标后，`SCALP_META_IN_EV=1`，`p_win = blend(calibrator, meta)`；
3. 硬过滤：软进后再 2 周达标，才开 `SCALP_META_HARD_FILTER=1`。

#### 4.2 因子归因 → ActiveSet prune

- 结算后按 `top_factors` 日聚胜率/PPE，尾部 10% 连续 7 天不达标 → 进入淘汰候选。
- 淘汰必须走现有 purge/lifecycle，不新开第三套权重。

#### 4.3 进化晋升门禁

- 所有新 `s5m_*` 因子必须过 Phase 1.3 五道门禁；
- 挖矿目标切换为三重障碍 + 净成本后的期望；
- 晋升报告输出必须含随机基准 p-value 与 parity_score，缺任一字段不允许进入 active set。

## 5. 数据模型变更

新增（全部 PG，D 盘库）：

- `scalp_daily_health`（JSONB）：每日体检快照，保留 90 天；
- `scalp_backtest_run`（JSONB）：每次策略回测的配置、结果、随机基准、PBO/DSR、parity；
- `symbol_scalp_profile`：每 symbol 的短线因子 IC/命中率/PPE/覆盖；
- `scalp_experiment_log`：每次行为改动的开关、时间窗、改前/改后指标；
- `master_intervention_review`：Master 干预审计（Phase 3.2）。

已有表不动结构，只核对字段：

- `scalp_signals`：entry_reason/exit_reason/cost_bps/slippage_bps/hold_minutes/top_factors；
- `paper_positions`：close_reason（已 VARCHAR(100)）、realized_pnl；
- `factor_runtime_weights.json`：只读，不改格式。

## 6. 与 AI 策略 / AI 选币 agent 的联动接口（非重点，但同步设计）

- 所有联动默认**只读展示**：`symbol_scalp_profile`、选币可交易性字段、观察名单告警。
- AI 选币 agent 的 prompt 上下文增加「短线因子历史命中率」摘要，但禁止让 LLM 直接改交易参数。
- AI 策略 agent 的复盘报告自动引用 `scalp_daily_health` 与 `scalp_backtest_run`，减少人工复制。
- 任何 agent 发起的参数改动必须写 `scalp_experiment_log`，否则审计视为无效。

---

## 7. 不做清单（防范围蔓延）

- 不接实盘，不加实盘入口；
- 不动中长线（4h/midlong）共享层默认行为；
- 在 Phase 1 门禁建立前，不扩大因子池、不加新门控层；
- 不用 LLM 做高频主信号，只保留 FlashVeto 边缘裁决；
- 不造第三套权重/回测/标签系统；
- 不把「回测好看」当上线依据，必须与纸盘 parity 对齐。

## 8. 风险与依赖

| 风险 | 影响 | 缓解 |
|---|---|---|
| 5m 历史数据交易所不支持 | 回测窗口不足 | 先回填可得窗口，缩小因子集，标注覆盖率 |
| 回测-纸盘差异 | 假阳性/假阴性 | parity_score 强制审计；成本用悲观参数 |
| 因子半衰期短 | 90 天验证仍不够 | 滚动评估 + 每月重估 |
| 多改动互相干扰 | 归因失败 | 单变量实验 + `scalp_experiment_log` |
| 回填限流/被交易所封禁 | 数据中断 | 分批 6h + 退避 + 断点续传 |
| 共享层被误改 | 中长线漂移 | 只加开关；CI 校验 midlong 相关测试 |
