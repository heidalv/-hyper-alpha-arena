# 短线 + 中线修复升级设计（对齐 2026-08-19 现码）

> 日期：2026-08-20  
> 配套审查：`docs/短线中线合并审查报告_20260820.md`  
> 范围：**设计方案**，本文件不改交易代码。实施时按优先级改，每项必须有可复现验收。  
> 原则：**以现码为准**；配置写「代码默认」或「某日事实清单曾登记」；绩效数字只标报告日期。

---

## 1. 目标与非目标

### 1.1 目标

1. 短线：信号不再被「涨跌幅补 0」污染；时段缩仓不被 FlashVeto 抹掉；预算/冷却用真实 `mode`。
2. 中线：因子路由开的仓不再被 LLM 碎平；中/长互锁改为同 nature；因子计算与成交同所。
3. 总控：短线禁新开时，减仓/平仓也不再误伤短线仓。
4. 证据：改完后按同一脚本重跑日检/周报，和 8/16、8/17 那几份对比，不拿旧数字当现状。

### 1.2 非目标

- 不把 8 月中旬「中长线架构文档」里的 SwingAgent 当现行方案。
- 不默认「打开因子路由」或「打开 EV 闸」——仓库没有当前 `.env`。改开关是运维决策。
- 本阶段不重做因子库、不换 LLM 模型、不加新策略品种。
- 不把 `test_swing_deprecated.py` 的失败当生产故障；另开测试债单。

### 1.3 总原则

| 原则 | 含义 |
|------|------|
| 入出场同源 | 谁开的仓，谁定平仓规则；禁止跨引擎碎平 |
| 配置诚实 | 代码默认写代码默认；线上值只写事实清单日期 |
| 失败收紧 | 闸门/仲裁/预算异常时倾向 skip，不 fail-open |
| 先止血再优化 | P0 不依赖回测；P1 改仓位公式；P2 才动证据与校准 |

## 3. 短线改造

### 3.1 P0-S1 涨跌幅补数

**现状**：`scalp_loop.py` 约 325–339 行。`_md["klines"]` 前面已经收成 `DataFrame`（约 237 行），补涨跌却写成 `_klines[-1].get("close")`——对 DataFrame 这是取列名 `-1`，不是最后一根。异常被 `except: pass` 吃掉。触发条件是 `float(price_change_1h_pct or 0) <= 0`（24h 同理），**真下跌也会走进这段补数**。

**改法**：

```python
# 伪代码
def _missing_pct(v) -> bool:
    return v is None or (isinstance(v, float) and math.isnan(v))

# 只用 iloc[-1] / iloc[-12] 取最后一根，不要 df[-1]
if _missing_pct(_md.get("price_change_1h_pct")):
    _md["price_change_1h_pct"] = _change_from_df(_md["klines"], bars=12)
# 24h 同理（288 根 5m）；0 和负数都保留，不重算
```

**验收**：

- 单测：`price_change_1h_pct=-1.5` 时补数函数不改写。
- 单测：字段缺失且 DataFrame 有足够行时，用 `iloc[-1]` / `iloc[-12]` 算出有符号涨跌。
- 单测：`df[-1]` 这种列访问不再出现。

**不要**：把阈值改成 `< 0`（仍会丢掉横盘 0）。只判断缺失。

### 3.2 P0-S2 FlashVeto 不再抹掉缩仓

**现状**：约 665 行 `_size_mult = _liquidity_mult`（周末 ×0.5，UTC 22–00 再 ×0.7）。FlashVeto 未否决时约 727 行写成：

`_size_mult = _veto.size_multiplier if _veto.verdict == "downsize" else 1.0`

`pass` 会把周末/薄时段缩仓抹成 1.0。

**改法**：改为 `_size_mult *= (_veto.size_multiplier if _veto.verdict == "downsize" else 1.0)`。否决拦截逻辑保留。不要默认「通过 = 恢复满仓」。

**验收**：周末且否决通过时，`size_mult` 仍为 0.5（若同时薄时段则为 0.35），不是 1.0。

---

### 3.3 P0-S3 / S4 预算与冷却使用真实 mode

**现状**：`scalp_loop.py` 约 995–1006 行 `budget_service.scale_factor_for_layer(..., "paper")` 和 `can_open(..., "paper")` 写死。`apply_short_tier_gate` 不接收 `mode`；底层 `check_short_tier_entry` 默认 `mode="paper"`，live 会走 paper 冷却。

**改法**：

- 两处预算调用传入本轮真实 `mode`（会话 `trading_mode`）。
- `apply_short_tier_gate` 增加 `mode` 并传给 `check_short_tier_entry`。
- 单测：`mode=live` 时冷却键 / 日限额与 paper 互不影响。

**验收**：同一策略在 paper 超限后，live 仍按 live 日限额判断（或反过来互不影响）。

---

### 3.4 P0-S8 总控对短线只禁新开，且减仓也跳过

**现状**：`backend/services/full_auto/master_execution.py` 约 551–573 行。`SCALP_MASTER_HARD_BLOCK` 只对 `buy/sell/pyramid/dca` 做 `continue`。紧接着注释写「scalp 未被独立交易的也跳过」，**没有 `continue`**。`close`/`reduce` 继续往下走。减仓对 `tier==short` 另有「浮亏 < 20% 不准减」（约 2362–2375 行），浮亏够大仍会 `master_running_reduce`。

**改法**（三选一，推荐 A）：

- **A（推荐）**：`not _allow_new and _is_scalp` 时，**open / close / reduce 全部 `continue`**，与注释一致。总控只动中长线去杠杆。
- **B**：open 跳过；close/reduce 仅当 `nature in (swing, long)` 才执行。
- **C**：保留减仓，但 short 的 20% 门槛改为「仅 mid/long」，短线减仓直接跳过。

**验收**：

- 单测：禁开窗口构造一条 `side=close, nature=scalp` 的 intent，执行后订单数不变。
- 对照：8/16 日检里的 `master_running_close` / `master_running_reduce` 在同类窗口不应再出现（改完后的新日检）。

**不要**：为了对冲总控，去放宽短线 EV 闸或周末缩仓。

## 4. 中线改造

### 4.1 现行路径（实施时不要接回 SwingAgent）

```
midlong_loop._tick
  → _run_mid = ("mid" in due) and universe   # 已接回，勿再改成恒 False
  → factor_route_decide / factor_route_open     # 仅当 MIDLONG_MID_VIA_FACTOR_ROUTE
  → execute_midlong_open(source=factor_route, nature=swing, tier=mid)
```

SwingAgent、`MIDLONG_MID_VIA_MLTO` 默认 false，保持弃用。前端在两开关都 false 时显示 `mid_paused`——这是现码行为，改默认开关是运维决策，本设计不擅自打开。

---

### 4.2 P0-M1 因子仓禁 LLM 碎平

**现状**：`backend/services/full_auto/midlong_position_manager.py` 约 810–913 行，方向复查会写出 `trend_broken` / `trend_weaken` 并执行平/减。因子路由仓会被这套叙事碎平。8/16 已加「持仓未满 `MIDLONG_POSITION_MGMT_LLM_INTERVAL_SEC`（默认 900s）不 LLM 平」，但 15 分钟后仍碎。

**改法**：

1. 开仓元数据打标：`entry_source=factor_route`（现码 `execute_midlong_open` 已有 `source`）。
2. 模式 B 方向复查：若 `entry_source==factor_route`（或 `open_source` 同类字段）：
   - **禁止** 因 `trend_weaken` / `trend_broken` / `llm_*` 执行 close/reduce。
   - **允许**：固定/动态 SL、TP、时间止损、`factor_invalidated`（IC 翻转且持续 N 根）、人工/风控强平、总控对 mid 的去杠杆（与短线 S8 分开）。
3. 可选：因子仓 LLM 只出 `watch` 日志，不执行。

**验收**：

- 单测：构造 `source=factor_route` 持仓 + LLM 返回 `trend_broken` → `executed=false`。
- 单测：同一持仓 `pnl_pct <= -sl_pct` → 仍平仓。
- 新周报：`exit_reason` 里 LLM 碎平占比下降（对比 8/17 那份，写清新报告日期）。

---

### 4.3 P0-M2 持仓互锁改为同 nature

**现状**：`midlong_position_manager.has_open_midlong_position`：同币任意未平仓，只要 `tier∈(mid,long)` 或 `nature∈(swing,trend_follow,position)` 就返回 True。中线被长线锁死。另外用 `.first()` 取「该币任一开仓」，若先扫到短线仓、后面还有 long，可能误判为无中长线（实施时一并修掉）。

**改法**：

```python
def has_open_position_of_nature(symbol, nature: str) -> bool:
    # 按 nature/tier 过滤后再 exists()，不要 .first() 任意一行再判断
```

- 中线开仓：仅当已有 `nature=swing` 或 `tier=mid` 时拦截。
- 长线开仓：仅当已有 `nature=trend_follow` 或 `tier=long` 时拦截。
- 同币中+长同时存在时，预算/保证金仍走现有组合上限，避免双开把保证金打满。

**验收**：有 long BTC 时，因子路由仍可开 mid BTC（若预算通过）。有 mid BTC 时不能再开第二张 mid BTC。同币先有 scalp 再有 long 时，长线存在性判断仍为 True。

---

### 4.4 P0-M3 因子 K 线与成交同所

**现状**：`FACTOR_BACKTEST_KLINE_EXCHANGE` 默认 `binance`；下单走 `get_active_exchange()`。

**改法**：

1. 运行时因子计算：`kline_exchange = get_active_exchange()`，不再默默用 binance。
2. 回测：允许显式 `FACTOR_BACKTEST_KLINE_EXCHANGE`，与实盘计算分离。
3. 日志每笔决策带 `kline_exchange` + `exec_exchange`，不一致打 warning。

**验收**：`active_exchange=asterdex` 时，因子路由日志里 K 线源是 asterdex（或配置显式指定的所），不是默认 binance。

**不要**：为了对齐交易所，去改成交所选择逻辑。

### 4.5 P1 止盈止损、配额、探针

**M4 动态 SL/TP**

- 因子仓 SL/TP 改为 `max(结构摆动, k*ATR)`，保留现码 5%/10% 作上限夹幅，避免过宽。
- 配置：`FACTOR_ROUTE_SL_ATR_MULT` / `FACTOR_ROUTE_TP_ATR_MULT`，默认建议 1.5 / 3.0（实施时用回测量，不在本文件锁死）。

**M5 V5 配额拆分**

- `backend/services/decision_core/unified_gate.py`：`normalize_v5_nature` 对 `swing` **不要**映射成 `trend_follow`。
- 新增策略桶 `factor_mid` 或沿用 `swing`，日配额与 `trend_follow`（长线）分开。
- 验收：长线日配额用尽时，中线因子单仍可开（受中线自己的限额约束）。

**M6 震荡探针**

- 代码默认 `MIDLONG_ALLOW_RANGE_PROBE` 改为 `false`。
- 若运维要开，必须同时满足：活跃因子数 ≥ 门槛，且 IC 方向稳定。

**M8 活跃因子**

- `FACTOR_ROUTE_MIN_ACTIVE_FACTORS` 默认 2 → **3**（M4 记录过当时 5 个活跃，提高门槛不会立刻饿死；若活跃掉到 2 以下应暂停而不是硬开）。

**M9 负 IC 反手**

- `|ic| < FACTOR_ROUTE_IC_ABS_MIN`（建议默认 0.02）时 **orient=0，跳过**，不反手。
- `|ic|` 够大才 `sign(ic)`。
- 连续 N 个因子 IC 为负时，写告警，不自动加大仓。

**M11 paper 缩仓放行**

- paper 置信度不足：默认 **skip**，与 live 一致。
- 若保留缩仓放行，必须 `size_mult <= 0.3` 且单独计数，周报单列。

## 5. 总控与短线/中线边界

```
总控触发
  ├─ 短线仓：禁新开 + 不减不平时（S8-A）
  └─ 中线/长线仓：按现有去杠杆 / 减仓（可继续）
因子中线仓
  ├─ 开：factor_route + 预算 + V5(独立桶)
  └─ 平：SL/TP/时间/因子失效 / 总控（非 LLM 碎平）
短线仓
  ├─ 开：scalp_loop + Gate + V5
  └─ 平：短线自己的 SL/TP/超时；总控不碰
```

## 6. 实施顺序（按改动量，不是按日历）

1. **短线纯逻辑**：S1、S2、S3/S4、S11（几乎只改判断，回归面小）。
2. **总控 S8**：先上单测再改 `continue`，避免误跳过中长线减仓。
3. **中线打标 + M1**：依赖持仓上的 `source` 字段完整；先补历史仓兼容（无 source 的当 `unknown`，LLM 仍可平，避免把旧仓锁死）。
4. **M2 互锁、M3 同所**。
5. **P1 仓位/SL/配额/探针默认**。
6. **P2 测试债 + 重跑报告**。

每步：改代码 → 单测 → 纸交易观察一轮日检 → 再合下一刀。不要一把改完再看盘。
