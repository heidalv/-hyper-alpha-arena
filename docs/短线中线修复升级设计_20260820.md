# 短线 + 中线修复升级设计（对齐 2026-08-19 现码）

> 日期：2026-08-20  
> 修订：同日复核后修正（S3 BudgetService、S8 按持仓拦截、M1 source 落库、M3 运行时/回测分离、M5 降级为门槛拆分等）  
> 配套审查：`docs/短线中线合并审查报告_20260820.md`  
> 范围：**设计方案**，本文件不改交易代码。实施时按优先级改，每项必须有可复现验收。  
> 原则：**以现码为准**；配置写「代码默认」或「某日事实清单曾登记」；绩效数字只标报告日期。

---

## 1. 目标与非目标

### 1.1 目标

1. 短线：信号不再被「涨跌幅补数」污染；时段缩仓不被 FlashVeto 抹掉；预算/冷却用真实 `mode`（含 BudgetService 真分源）。
2. 中线：因子路由开的仓不再被**规则/可选 LLM**方向复查碎平；中/长互锁改为同 nature；运行时因子计算与成交同所（回测默认保持独立）。
3. 总控：短线禁新开时，减仓/平仓也不再误伤短线仓（按**持仓**判断）。
4. 证据：改完后按同一脚本重跑日检/周报，和 8/16、8/17 那几份对比，不拿旧数字当现状。

### 1.2 非目标

- 不把 8 月中旬「中长线架构文档」里的 SwingAgent 当现行方案。
- 不默认「打开因子路由」或「打开 EV 闸」——仓库没有当前 `.env`。改开关是运维决策。
- 本阶段不重做因子库、不换 LLM 模型、不加新策略品种。
- 不把 `test_swing_deprecated.py` 的失败当生产故障；另开测试债单。
- **不**在现网 `daily_cap=0` 的前提下，假装「拆日配额桶」能修好 M5。

### 1.3 总原则

| 原则 | 含义 |
|------|------|
| 入出场同源 | 谁开的仓，谁定平仓规则；禁止跨引擎碎平 |
| 配置诚实 | 代码默认写代码默认；线上值只写事实清单日期 |
| 失败收紧 | 闸门/仲裁/预算异常时倾向 skip，不 fail-open |
| 先止血再优化 | P0 不依赖回测；P1 改仓位公式；P2 才动证据与校准 |
| 按持仓分流 | 总控/出场拦截优先看仓位字段，不只看决策 nature |

## 3. 短线改造

### 3.1 P0-S1 涨跌幅补数

**现状**：`scalp_loop.py` 约 323–343 行。`_md["klines"]` 已是 `DataFrame`（约 237 行），补涨跌却写成 `_klines[-1].get("close")`——对 DataFrame 这是取列名 `-1`，不是最后一根。异常被 `except: pass` 吃掉。触发条件是 `float(price_change_* or 0) <= 0`，缺失/0/负值都会进补数。

**改法**：

```python
# 伪代码
def _missing_pct(v) -> bool:
    return v is None or (isinstance(v, float) and math.isnan(v))

# 只用 iloc[-1] / iloc[-12] 取最后一根，不要 df[-1]
if _missing_pct(_md.get("price_change_1h_pct")):
    _md["price_change_1h_pct"] = _change_from_df(_md["klines"], bars=12)
# 24h 同理（288 根 5m）；0 和负数都保留，不重算
```

**验收**：

- 单测：`price_change_1h_pct=-1.5` 时补数函数不改写。
- 单测：字段缺失且 DataFrame 有足够行时，用 `iloc[-1]` / `iloc[-12]` 算出有符号涨跌。
- 单测：不再出现 `df[-1]` 列访问。

**不要**：把阈值改成 `< 0`（仍会丢掉横盘 0）。只判断缺失。

### 3.2 P0-S2 FlashVeto 不再抹掉缩仓

**现状**：约 665 行 `_size_mult = _liquidity_mult`（周末 ×0.5，UTC 22–00 再 ×0.7）。FlashVeto 未否决时约 727 行写成：

`_size_mult = _veto.size_multiplier if _veto.verdict == "downsize" else 1.0`

`verdict=accept`（非 downsize）会把周末/薄时段缩仓**赋值为** 1.0。仅影响 veto 带约 35–44 分。

**改法**：改为 `_size_mult *= (_veto.size_multiplier if _veto.verdict == "downsize" else 1.0)`。否决拦截逻辑保留。不要默认「通过 = 恢复满仓」。

**验收**：周末且 FlashVeto accept 时，`size_mult` 仍为 0.5（若同时薄时段则为 0.35），不是 1.0。

### 3.3 P0-S3 / S4 预算与冷却使用真实 mode

**现状**：

- `scalp_loop.py` 约 995–1006：`scale_factor_for_layer(..., "paper")` / `can_open(..., "paper")` 写死。
- `apply_short_tier_gate` 不接收 `mode`；`check_short_tier_entry` 默认 `mode="paper"`。
- **更底层**：`BudgetService.get_used_margin(layer, mode, ...)` 接收 `mode` 但**完全忽略**，始终查 `PaperPosition`。

**改法**：

1. scalp_loop 两处预算调用传入本轮真实 `mode`（会话 `trading_mode` / 已有 `_trade_mode`）。
2. `apply_short_tier_gate` 增加 `mode` 并传给 `check_short_tier_entry`（对齐 `unified_gate` 已有传法）。
3. **S3 必做**：`BudgetService.get_used_margin` / `_query_layer_used_margin` 按 `mode` 选择 paper / live 持仓源；live 不得静默读 PaperPosition。
4. 单测：`mode=live` 时冷却键与 paper 互不影响；live used_margin 与 paper 隔离。

**验收**：paper 超限后 live 仍按 live 日限额/已用保证金判断；仅改正 scalp_loop 传参但 BudgetService 未改 → 验收失败。

### 3.4 P0-S8 总控对短线仓 close/reduce 也跳过

**现状**：`master_execution.py` 约 551–573 行。`SCALP_MASTER_HARD_BLOCK` 只对 `buy/sell/pyramid/dca` 做 `continue`。注释「也跳过」**没有 `continue`**。`close`/`reduce` 继续往下；short 减仓另有「浮亏 < 20% 不准减」（约 2362–2375），浮亏够大仍会 `master_running_reduce`。统一出场 fast close 路径也需一并考虑。

**改法（推荐 B'，按持仓拦截）**：

- 在 close/reduce（含统一出场 fast close）执行前：若持仓 `trade_nature ∈ (scalp, intraday)` 或 `timeframe_tier == short` → `continue`。
- 新开仍用现有 `SCALP_MASTER_HARD_BLOCK && is_scalp_nature(decision)`。
- **不要**只看决策 nature（auto-coin / 标记错误时会误拦或漏拦）。
- **风控例外（显式 whitelist，默认仍 skip）**：仅当 `reason` 明确属于 `risk_engine` / `liquidation` / 保证金强平白名单时允许动短线仓；产品若决定「总控永不碰短线」，则 whitelist 为空。

**验收**：

- 单测：禁开窗口构造 short 持仓 + close/reduce intent → `close_position`/`reduce` 调用次数为 0。
- 单测：同 tick 的 mid/long reduce 仍可执行。
- 对照：新日检 short 的 `master_running_close` / `master_running_reduce` 相对 8/16 基线下降。

**不要**：为了对冲总控，去放宽短线 EV 闸或周末缩仓。

## 4. 中线改造

### 4.1 现行路径（实施时不要接回 SwingAgent）

```
midlong_loop._tick
  → _run_mid = ("mid" in due) and universe   # 已接回，勿再改成恒 False
  → factor_route_decide / factor_route_open     # 仅当 MIDLONG_MID_VIA_FACTOR_ROUTE
  → execute_midlong_open(source=factor_route, nature=swing, tier=mid)
  → try_execute_independent_agent_open → TradeProposal（_agent_independent=True）
```

SwingAgent、`MIDLONG_MID_VIA_MLTO` 默认 false，保持弃用。前端在两开关都 false 时显示 `mid_paused`——这是现码行为，改默认开关是运维决策，本设计不擅自打开。

出场（模式 B）：`manage_position` → `_dim_reversal` → staged TP → 方向复查（默认 `_rule_direction`；`MIDLONG_REVIEW_LLM=true` 才 LLM）→ 可写 `trend_broken` / `trend_weaken`。

### 4.2 P0-M1 因子仓禁方向复查碎平

**现状**：`midlong_position_manager.py` 方向复查（默认规则、可选 LLM）可执行 close/reduce，理由前缀 `trend_broken` / `trend_weaken`。15 分钟节流（`MIDLONG_POSITION_MGMT_LLM_INTERVAL_SEC=900`）后仍碎。

**阻塞**：`execute_midlong_open(..., source=...)` 的 `source` **未写入持仓**。`PaperPosition` 无 `entry_source` 列；`exit_state_json` 现也不含该键。出场无法识别因子仓。

**改法（分两步，不可跳过第一步）**：

**步骤 A — 落库**

1. `execute_midlong_open` → `try_execute_independent_agent_open` → `TradeProposal.extra` / `proposal_execution` 写入 `exit_state_json["entry_source"]="factor_route"`（或新列 + migration；优先 JSON 以减小迁移面）。
2. 历史仓无键 → 视为 `unknown`，保留现有复查，避免一把锁死旧仓。

**步骤 B — 出场分流**

1. `manage_position` 读 `entry_source`。
2. 若 `entry_source==factor_route`：
   - **禁止**因方向复查（规则 `_rule_direction` 与 LLM `_dim_direction`）执行 close/reduce。
   - **默认建议**：因子仓也跳过 `_dim_reversal` 的叙事平仓（`bias_reversal` / `no_progress`），只留 SL/TP/时间/`factor_invalidated`；若产品要保留 no_progress，须单独开关且写进周报。
   - **允许**：固定/动态 SL、TP、时间止损、显式 `factor_invalidated`（IC 翻转且持续 N 根——现码尚无，需新建）、人工/风控强平、总控对 mid 的去杠杆（与短线 S8 分开）。
3. 可选：因子仓复查只打 `watch` 日志，不执行。

**验收**：

- 单测：`entry_source=factor_route` + 规则/LLM 返回 close → `executed=false`。
- 单测：同一持仓价格触及 SL → 仍平仓。
- 单测：`entry_source` 缺失（unknown）→ 行为与现码一致。
- 新周报：因子仓 `exit_reason` 中 `trend_weaken/broken` 占比下降（写清新报告日期）。

### 4.3 P0-M2 持仓互锁改为同 nature

**现状**：`has_open_midlong_position`：同币任意开仓 `.first()` 后，若 `tier∈(mid,long)` 或 `nature∈(swing,trend_follow,position)` 即 True。中线被长线锁死；先扫到 scalp 可能漏检 long。

**改法**：

```python
def has_open_position_of_nature(db, account_id, symbol, nature: str) -> bool:
    # filter nature/tier 后 .exists()；禁止 .first() 任意行再判断
```

- 中线开仓：仅当已有 `nature=swing` 或 `tier=mid` 时拦截。
- 长线开仓：仅当已有 `nature∈(trend_follow,position)` 或 `tier=long` 时拦截。
- 同币 mid+long 同时存在：必须过现有 `portfolio_budget` / 单币集中度；验收写明不超 `PB_MIDLONG_MAX_SYMBOL_EXPOSURE_PCT`。
- 替换调用方：`midlong_factor_route.factor_route_open`、`mlto_cycle` 等。

**验收**：有 long BTC 时仍可开 mid BTC（预算通过）。有 mid BTC 不能再开第二张 mid。同币 scalp+long 时 long 存在性为 True。

### 4.4 P0-M3 运行时因子 K 线与成交同所

**现状**：`factor_route` → `factor_backtest_scorer._load_klines`，默认 `FACTOR_BACKTEST_KLINE_EXCHANGE=binance`。成交跟 `get_active_exchange()`。`_load_klines` 硬门槛约 ≥120 根；z-score 另有有效点要求。

**改法**：

1. **新增** `FACTOR_ROUTE_KLINE_EXCHANGE`（建议默认 `active`），仅用于运行时 `factor_route_decide`。
2. **不要**改 `_backtest_exchange()` 全局默认——会污染因子晋升/冷池/回测语义。
3. `active` 下 K 线不足（<120 或不足以算 IC）→ **hold + 明确 reason**，禁止静默回退 binance。
4. 日志每笔带 `kline_exchange` + `exec_exchange`；不一致打 warning。
5. 切换所后对 universe 跑覆盖率（4h/1d 深度），并**重算 IC / 活跃池**——旧 M4 负 IC 结论可能失效。

**验收**：`active_exchange=asterdex` 时因子路由日志 K 线源为 asterdex（或显式配置）；回测扫描仍可用 binance。覆盖率报告写入新日期验收文。

**不要**：为了对齐交易所，去改成交所选择逻辑。

### 4.5 P1 止盈止损、门槛、探针

**M4 动态 SL/TP**

- 因子仓 SL/TP 改为 `max(结构摆动, k*ATR)`，保留现码 5%/10% 作上限夹幅，避免过宽。
- 配置：`FACTOR_ROUTE_SL_ATR_MULT` / `FACTOR_ROUTE_TP_ATR_MULT`，默认建议 1.5 / 3.0（实施时用回测量，不在本文件锁死）。
- 可复用 midlong 结构 SL 辅助，与 staged TP 对齐。

**M5 V5 门槛口径拆分（降级重写）**

- **事实**：`unified_gate` 已 `daily_cap=0`，改 `normalize_v5_nature` **不会**让「mid 不占 trend 日配额」变绿——因为日帽硬拦已不存在。
- **要做的**：让 `swing` / `factor_mid` 在 `resolve_effective_entry_threshold` 等处使用**独立**置信度/RR/缩仓口径，不要被迫吃 long 的 trend_follow 门槛。
- **不要做的（除非产品另开 RFC）**：仅为了本项恢复 opens_today 日配额硬拦、新建全链路 daily_cap 桶。
- 验收：长线门槛收紧时，中线因子单仍按中线自己的阈值评估（受中线预算/活跃因子约束）。

**M6 震荡探针**

- 代码默认 `MIDLONG_ALLOW_RANGE_PROBE` 改为 `false`。
- 若运维要开，必须同时满足：活跃因子数 ≥ 门槛，且 IC 方向稳定。

**M8 活跃因子**

- `FACTOR_ROUTE_MIN_ACTIVE_FACTORS` 默认 2 → **3**（活跃掉到门槛以下应暂停而不是硬开）。

**M9 负 IC 反手**

- `|ic| < FACTOR_ROUTE_IC_ABS_MIN`（建议默认 0.02）时 **orient=0，跳过**，不反手。
- `|ic|` 够大才 `sign(ic)`。
- 连续 N 个因子 IC 为负时，写告警，不自动加大仓。

**M11 paper 缩仓放行**

- 现状：`TradeProposal.to_decision_dict()` 固定 `_agent_independent=True`，因子路由会走 Paper 探针软放行。
- 改法：因子路由提案设 `_agent_independent=False`，或 Paper 探针排除 `source_lane`/`entry_source` 含 `factor_route` 的提案；置信度不足默认 **skip**，与 live 一致。
- 若保留缩仓放行：`size_mult <= 0.3` 且周报单列。与 M6 关探针部分重叠，实施时一起回归。
