## §1 要求①：模拟仓必须按真实交易所配置模拟

### 1.1 问题定性

模拟仓（`mm_asterdex`，`mode=paper`）当前的失真**不在费率，而在行情与成交判定**：

| 环节 | 当前引擎 | 真实交易所 | 后果 |
|---|---|---|---|
| 决策周期 | **15s**（`MM_SHADOW_INTERVAL_SEC=15`） | 事件驱动 | 15s 内的往返穿越全不可见 |
| 盘口来源 | `market_orderbook_snapshots`：**上游 30s REST 轮询**，15s 网格**填充率 47.5%** | `@bookTicker` 实时、`@depth20@100ms` | 看到的盘口最多差 30s |
| 成交来源 | `market_trades_aggregated`：**15s 聚合桶**（只有 low/high/taker_buy/sell） | `@aggTrade` 逐笔 | 无法定位队列位置 |
| 成交判定 | `seg_low < bid*(1-pen)` **且** `seg_taker_sell>0` | 逐笔价+量、按队列消耗 | **既漏判也误判** |
| 队列份额 | 固定 `QUEUE_SHARE=0.30` | 由实际排队量决定 | 库存摆动与漂移亏损被低估约 3× |

`runner.py:577-580` 自己记录了同类失真的后果：
> 「此前实盘每段全量吃 $100、回放只吃 30%：库存摆动 ~3× 大、漂移亏损 ~3× 大——**回放正收益的配置在实盘变负的根因**」

而这一失真正好解释了核心矛盾：**`edge_json` 记 285 笔 / `+1.185bp` / 影子 30 天为正，而影子实跑 49 笔 / `−4.075bp`。**

### 1.2 修正方案：把行情与成交判定换成交易所同源数据

**新增 `backend/services/market_maker/tick_feed.py`（已落地）**：

```
TickFeed（抽象）
├── DbTickFeed        从 PG 读（回测/回放）
└── InMemoryTickFeed  调用方塞数组（实盘/测试）

数据源：
  asterdex_book_ticker    top-of-book，p50 36ms，1.027 亿行，32 币，3.9 天
  asterdex_trades         逐笔含 is_buyer_maker（主动方），p50 1.5s，191.7 万行，32 币，3.9 天
  asterdex_depth_snapshots 20 档，p50 105ms，10 币，94 小时
```

**成交判定改为队列感知（与交易所撮合语义一致）**：

```
挂买单于 bid 价 L，队列前方量 Q_ahead（= min(该档显示量, 近10s同价成交量)）
成交 ⟺ 主动卖在价格 L 上的**累计**成交量 > Q_ahead
     （TickFeed.consume_time(side="bid", price=L, q_ahead=Q_ahead, t_from=t)）

挂单在盘口移动时撤单重挂；盘口移开（买单价被击穿）视为已成交。
```

这与 `runner.py` 现有的两个失真点一一对应：**用逐笔替代 15s 桶**、**用队列消耗替代固定 30% 份额**。

### 1.3 费率与合约参数必须与交易所同源

模拟仓还必须对齐以下真实参数（否则模拟结果无意义）：

| 参数 | 值 | 来源 | 现状 |
|---|---|---|---|
| maker 费率 | **0 bp** | `GET /api/trading/config/fees` | ✅ 已对齐 |
| taker 费率 | **4 bp** | 同上 | ✅ |
| 最小名义 | **$5** | 同上 | ✅ |
| tick size | ASTER **0.0001**；BTC **0.1**；ETH **0.01** | `GET /fapi/v1/exchangeInfo` | ⚠️ **未接入** |
| 数量步长 `stepSize` | 各币不同 | 同上 | ⚠️ **未接入** |
| 最小名义的真实校验 | 交易所侧 `minNotional` | 同上 | ⚠️ **未接入** |

**应拉取一次 `exchangeInfo` 落库为 `asterdex_instruments`**（symbol/tick_size/step_size/min_notional/max_leverage），供模拟仓做：挂单价按 tick 取整、数量按 step 取整、名义下限校验。**现在模拟仓可以直接挂出不符合 tick 的价格，这是必须修的。**

## §2 要求②：实时深度看板（上下显示）

### 2.1 与原设计的差异

原设计 §2 是「5 币**横排**卡片（每张约 280px）」，只显示 top-of-book + 我方挂单。
**新要求是"挂单深度"实时、上下显示** ⇒ 改为：**每币一个纵向价格梯（price ladder），自上而下 = 从卖 20 档到买 20 档，我方挂单在梯上高亮**。

### 2.2 布局（纵向价格梯）

```
┌─ ASTERUSDT ──────────────── 中价 0.738850  ▲+0.02% ──┐
│  成交量柱(对数)  价格        累计量                     │
│  ▏              0.7409      312K      ← 卖20           │
│  ▎              0.7405      298K                       │
│  ▌              0.7392      47K                        │
│  ▊              0.7391      9.1K                       │
│  ███            0.7390      5.0K                       │
│  ██████         0.7389      11.3K     ← 卖一           │
│  ──────────── 0.738850 ──── 中价 ─────────────────    │
│  ██████         0.7388      40.0      ← 买一           │
│  ████████████   0.7387      5.27K                      │
│  ████████       0.7386      4.08K                      │
│  ▍              0.7371      21K                        │
│  ▏              0.7310      88K        ← 买20           │
├────────────────────────────────────────────────────────┤
│ 我方挂单：买 0.7387 ×120  (距中价 2.0bp, 队列前 $12)    │
│           卖 0.7390 ×120  (距中价 2.0bp, 队列前 $8)     │
│ 持仓：+120 @0.73870   浮盈 +$0.0021  持有 14s          │
│ 近5笔：B 0.7387×120 ✓成交  S 0.7390×120 ⏳挂单中        │
└────────────────────────────────────────────────────────┘
```

**必须标注的语义**（原设计原则"只展示真实存在的数据"继续有效）：
1. **我方挂单在梯上单独一行高亮**（青色边框 + "我方"标签），**并给出队列前方量估计**——这是"深度"对做市真正的意义所在；
2. **深度只有 10 个币有**：无深度的币（如 DOGE）如实显示「该币无深度采集」，**绝不画假深度**；
3. 深度数据带时间戳，卡片上显示 **depth 年龄**（>2s 标黄，>10s 标红）；
4. 梯子按价格排序，**买卖两侧各显示到 20 档**，中间标注中价；
5. 成交量柱宽度按 **log 缩放**（20 档量级可差 3 个数量级，线性会全挤成一条线）。
