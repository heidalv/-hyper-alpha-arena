# 短期因子策略（Scalp）深度分析：现状 vs 2026 主流量化实践

日期：2026-07-06
范围：`backend/services/scalp_factor_router.py`、`backend/services/factor_engine/*`、
`backend/services/scalp/*`、`backend/services/decision_core/execute_proposal.py`

---

## 0. 现状速览（端到端链路）

```
5m/15m K线 + 订单流(CVD/OI/Taker/资金费率)
   → factor_engine 计算 21个硬编码因子 + 130+ AI/WorldQuant/Alpha158 因子
   → Z-score归一化 → 按 IC/regime/衰减 加权 → Top-15 聚合 → CompositeSignal
   → ScalpFactorRouter：score=|direction|×100，5m/15m共振×1.3或×0.5，币圈微观结构+20，趋势软加分+5
   → ScalpStructureScanner advisory 扣分 → ScalpExecutionGate 分层(direct≥45 / veto 35-44 / hold<35)
   → 边缘分(35-44) 走 ScalpFlashVeto（5s LLM，Paper fail-open / Live fail-closed）
   → evaluate_scalp_proposal（V5统一门禁 + 数据契约 + short_tier熔断/冷却）
   → 预算/风险帽/杠杆 → structure_stop_calculator(SL/TP) → paper_engine 下单
   → 持仓期：scalp专用 trailing/保本
   → factor_ic_evaluator 每80 tick(~1h) 用14天样本重估IC → 回写运行时权重
```

这是一套**规则阈值 + 分层门控 + 边缘LLM裁决**的系统，因子合成用的是**IC加权线性聚合**，
不是端到端机器学习模型，也不是纯LLM决策。下面逐维度和 2026 年主流实践对比。

## 2. 逐项详细分析

### 2.1 因子合成方法 —— ✅ 方向正确，细节可以更稳健

当前做法本质是 **IC加权线性组合**（`factor_ic_evaluator` 按14天IC/胜率调整权重），这恰好命中
2026年最多篇研究一致推荐的"稳健区间"：从等权出发，进阶到ICIR/IC加权即可，**不需要一步到位上
XGBoost**——因为非线性模型只有在"点时数据(point-in-time)干净、有严格walk-forward基础设施"
的前提下才能兑现 Gu-Kelly-Xiu 论文里"2倍夏普"的优势，否则大概率是在过拟合噪声。

**但当前的合成公式偏简单粗暴**：`score = int(abs(composite.direction) * 100)` 只取方向强度的
绝对值，且只聚合 Top-15 个"方向最强"因子——这等于是**贪心截断法**而非"因子看作资产做均值-方差
优化"。主流经验里"3-5个低相关、逻辑独立的因子做等权/ICIR加权，往往优于过度优化的复杂模型"，
但前提是这些因子**互相独立**。目前 Top-15 里如果同时选中 RSI+MACD+Momentum+ROC（都是动量类
因子），实质上是把"动量观点"重复计权了 3-4 次，而非真正拿到 3-4 个独立信息源。

**建议（P1，成本中等）**：在 `factor_evaluation_pipeline._compute_weights` 之后、聚合之前，加一步
因子间 Pearson/Spearman 相关性检查（同 timeframe、同 symbol 滚动窗口），对相关性 >0.7-0.8 的因子
只保留 IC 更高者，或者给相关组内因子的合计权重设一个上限（例如"同一大类因子权重之和 ≤ 40%"）。
这是最低成本、最高确定性收益的改动，不需要引入任何机器学习模型。

### 2.2 因子池的新陈代谢 —— ⚠️ 偏静态，落后于最前沿实践

`factor_decay_monitor.py` + `factor_ic_evaluator` 能做到"因子衰减了就降权"，但从代码看没有发现
"因子彻底失效后自动移出因子池"或"自动生成新因子候选"的闭环。这与本次调研到的 2026 年最前沿实践
（例如 FMZ 上的 AI 自适应因子挖掘策略：LLM 定期生成新因子表达式 → Rank IC 回测验证 → 相关性去重
→ 末位淘汰，维持因子池在一个动态平衡的目标数量）有代差。

这一点**不算紧急**——AlphaForge 论文本身也指出"因子池不是越大越好，10个左右动态因子往往优于
50-100个静态大池"，当前 150+ 因子的静态池如果权重机制健康，实际生效的可能也就是头部 15-20 个，
问题不大。但如果未来想追平"前沿"而不只是"主流"，这是值得投入的方向。

**建议（P2，成本较高，暂不紧急）**：先补上 2.1 的相关性去重，观察一段时间"有效因子数量"是否
明显小于15，如果长期只有5-8个因子真正贡献权重，再考虑要不要投入"自动挖掘新因子"的能力，避免
过早优化。

### 2.3 回测与验证体系 —— 🔴 当前最大短板，也是行业公认的"防过拟合第一道防线"

这是本次调研里最一致的结论：**不管因子合成方法多先进，如果没有 walk-forward 验证 + 诚实的成本
模型，回测数字和实盘表现之间的鸿沟会很大**。头部开源框架（AlphaForge）把这件事列为"用了这套
框架前后最大的教训"：naive回测用收盘价成交、按5分钟K线年化夏普，实盘全面崩盘；改成"下一根K线
开盘价成交、按日频率算夏普、扣资金费率、模拟爆仓"之后，表现立刻从虚高变得可信。

**当前 Scalp 层完全没有独立回测 harness**（探索确认：只有 `scripts/diagnose_scalp_score.py` 这类
诊断脚本，以及运行时的 `factor_ic_evaluator` 用14天真实/纸面交易样本做事后评估）。这意味着：

1. 任何新因子、新权重公式、新阈值调整，**目前只能靠"上线跑一段时间看结果"来验证**，没有办法在
   上线前用历史数据做 out-of-sample 检验，试错成本高、周期长。
2. `factor_ic_evaluator` 的14天样本量对短线策略（45秒扫描一次）来说其实**不算多**——按主流建议
   "IS用90天/OOS用30天""至少覆盖一次牛熊震荡"的标准衡量，14天很可能不足以判断一个因子是真的
   衰减了还是恰好遇到了不利的市场状态（regime）。
3. 没有看到资金费率、滑点、极端行情下爆仓这几个因素在**事前**评估中被显式建模——目前是通过运行
   时风险帽/杠杆上限做"事中控制"，但缺"事前压力测试"这一环。

**建议（P0，长期投入，但收益最大）**：
- 短期（低成本起步）：把 `analyze_cycle_direction_sensitivity.py` 这套本次已经验证过的"从
  `crypto_klines` 历史数据算IC/命中率"的框架复用到 Scalp 因子上，先补一个**离线 walk-forward IC
  验证脚本**（训练窗口算IC → 冻结 → 未来窗口验证，滚动前进），而不必一步做到完整的成交模拟回测
  引擎。
- 中期：给这个验证脚本加上资金费率 + 滑点 + 手续费的扣减，输出"扣成本后的IC/命中率"，与当前
  "运行时胜率"做交叉验证。
- 长期：如果未来要引入更复杂的合成方法（哪怕只是给因子做正交化），都应该先有这套 walk-forward
  基础设施兜底，否则任何"看起来更聪明"的改动都有可能是在过拟合最近一段行情。

### 2.4 风控与执行 —— ✅ 已经是相对成熟的水平

频率限制（每tick限1仓、冷却300-600秒）、币种熔断（连亏4笔冷却6小时并持久化）、结构化止损
（ATR×1.5 + 5m摆动结构外侧）、动态杠杆、按nature区分的移动止盈——这套组合拳已经覆盖了主流
checklist里的大部分条目（止损止盈、频率控制、单笔风险硬顶、杠杆自适应）。相比很多开源crypto
量化项目（本次调研到的例子里也只是"ATR止损+凯利公式仓位"的水平），当前系统的风控**颗粒度更细、
失败模式设计更完整**（比如 Flash Veto 明确区分 Paper fail-open / Live fail-closed，这是很多
业余实现会忽略的细节）。

### 2.5 LLM边缘裁决 —— ✅ 方向对，是2026年的新兴模式而非传统量化标准做法

需要说明：**"用LLM在关键路径上做实时裁决"本身不是传统量化的主流做法**（传统量化要么全自动化
执行，要么用人工紧急干预），但确实是 2026 年加密量化圈子里正在兴起的模式（调研到的开源项目也
有类似"AI决策覆盖层"）。当前设计把LLM限定在"35-44分的边缘信号"（而非全量决策），并且明确区分
Paper/Live环境的失败降级策略，这个设计本身是合理、审慎的——**没有滥用LLM去替代系统化决策的主体
部分**，符合"LLM应该辅助边界模糊地带的判断，而不是替代核心统计信号"这条业内共识。

## 4. 两项改进的落地与验证结果（2026-07-06 补充）

在完成上述对比分析后，已按优先级实施了 P1（因子相关性去重）与 P0（walk-forward 验证脚本）
两项，并跑出了真实结果。

### 4.1 P1：因子同类去重（已实施）

**改动位置**：`backend/services/factor_engine/factor_signal_generator.py`
`_cap_category_share()` + `_aggregate()`；新增配置
`FACTOR_CATEGORY_MAX_SHARE`（默认0.40）、`FACTOR_CATEGORY_DEDUP_ENABLED`（默认true）。

**做法**：top-15 聚合选出因子后，按 `FactorCategory` 分组统计各类别的合计有效权重，
若某一类别（如 momentum: RSI+MACD+Momentum+ROC）合计权重超过总权重的40%，对该类别内
所有因子的权重做等比例缩放压到上限，不改变类内相对强弱，也不影响"只有单一类别可选"
时的退化场景（此时缩放对加权平均结果无影响，符合"没有对比对象就不该被惩罚"的直觉）。

**验证**：新增 `tests/backend/unit/test_factor_category_dedup.py`（5个用例，全部通过），
覆盖：单类别不受影响、主导类别被压低且不影响其他类别、开关禁用时完全跳过、
端到端聚合场景下"5个同向momentum + 1个反向trend"的合成方向确实比未去重前更明显地被
反向因子拉动。运行 `test_scalp_factor_router.py` 回归时发现一个**与本次改动无关的
预置失败**（`test_sl_tp_ratio`，`structure_stop_calculator.compute_sl_tp` 在缺 K 线上下文
时返回的 TP 超出测试断言的 6% 上限；关闭因子去重开关后该测试仍然失败，确认与本次改动
无关，未在本次任务中处理）。

### 4.2 P0：Scalp 因子 walk-forward 验证脚本（已实施并跑出真实结果）

**新增脚本**：`scripts/walk_forward_validate_scalp_factors.py`，复用
`cycle_direction_probability` 的权威指标实现，对 `alpha_market.crypto_klines` 的真实 5m
历史数据做**滚动、完全隔离的样本外分段评估**（因子公式本身无可拟合参数，采用"按时间顺序
切成互不重叠的折、每折独立算IC"的简化 walk-forward，而非"IS拟合参数→冻结→测OOS"的经典形式；
详见脚本内文档字符串的方法说明）。同时内置成本模型：只有"方向×前瞻收益 > 假设往返成本
(默认0.12%)"才算真正命中，避免"账面命中但不够付手续费"的假阳性。

**数据现状**：当前数据库 5m K 线仅约7天历史（BTC/ETH/SOL/BNB/WIF 约2000根/币），
只有这5个币种满足 `--min-bars 500` 门槛，其余（XRP/DOGE/AVAX等）历史不足。**这意味着
本次结果的置信度有限**，仅作为方向性证据，不构成"因子已验证有效/无效"的最终结论
（主流建议至少覆盖牛熊震荡多个周期，通常需要数月至数年数据）。

**运行结果**（`--forward-bars 12` ≈ 1小时前瞻，30折）：

| 因子 | IC均值 | 同号折占比 | 成本调整命中率 | 结论 |
|------|--------|-----------|---------------|------|
| rsi | -0.0765 | 56.7% | 37.2% | 中等/需继续观察 |
| macd_hist | +0.0351 | 56.7% | 42.0% | 中等/需继续观察 |
| momentum | -0.0405 | 56.7% | 39.5% | 中等/需继续观察 |
| di_diff | -0.0926 | 66.7% | 38.3% | 中等/需继续观察 |
| ema_align | -0.0609 | 66.7% | 36.0% | 中等/需继续观察 |
| atr_pct | +0.0040 | 43.3% | - | 不稳定（regime噪声） |
| vol_ratio | -0.0037 | 50.0% | - | 预测力极弱 |

**换成 `--forward-bars 6`（≈30分钟前瞻）后，momentum 和 ema_align 从"中等"升级为
"稳定有效"，但符号仍是负的**（同号折占比分别达70%、73.3%）。

**这是一个值得高度关注的发现**：momentum、ema_align、di_diff、rsi 这几个"趋势延续类"
因子，在当前 Scalp 路由器里被映射为"正值=看多延续"，但实证结果显示它们与未来
30分钟-1小时收益是**负相关**——也就是说，在这批头部币种的这一周行情里，短线更像是
"强势后均值回归"而不是"强势后延续"，与本项目此前 `CYCLE_DIRECTION_RESEARCH` 报告里
"短周期偏均值回归、长周期偏趋势"的结论方向一致，且把这个结论从"周期方向识别"进一步
下沉验证到了 Scalp 因子层面。

**本次不直接改动生产因子方向映射**，原因：
1. 样本仅约7天、5个币种，远达不到主流建议的"至少覆盖一次牛熊震荡"的验证标准，贸然
   反转方向映射有过拟合到这一周行情的风险——而这正是本工具要防范的问题，不应被同一
   工具的初次小样本结果自我推翻。
2. 现有 `factor_ic_evaluator` 已经在用真实成交的胜率/IC 做运行时降权（阈值：胜率<40%→
   权重0.25），如果这几个因子真的方向持续偏差，理论上会被运行时闭环自然压低权重——
   本次结果可以作为**交叉验证运行时权重是否已经生效**的参照，而不必重复造轮子。

**建议的后续动作（不在本次任务范围内，供下次排期参考）**：
- 持续积累5m历史（自然增长），每隔1-2周重跑本脚本，观察 momentum/ema_align 的负IC是否
  随样本增多而稳定或消失。
- 对照 `factor_ic_evaluator` 当前对这几个因子的运行时权重（`data/factor_runtime_weights.json`），
  确认闭环是否已经在降权；如果闭环样本量也不足（`MIN_SAMPLES=8`），说明两套验证目前都还
  处于"数据不够、不能下结论"的阶段，是更大的数据积累优先级问题而非算法问题。

## 5. 一句话结论

短期因子策略的**核心方法论（IC加权线性聚合、多周期共振、分层风控、LLM仅裁决边缘信号）与
2026年主流量化实践方向一致，部分风控细节甚至优于常见开源实现**；真正的差距集中在
**"验证基础设施"**——没有独立的 walk-forward 回测/成本建模能力，导致任何因子或阈值调整目前都
只能"上线用真钱/纸面钱试错"，这是当前投入产出比最高的改进方向。
