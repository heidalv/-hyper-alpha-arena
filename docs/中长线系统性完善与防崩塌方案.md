## 1. 系统全景

### 1.1 当前三层架构的真实状态

```
┌─ 短线(scalp) ────────────────────────────────────────────────┐
│  ScalpFactorRouter → 纯规则(因子引擎+EV门控)，无 LLM 开仓    │
│  独立循环(45s) | 预算15% | 实测: 净亏 -21/周(改进中)         │
│  问题: TP太远/SL死亡区间/AI反向平仓亏损放大                   │

│  SwingAgent → LLM分析(1次/tick) → 独立开仓决策               │

│  MLTO: 默认不走MLTO(MIDLONG_MID_VIA_MLTO=false)              │
└──────────────────────────────────────────────────────────────┘

┌─ 长线(trend) ────────────────────────────────────────────────┐
│  TrendAgent → LLM分析(1次/tick) → 独立开仓决策               │
│  + MLTO thesis维护(论点账本+辩论+学习闭环)                   │
│  独立循环(90s) | 预算40% | 实测: 3笔 胜率67% 净+5.1          │
│  问题: MLTO不控开仓(CONTROLS_EXEC=false)，论点系统空转        │

└──────────────────────────────────────────────────────────────┘

┌─ 总控(MasterController) ─────────────────────────────────────┐
│  6路分析师 → MasterController LLM综合 → 建议执行              │
│  主tick(90s) | 主要服务short tier | 不能覆盖中长线决策         │
│  问题: master_running_close/reduce 历史胜率5-16%(已加硬门控)  │
└──────────────────────────────────────────────────────────────┘

┌─ 进化学习(5轨并行) ──────────────────────────────────────────┐
│  L1 wisdom(1h) → L2 prompt优化(12h) → L3架构(24h)            │

│  问题: 多轨并行竞争同一参数空间，存在治理仲裁缺口              │
└──────────────────────────────────────────────────────────────┘
```

### 1.2 关键发现

| 发现 | 影响 |
|------|------|
| **中长线实测胜率更高**（中线50%/长线67% vs 短线42%） | 资源应向中长线倾斜 |
| **MLTO论点系统空转**（CONTROLS_EXEC=false） | 7阶段编排器的辩论+论点能力浪费 |
| **总控对中长线无直接控制** | 三层独立，总控只做分析师报告供给 |

| **提示词"把LLM当计算器"** | 大模型的推理能力被浪费 |

## 2. 中长线盈利的根因分析

### 2.1 为什么中长线能盈利而短线不能

| 维度 | 短线(scalp) | 中线(swing) | 长线(trend) |
|------|-------------|-------------|-------------|
| 持仓时间 | 5-45min | 2-8h | 2h-7天 |
| 手续费影响 | **致命**(频繁开平) | 中等 | 小 |
| 噪声影响 | 极高(5m K线) | 低(1h/4h) | 极低(4h/1d) |
| 趋势捕获 | 弱(快进快出) | 中(波段) | **强**(让利润奔跑) |
| AI分析价值 | 低(数据太少) | 中 | **高**(宏观+链上+叙事) |
| 盈亏比 | 差(0.36实测) | 好(RR≥1.5) | **最好**(分批TP+trailing) |

### 2.2 中长线盈利的三个支柱

1. **深度分析**：LLM 综合宏观叙事+资金流+链上数据+历史经验 → 高质量方向判断
2. **趋势捕获**：分批止盈(8%/15%/25%)+ATR trailing → 让盈利的单子跑到最大
3. **论点管理**：MLTO 持续更新论点 → 方向不对时主动退出，方向对时金字塔加仓

## 4. MLTO编排器激活与可视化

### 4.1 当前状态

MLTO 有完整的 7 阶段流水线，但：
- `MIDLONG_MLTO_CONTROLS_EXEC=false` → MLTO不控开仓
- `MIDLONG_MID_VIA_MLTO=false` → 中线不走MLTO
- 论点系统在"空转"（维护thesis但不影响决策）

### 4.2 激活方案

**阶段1：先激活长线MLTO开仓门控**
```bash
MIDLONG_MLTO_CONTROLS_EXEC=true   # MLTO控长线开仓
MIDLONG_THESIS_OPEN_GATE=true     # 论点就绪度门控生效
# 中线暂不激活(MIDLONG_MID_VIA_MLTO保持false)
```

**效果**：长线开仓前必须通过：
1. 论点方向明确（direction_history最近5次多数一致）
2. 论点稳定（stable_since > 300秒）
3. 复盘次数达标（review_count ≥ 1）
4. 就绪度够（open_readiness ≥ 50）
5. 灰区辩论通过（如果信号在灰区）

**阶段2：激活中线MLTO**（长线验证OK后）
```bash
MIDLONG_MID_VIA_MLTO=true
```

## 5. 总控(MasterController)提示词审查与重构

### 5.1 当前状态

- 系统prompt定位"$5亿对冲基金CIO"，有6步分析框架（宏观→量价→心理→共振→反向→合成）
- **与中长线平行独立**，不互相调用、不覆盖
- 输出经Pydantic校验 + PositionSizingAgent重算 + UnifiedRiskGate + master_close_guard
- 历史胜率差（master_running 5%/reduce 5%），已加"硬事实门控"

### 5.2 总控提示词评估

**优点**（比swing/trend好）：
- 已有6步CoT结构（宏观叙事→量价→心理→共振→反向→合成）
- 有5条交易哲学
- 有明确的tier隔离约束

**问题**：
1. system prompt 硬编码在代码里（`trading_analysts.py:3433-3488`），无法通过配置页修改
2. prompt太长（11层拼接），LLM 有效注意力被稀释
3. 接收6路分析师报告但其中5路是规则化数据（KlineAnalyst是唯一LLM），大部分是数字罗列而非洞察
4. 对中长线的实际影响很小（三层独立架构，总控主要服务short tier）

### 5.3 总控改进方案

**不在本次重构范围内大改总控提示词**——因为：
1. 总控与中长线是平行系统，改总控不影响中长线盈利
2. 总控主要影响短线，短线正在被重构为纯因子引擎
3. 总控的硬门控（master_close_guard）已经很好

**改进建议**（低优先级）：
1. 把 system prompt 从代码移到磁盘文件，支持配置页编辑
2. 6步框架本身已经不错，不需要大改
3. 减少 prompt 层数（11层→5层），避免注意力稀释

## 6. 进化学习层防崩塌设计

### 6.1 当前5轨进化学习的风险

| 轨道 | 频率 | 写入目标 | 风险 |
|------|------|---------|------|
| L1 wisdom | 1h | hermes_db + _global_ StrategyMemory | 低 |
| L2 prompt优化 | 12h | prompt_versions表（A/B测试） | **中**——可能优化出"过拟合"的prompt |
| L3 架构 | 24h | architecture_proposals | 低 |
| L4 策略创生 | 24h | genesis_candidates（孵化） | **中**——新策略可能在小样本上表现好 |
| NSGA-II遗传 | 3天 | v5_runtime_gates.json | **高**——直接改全局参数 |
| 因子发现 | 24h | factor_runtime_weights.json | 中 |
| IC闭环 | 实时 | factor_runtime_weights.json | 中 |
| 反思 | 事件 | key_lessons + ChromaDB | 低 |
| 晋升扫描 | 定期 | promotion_gate_registry.json | 中 |

### 6.2 核心风险：参数空间竞争

多个进化轨道可以同时修改同一个参数：
- NSGA-II 和 OpenCode 提案都能改信号权重
- L2 prompt优化 和 L4策略创生 都可能影响同一个agent的行为
- IC闭环 和 因子发现 都写 factor_runtime_weights.json

**当前防护**：
- `GovernanceArbiter` 优先级仲裁（manual>validated>nsga2>proposal>experimental）
- `RuntimeGovernor` 统一intent表

**残留风险**：优先级仲裁是建议性的，不强制——高优先级来源仍可覆盖"属于"其他来源的参数。

### 6.3 防崩塌设计

#### 设计1：参数所有权锁定

给每个可调参数标记"所有者"，只有所有者能修改：

```python
PARAM_OWNERSHIP = {
    # 短线参数 → 只能通过短线配置页修改
    "tp_pct": {"owner": "scalp_config_page", "auto_evolution_locked": True},
    "sl_pct": {"owner": "scalp_config_page", "auto_evolution_locked": True},
    
    # 中长线参数 → 只能通过中长线配置页修改
    "TIER_MID_TP_PCT": {"owner": "mid_config_page", "auto_evolution_locked": True},
    
    # 因子权重 → IC闭环和因子发现共享
    "factor_runtime_weights": {"owner": "factor_ic", "allowed": ["factor_discovery", "factor_ic"]},
    
    # 信号权重 → NSGA-II和OpenCode共享
    "signal_weights": {"owner": "nsga2", "allowed": ["nsga2", "opencode_validated"]},
}
```

进化系统试图修改 `auto_evolution_locked=True` 的参数时，记录"建议"但不自动应用——需人工确认。

#### 设计2：进化产出健康度监控

每次进化产出（新prompt/新策略/新参数）后，设置48小时观察期：

```
进化产出 → 应用 → 48h观察期
  ├─ 胜率 > 基线+5% → 保留
  ├─ 胜率 ≈ 基线 → 继续观察到7天
  ├─ 胜率 < 基线-10% → 自动回滚
  └─ 连续3笔全亏 → 立即回滚 + 标记"可疑"
```

**已有机制**（确认）：
- `opencode_proposal_applier._cross_validate_validated_proposals`：24h后复查
- `wisdom_tracker`：10样本+EMA<0.25自动停用
- `_check_adaptation_needed`：7/10/13/15连亏阶梯响应

**需增强**：
- NSGA-II的champion参数也需要48h观察期（当前直接写入v5_runtime_gates.json）
- L2 prompt A/B测试的最小样本量需要提高（当前≥3，建议≥10）

#### 设计3：LLM超时/降级链

```
LLM调用 → 超时(30s) → 重试1次 → 再超时
  ├─ SwingAgent: 回退到orchestrator.mid_bias规则（已有_fallback）
  ├─ TrendAgent: 回退到orchestrator.long_bias规则（已有_fallback）
  ├─ thesis_update: 跳过本tick更新，用旧thesis（已有）
  ├─ 辩论层: 回退到纯规则辩论（已有_rule_turn）
  └─ MasterController: 回退到规则化fallback（已有_rule_based_fallback）
```

**已有且充分**——所有LLM调用点都有规则化fallback。

#### 设计4：DB写入失败保护

```
DB写入 → 失败
  ├─ 进程内缓存保留（thesis_store._THESIS_CACHE）
  ├─ 下次tick重试（幂等写入）
  ├─ 3次失败 → 降级到"只读模式"（不做进化更新）
  └─ 日志告警
```

**已有**：hermes_db._write_lock + 进程内缓存 + 幂等设计。

#### 设计5：防止"错误教训"毒化

这是最重要的防线：

```
亏损 → causal_analyzer诊断 → 分类
  ├─ REGIME_SHIFT（市场变了）→ 教训标记"市场因素"，不归咎策略
  ├─ UNTRADABLE_MARKET（不可交易）→ 教训标记"环境因素"
  ├─ OVER_TRADING（过度交易）→ 教训标记"执行因素"
  ├─ STRATEGY_ERROR（策略错了）→ 教训标记"策略因素"，回灌prompt
  └─ UNKNOWN_RISK（未知）→ 标记"待观察"，不立即回灌

教训回灌 → 7天衰减 → 10样本后EMA评估
  ├─ effectiveness > 0.5 → 继续使用
  ├─ effectiveness 0.25-0.5 → 降低权重
  └─ effectiveness < 0.25 → 停用（已有）
```

**已有且充分**——causal_analyzer + wisdom_tracker + Hebbian衰减。
