# AutoCoin 选币改造落地设计稿

> 文档版本：V1.0  
> 日期：2026-08-02  
> 前置文档：[AI选币深度调研报告（会话产出）] + `docs/AutoCoin选币模块升级设计方案.md`  
> 目标读者：开发落地 / 产品验收  
> 原则：**先修断线 → 再加维度 → 再上快通道 → 最后调全量间隔**；每阶段可独立回滚。

---

## 0. 一句话目标

把 AutoCoin 从「30 分钟量价五维选池」升级成「**综合情报选币**」：  
**量价 + 资金流/CVD/OI + 鲸鱼 + 新闻事件 + 板块联动**，并用 **快/常/慢三档节奏** 匹配币圈热点半衰期；输出仍只服务短线 `scalp`。

---

## 0.1 紧急前置：选币“卡死”排查结论（2026-08-02）

> **升级前必须先恢复扫描。** 当日日志已证实：不是调度器线程死锁，而是 **每轮 Phase1 扫描崩溃**。

| 项 | 结论 |
|----|------|
| 现象 | 池子长期几乎不换币；前端/文件像“好久没更新” |
| 硬故障 | `scan_candidates` 使用 `_os.getenv`，但该函数未 `import os as _os` → `NameError: name '_os' is not defined` |
| 证据 | `logs/backend.log` 2026-08-02 19:44:41：`会话 fa_10d44c724e 扫描失败: name '_os' is not defined` |
| 调度器状态 | **仍在跑**：失败后 `sleep(1800)` 再试；属于 **崩溃重试环**，不是卡死 |
| 为何文件 mtime 还会变 | 健康检查路径会跑 **到期续期**（`Expiry renewed`），重置 `injected_at` / 写回 json，造成“有写入但币种不变”的假象 |
| 软停滞 | 池满 7/7 + 到期综合分≥0.45 就续期 + 替换门槛 `REPLACEMENT_MARGIN=0.20` → 即使扫描成功也很难换新币 |
| 修复 | 已将 Phase1 中 `_os` 改为模块级 `os`（`auto_coin_selector.py`）；**需重启后端进程后生效** |
| 验证 | 重启后看日志应出现 `Phase 1 done` / `Phase 4`；可用 API `scan-now` 立即触发一轮 |

## 2. 现状基线（改造锚点）

| 组件 | 现状 | 问题 |
|------|------|------|
| 主循环 | `AutoCoinScheduler` sleep **1800s** | 单一频率，热点慢半拍 |
| Phase1 评分 | 五维 + regime 权重 + 可选 `factor_match` + 社交 bonus | factor 常因 `FEATURE_FACTOR_EXPOSURE_ENABLED=false` 空转 |
| Phase2 Enrich | 调新闻/鲸鱼 | 接口名错误 / 方法不存在，异常被吞 |
| 板块 | `auto_coin_sectors.py` 静态 ~40 币 | 只做多样性，无联动 |
| 下游 | 仅 `scalp`；V5 缩仓/严 RR | 保持，不放松实盘门禁 |

**改造后逻辑不变的契约：**

- 输出仍是「注入 session 的 auto_coin 池」（默认容量 7）
- 仅允许 `AUTO_COIN_ALLOWED_NATURES={"scalp"}`
- 失败降级：任何新维度缺数据 → 跳过该维，**不阻断**旧五维流水线

## 3. 目标架构

```
                    ┌─────────────────────────────────────┐
                    │  Event Bus（轻量内存触发器）           │
                    │  爆量Z / OIΔ / 鲸鱼异动 / 新闻冲击     │
                    │  / 板块龙头异动 / Trending 跃迁         │
                    └──────────────┬──────────────────────┘
                                   │ enqueue
           ┌───────────────────────┼───────────────────────┐
           ▼                       ▼                       ▼
   Fast Lane 120–300s       Normal Rescore 600–900s    Full Scan 1800–3600s
   只评 watchlist+事件币      重评观察池 Top50            全市场五维+扩维
           │                       │                       │
           └───────────────────────┴───────────┬───────────┘
                                               ▼
                                    Candidate Merge & Rank
                                               │
                         ┌─────────────────────┼─────────────────────┐
                         ▼                     ▼                     ▼
                   Enrich TOP30          AI Review TOP15        Inject / Eval
                   (news/whale/flow)     (降频或事件强制审)      (池替换/淘汰)
```

**关键设计决策：**

1. **全量扫描间隔可先保持 1800s**；性能与热点响应靠 Fast Lane 解决。  
2. **新维度先进 Enrich + AI Prompt，再进 Phase1 硬分**（降低全市场 API 压力）。  
3. Phase1 全市场只算「便宜信号」；贵信号（鲸鱼逐笔、新闻 LLM）仅对 Top/事件币计算。

## 4. 分阶段实施计划

### 阶段总览

| 阶段 | 名称 | 工期估 | 依赖 | 交付后系统状态 |
|------|------|--------|------|----------------|
| **M0** | 止血断线 | 0.5–1 天 | 无 | 新闻/鲸鱼/字段可用；有日志可观测 |
| **M1** | 评分扩维（软接入） | 1–1.5 天 | M0 | 综合分含 flow/whale/news；缺数据降级 |

### 5.2 接口契约

#### `NewsIntelligenceService.get_symbol_sentiment`

```python
def get_symbol_sentiment(self, symbol: str, hours: int = 24) -> Dict[str, Any]:
    """
    返回:
    {
      "sentiment": float,          # -1~+1，来自 get_aggregate_sentiment
      "sentiment_label": str,      # bullish/neutral/bearish
      "social_volume": int,        # 近 hours 相关新闻条数
      "top_events": List[dict],    # 最多 3 条 {title, direction, strength, confidence}
      "freshness_min": float|None, # 最近一条距现在分钟数
      "available": bool,
    }
    """
```

规则：

- `sentiment > 0.25` → bullish；`< -0.25` → bearish；否则 neutral  
- 无信号：`available=False`，`sentiment=0.0`，**不要**用涨跌幅伪造（M0 起废除 HL 伪情绪回退，或降级为 `proxy_price_sentiment` 并打标，禁止写入 `news_sentiment` 主字段）

#### `AggregateWhaleCollector.get_recent_trades_summary`

优先读单例缓存 / 最近一次 `collect` 结果，避免选币时对全所 `fetch_trades` 打爆限频。

```python
def get_recent_trades_summary(self, symbol: str, limit: int = 20) -> Dict[str, Any]:
    """
    返回:
    {
      "net_direction": "buy"|"sell"|"neutral",  # direction>0.15 buy; <-0.15 sell
      "buy_volume": float,   # whale_buy 合计 USD
      "sell_volume": float,
      "net_usd": float,
      "whale_count": int,
      "confidence": float,   # 0~1
      "available": bool,
    }
    """
```

若缓存无该 symbol：`available=False`，不抛异常。

## 6. M1 — 评分扩维（软接入）

### 6.1 评分模型（V3 Soft）

保留原五维作为 `base_score`，新增附加维，合成：

```
composite = w_base * base_score
          + w_flow * flow_score
          + w_whale * whale_score
          + w_news * news_score
          + w_sector * sector_rs_score   # M2 接入前 sector=0.5 中性且权重归入 base
```

缺数据时该维权重 **重新归一化到可用维**（不是填 0.5 混过 cutoff）。

### 6.2 各维定义

#### `base_score`（现有）

`vol / mom / fund / vola / trend` + regime 权重（代码已有，不改公式，只改合成层）。

#### `flow_score`（资金流 / 衍生品）

数据源优先级：

1. 已有 CVD 聚合（`ACTIVE_MARKET_FLOW_EXCHANGES` / 指标缓存）  
2. OI 变化（`oi_history` 或 HL snapshot）  
3. Funding 偏离（可与现有 `fund_score` 互补，避免双计：flow 侧用 OI×price 同向，fund 仍独立）

建议公式（可配置）：

```
oi_component   = clip( oi_change_pct / 8.0 , -1, 1)          # ±8% → ±1
cvd_component  = clip( cvd_direction_or_z , -1, 1)
align_bonus    = 0.15 if sign(oi)*sign(price_change_1h)>0 and |oi|>阈值 else 0
flow_raw       = 0.45*oi_component + 0.45*cvd_component + align_bonus
flow_score     = 0.5 + 0.5*flow_raw                         # 映射到 0~1
```

无 CVD/OI：`flow_score` 标记 unavailable，不参与加权。

#### `whale_score`

```
dir = +1 buy / -1 sell / 0 neutral
whale_score = 0.5 + 0.5 * dir * confidence
```

`available=False` → 跳过。

#### `news_score`

```
# freshness 衰减：120 分钟半衰期
decay = 0.5 ** (freshness_min / AUTO_COIN_NEWS_HALF_LIFE_MIN)
news_score = 0.5 + 0.5 * sentiment * decay * max(confidence, 0.3)
```

强利空硬门（见 6.4）。

| 参数 | 默认 | 说明 |
|------|------|------|
| `AUTO_COIN_W_BASE` | `0.55` | 原五维 |
| `AUTO_COIN_W_FLOW` | `0.20` | CVD/OI |
| `AUTO_COIN_W_WHALE` | `0.10` | 鲸鱼 |
| `AUTO_COIN_W_NEWS` | `0.10` | 新闻 |

| `AUTO_COIN_SCORE_V3_ENABLED` | `false` | **总开关，默认关**；M1 合入后灰度开 |
| `AUTO_COIN_NEWS_HALF_LIFE_MIN` | `120` | 新闻衰减半衰期（分钟） |
| `AUTO_COIN_FLOW_OI_CLIP_PCT` | `8.0` | OI 变化裁剪 |
| `AUTO_COIN_MIN_SCORE` | `0.50` | 门槛不变（验收对比用） |

Regime 微调（可选，M1 末加）：

| Regime | 调整 |
|--------|------|
| trending | `W_BASE` 内 mom/trend 已重；外层 `W_FLOW +0.05`, `W_NEWS -0.05`（归一化） |
| extreme | `W_WHALE +0.05`, `W_FLOW +0.05`, `W_NEWS` 仅硬门 |
| ranging | `W_BASE` 偏流动性；外层保持默认 |

### 6.4 硬门（先于加权）

| 条件 | 动作 |
|------|------|
| 新闻 `sentiment <= -0.6` 且 `strength >= 4` 且 freshness ≤ 180min | **禁止入选**（本轮 + 冷却 `AUTO_COIN_NEWS_COOLING_HOURS=4`） |
| 24h 跌幅 ≤ -15%（已有 AI Layer F 思路） | Phase1 直接丢弃或分上限 0.35 |
| Universe 不合格 | 保持现有硬门 |
| 鲸鱼 `confidence>=0.8` 且净卖 + 价格假突破（可选 M1.1） | 降权，不硬杀（防误杀） |

### 6.5 计算分层（控成本）

| 阶段 | 计算内容 |
|------|----------|
| Phase1 全市场 | 仅 `base_score` + 便宜代理（若有缓存的 OI/CVD 字典则加 flow；否则不加） |
| Phase1 后 Top100 | 补算 whale/news（读缓存，禁止同步全所拉取） |
| Phase2 Top30 | 完整 Enrich，刷新 flow/whale/news，**重算 composite 一次** |
| Phase3 | Prompt 必须带 available 标志与各维分数 |

## 7. M2 — 板块联动

### 7.1 目标

从「多样性装饰」升级为「**题材 beta + 龙头跟风**」。

### 7.2 模块改动

| 文件 | 职责 |
|------|------|
| `auto_coin_sectors.py` | 扩展：静态底表 + 外部分类缓存 + `get_sector_peers` |
| 新建 `auto_coin_sector_signal.py` | 板块收益、RS、龙头检测 |
| `auto_coin_selector.py` | 接入 `sector_rs_score`；龙头币入 watchlist |

### 7.3 动态分类策略

1. **L1 静态表**（现有 `SYMBOL_SECTOR_MAP`）保证离线可用  
2. **L2 缓存**：启动/每 6h 从 CoinGecko categories（或交易所 tags）刷新；失败用 L1  
3. 未知币：`other`，但若 24h 成交额进市场 Top N 且与某板块收益相关 ρ≥0.7，则 **临时挂靠** 该板块（可选，M2.1）

板块枚举建议统一：

`major / defi / infra / meme / ai / gaming / data / rwa / other`

（与现表兼容，避免前端大改。）

### 7.4 板块信号算法

对每个板块 `S`：

```
sector_ret_4h = 成交额加权 mean(ret_4h of members in tradable universe)
leader = argmax(volume_z_1h * ret_1h) among members with vol_24h >= 门槛
```

对币 `i ∈ S`：

```
rs_4h = ret_4h(i) - sector_ret_4h
sector_rs_score = clip(0.5 + rs_4h / 0.10, 0, 1)   # 相对板块 ±10% → 满幅
```

**龙头触发（进 Fast Lane 观察池）：**

```
IF leader.ret_1h >= AUTO_COIN_SECTOR_LEADER_RET_1H
AND leader.volume_z_1h >= AUTO_COIN_SECTOR_LEADER_VOL_Z
THEN enqueue peers (同板块 Top K by vol，排除 leader) 到 watchlist，TTL=AUTO_COIN_WATCH_TTL_MIN
```

多样性：保留现有 `get_diversity_score`；注入时同板块最多 `AUTO_COIN_MAX_PER_SECTOR` 个。

### 7.5 M2 参数

| 参数 | 默认 | 说明 |
|------|------|------|
| `AUTO_COIN_SECTOR_SIGNAL_ENABLED` | `false` | 总开关 |
| `AUTO_COIN_SECTOR_CACHE_HOURS` | `6` | 动态分类刷新 |
| `AUTO_COIN_W_SECTOR` | `0.05`→开启后建议 `0.10`（同时降 `W_BASE` 至 0.50） | |
| `AUTO_COIN_SECTOR_LEADER_RET_1H` | `0.04` | 龙头 1h 涨幅阈值 4% |
| `AUTO_COIN_SECTOR_LEADER_VOL_Z` | `2.0` | 成交量 Z 分数 |
| `AUTO_COIN_SECTOR_PEER_TOP_K` | `4` | 跟风观察数量 |
| `AUTO_COIN_MAX_PER_SECTOR` | `2` | 池内同板块上限 |
| `AUTO_COIN_WATCH_TTL_MIN` | `45` | 观察池存活分钟 |

## 8. M3 — 三档调度

### 8.1 调度模型

替换「单一 `asyncio.sleep(1800)`」为协调器（可仍在 `AutoCoinScheduler` 内）：

| Lane | 默认间隔 | 触发 | 工作内容 |
|------|----------|------|----------|
| **Full** | `AUTO_COIN_SCAN_INTERVAL=1800` | 定时 | 全市场 Phase1→…→Eval（现流程） |
| **Normal** | `AUTO_COIN_NORMAL_INTERVAL_SEC=900` | 定时 | 仅重评 `watchlist ∪ active_pool ∪ last_top50` |
| **Fast** | `AUTO_COIN_FAST_INTERVAL_SEC=180` | 定时轮询事件队列 + 最短间隔 | 只评事件币+peers；命中阈值可 `force_ai_review` |

并发规则：

- 同一 `session_id` **同时只跑一个 lane 任务**（锁）；Fast 可抢占排队中的 Normal，不打断正在跑的 Full  
- Fast 产出的高分币写入 `pending_inject`；若距上次 AI 完整审核 < 间隔，允许 **事件强制审**（见参数）

### 8.2 事件源（轻量）

| 事件 | 检测 | 入队 payload |
|------|------|----------------|
| 爆量 | 1h vol_z ≥ 阈值（对 watch/top 集） | `{sym, type:volume}` |
| OI 急变 | \|oi_change_pct\| ≥ 阈值 | `{sym, type:oi}` |
| 鲸鱼 | available 且 \|direction\|≥阈值 且 confidence≥0.6 | `{sym, type:whale}` |
| 新闻 | \|sentiment\|≥0.5 且 freshness≤60min | `{sym, type:news}` |
| 板块龙头 | M2 条件 | `{sym:leader, peers:[...], type:sector}` |
| Trending 跃迁 | CoinGecko 新进前 7 | `{sym, type:social}` |

事件去重：`symbol+type` 冷却 `AUTO_COIN_EVENT_DEDUP_SEC=300`。

## 14. 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| 鲸鱼 collect 未覆盖选币符号 | whale 维长期 unavailable | 对 Top30 懒加载单币 summary；失败降级 |
| 新闻源偏 BTC/ETH | 山寨 news_hit 低 | RSS 标题符号抽取 + 仅硬门用强信号；弱信号不降权 |
| Fast Lane 过频导致池抖动 | 交易成本↑ | `MIN_HOLD`、替换 margin、事件去重、日替换熔断 |
| LLM 费用上涨 | 成本 | `FAST_AI_MAX_PER_HOUR` + 默认降频 |
| 板块跟风买在高潮 | 亏损 | peer 仅进 watchlist，仍走 MIN_SCORE + AI；试仓 Layer D/E |
| asyncio 线程嵌套老问题 | 调度不稳 | M3 改调度时一并改为「主 loop create_task」，去掉线程内 `asyncio.run`（顺手修 P6） |

## 16. 开发前逻辑确认（给不懂代码的同学）

用买菜类比：

1. **以前**：每 30 分钟去一次大市场，只看「贵不贵、人多不多」，回来决定篮子里放哪 7 样菜。  
2. **M0**：把坏掉的「新闻电话」和「大户动向电话」修好——以前假装打通了，其实没响。  
3. **M1**：买菜时还要看「资金往哪流、大户买不买、有没有突发坏消息」。  
4. **M2**：知道青菜是一类、肉是一类；青菜带头涨价时，留意同类，但篮子里同类最多 2 样。  
5. **M3**：不必每次都逛完整个市场——有人喊「那边突然排队」就先跑去看（快通道）；平常 15 分钟看一眼观察清单；半小时再全场巡一遍。

**验收就看三句话：**  
坏电话是否真能打通；有突发时是否 5 分钟内有反应；选进来的币 4 小时后整体不比现在更差。
