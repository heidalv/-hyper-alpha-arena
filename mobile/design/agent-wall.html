Agent Wall 移动端关系设计

不用画布，但保留画布的三样东西：全局分布、连接关系、当前运行情况。

核心思路：把「墙」换一个轴

  • 画布是二维全局视图；手机换成一维焦点视图。
  • 全局 → 分组摘要条：一组一行，右侧 mini 状态栈，密度天然可控。
  • 连接 → 关系条：一次只画焦点节点的 3–5 个邻居，永远不重叠。
  • 运行情况 → 关系条上的流动点表示边在传数据，虚线表示断链/未生效。

为什么关系条能替代画布

  • 节点卡的边框色 + 左侧竖条＝画布上的节点状态灯。
  • 节点卡下方的 ok / 12s 前 ＝画布上的状态标注。
  • 连接柱上的流动点 ＝ 画布上的动画边（数据在传）。
  • 虚线连接柱 ＝ 画布上的红色/灰色边（断链 / 未生效）。
  • 连接柱中央的标签 ＝ 画布上的边标签（"开仓权威"）。

换句话说：画布上的每个视觉元素都有一一对应，只是从"同时看到全部"改成"聚焦时看到相关的那几个"。

三种视图的分工

  • 屏 1 分组总览：回答"哪里出问题了"。点进去 = 缩小范围。
  • 屏 2 节点关系：回答"这个节点和谁连着、哪条线不通"。是排查的主力页。
  • 屏 3 链路透镜：回答"业务上这条链走到哪一步了"。这是画布做不到的——画布只画拓扑，不画业务顺序。

交互细节

  • 关系条横向滑动（overflow-x），纵向不劫持页面滚动。
  • 相邻节点可点，等于「沿着边走一步」，比画布的缩放平移更适合拇指。
  • 边标签在最窄处也保留：宁可换行，不省略（因为边标签就是业务语义）。
  • 三种边状态：实线流动＝在传；红虚线＝断链；黄虚线＝未生效。停用节点半透明，不算故障。

数据映射（真实字段）

  • 分组摘要：/api/agent-wall/state → groups[] 的 total/ok/stale/dead/never/disabled
  • 节点四态：nodes[].status（ok/stale/dead/never/disabled）+ status_detail.reason
  • 边健康：edges[].health.state（ok/stale/broken/ineffective）+ reason
  • 边标签：edges[].label；边类型：edges[].kind（data/trigger/decision/audit/ledger/advice/config）
  • 实时内容：/api/agent-wall/tail?nodes=a,b（≤12 节点，服务端游标增量）

注：edges[] 已过滤悬空边（宁可少画也不画假边），所以关系条上的邻居一定真实存在。
