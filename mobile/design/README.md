# AlphaArena Android 移动端 · 样式设计说明（V4）

> 交付物：
> - `mobile/design/index.html` — **10 屏样式全览**（双击浏览器打开，零依赖、离线可用）
> - `mobile/design/interactive.html` — **可交互原型**（Tab 切换 / 环境切换 / 3s 节点轮询 / 真实追加的流式日志）
> - `mobile/design/agent-wall.html` — **Agent Wall 无画布方案**（关系条 + 链路透镜，单独拿出讨论）
> - 文中所有数值均为 **mockup 示意**，不是当前实盘数据。

## 1. 层级（唯一权威，V4 已锁定）

```
底部导航（业务模块，3 个）
 ├── 仪表盘   →  2×2 总览：高频(实盘/模拟) + 交易(实盘/模拟)
 ├── 高频     →  实盘 / 模拟        ← 模块内第二级
 └── 交易     →  实盘 / 模拟        ← 模块内第二级
```

- **高频** 与 **交易** 是**并列**的两个业务线，不是包含关系。
- **模拟 / 实盘** 不是模块，是**每个模块内部的第二级**。
- 第二级用 App 栏正下方的「环境切换控件」（`.envtabs`）表达：

```
┌──────────────┬──────────────┐
│ ● 实盘        │ ● 模拟        │   ← 每个按钮内自带该环境的权益简值与涨跌
│ $24.3k +1.18%│ $10.2k +1.86%│      切换前就能比较，避免来回横跳
└──────────────┴──────────────┘
```

规范：控件 44dp 高、两段等宽、中缝 1px 分隔；选中态用该环境的身份色描边 + 底色。
在**盘口**这类环境无关视图上，按钮内的简值换成「我方挂单量 / 队列占比」，不放权益。

## 2. 设计目标与信息优先级

移动端只解决一件事：**看运行情况**。本项目是**全自动交易**，所以人不该是下单主体，而是**监督者**。

| 优先级 | 问题 | 落在哪 |
|---|---|---|
| P0 | 自动化链路还在转吗？哪一段断了？ | 仪表盘首屏「链路健康」+ 节点四态 |
| P0 | 数据到底在不在流？ | 全局顶部连接状态条（连没连 / 从哪来 / 多久前） |
| P0 | agent 此刻在做什么？ | 实时日志流 + 执行链 |
| P1 | 两个环境各自表现如何？ | 仪表盘 2×2；模块内环境切换 |
| P1 | 高频这一笔挂得值不值？ | 高频 · 盘口 / 成本桥 |
| P2 | 模拟结论能不能代表实盘？ | 同决策命中率 + 偏差明细 |
| P3 | 出事了怎么脱身？ | 兜底平仓（折叠在页底，强制二次确认） |

**明确不做**：策略参数编辑、回测配置、日志全文检索、密集表格、**手动开仓面板**。

### 4.1 高频页的信息顺序（V5 按截图反馈修正）

初版高频页只有「今日净收益 + 每腿 bp + 腿速/成交率/点差」，**缺账户维度**。修正后顺序固定为：

```
① 今日表现     今日净收益 · 每腿净 bp · 腿速 · 成交率 · 均点差 · 数据龄
② 账户总览     账户总权益（等宽大字）· 今日盈亏 · 本期累计
               ├─ 可用 / 持仓价值（含个数）
               └─ 已实现盈亏 / 未实现盈亏
③ 成本 · 本期  累计手续费（taker 笔数）· 资金费 · 滑点 · 净额
               └─ 全历史审计口径（单独一行，显式标「全历史」）
④ 报价与成交流  实时日志渲染器
⑤ 机器两腿     挂单价 + 数量 + 队列前方占比
⑥ 自动判断     报价 / 闸门拒绝 / 成交 计数 + 实盘就绪度
```

要点：
- **权益口径必须写在明面上**（`可用 + 冻结 + 浮盈`），因为账户表的 `total_equity` 字段曾陈旧不更新，
  界面不能只给一个数字而不说它怎么来的。
- **金额用 4 位小数**。这条车道的单笔量级很小（实测 22 笔成交净额 +0.0038 USD），
  两位小数格式化后必然显示 $300.00，看起来像死的。
- **手续费要显眼**，它不是明细项而是第一成本项：实测强平腿的 taker 费占整夜亏损 97%。
  同时给出「全历史」与「本期」两个口径并标注清楚，避免读者把两个时代的数字混起来。

### 4.2 兜底平仓（V5 按需求补入）

持仓必须能随时精准脱身，所以 `交易` 模块（实盘 / 模拟两侧一致）提供两级兜底：

```
┌─ 自动仓位 · 4 ────────────────────────────────┐
│ ● BTC  多 3x  0.0098 BTC   +$318.40   [平仓] │ ← 每行一个键，常驻不折叠
│ ● SOL  空 2x  6.20 SOL      -$94.20   [平仓] │
│ ● ETH  多 2x  0.184 ETH    +$182.10   [平仓] │
│ ● XRP  多 4x  412 XRP        +$6.30   [平仓] │
│                                               │
│ [ 一键全平（4 个仓位） ]                       │ ← 点击后弹悬浮确认窗
└───────────────────────────────────────────────┘
```

**单条平仓**（`data-close-pos`）：
- 按钮 28dp 高、常驻在每行右侧，实盘红 / 模拟紫，与身份色一致。
- 点击 → 悬浮确认窗，内容必须包含：仓位全称（`SOL 空 2x 6.20 SOL`）、当前未实现盈亏、
  预估平仓手续费、**平仓后的保证金占用**、以及「市价成交、不可撤销」的措辞。
- 执行结果写进决策流：`兜底平仓｜平仓已提交 · SOL`。

**一键全平**（`data-close-all`）三重保护：
1. 必须点按钮才弹窗（不做长按、不做快捷键，避免误触）；
2. 弹窗列清**每一个**仓位 + 合计未实现盈亏 + 名义额 + 预估总手续费 + 平仓后占用，
   并写明「平仓后不再有新仓位产生，直到你恢复自动开仓」；
3. 确认键带**冷静期**：实盘 3s / 模拟 2s，倒计时结束前 `disabled`，防连点误触。

取消键永远在左、确认键在右；确认键是该屏唯一的实心身份色元素。
执行后会往决策流写一条 `人工干预` 记录（`一键全平 N 个仓位（人工干预）`），
这样事后审计能看到人插过手，而不是只看到仓位凭空消失。

**模拟侧也保留同样的两级兜底**——用来演练「自动化卡死时怎么脱身」，且不会碰到真钱。

## 5. 三个自研组件的规范

### 5.1 环境切换控件（`EnvTabs`）
- 位置：App 栏正下方，**只在「高频」「交易」模块出现**（仪表盘无环境）。
- 结构：两段 + 1px 中缝；每段两行（环境名 + 该环境实测简值）。
- 选中态：实盘 `rgb(239 68 68 / .16)` 底 + 红字 + 红描边；模拟同理用紫。
- 联动：切换后**状态条、徽标、横幅、危险按钮、流内容**全部换色换数据源。
- 落地：一个 `env: 'live' | 'paper'` 状态驱动，**不复制组件**。

### 5.2 流式日志渲染器（`StreamView`）
移动端渲染长连接的四个必需控件，缺一个都会出事：

| 控件 | 作用 | 规格 |
|---|---|---|
| 暂停 | 全局停流（本地），保住注意力 | 状态点变灰 + 文案「流已暂停（本地）」 |
| 缓冲上限 | 防内存与 DOM 膨胀 | 200 行，超出丢最旧，页脚常显 `184/200` |
| 自动滚动 + 上滑冻结 | 手一碰就停，别抢滚动 | 滚动位置距底 > 24px 即冻结 |
| 点击行看 raw | 中文是编译过的，原文要能回溯 | 后端 `to_zh()` 给中文，`raw` 保原文 |

另加两个：**合帧渲染**（100ms 批量打 DOM，避免高频事件逐条 reflow）、**流速开关**（1× / 4× / 停）。
日志行左侧 2px 色条表示语义：绿=正常/已通过、琥珀=需看、红=异常。

### 5.3 连接状态条（`NetStrip`）
贯穿所有页面的地基，一行回答三件事：

```
● 实盘报价在流   │  深度 105ms        │  运行态 2.1s
  连没连            数据来自哪(接口/节点)    多久前（超阈值变琥珀/红）
```

**必须如实标注**：`/api/hft/board` 的运行态可能来自 `snapshot_file`（准实时）或 `in_process_runner`（可能陈旧），
界面要显示来源与年龄，**不假装实时**。

### 5.4 主题（日间 / 夜间 / 跟随系统）

**三档开关**：跟随系统（默认）/ 日间 / 夜间。入口在设置页顶部「外观」，并可在 App 栏放一个快捷按钮。

| 项 | 规格 |
|---|---|
| 令牌 | 名字不变，只换值：`--terminal-bg / card / card-2 / border / profit / loss / primary / muted / text / warning / paper` |
| 作用域 | 两个都挂在 `<html>`：`.light` / `.dark`（`hooks/useTheme.tsx` 的 `applyThemeClass()` 切换） |
| 跟随系统 | `matchMedia('(prefers-color-scheme: light)')` + `change` 监听，系统切深色时看板同步切 |
| 持久化 | `localStorage.alphaarena_theme = 'system' \| 'light' \| 'dark'` |
| 首帧防白闪 | 主题必须在 body 渲染前同步落地，否则深色用户会看到一闪的白 |
| 跟随态的图标 | **必须显示此刻实际解析成什么**（太阳/月亮随系统变），否则用户无法判断跟随是否生效 |

**浅色不是深色「减淡」，是按光环境重定对比度基准**（详见 `design/light-mode.html`，逐令牌给了理由）：

| 令牌 | 夜间 | 日间 | 为什么必须改 |
|---|---|---|---|
| `profit` | `#00dc82` | `#059669` | 亮绿在白底上几乎不可读 |
| `loss` / 实盘身份 | `#ef4444` | `#dc2626` | 白底上要压深才实 |
| `paper` / 模拟身份 | `#8b5cf6` | `#7c3aed` | 同上 |
| `warning` | `#f59e0b` | `#d97706` | `#f59e0b` 在白底对比度不达标 |
| `primary` | `#3b82f6` | `#2563eb` | 保证正文级可读（≈4.9:1） |
| `bg` | `#0a0e17` | `#f6f8fb` | **不用纯白**：纯白刺眼，且卡片浮不起来 |
| `card` | `#111827` | `#ffffff` | 层次靠「白压灰」而非「亮压暗」 |
| `border` | `#1f2937` | `#d6dee8` | 浅色下边框是主要分隔手段，不能太淡 |
| 遮罩 | 黑纱 64% | 深纱 38% | 浅色下重遮罩会把整屏压成灰板、内容全看不清 |
| 投影 | 无（靠发光） | `0 1px 3px rgb(15 23 42 / .05)` | 浅色下层次手段换成「细边 + 极轻投影」 |

**四个浅色专属坑**：
1. 页面底不用纯白（刺眼 + 卡片浮不起来）；
2. 遮罩浓度必须降低，否则弹层背景糊成一块；
3. 流式日志的深底要换成浅底 —— 深色块在白天像屏幕上开了个洞；
4. **断流态不能用降透明度**（浅灰文字会直接消失），要改用 `filter: saturate(.35)` 抽掉颜色、保留对比。

**已验证的工程状态**：`mobile/app/hooks/useTheme.tsx` 的三态管道（`ThemeMode = 'system' | 'light' | 'dark'` + `matchMedia` 监听 + `localStorage`）**本来就是齐的**，
缺的是三档 UI 与浅色令牌质量。本次补齐：`components/settings/SettingsPage.tsx` 新增 `ThemeSettings`（三档选择）、
`app/index.css` 重定浅色令牌并修掉一个选择器缺陷（详见下）、`tailwind.config.js` 增补 `card-2` / `paper` / `boxShadow.card`。

> ⚠️ **修掉的选择器缺陷**：原 `index.css` 里 `body` 规则处在 `@layer base` 中、不带作用域，
> 于是 `.light` 只覆盖了令牌声明，而 body 上的 `@apply bg-terminal-bg` 解析结果在非 `.light` 祖先下会退化。
> 现在把作用域组显式写成 `:root, .dark, .light`，并分别声明 `color-scheme`，保证系统控件（滚动条、输入框）
> 也跟着主题走。


贯穿所有页面的地基，一行回答三件事：

  连没连            数据来自哪(接口/节点)    多久前（超阈值变琥珀/红）

## 6. Agent Wall 无画布方案（详见 `agent-wall.html`）

38 节点 / 96 条边在 390dp 上必然重叠成毛线。解决方式是**把「墙」换一个轴**：从「二维全局地图」改成「一维焦点 + 业务链」。

| 画布上的东西 | 移动端的对应物 |
|---|---|
| 节点状态灯 | 节点卡左侧 2px 竖条 + 徽标色 |
| 节点状态标注 | 节点卡下方 `ok · 12s 前` |
| 动画边（数据在传） | 连接柱上的**流动点**（CSS 动画） |
| 红色边（断链） | **红虚线**连接柱 |
| 灰色边（未生效） | **黄虚线**连接柱 |
| 边标签 | 连接柱中央文字，绝不省略 |
| 全局拓扑 | **链路透镜**：纵向路径 + 并行泳道 + 流动线 |

三个视图分工：
1. **分组总览** — 回答「哪里出问题了」，一组一行 + mini 状态栈。
2. **节点关系** — 回答「这个节点和谁连着、哪条线不通」，横向关系条，一次只画 3–5 个邻居。
3. **链路透镜** — 回答「业务上这条链走到哪一步」，**这是画布做不到的**（画布只画拓扑，不画业务顺序）。

关键设计：**分叉点直接画两个落点**（执行·模拟 / 执行·实盘），在同一张图里说明「同一条链、两个环境」。

## 7. 数据字段映射（落地用）

### 7.1 Agent 运行链路
| 界面元素 | 端点 | 字段 |
|---|---|---|
| 分组摘要条 | `GET /api/agent-wall/state` | `groups[]` → `total / ok / stale / dead / never / disabled` |
| 节点四态 | 同上 | `nodes[].status`（ok/stale/dead/never/disabled）+ `status_detail.reason` |
| 边健康 | 同上 | `edges[].health.state`（ok/stale/broken/ineffective）+ `reason` |
| 边标签 / 类型 | 同上 | `edges[].label` / `edges[].kind`（data/trigger/decision/audit/ledger/advice/config） |
| 实时内容 | `GET /api/agent-wall/tail?nodes=a,b` | `lines{node: [{ts, text, raw}]}`，**服务端游标增量，≤12 节点** |
| 断链与逻辑错误清单 | `GET /api/agent-wall/audit` | `kind=live` 现场重算 / `kind=static_verified` 实测 |

> `state` 单请求拿全，2–3s 轮询；`tail` 一次覆盖所有可见节点，**不要做每节点一个端点**
> （后端单进程、GIL 长期贴 1 核，24 节点各自轮询会让请求数放大 24 倍）。

### 7.2 高频交易
| 界面元素 | 端点 | 字段 |
|---|---|---|

| 账户重置 / 启停 | `POST /api/hft/account/reset`、`/control/*` | `balance`（默认 300） |

**三条口径纪律**（都在后端注释里踩过坑，界面上必须体现）：
1. **同一张卡片上的数字必须同处一个时代**。`realized_usd` 与 `fee_usd` 都按 `stats_since`（重置时刻）裁剪；
   全历史量只能出现在带「全历史」标签的位置，且不与本期相加。
2. **金额不能拿 bp 之和去乘名义之和**。`Σbp × Σnotional` 会把每笔的 bp 当成全部名义的 bp，
   实测虚报 71~103 倍。一律**逐行折算后求和**。
3. **`equity-series` 是净额累计，不是账户权益**。两者口径不同时要如实披露差值，不做缩放粉饰。

## 8. 交互与安全规则

1. **所有可执行动作二次确认**：单条平仓、一键全平、暂停自动开仓、重置资金、启停会话。
   确认面板必须写清「影响什么 / 不影响什么 / 怎么恢复」。
2. **危险动作按钮排布固定**：取消在左、确认在右，确认是唯一的实心身份色元素。
3. **不可逆操作加冷静期**：一键全平这类影响全部仓位的动作，确认键实盘 3s / 模拟 2s 后才可点。
4. **人工干预必须留痕**：任何兜底平仓都往决策流写一条记录，事后审计要能看出"人插过手"。
5. **横向手势不劫持纵向滚动**：`touch-action: pan-y` + 位移阈值 3px。
6. **数据新鲜度显式呈现**：任何依赖快照/运行态的数据都带年龄标签，超阈值变琥珀/红。
7. **断流态单独设计**：整屏降饱和 + 两个环境一起标陈旧 + 明确写「服务端是否仍在交易＝未知」。
8. **不使用系统 Alert / Confirm**：全部走 BottomSheet，保证触控尺寸与暗色一致性。
9. **手动开仓不存在**：只保留平仓兜底（自动化卡死时脱身用）；单条平仓键常驻不折叠，全平键在下方独立成行。

## 12. 运行控制台（开关 / 紧急停摆）

对接设计见 `BACKEND_DESIGN.md`，界面稿见 `control.html`。要点复述在此，因为它是**安全特性**而非普通功能：

**前提**：App 就是**打包的前端**，直接打现有 API，没有独立 App 后端。
因此在做开关之前，先有两个硬阻断要解（详见 `BACKEND_DESIGN.md` §0 / §0.5）：

| 阻断 | 现状 | 后果 |
|---|---|---|
| **地址** | `client.ts` 写死 `API_BASE='/api'`；`useWebSocket` 用 `window.location.host` | 打包后页面 origin 变成 `https://localhost` → `/api` 打到壳自己，**全部 404** |
| **鉴权** | `middleware/auth.py` 要求所有写操作带凭证；而 `mobile/app/**` grep `Authorization/token/login` **0 命中** | 读能用、**一写就 401**；没有登录入口，无从恢复 |

这两个都是「界面看起来正常、实际不可用」的类型，比开关设计更优先。

**第一原则：手机端的「停止」按钮不是安全机制。**
断网、App 被杀、token 过期、服务器假死，任一种都会让账户继续跑而你按不到停止。
所以停摆必须在**服务端闭环**，默认失败方向是「停」。

### 12.1 五级开关

```
L0 全局总闸      kill_switch            影响：全部交易 + 全部 Agent 任务
 └ L1 模块闸     hft / trade / agent
    └ L2 对象闸  lane.status / session.status / accounts.disable_trading
       └ L3 策略闸 ai_strategy.status
          └ L4 任务闸 job_registry.enabled
（另有 L5 进程闸：环境变量，需重启）
```

- **上级为停 ⇒ 下级不执行，但不改写下级自身状态**。总闸是「求值时的与条件」，不是对下级的写操作。
  重新打开总闸时，各车道回到原本状态，而不是「全被改成 stopped」。
- 上级关闭时，下级开关**变灰且不可点** —— 明确告知被上级锁住，而不是「点了没反应」。
- 所有执行路径必须走同一个求值入口（`can_trade()`），禁止各模块自己拼 `if`。

### 12.2 四个界面元素

| 元素 | 屏 | 要点 |
|---|---|---|
| 分级开关面板 | `control.html` 1 | 总闸大字 + 模块闸 + 对象闸；被锁的开关明确变灰 |
| 判定链 | 同上 / 3 | 渲染后端 `why-stopped` 的整条链，**前端不自己判断**「是否在跑」 |
| 紧急停摆确认 | `control.html` 2 | 同卡内写清「会停什么 / 不会动什么」；默认不平仓；3s 冷静期 |
| 停摆触发器 | `control.html` 3–4 | 触发后「为什么停了」+ 触发器一览；**全部在服务端，手机不参与判定** |

### 12.3 三条不可妥协的规则

1. **默认只停新开仓，不平仓**。平仓不可逆，必须让人主动选。
2. **触发停止后不自动恢复**。抖动过去就自动恢复等于无感重启，人会在不知情下重新暴露于风险。
3. **紧急操作必须幂等**。人会慌、会连点；对「全平」来说，重复执行本身就是事故（第二次会打在已平的仓位上）。
   控制类 POST 一律带 `X-Idempotency-Key` + 单飞锁。

### 12.3.1 停摆触发器接进**已有的**看门狗

后端实测已有 6 个看门狗（`backend-watchdog.ps1` 进程存活、`job_watchdog` 300s 任务滞后、
`hang watchdog` 循环超时、`market_data_hub` stale 30s、`user_stream_guard` 15s、`evo-quick-watchdog`），
**全部是「检测 → 自愈」或「检测 → 告警」，没有一个会停交易**：

```python
# job_registry.py:462 —— 发告警，然后就没有然后了
send_alert("P1", f"定时任务中断: {j['name']}", ...)

# full_auto_trading_service.py:4027 —— 释放锁让下一轮 tick 能进，交易继续
self._force_release_unified_loop_state(session_id, reason="循环超时，线程 detached")
```

所以「任务中断 → 发条钉钉 → 系统继续按老参数交易」是当前真实行为。
**缺口是「停」这个动作，不是缺检测器。** 改法：`evaluate_breakers()` 接进已有的 `job_watchdog`（300s 一跑），
命中阈值即打开 L0 总闸——**零新增进程、零新增采集**。

⚠️ 阈值必须比告警严：现在系统对「陈旧」是**自愈**（回落 REST、重启进程），
一陈旧就停会导致**过度停摆**（数据源抖一下策略就停了，比不停更糟）。
只有「持续超阈值 **且** 自愈也失败」才停。

### 12.4 与前端现有设计的关系

- 仪表盘（`index.html` 1.1）的「链路健康」下方应加一行**总闸状态**，因为它是比盈亏更靠前的信息。
- 断流态（`index.html` 1.10）已有「服务端是否仍在交易＝未知」的措辞，与停摆触发器配合后可以更准确：
  断流时若总闸已被看门狗触发，应显示「已自动停摆（actor=breaker:data_stale）」，而不是「未知」。
- 「操作记录」可直接复用 `control_audit` 表，与事件流（`index.html` 1.2）同一种渲染器。
