## 0. 口径验证与数据质量门（先读这一节，否则后面表格会误读）

### 0.1 通用 CTE（后文所有 SQL 复用它）

```sql
WITH base AS (
  SELECT p.id, p.symbol, p.side, p.timeframe_tier AS tf, p.trade_nature AS tn,
    COALESCE(NULLIF(lower(p.exit_state_json::json->>'entry_source'),''),'UNTAGGED') AS src,
    NULLIF(split_part(COALESCE(p.close_reason,''),':',1),'') AS cr,
    COALESCE(p.unrealized_pnl,0)::float AS net,
    COALESCE(p.partial_realized_pnl,0)::float AS partial,
    COALESCE(p.partial_fee_paid,0)::float AS pfee,
    COALESCE(p.peak_unrealized_pnl,0)::float AS mfe,
    COALESCE(p.trough_unrealized_pnl,0)::float AS mae,
    COALESCE(p.peak_pnl_pct,0)::float AS mfe_pct,
    COALESCE(p.trough_pnl_pct,0)::float AS mae_pct,
    COALESCE(p.leverage,0)::float AS lev, COALESCE(p.margin,0)::float AS margin,
    COALESCE(p.reduce_count,0)::int AS rc,
    COALESCE(p.size,0)::float * COALESCE(p.entry_price,0)::float AS notional,
    CASE WHEN p.closed_at IS NOT NULL AND p.opened_at IS NOT NULL
         THEN EXTRACT(EPOCH FROM (p.closed_at - p.opened_at))/3600.0 END::float AS hrs
  FROM paper_positions p
  WHERE p.account_id = 14 AND p.status='closed'
    AND p.opened_at >= now() - make_interval(days => :d)   -- :d = 30 或 7
)
```

### 0.2 口径验证：`unrealized_pnl` 已含分批盈亏，**不可**再叠加 `partial_realized_pnl`

代码证据（`backend/services/paper_trading_engine.py:1949,1960,2001-2006`）：

```python

pos.unrealized_pnl = total_pnl                   # 2006  ← 权威口径
# 注释原文：「已含分批 partial_realized_pnl」…「读取 closed 仓位 unrealized_pnl 时禁止再叠加，否则双计」
```

数据侧复核：

| n(closed,30d) | 有 partial 的行 | 有 reduce 的行 | `unrealized_pnl` 合计 | `partial_realized_pnl` 合计 |
|---|---|---|---|---|
| 1187 | 60 | 30 | -295.32 | +12.70 |

`partial` 只覆盖 60/1187 行（5.1%），且合计 +12.70 是净额的一小部分，与「已并入」一致。**本报告全部使用 `unrealized_pnl`，不再叠加 partial。**

另注：`unrealized_pnl` 是**价格损益（毛）**，手续费单独记在 `partial_fee_paid`（30 天合计 +6.43，全账户累计 `total_fee_paid`=64.38）。即本报告口径略偏乐观约 6.4/295 ≈ 2%。

### 0.5 数据质量门 3：`close_reason` 有脏值 + 编码

部分行把诊断文本直接写进了 `close_reason`，与标准枚举值混在一列，例如 `[no_progress] hold=75.6h≥72h peak_R=0.36<0.50 cur_R=-0.05`、`[swing_invalidation] mid 持仓=long 与 mid_bias=bearish(conf=69%) 强反向`。本报告统一取 `split_part(close_reason,':',1)` 归一化；上述 5 行「单行自成一类」样本不足（n=1）不计入结论。

`exit_state_json` / `close_reason` 中的中文经 psycopg 输出为 GBK 乱码（终端显示为 `ԭʼ��ͷ`），不影响数值与枚举键，仅影响文本可读性。

## 5. 归因五：峰值回撤（giveback）

定义：`giveback = peak_unrealized_pnl - unrealized_pnl`（美元，正数表示吐回去的浮盈）。
> 用美元而非 `peak_pnl_pct`，因为后者是**未杠杆价格百分比**且跨品种/跨杠杆不可比（§0.4）。

### 5.1 总体

  SUM(CASE WHEN mfe>0 THEN 1 ELSE 0 END) had_mfe,

  ROUND(SUM(CASE WHEN mfe>0 THEN mfe-net ELSE 0 END)::numeric,2) total_giveback,

FROM base;

### 6.3 结论（明确说明数据不支持）

**「高分是否真的更赚」——数据不支持任何结论。** 理由：

1. **n 太小**：四桶分别为 6 / 27 / 11 / 2，`<0.85` 与 `<0.65` 桶 n<10，`<0.65` 桶 n=2。

- short 车道入场也落 `analysis_run_id`（否则永远无法归因 87% 的样本）；

## 9. 一页纸结论

1. **全系统 30 天净 -295.32（-5.9% 期初权益），7 天 -109.61 且在恶化（ROI -0.98% → -1.64%）。**
2. **亏损高度集中在三处**：`sl`（-339.27，胜率 0.4%）、thesis 族出场（`thesis_invalidation` + `thesis_should_close` = -279.63）、四个品种（ASTER/VIRTUAL/XRP/XPL = -310.27）。
3. **不对称是结构性的**：全样本打平需 **48.46%** 胜率，实际 **41.28%**，**缺口 -7.18 pp**。
4. **决定性发现：剔除 `sl` 通道后，系统立刻由负转正（实际胜率 51.10% > 打平所需 49.81%，盈余 +1.29 pp）。**
5. **`mlto` 是负期望来源（n=41，-203.74，ROI -2.39%）**，且 MFE +13.45 → 实得 -4.97，**平均每笔吐掉 18.46 浮盈**；`trend_e1` 是唯一硬正期望（n=15，+56.83，ROI +12.84%，盈亏比 4.01，回吐仅 3.72）。
6. **反事实**：中长车道对 `mfe>3` 的单移到保本止损 → **+383.37**；但短车道同样操作 → **-91.73**。**「统一收紧止损」会亏钱，必须分车道。**
7. **落地顺序**：关 mlto → 黑名单四品种 → 短车道放宽止损 → 加峰值回吐保护 → 分步加权 trend_e1。
8. **不可信的部分已逐条列明**（§8）：任务 6 信号强度分层**基本不可用**（3.9% 覆盖、n=2~27、非单调），短车道 MAE 不可用（22.3% 覆盖），30 天窗口跨纪元需谨慎。
