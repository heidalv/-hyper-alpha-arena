## 二、根因：`_calc_tp_sl` 的多空判据只认 `"buy"`

`position_memory_manager._calc_tp_sl` 原来写的是：

```python
if side == "buy":      # 多头分支
    sl = price * (1 - sl_base) ; tp = price * (1 + tp_base)
else:                  # 空头分支
    sl = price * (1 + sl_base) ; tp = price * (1 - tp_base)
```

而滚仓链路传进来的 `side` 是 **`"long"`**：

```
midlong_position_manager._exec_pyramid
  → side = _pos_direction(position["side"])      # → "long" / "short"
  → position_manager.evaluate_pyramid(side="long", ...)
  → self._calc_tp_sl("long", new_avg, ...)       # → 走 else（**空头分支**）
```

于是多头仓拿到一对**方向全反**的 TP/SL。

### 可证等式（不是推测）

```
80788.191962 / 1.03   = 78435.13782718
65689.42793  / 0.8375 = 78435.13782687      ← 同一个参考价，误差 3.2e-7
```

同一个参考价 `78435.1378` 分别套了两条**空头**公式（`×(1+3%)` / `×(1−16.25%)`）。
其中 3% = tier=long 的止损层上限 `MIDLONG_MAX_SL_PCT_LONG`，
16.25% = `sl_base_min 6.5% × rr_low_wr 2.5`（trend_follow 配置）。
参考价 78435.14 是 plan 用的 `new_avg`（按决策时 mark 80808.3 加权），
与成交后 DB 均价 78492.80 差 **57.66** —— 正是"成交价 80968.54 高于 mark"造成。

若走多头分支，同一参考价应得 `sl=76082 / tp=91181`，与事故值相差 4700 / 25000。

### 为什么潜伏至今

滚仓路径此前**几乎从不触发**（近 30 天长线平均加仓 0.06 次），所以这段代码从没被真正执行过。
轮99/102 按用户口径恢复"长线 = 滚仓盈利引擎"后，它第一次跑起来就中了。

## 三、四道防线（本轮全部落地）

### ① 根因：`side` 词表归一

`_calc_tp_sl` 主分支与止损封顶块都改为：

```python
_is_long = str(side or "").strip().lower() in ("buy", "long")
```

`long/buy/LONG/Buy/" long "` 五种写法实测等价（`short/sell` 同理）。

### ② 写入侧：`safe_tp_price`（`safe_sl_price` 的镜像）

新增 `PaperTradingEngine.safe_tp_price(tp, *, side, market, entry)`：
多头 TP 必须在 **entry 之上**、空头在 entry 之下，否则返回 `0`（= 不更新）。

- **判据用 entry 而不是现价**：现价在触发那一刻本来就该越过 TP，用现价会把**正常触发**误判为非法；
  用 entry 同时放行"把 TP 挪到现价下方锁利"这类合法收紧。
- **失败方向**：市价/开仓价缺失、或市价与开仓价偏离 >50%（含 Mock 被强转成 1.0 的假数值）→ 按原值放行，
  不因一次取价失败而放弃止盈管理。

接线 5 处：`tp_direction_illegal` 内部、下单收口、建仓（滑点后复验）、加仓合并、`update_position_tp_sl`。

### ③ 触发侧：`tp_direction_illegal`

存量脏 TP（修复前写进去的）仍会躺在库里，任何一次 tick 都可能拿它当成交价。
在 **4 个 TP 触发点**统一再判一次：方向非法 → 拒绝成交 + ERROR 留痕。

> 关键认识：**光靠成交价修正救不了 TP**。轮64 为 SL 加的 `min(触发线, 市价)` 修正，
> 对多头反向 TP 恰好失效 —— `min(65689, 80808) = 65689`，"修正"反而确认了幽灵价。
> 唯一正确处置是拒绝成交。

### ④ 长线车道契约：加仓不得写固定 TP，快路径不得做定点止盈

修好方向后 `_calc_tp_sl` 会给出 `new_avg × 1.1625`（**+16.25%**）—— 一个**可达**的固定止盈。
它会被 `_enforce_max_hold_timeout` 的 Layer-0 硬 TP 判定在 +16.25% **整仓平掉**，
与长线车道的定义直接冲突：

- `trend_e1_engine._adopt_position` 明写「趋势仓不设固定 TP（让利润奔跑；唯一出场 = 规则失效 / Chandelier）」并置 `None`；
- 车道自己的 `ExitPolicy.for_lane("long").tp_pct` 就是 **null**；
- 用户口径：长线车道的盈利引擎是**滚仓**，不是定点止盈。

因此：

- 新增 `add_order_tp_decision(pos, order_tp, market)` → `(值, 动作)`：
  `trend_lane_clear`（长线车道清空）/ `inverted_reject`（方向非法拒写）/ `write` / `keep`，
  加仓合并路径改走它（原先是 `existing.tp_price = order.tp_price` 裸赋值，绕过了所有闸门）；
- `reprice_position`（秒级快路径）按车道跳过固定 TP，与 `_run_v2_protection` 已有行为对齐。
  慢速 tick 的 `_enforce_max_hold_timeout` 仍是 Layer-0 failsafe（设计如此）。

> 同型缺陷：「契约写在慢速路径上、真正触发的快路径从没继承」——
> 与轮99 `long_v2_enabled()` 那条"注释说跳过、条件写成别的变量"是同一个病。

## 五、全库扫查：这不是第一次出血 —— 历史 80 笔同类，≈ −903

修完 #4712 后按同样的方向判据扫全库，发现**这不是孤例**：

| 口径 | 结果 |
|---|---|
| `close_reason='tp'` 却成交在**亏损侧**（多头 close<entry / 空头 close>entry） | **80 笔** |
| 仓位级盈亏合计 | **≈ −903.16**（按订单口径 −808.63） |
| 时间窗 | 2026-07-08 → 2026-08-23 |
| 账户分布 | 14: 46 笔 / 149: 29 笔 / 156: 5 笔 |
| tier 分布 | `short/scalp` 51 笔、`research/pair_research` 29 笔 |
| **中位持仓时长** | **26.5 秒**（80 笔中 74 笔 < 5 分钟；对照组 331 笔正常 TP 平仓中位 2537 秒） |
| 其中无加仓/无补仓 | **80 / 80** ⇒ 不是"加仓后均价漂移"，是 TP 从写进去那一刻就是反的 |

个案解剖（`#2529 HEI long scalp`）：开仓单 14232 在**写入时**就带着
`tp=0.20477952 / sl=0.19758024 / entry=0.22011` —— TP 比开仓价低 **6.96%**。
开仓 05:09:49，05:10:26 就被这条 TP"止盈"平掉，记 −6.97%；37 秒。

### 这类是怎么写进去的（与 #4712 同族、但不同落点）

`_calc_tp_sl` 的"AI 主驾"采纳逻辑：

```python
tp_price = raw_tp if raw_tp >= _hard_floor_tp else _hard_floor_tp   # 多头
```

`_hard_floor_tp` 是**按价格百分比**算的（scalp 1.012 / swing 1.03 / …），
它是一个"别太近"的下限，**不是方向判据**；而且它只保护"AI 给的 TP 太近"这一种情形。
更关键的是：scalp / `pair_research` 等入场路径会把 AI/策略给的 TP **直接**带进
`place_order(tp_price=...)`，那条路上连这个百分比下限都没有。

### 因此补了第五道落点：**取到真实市价之后再复验一次**

新建仓时订单上的 TP 校验用的是 `place_order` 的 `price` 形参，
而**市价单的 `price` 就是 `None`** —— DB 实证：滚仓单 23846 `price=None`，只有 `filled_price`。
所以那次校验对市价单是空转。修复：在 `current_price` 取到之后（滑点模拟之前）再判一次，
按"限价单用自身 `price`、市价单用 `current_price`"选参考入场价，方向非法就丢弃该 TP 并 ERROR 留痕。

至此写入侧共 6 处（`tp_direction_illegal` 内部 1 + 下单收口 2 + 建仓 1 + 加仓合并 1 + AI 改 TP 1），
触发侧 4 处。

> 残留（诚实标注）：**SL 侧在下单收口没有同级的"取价后复验"**。
> `clamp_sl_price` 只夹"过远"，不判方向；历史数据里也**没有**观察到反向 SL 的样本
> （80 笔全是 TP 侧）。因此本轮只补了 TP，SL 侧仍依赖 `_ensure_sl_inside_liq`、
> 最小止损距离守卫、以及 `update_position_tp_sl` / 加仓合并两处的 `safe_sl_price`。
>
> **上线后应观察到的变化**：scalp / research 车道的持仓时长会变长
> （原先那 80 笔的中位持仓只有 26.5 秒 —— 它们是被反向 TP 秒平的，不是真的做了 26 秒交易）。
> 若之后 scalp 出现大量"没有 TP、靠阶梯/追踪离场"的仓位，属预期行为而非故障。

## 八、未做 / 遗留（诚实标注）

6. **6 条陈旧 pending 挂单**（id 20540/20984/21003/21708/22600/23133，2026-07 遗留）价格落在错误一侧，
   经查它们不参与触发（触发只看 `pos.tp_price`），但会污染挂单列表 —— 未清理，待人工确认。
7. 车道分离阶段 3c/3d/4/5 未动（`midlong_exit_guard` 合并、8 个待判定模块、命名空间拆分、入场路径拆分）。
