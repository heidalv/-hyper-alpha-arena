## 一、官方依据（本轮实查）

- 更新日志 2026-09-10（[Change Log](https://api-docs.deepseek.com/updates/)）：
  「DeepSeek-V4.1-Flash … **with native multimodal visual understanding** …
  Change the model name to **`deepseek-flash`** to call the latest V4.1 Flash model.
  The previous-generation models V4 Flash and V4 Flash Vision Exp have been **retired**;
  for compatibility, the model names `deepseek-v4-flash` and `deepseek-v4-flash-vision-exp`
  are **temporarily routed** to V4.1 Flash.」
- 图像理解指南（[Vision](https://api-docs.deepseek.com/zh-cn/guides/vision)）：图片走 OpenAI 兼容的
  `content` **块数组** —— `{"type":"image_url","image_url":{"url":"data:image/png;base64,…"}}`；
  支持 JPEG/PNG/GIF/WebP、base64/外链/Files API 三种传入方式；**每图 ≤1024 token**；
  **图片只能出现在 `user` 消息里**（system/assistant 带图返回 400）。
- 2026-08-21 新闻（[V4-Flash-Vision-Exp](https://api-docs.deepseek.com/zh-cn/news/news260821/)）：
  多模态支持 Chat Completions / Messages / Responses 三种格式。

## 三、改了什么

| 位置 | 改动 |
|---|---|
| `model_gateway.DeepSeekTransport.complete` | 有图时把 user 消息组装成块数组（文本块 + `image_url` data URL）；**system 保持纯字符串**（符合"system 带图 400"）；声明了 images 但一张都没有 b64 ⇒ 退回纯文本，**不编造图片块** |
| `model_gateway` 模型默认名 | `deepseek-v4-flash`（官方已标记为临时路由的旧名）→ **`deepseek-flash`** |
| `.env` `DEEPSEEK_MODEL` | → `deepseek-flash` |
| DB `llm_configurations` id=17 | `model` 与 **`model_deep`** 均 → `deepseek-flash`（注意：`_resolve_tier_model` 对 `tier=deep` 读的是 `model_deep` 列——只改 `model` 不够，这是本轮先踩到再修掉的坑） |
| `analysis/tasks.py` 图审 `images_for` | `["glm_opencode","glm_opencode_alt"]` → **`["deepseek","glm_opencode","glm_opencode_alt"]`**（图重新发给主票） |
| 代码注释 | 删掉上一轮"DeepSeek 传输是纯文本"的错误注释，替换为官方依据 |

## 六、未做（可选优化，等你发话）

1. **Files API 未接**：多图/大图场景下可先上传拿 `file_id` 复用，省带宽（我们每轮渲染 1~3 张、
   每张 ~17KB，暂不需要）。

   若想省 token 可对缩略图用 `low`（缩到 512×512）。
3. 图审的 `images_for` 里 GLM 两条仍在列（GLM 已不是主票/备胎），仅在它被顶上来时才有意义；
   要精简可去掉。
