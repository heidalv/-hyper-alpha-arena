## 二、逐项：根因、证据、口径决策

### P2-13 时间单位（`ml/activation_service.py:142,145`）

`crypto_klines.timestamp` 是 int4 **epoch 秒**（实测 BTC/15m 末行 `1789739100`），
原代码 `pd.to_datetime(df["timestamp"], utc=True)` 少了 `unit="s"`，pandas 按**纳秒**解释
→ 全部 K 线落到 1970-01-01，并随 `data/factor_matrices/{SYMBOL}_{TF}.csv` 落盘
（磁盘上那份 1970 索引的 CSV 就是物证）。

仓内其它 3 处转换器都显式带单位（`data_center.py:199` `unit="s"`、
`technical_indicators.py:239` `unit="ms"`、`midlong_walk_forward_hook.py:97` `unit="s"`），
**只此一处漏**。修法：抽 `_epoch_like_to_utc()`，数值列一律按秒解，
字符串 / NaT / tz-aware 输入原样兼容（四种输入形状都有断言）。

### P2-7 孤儿快照（`full_auto_trading_service.py:2154`）

原写法 `db.execute("SELECT … NOT IN (SELECT id FROM full_auto_sessions)").scalar() if False else None`
三处都错：

1. `if False` → 恒 None，而且 `_orphan` **从未出现在任何日志里**（算了却不打印）；
2. `decision_snapshots` 在 **AnalyticsBase**（`alpha_analytics`），
   `full_auto_sessions` 在 **Core**（`alpha_arena`）—— **两个物理库**，
   跨库 `NOT IN (SELECT …)` 在单条 SQL 里不可能成立（这才是当初被"就地禁用"的真因）；
3. `execute("裸 SQL")` 在 SQLAlchemy 2.x 需要 `text()` 包装。

修法：Analytics 侧按 `session_id` 分组计数、Core 侧取合法 id，
Python 里求差集（抽成纯函数 `orphan_snapshot_stats()` 以便测试），
并把结果真的打进启动摘要。实测当前账户：快照分属 `{10: 5524, 12: 447}`，
在线 session `[10, 12]` → **孤儿 0 条**（健康）。

### P2-9 层预算 fail-OPEN（`proposal_execution.py:259`）

`except Exception: pass` 把「层已满」变成「放行」。这层与 `master_execution` 不同：
**没有配套的 `can_open()` 硬闸门**，`_bf <= 0`（层用量 ≥ `layer_allocations` 的 100%）
就是「预算已满 → 不开新仓」的全部实现。故一旦
`build_portfolio_for_agents()` 或预算服务抛错，层已满也会按原始满仓下单 = 绕过层额度。

修法：**fail-CLOSED**（告警 + `_mark_block("budget_error")` + `return False`），
与 `paper_execution.py:483-490` 的统一风控异常同姿态。
顺带修掉 `master_execution` 侧 `_equity > 0 and _req_margin > 0` 不成立时整段闸门
被无声跳过的问题（该处保留不拦截语义，只补 debug 痕迹 —— 理由写在该处注释里）。

### P2-10 微仓硬事实闸门 fail-OPEN（`paper_risk_helpers.py:81`）

原 `return True, f"tiny-close guard error: {_e}"`。方向性论证（这是本轮唯一的"判断型"决策）：

- 该闸门的存在意义是**别把微仓小亏秒平**（`master_running_close_tiny` 小亏秒平是历史事故），
  复核最短持有 / `MASTER_CLOSE_TINY_DISABLED_TIERS` / `master_close` 硬阈值；
- 不放行 ⇒ 持有 ⇒ 交 SL/TP 管理，与 `if not _tc_ok: close_tiny_hold; continue`
  的**正常拒绝分支走完全同一条路径**，且 SL 是独立安全网；
- 反方向（该平不平）**不可能**增加清算风险 —— 平掉一个微仓本来就不降低清算风险。

⇒ 改为 `return False`。附带修掉"静默"：调用方只在**拒绝**分支打印 detail
（`master_execution.py:2729-2730` / `:2789-2790`），改判后错误自动进入
`close_tiny_hold` 事件；另加一条 warning 日志双保险。

### P2-6 AI 选币闸门文案（`sub_position_manager.py:387,420-427`）

`settings.AUTO_COIN_ALLOWED_NATURES = frozenset({"scalp"})`（同处注释已说明理由：
中线已并入长线 `mid_view`，auto-coin 选出的币只进短线 scalp，由 `scalp_loop.py` 处理），
而闸门注释写「只允许短线(intraday)/中线(swing)」「AUTO_COIN_ALLOWED_NATURES 本就包含这两者」、
拒绝文案写死「只允许短线/中线交易」→ 运行时输出
「只允许短线/中线交易(允许: ['scalp']，当前: swing)」，一句自己打自己的话。

修法：展示名统一由 `lane_semantics`（轮63 建立的车道语义唯一真源）推导，
实测输出变为「只允许**日内(scalp)**车道」；两条静默 fail-open
（库兜底 `except: pass`、模块导入 `except ImportError: pass`）补 warning。
**判定方向一字未改**（`nature not in allowed ⇒ 拒绝`）。

### P2-8 手续费重复扣除（`full_auto_trading_service.py:1686,1719`）

逐仓位 `pos_pnl = … + partial_pnl - partial_fee` 扣了一次分批费；
循环后 M1-2 的「漏扣全平费」补丁又 `total_pnl -= _close_fees`（该策略**全部**
`close_reason` 非空订单的 fee 之和）—— 而
`paper_trading_engine.py:2515-2537` 在累加 `partial_fee_paid` 的**同一次调用**里
就写了 `PaperOrder(fee=partial_fee, close_reason=…)`，两者是同一笔钱的两种记账，
账本总额是分批费的**超集** ⇒ 分批费被扣两次。

实测（account 14，12 个有分批费的策略）：旧口径重复扣除 **5.8274**，
无一例账本 < 分批费（超集前提成立，测试里也把这条前提钉住了）。

修法：只补扣 `账本总额 − 仓位行已扣额`（差额即尚未计入的全平费），
差额为负时补 0（账本不完整时按更保守的仓位行口径，**绝不倒加钱**）。
win/loss 判定仍用含分批费的 `pos_pnl`，**胜率口径不变**。

## 三、本轮新发现：P2-15 治理工具自身的脆弱性

`backend/scripts/audit_config_effective.py:229-261` 的「后缀拼接读取」是**按行文本**
识别的启发式：`RE_COMPOSED_GETENV` 找"拼接式 getter 调用"，`RE_SUFFIX_LITERAL`
收集**同一文件**里的 `_XXX` 引号字面量作为候选后缀；二者共现即把该后缀对应的
**整类**键豁免出死键清单。

我在写 P2-14 的注释时无意中触发了它（一句形如拼接式 getter 调用的**说明文字**
+ 一个 `"_ENABLED"` 字面量），后果是：

- 全仓 `*_ENABLED` 键一次性从 `env_truly_dead` 消失；
- `ANOMALY_DETECTOR_ENABLED`、`MARKET_SCANNER_ENABLED`、`ONCHAIN_DATA_ENABLED`、
  `ARBITRAGE_ENABLED` 这 4 个真死键随之隐身；
- `DEAD_ALLOWLIST` 里为它们写好的原因分类变成**永远走不到的死条款**；
- `test_env_registry_visibility_20260910` 变红（我最初用 `git stash` 验证时误判为"既有失败"，
  实际是我的新测试文件带进去的 —— 教训：baseline 验证必须连新增文件一起回退）。

处理：**消除触发源**（新代码不再写出那种形状 + 两处留警告注记），
 启发式本身**未改** —— 收紧它需要先统计每个后缀会豁免多少键
（`_ENABLED` 与 `_PAPER` 性质完全不同：前者是通用词缀，后者是真实的车道后缀），
属独立一轮。已记入审计报告 P2-15。

## 四、方法学教训（本轮再次踩到，已固化成纪律）

1. **注释里引用旧写法会骗过自己的断言**。本轮 4 条验证断言因此误报，
   修法是：源码级守卫一律先剥注释；引用旧写法的地方改用 AST
   （`ast.IfExp(test=Constant(False))`）或把窗口收窄到判定块本身。
2. **在源码/注释里写出"被工具按文本识别"的形状，等于给工具下毒**。见 P2-15；
   因此 `_ENABLED`、拼接式 getter 调用形状在本轮新代码里一律**运行时拼接**。
3. **baseline 验证要连新增文件一起回退**，否则会把"自己引入的破坏"误判为既有失败。
4. 补一条"前提校验"测试：P2-8 的差额法依赖「订单账本 ≥ 仓位行分批费」，
   该前提被写成断言（数据侧），前提一破测试先炸。
