## 〇、结论先行

**判定：混合状态——存在若干条真实的、有读写证据的反馈闭环，但「报告里的闭环」明显大于「代码里的闭环」；其中每 5 分钟的 QAA 优化周期是零产出的空转心跳，成熟度状态文件冻结近一个月，DRL/RL 模型与 learning_core 全家桶在生产中处于休眠或纯 API 状态。**

一句话总结：

1. **真闭环（有完整读写证据）**：outcome → StrategyMemory/StrategyRegimeScore/连亏熔断 → 实盘决策（参数自适应、仓位、EV 闸、LLM prompt）——这条主干是通的。
2. **假闭环（报告称在跑，代码/数据证明空转）**：
   - QAABridge 每 5 分钟 `run_optimization_cycle`：24,367+ 条进化历史里 **optimize_start / optimize_result / grayscale_* 出现次数全部为 0**——从未产生过任何优化计划；
   - `data/maturity_state.json` 自 **2026-08-16** 起无人刷新（`run_maturity_tick` 没有定时调用者），而门控在消费它；
   - `ai_decision_calibrator`（LLM 置信度校准）只被 API 展示页读取，无任何决策消费者；
   - DRL 模型照常影子训练，但 `ENABLE_DRL_INTEGRATION=false` + `DRL_SHADOW_MODE=false`，决策路径完全绕开 DRL；
   - `learning_core`（orchestrator/backtest_loop/ledger/continual_learning/map_elites）全部只由 API 手动触发，无任何定时调度。
3. **进化（NSGA-II / hypothesis_scan）的反馈源是回测 fitness，不是实盘 outcome**；实盘结果反哺进化只有「偏离预警 → 紧急重进化」一条窄路（且带 24h 冷却）。

## 二、QAABridge 每 5 分钟 `run_optimization_cycle` 到底优化了什么

### 2.1 调用链

1. `startup.py:878-882`：`task_scheduler.add_interval_task(qaa_bridge.run_optimization_cycle, 300, "qaa_optimization_cycle")`——每 5 分钟。
2. `qaa_evolution_bridge.py:578-599`：调用 `self.optimizer.run_cycle()`；对返回的 plans **只写 history 日志**（`:584-595`），真正的写操作发生在 QAA 包内部。
3. `qaa_architecture_package/qaa/evolution/optimizer.py:117-152` `run_cycle`：
   - `_check_active_plans()` → `_apply_plan()`（`:207-270`）：读 tunable 当前 genome → CMA-ES（`QAA_OPTIMIZER=cmaes`，`.env:498`，eval_fn 存在时）或朴素 −10% → `tunable["set"](new_config)`。
   - `set_config` = `qaa_evolution_bridge.py:224-235`：`AIStrategy.genome = new_config; db.commit()`——**直接改主库策略 genome**。
   - 新计划生成需要 `_feedback.get_degrading_targets(min_entries=10)`（`feedback.py:211-232`）。
4. 观察期后 `_evaluate_plan`（`optimizer.py:272-316`）按反馈评分确认/回滚。

### 2.2 为什么它在空转（三重证据）

**证据 1（代码）——评分恒等导致永远检测不到退化：**
- `OutcomeAdapter.feed_outcome(outcome, decision_quality=0.5)`（`qaa_evolution_bridge.py:97`）把 rating 记为 `decision_quality`；
- 唯一调用点 `QaaBackend.handle_outcome`（`learning/backends/qaa_backend.py:33`）**不传 decision_quality** → 所有条目的 rating 恒为 0.5；
- `get_degrading_targets` 要求 `trend == "degrading"`（`feedback.py:184-192`：前半 vs 后半均值差 < −0.03）——**全等评分下 trend 恒为 "stable"，退化目标列表恒为空，计划恒为 0**。
- 且 feedback 条目是纯内存对象（`feedback.py:118-121`），进程重启即清零，连"跨重启累积"都做不到。

**证据 2（数据）——24,367 条历史里优化动作出现 0 次：**
对 `data/qaa_evolution/evolution_history.jsonl`（80.8MB，末条 2026-09-13 23:20 UTC）统计：

```
optimize_start       = 0
optimize_result      = 0
optimize_proposed    = 0
optimize_running     = 0
grayscale_confirmed  = 0
grayscale_rollback   = 0
```

历史里大量出现的是 `trade_outcome`（outcome 采集真实运行）和 `hypothesis_generated/hypothesis_rejected`（假设扫描真实运行），但**没有任何一次优化应用/确认/回滚**。

**证据 3（代码）——灰度发布（路径 B）在纸面下从不触发：**
- 灰度计划唯一入口 `auto_optimizer.queue_optimization`（`auto_optimizer.py:72`）← `strategy_health_service._heal_pause_reoptimize:328`；
- 该 heal 动作对模拟账户（`loss_locks_disabled`）**降级为 REDUCE_RISK**（`strategy_health_service.py:284-304`），不排队重优化；live 又无真实账户（报告记载 hyperliquid 未启用）→ 灰度计划事实上从不创建，与历史文件 0 条灰度记录互相印证。

### 2.3 结论

`run_optimization_cycle` 每 5 分钟执行的是：**一次必然返回空计划列表的退化检测**。它写入的唯一目标（`AIStrategy.genome`）从未被它写过。`LEARNING_SYSTEM_STATUS_REPORT.md` 中「每5分钟执行一次策略优化和质量评估」「确保策略参数持续调优」的表述与代码事实不符。

## 四、maturity / calibration 是否构成「不成熟就不让交易」的门槛

**不是。** `maturity_controller.py:1-35` 明确设计语义：成熟度输出 `conf_relief`（置信度门槛的加减分），warmup 放宽（鼓励积累样本）、mature 按胜率微调，且 **live/真金恒为 `relief=0`**（`:305-306`）。它改变的是「软门槛松紧」，不是「允许/禁止交易」的开关。

「不让交易」的硬门槛另有其人（且是真实闭环）：
- 连亏 15 次暂停策略（`unified_learning_service.py:1320-1335`，含 SymbolLockRegistry 锁）；
- 连亏 50 次永久禁用（`:1278-1296`，写 `genome.permanently_disabled` + `status=archived`，真实落库列）；
- 短线/中线币种级连亏熔断（`short_tier_entry_gate` / `midlong_circuit_gate`，每笔平仓即时记账，开仓前检查）。

结论：问「maturity 是否是不成熟不让交易」——不是，它是松紧旋钮；且该旋钮当前还冻在 8/16 的快照上（断点 B）。

## 五、最终判定

### 真实闭环（代码 + 数据双证）——「真闭环反哺」的部分

1. **outcome → StrategyMemory → 参数自适应 → 实盘列**（每 tick 执行，`strategy_lifecycle.py` → `health_check_cycle.py:473`）；
2. **outcome → StrategyRegimeScore → 仓位编排/进化触发/LLM 警告**；
3. **outcome → Kelly → multi_symbol_kelly → 仓位上限**（30min，`ENABLE_KELLY_POSITION=true`）；
4. **outcome → 连亏熔断/暂停/禁用**（事件级硬门槛）；
5. **outcome → 置信度校准（confidence_calibrator / scalp_confidence_calibrator）→ EV 闸硬拦截**；
6. **outcome → key_lessons / RAG（chromadb 活跃）→ LLM 决策 prompt 软约束**；
7. **outcome → 因子 IC/信号权重 → 因子路由开单**（因子侧，8/22 报告与 `factor_runtime_weights.json` 9/13 23:07 更新佐证）。

### 「报告里闭环、代码里空转」的部分

- QAA 5min 优化：**零产出**（0 计划实证）；
- QAA 灰度发布：**从不触发**（纸面降级短路）；
- maturity 松紧：**消费 28 天前的冻结快照**；
- ai_decision_calibrator：**拟合了没人读**；
- DRL / RL sizer：**训练/模型存在，决策开关关闭**；
- learning_core / strategy_optimizer / 贝叶斯优化层：**无生产调度，仅 API**；
- 进化引擎反馈源：**回测而非实盘**（实盘仅有一条 24h 冷却的偏离预警窄路）。

### 一句话结论

**主干反哺是真闭环**（outcome → 记忆/矩阵/熔断/Kelly/校准 → 下一次开仓决策，证据链完整）；**但「学习进化」宣传里最响亮的三个组件——QAA 每 5 分钟优化、灰度发布、数据成熟度自适应——全部处于「定时器在跑、实际零产出或读冻结数据」的状态**；DRL/RL/learning_core 则是「建好了、没接线」。系统当前实际依赖的是：硬熔断 + 规则自适应 + Kelly + EV 校准 + LLM 提示词软约束，而不是任何自动调参/自动进化的闭环。
