## 一、那"多出来的一档"是什么（事实核查）

| 问题 | 事实 |
|---|---|
| 谁加的 | `brain_debate.HORIZONS` 自**轮130**（提交 `51632cb`）起就是三档（日内/中期/长期趋势），来源是当时的用户原话「牛熊分析需要明确周期，**日内中期 和长期趋势**」 |
| 本轮我动过吗 | **没有**。`git log -S'HORIZONS: Tuple'` 只有轮130 那一个提交；我轮155-158 对 `brain_debate.py` 的改动只有两处：`_llm_transport` 默认值改 deepseek、辩论输出上限 900→2500 |
| 它有车道吗 | **没有**。`TIER_PRIMARY_HORIZON` 只有 `mid→intraday`、`long→trend` ⇒ 中期的裁决**从不成为 `primary_verdict`**（即从不影响决策），只被记进 `horizon_verdicts` |
| 它的实际代价 | ① 每轮辩论多写一段"中期论点"，直接吃输出 token（轮158 定位的 900 截断里就有它一份）；② 我这轮把契约注册进 schema 时，它被一并注入 system prompt，等于把这一档"放大"了 |
| 你的口径 | 两周期，唯一真源写在 `backend/config/cycle_semantics.py`（轮48 记录你的原话）：**日内(intraday) + 长期趋势(trend)** |

## 二、本轮改动

1. `HORIZONS` 三档 → **两档**（日内 / 长期趋势）；`primary_horizon()` 的兜底值 `"swing"` → `"intraday"`。
2. 原本挂在"中期"桶的证据 **并入日内桶**：4h 结构、7d/30d 收益、`technical` 六分析师信号、因子路线；
   顺带修掉一行**自相矛盾**的代码：
   `by_hz["swing" if primary_horizon("mid") == "intraday" else "intraday"]`（结果恒为 `"swing"`）。
3. `schemas` 的辩论契约模板改为**可调用并派生自 `HORIZONS`**（单一真源）：
   周期档只允许在一处定义，杜绝"代码改了两档、system prompt 里还留着三档"的漂移。
4. 画布 `agent_wall` 辩论节点文案：三档 → **两个周期（日内 / 长期趋势）**。
5. 日志行 `中期=%s` 去掉（否则格式化参数会对不上）。
6. 测试：新增 `test_two_horizons_20260921.py`（6 项棘轮）；同步
   `test_brain_debate_wiring_20260920`（档数/未知档断言）与 `test_analysis_schemas_20260904`（支持可调用模板）。

## 三、验证

```
① 静态：HORIZONS = [('intraday','日内'), ('trend','长期趋势')]
        TIER_PRIMARY = {mid: intraday, long: trend, short: intraday}
        primary(mid/long/short) = intraday / trend / intraday
        契约 horizons 键 = ['intraday','trend']；契约里是否还出现 swing/中期 = False/False
② 真跑一次完整辩论（ETH mid，43.2s）：
        verdict=reduce  primary_horizon=intraday  primary_verdict=reduce
        horizon_verdicts = {"intraday": "reduce", "trend": "reduce"}   ← 只有两档
        used_llm=true
③ 测试：周期相关 147 passed / 0 failed（含新增 6 项棘轮）
```

棘轮要点（防复发）：周期档必须**恰好两档**、必须与 `cycle_semantics` 的 `INTRADAY/TREND` 一致、
**每一档都必须有车道以它为主周期**（不许再有"没有车道的多余档"）、契约键必须与 `HORIZONS` 同源。
