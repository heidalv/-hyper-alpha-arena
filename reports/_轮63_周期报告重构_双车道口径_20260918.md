# 周期报告重构 — 双车道口径（轮63 · 2026-09-18）

## 一、为什么「哪个是哪个分不出来」

不是渲染 bug，是**全库并存 7 套互相打架的周期词表**，同一个标签在不同层指不同对象：

| 层 | 词表 | 「日内波段」被归到 |
|---|---|---|
| 引擎权威映射 `tp_sl_authority.TIER_TO_NATURE` | short / mid / long | `mid` = swing ✓ |
| `sub_position_manager.NATURE_TO_TIER` | scalp/intraday/swing/… | **short** ✗ |
| `sub_position_manager.NATURE_RULES` 显示名 | — | scalp 与 intraday **都叫「日内」** ✗ |
| `position_construction.normalize_lane` | short/mid/long/research/arb | **short** ✗ |
| UI `agent-monitor/page.tsx` | 日内波段 / 长线趋势 | `mid` ✓ |
| 报告层 `_horizon_of` | scalp / midlong / long | `midlong` ✓（但名字叫「中线」） |
| 因子层 `cycle_semantics` | intraday / trend | `midlong→trend`（**另一层**，见下） |

实测（`paper_positions` 全库）：

```
scalp        + short     3041 笔   中位持仓 0.95h
intraday     + short        3 笔   中位持仓 0.77h   ← 与 scalp 同 tier
swing        + mid        288 笔   中位持仓 4.01h   ← UI 说的「日内波段」
trend_follow + long        74 笔   中位持仓 12.20h
position     + long         7 笔   中位持仓 14.56h
```

三个由此产生的**实际缺陷**：

1. `_horizon_of()` 把 `nature=intraday` 兜底成 `scalp` → 3 笔静默掉出中线报告。
2. LLM 总结把**同一段文字**写给全部三行 → 点「长线」看到的是三周期混合总结。
3. 亏损归因文案把内部枚举直接写进给人看的报告：`"midlong 近 1 天盈利 +5.24，无亏损归因"`
   （前端原样渲染，用户看到的就是这串内部代码）。

另有一个隐藏缺陷：**时间基准错位**。DB 的 `closed_at` 是本地 naive（Asia/Shanghai），
而旧代码用 `datetime.utcnow()` 做比较基线，差 8 小时 —— 实测有 4 笔「未来」时间戳
被算进 24 小时窗口，且按 UTC 日归档会把两个本地交易日混进同一天。

## 二、唯一口径（两条车道）

| | 日内 | 长线趋势 |
|---|---|---|
| 规范名 | `intraday` | `trend` |
| 展示名 | 日内波段（中线槽位） | 长线趋势 |
| 主看周期 | **1h** | **4h** |
| 确认周期 | 15m / 4h | 1d / 1w |
| 引擎 tier | `mid` | `long` |
| 引擎 nature | `swing` | `trend_follow`（含 `position`） |
| 期望持仓 | ≤ 24h（区间 0.5h–24h） | 24h–168h |
| 实测中位持仓 | 4.0h | 23.3h |

- **`scalp` 不再是独立车道**：短线车道已于 2026-09-17 停用，存量 scalp 仓位实测中位
  持仓 0.95h，本就是日内行为，归入 `intraday`。它的 D1 超时退出监控一并迁到日内段，
  否则该指标会随短线车道停用而从报告里消失。
- **`research`（pair_research/research）不进交易报告**，是研究车道。
- 中国用户口径里的「中线」**就是日内车道**（同一件事的两个叫法），
  这正是旧版把它渲染成「中线 / 长线」两个 tab 却都对不上号的根源。

### 为什么不和因子层的 `cycle_semantics` 合并

`cycle_semantics.py` 是**因子前瞻层**的真源：它把 `midlong` 标成 `trend`，因为因子发现的
`horizon="midlong"` 实际 interval 是 4h、前瞻 24h。而持仓层的 `mid` 档实测中位持仓只有 4h。

**强行合并会把「因子前瞻期」与「实际持仓期」再次混为一谈** —— 轮44 已量化该错配 ≈7.5×
（活跃因子前瞻 24h ↔ 中线车道实际持仓中位 3.2h）。两层刻意分离，但共用同一套 K 线周期词
（`report_timeframe` / `confirm_timeframes`），不会各说各话。

## 三、页面上会看到什么

`/reports` 页面：视图切换（日报 / 周报 / 趋势周期）+ **车道切换**。
车道词表由 `GET /api/period/lanes` 下发，前端不再维护一份自己的周期映射。

每张卡片顶部固定展示**周期身份条**：

```
🕐 日内波段（中线槽位）  [主看 1h]
   期望持仓 0.5h–24h · tier=mid / nature=swing
```

- 两条车道配色不同（日内=天蓝，趋势=紫），图标不同 → 不只靠文字区分。
- 段内新增**持仓时长分布**：中位 / p90 / >24h 笔数。
  **中位持仓超出该车道期望区间会标黄告警** —— 报告能自证「这是不是这条周期该有的行为」。
- 在手仓位标签显式标出引擎写下的 `nature/tier`（悬停可见），
  避免再次出现「报告说中线、引擎写 scalp」的二次错位。
- 新增**数据质量块**：本车道内标签矛盾 / 无标签的样本数，不再静默归并。

## 四、兼容与迁移

- **API**：`lane` 为主参数，`horizon` 保留为兼容别名，旧值自动解析
  （`scalp/midlong→intraday`、`long→trend`、中文名也可）。旧前端深链不会变空白。
- **数据库**：`period_daily_reports` 新增 `lane` 列，`horizon` 保留为兼容别名（两列同值）。
  迁移 `add_period_lane_column` 做回填 + 对齐 + 唯一索引。
- **历史回填**：迁移时发现**真实脏数据** —— 同一天 `scalp` 与 `midlong` 两行塌缩成同一车道
  （每天都是这样），唯一索引因此建不上。改为按本地日窗口从 `paper_positions`
  **重新聚合**（`rebuild_daily_report`），而不是搬旧 payload：旧 payload 是两份互不相干的
  分档内容，直接合并会把同一批仓位算两遍。

  已回填：5 账户 × 33 天 × 2 车道 = 330 行，重复行 0、`horizon≠lane` 0。
