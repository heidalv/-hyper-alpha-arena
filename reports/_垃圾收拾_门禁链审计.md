# 门禁链审计：信号 → 决策 → 下单 全链路防御性阻断点

> 审计时间：2026-09-13　·　审计方式：只读（未修改任何项目文件）
> 范围：`backend/services/` 下 decision_core / signal_engine / risk / risk_management / strategies / strategy / strategy_orchestrator / scalp / carry / market_maker / full_auto / adaptive_executor / exit / calibration 及 `config/settings.py`、`.env`、PostgreSQL 运行态。

## 1. 决策入口（周期性生成信号的 loop/service）

系统是**多循环并行**架构，三条互相独立的信号生成链 + 一个共同的"下单收口点"：

| 车道 | 入口文件与函数 | 周期/驱动 | 信号源 |
|---|---|---|---|
| 总协调器（心跳） | `backend/services/full_auto/loops/coordinator_loop.py:18` `run_unified_loop` → `_run_unified_loop_inner`（注册于 `full_auto/orchestrator.py:51`，由 `services/scheduler.py` APScheduler 驱动，默认 30–45s） | 每 tick | 编排器缓存 + 分析师 + Master LLM |
| 中长线独立循环 | `backend/services/full_auto/loops/midlong_loop.py:20` `run_midlong_independent`（~45s）→ `full_auto_trading_service.py:2646` `_maintain_mlto_theses_for_session` → `backend/services/mlto/brain.py:1941` `run_midlong_brain_batch` → `brain.py:1652` `maybe_open` → `midlong_executor.py:322` `execute_midlong_open` → `midlong_helpers.py:227` `try_execute_independent_agent_open` | 独立线程 | MLTO 论题主脑（LLM，MIDLONG_BRAIN_MODE=llm） |
| 短线因子独立循环 | `backend/services/full_auto/loops/scalp_loop.py` `run_scalp_independent` → `scalp_factor_router` → `scalp/scalp_execution_gate.py:52` `ScalpExecutionGate.evaluate` → `decision_core/execute_proposal.py:105` `evaluate_scalp_proposal` → `decision_core/pipeline.py:14` `evaluate_open_decision` | 独立线程 | 因子评分器（非 LLM） |
| Master 主路径（旧 LLM 决策） | `backend/services/full_auto/master_execution.py` `execute_master_decisions`（V5 调用点 ~:2057） | 由交易循环触发 | Master LLM（中线已废弃，长线删除，仅保留短线/兜底） |
| 下单收口点（paper） | `backend/services/paper_trading_engine.py:915` `paper_engine.place_order` | 所有车道必经 | — |

关键结论：**中长线唯一决策源 = midlong_loop + MLTO 主脑**（`MIDLONG_BRAIN_MODE=llm`）；短线 = scalp_loop 因子路由；`paper_engine.place_order` 是所有车道的最终共同闸门（live 对应 `trading_commands.py` 三入口 + `RiskEngine.pre_trade`）。

## 5. 概率链评估：一个信号通过全部门禁的叠加概率

以 **paper 中长线多头**为例逐层粗估（每层独立概算）：

| 层 | 粗估通过率 | 依据 |
|---|---|---|
| 论题 recommend_open=true + 方向明确 + 无效价（LLM 意愿） | ~0.4 | LLM 保守输出 |
| 熔断闸 learned 多头（mid 层）：up 需 chg24∈[3,6) 或 chop 需 pos≥60 且 chg≥2；down 直接拦 | ~0.15 | [3,6) 窄带 + chop 双条件，X8 实测放行集 n=28/184≈15% |
| 位置闸（ranging 下 pos<60%）+ swing 共识 + MTF | ~0.6 | chop 让位后主要剩 ranging 场景 |
| V5（conf 50 默认 vs 门槛 38 通过；RR=TP/SL=2.0 ≥1.6 通过；minTP 通过；StrictData 依赖注入成功） | ~0.9 | 主脑默认 SL5%/TP10% 恰好压线 |
| 组合净敞口 ≤150% + 并发 <4 + TradeGate 同 nature 无反向仓 | ~0.9 | 小资金账户易过；但若同币已有同 nature 反向仓（如当前 XPL short swing），同向/反向都受影响 |
| place_order 收口（TradeGate/PositionConstruction/RiskEngine/UnifiedRiskGate/配额 trend 6） | ~0.9 | 配额与硬规则 |
| **单信号乘积** | **≈ 0.4×0.15×0.6×0.9×0.9×0.9 ≈ 2.6%** | 每 tick 每 symbol |

- **中长线空头（paper）**：还需 down 日线 regime + learned 三条件（pos≥60、RSI 55-80、chg24≤−1%）→ 通过率再乘 ~0.05–0.1，单信号 ≈ **0.1–0.3%**。
- **短线 scalp**：★`SCALP_OPEN_DISABLED=true` + 引擎层硬闸 → 新开仓概率 **≈ 0（设计上关闭）**；live 另有影子模式（永不下单）。
- **实盘**：会话 paused + live 口径更严（RR 1.8、DCP enforce、EV 硬拦、引导期门槛对齐后仍 +5 置信）→ 比 paper 更低。

**叠加结论：单次信号→真实成交的总通过概率在中长线多头约 2~3%、空头 <0.5%、短线 ≈0%。** 由于循环每 30–45s 重复产生信号，低单次概率会被"多 tick 重试"部分补偿，但 learned regime 闸（chg24∈[3,6)）与位置闸这类**结构性窄带条件**不会因重试而显著改善——它们是当前"不交易"的主要结构性成因（叠加 20+ 层门后，历史上还出现过 DCP+RR+StrictData 多闸互斥死锁的修复记录，见 `midlong_location_gate.py:73-114`、`pipeline.py:102-113` 注释）。

## 6. 一句话结论

> 系统当前是 **paper 模拟模式**（唯一 running 会话 `fa_7e12e7a1b6` 为 paper；live 会话自 8/31 暂停），信号→下单链路被 **30+ 层防御性门禁**层层过滤（LLM 意愿→论题成熟度→regime/learned 熔断→位置/图审/MTF→V5 置信+RR+minTP→EV→组合预算→TradeGate→RiskEngine→UnifiedRiskGate→日配额），其中"不满足即跳过开仓"就是各层的默认语义，且短线车道被 `SCALP_OPEN_DISABLED=true`+影子模式**硬性关闭**，叠加后单信号真实成交概率约 **中长线多头 2~3%、空头 <0.5%、短线 ≈0%**——"不交易"主要是这套纵深防御 + 窄带 learned 条件的结构性结果，而非单一 bug。
