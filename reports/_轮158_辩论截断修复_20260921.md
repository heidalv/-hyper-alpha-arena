# 轮158 —— 辩论轮"无可解析 JSON"的真相：被 max_tokens 截断

日期：2026-09-21
来源：轮157 给 `extract_json` 失败加了原文摘要后，第一次看清失败原文 —— 顺手把根因也定了。

---

## 一、证据（`reports/_probe193_debate_truncation.txt`）

```
mlto_debate 最近 14 行（上限 MIDLONG_DEBATE_MAX_OUTPUT_TOKENS = 900）
   15:57:55 ok    out=400  in=747
   15:57:52 ok    out=520  in=749
   15:57:02 ok    out=433  in=754
   15:56:53 ok    out=775  in=1502
   15:56:41 error out=900  in=1492  nojson ← 正好等于上限
   15:56:32 error out=900  in=1208  nojson ← 正好等于上限
   15:56:01 error out=900  in=1204  nojson ← 正好等于上限
近 3h：error n=175 avg_out=754 max_out=1510 / ok n=46 avg_out=416
```

**每一条"输出中无可解析 JSON"的 `output_tokens` 都等于上限 900** —— 回答被砍成半截 JSON；
成功的行只需 400~775。辩论每轮要写
`argument + evidence + counterargument + weakness + 三个周期的 horizons`，
而 DeepSeek 的 **thinking token 也计入 completion_tokens** ⇒ 900 远不够。

> 这也解释了轮155/157 里"辩论 schema 失败率高"的**另一条**成因：轮157 修的是"契约打架"
> （形状不对），本轮修的是"输出被截断"（永远凑不齐 JSON）。两条都是同一个 task 上的独立缺陷。

## 二、修复

| # | 改动 | 说明 |
|---|---|---|
| 1 | `MIDLONG_DEBATE_MAX_OUTPUT_TOKENS`：代码默认 **900 → 2500**（`.env` 同步） | `max_tokens` 只是上限、不预扣费 ⇒ 不影响成本（用户明确"先不要考虑 LLM 预算"）。回滚：设回 900 |
| 2 | `RawCompletion` 新增 `finish_reason`，DeepSeek 传输回填；`extract_json` 失败且 `finish_reason=="length"` 时账本写 **"输出被 max_tokens 截断（finish_reason=length）"** | 此前只写"无可解析 JSON"，**没有任何线索**，定位绕了好几轮；现在截断一眼可见 |

## 三、验证

- 新增 `test_debate_truncation_20260921.py`（4 项）：`finish_reason` 默认值 / 传输回填 /
  **截断时账本文案必须点名"截断"** / 辩论上限默认值棘轮（不得回到 900）。
  连同 `test_debate_schema_20260921.py`：**10 passed**。
- 线上：重启后观察辩论轮账本（`out` 应远低于 2500，错误行显著减少）。

## 四、遗留

1. 若把上限抬到 2500 后仍出现 `finish_reason=length`，说明该 task 的单轮输出确实超长，
   下一手应是**拆轮**（把 evidence/counterargument 与 horizons 分成两次调用），而不是继续抬上限。
2. `MiniMaxTransport` 仍注册（供回滚），未清理。
