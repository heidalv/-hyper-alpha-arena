# 全链路持续优化 · 第3轮（2026-09-16 调研轮16）

> 用户指令：「对 AI 自动交易全链路进行持续优化」；此前明确「现在就是在弄**中线选币**和

## 1. 结论

**AI 选币不是"选得不好"，而是选出来的币在执行层根本没有策略行 —— 与论题质量、与任何
风险闸都无关。** 已修好并线上验证。

```
按 symbol 归因（审计 JSONL，近 7 天，session=fa_7e12e7a1b6）

  DOT   25 行  100% skip@exec   eval_false:no_active_strategy   ← 策略供给缺口（缺陷）
  FET   31 行  100% skip@writer regime_extreme×26 / long_regime_block×5  ← 方向闸（合法）
  TIA   51 行  100% skip@writer long_regime_block×51                     ← 方向闸（合法）

策略宇宙（active）: BTC,ETH,SOL,BNB,VIRTUAL,ASTER,XPL,UNI,XRP   ← 恰好 9 个固定币
AI 候选池        : mid=[APT,DOT]  long=[FET,APT]                ← 与上面**零交集**
```

`proposal_execution.py:93` 要求 `ai_strategies(primary_symbol, timeframe_tier, status='active')`
存在，否则**在进入任何风险闸之前**丢弃提案。而：

- 建策略链 `auto_create_strategy` → `auto_launch_strategy` 与 `bg_create_strategy`
  （自带"已废弃，不应被调用"）**全仓无调用点**；
- 唯一在跑的建策略路径是 `health_check_cycle.py:827` 的模板匹配，它只遍历
  `session.symbols`（9 个固定币），AI 候选池内的 symbol 不在其迭代范围内
  （实测 22:39–22:40 它为 SOL/BTC/ETH/VIRTUAL 建了 `tpl_*` 策略，但没有 DOT/APT/FET）。

⇒ **"AI 选币"选出来的币 100% 死在"没有策略行"。** 这是策略供给缺口，不是风控。

## 2. 修复：AI 候选的策略按需供给

`resolve_independent_strategy`（`midlong_helpers.py`）是那道"返回 None 就全盘拒绝"的闸，
在它尾部补一步：**真的走到开仓时**为 AI 候选**克隆**一条策略行。

| 约束 | 实现 | 回滚 |
|---|---|---|
| 总开关 | `MIDLONG_AI_AUTOCREATE_STRATEGY`（默认 true） | `=false` |
| 每日上限 | `MIDLONG_AI_AUTOCREATE_MAX_PER_DAY`（默认 3） | `=0` |
| 作用域 | **只对当前 AI 候选池内的 symbol**（60s 缓存） | 池外一律不动 |
| 实盘许可 | `MIDLONG_AI_AUTOCREATE_LIVE`（默认 **false**，实盘从严） | `=true` |

- 克隆母本 = 同账户同层 active 策略（优先 `full_auto`），杠杆/仓位口径/因子集合一致；
  **不继承 `genome`**（母本 genome 内嵌原 symbol 的模板绑定，跨 symbol 无意义）。
- 失败方向全部保守：候选池读取失败 ⇒ 不补；计数读取失败 ⇒ 按超限处理；任何异常 ⇒
  保持历史行为（拒绝）。**不允许本闸变成新的放行口。**
- 风险边界不变：只解锁"允许评估"，开仓仍要过论题 + 全部既有入场闸
  （相关性簇 / 组合预算 / 位置闸 / regime / 持久性）。
