## 2. 根因：两处叠加，都不在上游

### 根因① `_enforce_min_sl()` 每 tick 推翻上游封顶（下限无脑赢）

`paper_trading_engine` 每个保护 tick 调 `_enforce_min_sl(pos, entry, nature)`，按 nature
**硬下限**把 SL 往外推：`swing 4.5% / position 5.5% / trend_follow 6.5%`。

于是上游三层封顶（轮7 提案层 `clamp_stop_distance`、价格层 `tp_sl_prices`、轮15
`PosMgr._calc_tp_sl`）**在下单瞬间生效、下一个 tick 就被推翻**：实测 6 笔未平仓的
SL 距离**全部精确等于该下限**（4.67% = 4.5% + 均价漂移；6.50% = 6.5%）。这也解释了
为什么轮7/轮15 改了代码、日志都打出了"sl=2.00%"，库里却是 4.5%。

### 根因② 同一语义两种键名拼写，mid 层静默失效

| 层 | 键 | `.env` 原状 |
|---|---|---|
| 提案层（轮7） | `MIDLONG_MAX_SL_PCT_<TIER>` | MID=0.02 ✓ / LONG=0.03 ✓ |
| 引擎收口层（§88 2026-09-11） | `MIDLONG_SL_MAX_PCT_<TIER>` | **只有 LONG=0.03，没有 MID** |

引擎层读的是后者 ⇒ mid 层 `cap=0` ⇒ 上限形同虚设；long 层虽配了 3%，但被根因①
在下一个 tick 拉回 6.5%（实测 BTC long 正是 6.50%）。

### 为什么这件事最值钱

24h 归因：`sl` n=3 净 **−105.20**（单笔约 −35），是最大亏损源；而赢家持仓期最大逆行
（MAE）只有 **1.20%**（n=18）。止损给到 4.5% ⇒ 输家一路走到 4.5% 才砍、赢家几乎从不
深水（≤1.2%）→ 盈亏比结构性倒挂。反事实（轮7 已算）：cap=2% 时 0/18 赢家被误杀，
区间净额 −23.49 → **+73.54**。

## 3. 修复（5 个文件 + `.env` + 事实清单）

| 文件 | 改动 |
|---|---|
| `paper_trading_engine.py` | ①`_enforce_min_sl(pos, entry, nature, tier)`：**上限比下限更紧时下限降为上限**；②同 tick 紧邻调用 `clamp_sl_price` 收窄"过远"的存量 SL（只夹过远一侧，**保本/盈利侧永不触碰**） |
| `master_execution.py` | AI 动态调价块同族"最小距离"同样让位于上限，并收口（否则 AI 想收紧的 SL 会被推远） |
| `midlong_trade_design.py` | `clamp_stop_distance` 同时接受两种拼写；**显式 0 = 关闭**，不再回退另一键 |
| `settings.py` / `env_registry.py` | 声明并登记 `MIDLONG_SL_MAX_PCT` / `_MID` / `_LONG`（§73.4） |
| `.env` | 补 `MIDLONG_SL_MAX_PCT_MID=0.02`（附 6 行说明为何必须用这个键名） |
| `docs/RUNTIME_CONFIG_FACTS.md` | 新增「止损距离：上限赢过 nature 硬下限」章节；同时补齐轮11/14 漏同步的两项传输名单（漂移检查恢复 **NO DRIFT**） |

**上线前风险评估**（新增只读脚本 `backend/scripts/audit_sl_distance_cap.py`）：存量 6 笔
全部超上限，但**没有一笔会被立即打掉**（最深的 XRP 才 −1.23%，对 2% 上限仍有余量）。

**回滚**：把对应键显式置 0 —— 下一 tick `_enforce_min_sl` 会把 SL 拉回旧下限（**自愈**，
不需要改库）。契约测试含该路径。
