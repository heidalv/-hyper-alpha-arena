# 轮132 致命修复 + 去掉 LLM 省钱限制 + 开仓漏斗打通 — 2026-09-20

## 一、致命 bug（把中线开仓全挂的那个）
实测日志（11:47 起 **24 次**）：
```
[MidLong] stage=fuse tier=mid symbol=AAVE 熔断窄带 paper 缩仓×0.25（…）
[MidLongBrain] 开仓失败 AAVE mid: name 'tier' is not defined
```
回溯定位（`exc_info=True` 落盘的回溯）：
```
File "backend/services/full_auto/midlong_executor.py", line 316, in apply_regime_to_open
    tier, sym_u, act, reg_size * 0.5,
NameError: name 'tier' is not defined
```
`apply_regime_to_open()` 的 **ranging 分支**日志打了 `tier=%s`，但该函数**形参里没有 `tier`**；
而当前最常见的 regime 恰是 `ranging` ⇒ 每次开仓走到这里必抛异常，被 `maybe_open` 兜成
「开仓失败」⇒ **中线零成交**（AAVE 11:47 `accepted=1 rec_open=1` 却无成交即此因）。

同类问题还有三处（同一函数/调用链）：
| 位置 | 问题 |
|---|---|
| `apply_regime_to_open` ranging_block 分支 | 2 个 `%s` 只给 1 个实参（logging 内部报错、输出被打断） |
| `apply_regime_to_open` 调用点 | 漏传 `tier` |
| `execute_midlong_open` hold 分支 | 6 个 `%s` 只给 5 个实参（缺 `tier`） |

**根因**：轮124/125 批量给 `[MidLong]` 日志补 `tier=%s` 时，没有校验"这个名字在该函数里是否在作用域内"。
这与 轮117 的 `name 'side' is not defined` 是同一类事故（当时也是打日志用了作用域外的名字）。

### 修复与防回退
- 补 `tier: str = ""` 形参（docstring 记录事故）；三处日志实参补齐；调用点传 `tier`。
- 新增守卫 `backend/tests/unit/test_midlong_log_scope_guard_20260920.py`（**全库扫描**，8 项）：
  ① 占位符数 == 位置实参数（抓静默 logging 错误）；
  ② 实参裸名字必须在**本函数 / 外层函数（闭包）/ 模块级**作用域内（抓 NameError）；
  ③ 专项：打了 `tier=%s` 的日志，作用域里必须有 `tier`；
  ④ 运行时：`apply_regime_to_open` 四个 regime 分支 + 不传 `tier` 都要能跑通。
  > 首版守卫有**误报**（把模块常量与闭包变量当成"作用域外"）——已按 Python 作用域语义精确化后再用；
  > 误报修掉后全库 8/8 通过，说明其余疑似点确为闭包/常量。

## 二、按用户指令去掉"为省 LLM 预算"的限制
用户原话：「强调过，先不要考虑 llm 预算，你怎么还想给我省，你这个省会坏大事情」。
`brain_debate` 默认值全部改为**不为省钱设限**：

| 开关 | 原 | 现 |
|---|---|---|
| `MIDLONG_DEBATE_LLM_RISK` | false（风控角色走规则，省 3/5 调用） | **true**（风控角色也走 LLM） |
| `MIDLONG_DEBATE_MAX_ROUNDS` | 1 | **2** |
| `MIDLONG_DEBATE_HOURLY_CAP` | 6 | **0 = 不限**（>0 才生效，仅作失控保护） |
| `MIDLONG_DEBATE_COOLDOWN_S` | 1800 | **120**（仅防同 tick 重复，非预算控制） |

保留开关只为**可控性/回滚**，不再是省钱手段；`env_registry` 注释同步更正。
