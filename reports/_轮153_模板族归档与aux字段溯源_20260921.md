## 五、`active_addresses` 空值溯源

### 5.1 谁在写（唯一写入者）

```
unified_data_pool.py:580   record_aux_snapshots(_aux_db, symbols, onchain_data, social_data)
   ↑ 唯一调用者；闸门 UNIFIED_DATA_POOL_KLINE_AUX_ENRICHMENT（默认 true）
kline_enrichment_service.py:295  record_aux_snapshots(...)
   → 每 symbol 写一行 (symbol, timestamp_ms=now_ms)，同毫秒则更新（唯一键 symbol+timestamp_ms）
   → 取值全部来自 onchain_data[symbol] / social_data[symbol]，缺失即 None
```

`onchain_data` = `onchain_collector.collect_all(symbols)`；
`social_data` = **硬编码空字典**（`unified_data_pool.py:568`，注释写明
`social_sentiment_collector 已于 2026-08-17 移除`）。

### 5.2 逐列：源在哪、为什么空（近 3 天非空率）

| 列 | 近 3 天非空率 | 唯一来源 | 为什么空 |
|---|---|---|---|
| `fear_greed` | 100.0% | alternative.me（`_collect_fear_greed`） | — |
| `btc_dominance` | 100.0% | `_collect_btc_dominance` | — |
| `tvl` | 100.0% | DefiLlama `_collect_tvl(symbol)` | — |
| `exchange_net_flow` | **0.0%** | **仅 Coinglass**（`cg_chain[base]`） | 需要 Coinglass key；无 key 时 `_collect_coinglass()` 返回 `{}`（默认无 key） |
| `whale_tx_count` | **0.0%** | 无真实源 | 2026-07-10 数据修复**删除了合成假数据**（原 `n_tx//500`、`estimated_btc_sent*30%`）；真实源需付费 API |
| `whale_tx_volume` | **0.0%** | 同上 | 同上（原 `estimated_btc_sent*15%/30%` 已删） |
| `active_addresses` | **7.1%**（720/10081） | **仅 BTC**：`_collect_blockchain_info` → `result["active_addresses"] = int(data["n_tx"])` | ① ETH 那路的合成值（`block_num % 100000`）已在 2026-07-10 删除；② **语义错标**：写入的是 blockchain.info 的 `n_tx` = *全比特币网络日交易笔数*，不是活跃地址；③ 只有 BTC 分支拿得到（`collect_all` 里 `base=="BTC"→btc_chain`，其余 symbol `chain_data={}`） |
| `social_score` | **0.0%** | `social_data`（社交采集器） | 采集器 2026-08-17 移除，`social_data` 恒为 `{}` → 永远 `None` |
| `news_sentiment` | **0.0%** | 同上 | 同上（且 `context_pack` 的 SELECT 取了这个列但**没有**往下发，取了也不用） |
| `discussion_volume` | **0.0%** | 同上 | 同上 |

**一句话回答"为什么空"**：这张表只有 3 个字段（fear_greed / btc_dominance / tvl）
来自**免费且无需 key** 的全局宏观源，所以恒满；其余 6 个字段全部依赖
（a）付费 key（Coinglass）、（b）已被删除的社交采集器、或（c）2026-07-10 为了
"不编数"而主动删掉的合成路径 —— 因此结构性为 NULL，不是坏了。

**`active_addresses` 的特例**：它是唯一"有值但错"的列 —— 22 个非 BTC symbol 全 NULL，
BTC 有值却是**网络级日交易笔数**被挂在"活跃地址"名下（3 天 720 行，即采集器差不多每 6 分钟写一次同一个日频数字）。
