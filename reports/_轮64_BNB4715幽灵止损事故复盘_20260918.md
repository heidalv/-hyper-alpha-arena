## 二、成因链（四层缺陷叠加，缺一不可）

### 缺陷① 峰值用「比例」持久化，加仓换均价后不换算

```
peak_pnl_pct = 峰值价 / entry − 1        ← 只在 entry 不变时有意义
```

加仓把 entry 从 **737.573485** 加权到 **742.519273**，但加仓路径只重置了
`tp_level_reached` 与 DSM 追踪状态，**没有动 `peak_pnl_pct`**。

### 缺陷② 用失真的比例反推峰值 → 幽灵峰值

```
_peak_price_from_pos:  long 峰值价 = entry × (1 + peak_pnl_pct)
```

- 用**旧** entry 反推：737.573485 × (1 + 0.052059) = **775.9711** ← 与 SL/0.985 完全吻合
- 用**新** entry 反推：742.519273 × (1 + 同一个比例) = **781.17** ← 比真实峰值高 5.20

### 缺陷③ 峰值追踪融合把幽灵峰值写进 SL

`_run_v2_protection` 的保本推进处：

```python
_cand = max(_sl, _peak_price * (1 - 0.015))     # long
```

→ `775.9711 × 0.985 = 764.331523` 被写进 `pos.sl_price`。

### 缺陷④ SL 落在现价错误一侧 + 成交价用 SL 价

```python
hit = (pos.side == "long" and current_price <= float(pos.sl_price))
# 751.0 <= 764.33 → 恒真 → 立即触发（且是"反向"触发）

close_position(..., fill_price_override=float(getattr(pos, _px_attr) or 0))
# 用 sl_price 成交，而不是市价 → 幽灵成交
```

**注意 `breakeven_tp` 这个标签是结果不是原因**：

```python
def normalize_close_reason(reason, pnl):
    if r == "sl":
        if pnl > 0: return "breakeven_tp"     # 止损被记成"保本止盈"
```

实际触发的是 **SL**，只因成交价被抬到市价之上才显示成盈利止盈。

**四层叠加的净效果**：加仓（正常）→ 峰值失真 → SL 被推到现价上方 → 立即以该价成交 →
账面 +12.11，而真实情况是**加仓价 752.596 高于当时市价 751.0，加仓那部分当场浮亏**。

## 三、修复（三层，各自独立）

### ① `rebase_peak_pct_for_entry()` —— 换均价时保持峰值价格不变

峰值价是客观事实，比例只是它的表示口径。加仓路径调用：

```python
_old_entry = float(existing.entry_price or 0)
existing.entry_price = (…)                      # 加权平均
…
self.rebase_peak_pct_for_entry(existing, _old_entry, existing.entry_price)
```

- long：`peak_new_pct = 峰值价 / 新均价 − 1`
- short：`peak_new_pct = 1 − 峰值价 / 新均价`
- `peak_unrealized_pnl`（美元口径）同样按新仓量重算

### ② `safe_sl_price()` —— 保护侧不变式

多头 SL 必须 **低于**现价、空头必须 **高于**现价，否则拒绝写入。

接入点（全部 SL 写入口）：峰值追踪融合、分批锁利、`_tighten_sl_unified`
（staged_tp1/2/3、unified_trailing、profit_drawdown、breakeven_sl）、
ExitPolicy `tighten_sl`、`update_position_tp_sl`。

**设计取舍**：取价走 `_as_float_or_none` + 与 entry 偏离 ≤50% 的可信度检查，
**市价不可用/不可信时放行** —— 宁可漏拦一次，也绝不因为一次坏取价而 *放弃* 止损管理。

### ③ `reprice_position` 成交价修正 —— 成交价不得优于市价

```python
_fill = min(trigger, market) if long else max(trigger, market)
```

正常情况 SL 就在市价止损侧，仍按 SL 线成交（保持原语义）；仅当触发线越界时才用市价兜住。

## 六、为什么现在才暴露

`add_count` 全库绝大多数为 0（本次事故是少见的真实加仓）。这条路径需要
**「已有可观浮盈」×「发生加仓」×「峰值够高以致 ×0.985 落到现价之上」**三者同时成立，
概率低但一旦成立就必然幽灵成交。事故前 5 个开仓持仓全部 `add_count=0`，故未复现。

**潜在同类风险（已由不变式兜住）**：`trend_e1` 接管存量长仓时（`_adopt_position`）
也会继承按旧 entry 算出的 `peak_pnl_pct`；不变式会在写 SL 时拒绝越界值。
