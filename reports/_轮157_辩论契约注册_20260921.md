# 轮157 —— 牛熊辩论的输出契约从未注册（导致"契约打架"）

日期：2026-09-21
来源：轮155 全面验证里留下的遗留项 ①（`mlto_debate` schema 失败率极高）——本轮把它查到底并修掉。

---

## 一、根因

`ModelGateway.call` 做两件事：
```python
if system and schemas.CONTRACT_MARK not in system:
    system = f"{system}\n{schemas.output_contract(schema_task or task)}"   # ① 注入契约
...
valid, errs = schemas.validate(schema_task or task, obj)                     # ② 校验
```
而 `validate()` 对**未注册**的 task 走 `COMMON_REQUIRED`
（`direction / strength / confidence / key_factors / summary`）。

审计（`scripts/_probe189_task_schema_audit.py`，全部 `gw.call/dual_call/run_dual_task` 调用点 vs
`TASK_SCHEMAS`）结论：**`mlto_debate` 是唯一一个未注册的 task**，于是：

- **牛方/熊方**：按辩论自己的 prompt 输出 `{argument, evidence, horizons, counterargument, weakness, confidence}`
  → 被判 schema 失败（`status=error`）。8h 统计：MiniMax 时期 **444 error / 560 = 79%**。
- **风控轮**：反过来**照抄了注入的公共契约**（`summary/direction/strength/key_factors`）
  → 校验通过（`status=ok`），但辩论解析器要的是 `argument` → **读不到** → 静默退化成规则中性。
- 近 12 行账本实测：`argument` 只出现 5/12、`confidence` 7/12 —— **一半的辩论轮根本没进辩论层**。

> 这也解释了轮155 报告里那条"辩论 schema 失败率与模型无关"——它确实与模型无关，
> 是**契约注册缺失**，任何模型都必然踩。

## 二、修法

`schemas.TASK_SCHEMAS` 新增 `mlto_debate`（契约来自 `debate_layer` 的两个 prompt +
`brain_debate._horizon_instruction`）：

```python
"mlto_debate": {
    "required": {"argument": "str", "confidence": "number:0:1"},
    "template": {argument, confidence, evidence, counterargument, weakness,
                 horizons: {intraday|swing|trend: {stance, confidence, argument}}},
}
```

- 只把 `argument` + `confidence` 列为**必填**：`horizons` 是嵌套对象且辩论层自带
  `_salvage_horizons` 容错，不该让整轮在账本里变 error；
- `horizons` 写进 **template** ⇒ 注入 system 的契约与辩论 prompt 一致（含三周期与 stance 枚举），
  从此不再出现"两套 JSON 契约打架"。

附带的观测改进：`extract_json` 失败时账本只写"输出中无可解析 JSON"，无任何原文线索
（辩论轮约 1/3 落这一类）。现在加原文摘要（只加观测，不改判定），下一轮可据实定位。

顺带修好一个**既存红测试**：`test_analysis_schemas_20260904.py::test_每个task的template与required类型自洽`
用"任何 dict → weights"的粗推断，把 `midlong_thesis.invalidation`（`inv_px`）误判 ⇒ 恒红。
改为直接调用**生产校验器** `schemas._check`（判据与线上一致，且更强）。
