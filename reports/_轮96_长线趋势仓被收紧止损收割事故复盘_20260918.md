#### 长车道（ETH/SOL-4714/LINK）：`midlong_position_manager` 的 2×ATR 收紧

`exit_state_json.trend_adjustment = {"trailing_atr_mult": 2.0}`（ETH/BNB）、`1.8`（SOL）。

```python
# midlong_position_manager.py:1796-1814
if _review_action == "tighten_trailing":
    _atr_mult = float(_trend_adj.get("trailing_atr_mult") or 0)      # 2.0
    _atr_pct  = float(_sym_mkt.get("volatility_value", 0.02))        # 短周期 ATR% ≈ 0.5%
    _band = mark * _atr_pct * _atr_mult                              # ≈ 1.0% 价格
    _new_sl = mark - _band                                           # 止损 = 现价 − 1%
    _exec_tighten(..., new_sl=_new_sl, ...)
```

| pos | 峰值 | 反推 `mark`（= sl/(1−1.0%)） | 实测峰值 |
|---|---|---|---|
| 4713 ETH | +3.11% | 2495.85/0.99 = 2521.1 → **+3.14%** | ✅ |
| 4716 LINK | +6.03% | 11.9607/0.99 = 12.0815 → **+6.06%** | ✅ |

即：**趋势复查一旦判 `tighten_trailing`，就把止损拉到"现价下方 1%"**；
下一次 1% 级别的正常回撤就把一笔设计持仓 3–7 天的趋势仓扫出局。
`_band` 用的 `volatility_value` 是**短周期**波动率（ETH ≈ 0.5%），
对一个 4h/1d 判断的趋势车道来说这是 scalp 量级的带宽。

## 二、用户三个判断的核实

### ① "我不相信 LLM 能让全部止盈" —— **成立**

7 笔全是机械止损线成交，没有一笔走 LLM 的止盈决策。
（讽刺的是：长车道的止损**之所以**被拉近，触发因是 LLM 趋势复查给出 `tighten_trailing`；
但**执行**的是硬止损线，不是止盈。）

### ② "是不是有好几个点在同时控制仓位管理" —— **成立，而且比想象的更多**

当前能写 SL / 决定出场的地方（`grep` 实测）：


而 `unified_exit_state_machine.py` 开头写的是：

> **"所有离场动作（close/reduce/tighten_sl）必须经此状态机仲裁。禁止任何模块绕开此处直调。"**

**这条不变量没有被执行**：`midlong_position_manager._exec_tighten()` 直接调
`paper_engine.update_position_tp_sl()`（`:1110-1114`），完全绕过状态机。

### ③ "之前不是统一了仓位管理么，怎么全没了" —— 统一过，但**守卫缺口**在长车道

`trend_e1_engine.py` 自己的文档（`:5-23`）声明：

> 出场 = 规则失效 或 收盘 < Chandelier(最高收盘 − 3×ATR20)
> `long_trend_v2.manage_long_position（midlong 循环）跳过`，不再双重管理
> `paper 引擎 max_hold 复审跳过`；**唯一出场 = 规则失效 / Chandelier**

实现侧的守卫只有三处：

| 位置 | 作用 | 是否覆盖本次事故 |
|---|---|---|
| `trend_e1_engine.long_lane_open_allowed` | 拦"非 E1 来源的 long 新开仓" | 只管开仓 |
| `paper_trading_engine.py:2955 is_e1_position` | max_hold 兜底强平跳过 | 只管 max_hold |
| `position_exit_orchestrator.py:63-65 if _is_e1_peo(p): continue` | PEO 分档 TP/trailing 跳过 | ✅ 有效，但**管不到 `midlong_position_manager`** |

**`midlong_position_manager.py` 全文没有一处 `is_e1_position`** ⇒
"midlong 循环跳过 E1" 只是**文档承诺**，代码里没人执行。
于是 E1 趋势仓照样被 midlong 的趋势复查管，照样被 `tighten_trailing` 拉近止损。

### ④ "开仓不到一天就全平" —— 与 `min_hold 72h` 的关系

`settings.TIER_PROTECTION_PARAMS["long"].min_hold_sec = 259200`（72h），
`unified_exit_state_machine` 第 10 行：**"硬事实层：SL/TP/爆仓/紧急回撤 → 直通执行（不可拦截）"**。

## 四、修复方案（需用户拍板，因为这是交易行为决策）

> **用户已确认：A + B + C + D 全做，并把 BTC #4712 的止损放回结构位。**
> 实施结果与验证见文末「六、实施记录」。

### A. 恢复 E1"单一出场"契约（最小改动，推荐先做）

在 `midlong_position_manager.manage_position()` 入口加
`if is_e1_position(position): return _summary("E1 独占车道，交 Chandelier 管理", action="skip")`，
并把这条不变量写成测试（E1 仓位不得被 midlong 改 SL）。
→ 效果：长线趋势仓不再被 1% 带宽的追踪止损收割，唯一出场回到"规则失效 / Chandelier"。

### B. 给 `tighten_trailing` 加**车道最小带宽**

长线车道收紧后的 SL 与现价距离不得小于 `max(2×ATR(4h), 3%)`（可配）；
即"要收紧也只能收到 3% 以内"，1% 级回撤不可能触发。
→ 效果：即使将来又有别的模块来收紧，也收割不了趋势仓。

### C. 让 `min_hold` 覆盖"追踪派生"的止损（最根本，改动最大）

把 SL 分成两类：**结构止损**（Chandelier / 初始 SL / 紧急）与**追踪派生止损**（tighten_trailing / trailing_lock / 保本）。
后者在 `min_hold` 内只允许"抬到某高度"而不允许**成交**（或直接禁止在 min_hold 内抬高）。
→ 效果：72h 最短持仓对"被挪近的止损"也生效，不再名存实亡。

### D. 放宽中车道追踪参数（改 `.env` 即可，可随时回滚）

`EXIT_POLICY_MID_TRAILING_ACTIVATION_PCT` 1.0 → 2.5~3.0；
`EXIT_POLICY_MID_TRAILING_CALLBACK_PCT` 0.5 → 1.2~1.5。
→ 效果：中车道（最短持仓 12h）不再"涨 1.5% 回吐 0.5% 就走"。

### 反向选择（不推荐）

保持现状，把这些微利出场当作"高胜率小止盈"策略接受。
**不推荐的理由**：长线车道的设计前提是"让利润奔跑"（`tp_stages=[8,15,25]%`，
止损 −8%~−16%），实际却在 +3%~+6% 被 1% 回撤退出，赔率结构被彻底破坏
（这次 7 笔合计只 +58.48，而单笔设计目标是 8%+ 的价格空间）。

## 六、实施记录（用户确认后，同日完成）

### 6.1 紧急处置：BTC #4712（唯一在册的长线趋势仓）

处置**前**：`entry 76464.5 / SL 80287.7 / 现价 80955.9` ⇒ 止损距现价只剩 **−0.825%**，

处置留痕写进 `exit_state_json.trailing_suppressed`（可审计、可回滚）。

### 6.2 Fix A —— E1 长车道独占守卫

`midlong_position_manager.manage_position()` 开头新增 `is_e1_position` 判定：
E1 仓位直接返回 `action="manage_skip_e1"`，**不滚仓 / 不收紧止损 / 不减仓**。
守卫位置在**所有副作用之前**（有测试断言）。
守卫自身 import 失败时按"非 E1"继续 + WARNING（理由写在代码里：fail-closed 会连带停掉
mid 车道的正常管理，而 import 失败本身已意味着 E1 整链断裂）。

### 6.3 Fix B —— 车道最小收紧带宽

抽出可测纯函数 `clamp_tighten_band(side, mark, new_sl, tier)`：
收紧后的止损与现价距离不得小于 `MIDLONG_TIGHTEN_MIN_BAND_PCT_<TIER>`
（long 3% / mid 1% / short 0=不设限，可经 env 覆盖）。

- 方向不变式（有测试穷举）：该函数**只能把止损推远，绝不推近**；
- 因此它不可能"撤掉保护"——是否接受这个更宽的值仍由
  `update_position_tp_sl` 的「只收紧不放宽」规则裁决；
- 顺带修掉一个配置陷阱：`_cfg_float` 走 `getattr(settings, key, default)`，
  **属性未在 settings 声明时 env 覆盖静默失效** ⇒ 三个键已补进 `settings.py`
  并登记 `env_registry.KNOWN_FLAGS`，另加一条测试钉住"必须在 settings 声明"。

### 6.4 Fix C —— min_hold 内拒付「追踪派生」止损（最根本）

给止损加了**来源标记**，把"锁利工具"与"保护工具"分开：

- `update_position_tp_sl(..., sl_source=...)` 把来源写进 `exit_state_json.sl_meta`；
- 7 个**追踪派生**写入点已标注（midlong / PEO ×2 / analyst_cycle / scalp_review /
  full_auto_trading_service ×2）；
- E1 的 Chandelier 与紧急止损**故意不标注**（有反向断言：它们是结构位，保护期不挡）；
- `reprice_position`（秒级硬线成交路径）在成交前调用 `_sl_min_hold_verdict`：
  **追踪派生 + 仍在 min_hold 内 + 止损位于盈利区 + 未触紧急亏损** ⇒ **不成交**，
  把止损回退到 `max(结构位, 入场×(1+最小锁定利润))` 并落库 `sl_deferred_min_hold` 事件。
- 回退位为什么不能只用结构位：E1 的 Chandelier 长期在入场价**之下**，直接回退等于把已锁利润
  全还回去 ⇒ 新增 `MIDLONG_MIN_LOCK_PROFIT_PCT_<TIER>`（long 2.5% / mid 0.5% / short 0）。
  浮盈不足 2.5% 时该地板在市价之上 ⇒ 退回结构位（趋势车道允许回吐到结构位，这是设计语义）。
- **失败方向**：判定异常 / 无结构位 / 亏损区 / 紧急亏损 ⇒ 一律**照常成交**。
  真实止损绝不因为"状态读不出来"被挡住。

### 6.5 Fix D —— 中车道追踪放宽（`.env`，可随时回滚）
