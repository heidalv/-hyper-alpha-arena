## 两处**自我更正**（都在本轮验证里被抓出来）

1. **"deepseek 非 2xx = 11" 是我的过滤器错误**：它把日志里任意含 `40`/`50` 的行都算了
   （延迟数字如 4050ms 也会命中）。改用 HTTP 状态码精确正则后：**102 × HTTP 200，非 2xx = 0**。
2. **`single_model + MiniMax-M3` 4 行不是当前行为**：已定位到 14:31–14:35 的过渡窗口
   （新代码 + 旧 `.env`），`.env` 生效后 32 行全部 deepseek。

## 遗留项（未修，如实列出）

1. **`mlto_debate` 的 schema 失败率很高，且与模型无关**：近 8h 按模型统计
   `MiniMax-M3`：error **444** / ok 116（79% 失败）；`deepseek-v4-flash`：error 9 / ok 6
   （样本小）。逐小时看，改造前每小时失败率也是 60~90%。
   ⇒ **这是该 task 的 schema/提示词与模型输出格式长期不匹配**，不是本轮引入；
   辩论层目前 record-only（`MIDLONG_DEBATE_APPLY=false`），不影响开仓，但这条链路实际上
   大部分时候产不出结构化结果，值得单独一轮修。
2. **图审无带图票**：DeepSeek 传输是纯文本（`complete()` 忽略 `images`），
   `images_for=["glm_opencode","glm_opencode_alt"]` 只在 GLM 被降级顶上主票时才会真的收到图；
   其余情况 K 线图无人消费，图审退化为数值深度分析。
3. **`MiniMaxTransport` 与 `MINIMAX_*` env 仍在**（有意保留供回滚）。
   要彻底移除：删类 + 摘 `TRANSPORTS`/transports 字典 + 删 `.env` 三个键 + 摘 env_registry 登记。
